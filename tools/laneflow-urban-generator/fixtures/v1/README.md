# LF-CN-URBAN 规范数据基线

本目录冻结[正式配置](../../../../examples/config/cn-urban.toml)的规范夹具 manifest。
源码入口与完整重建命令见[生成器说明](../../README.md)。夹具以固定配置、20-cell
生成规则和七个载荷的摘要表达；集成测试重建实际 LFRE / LFCA / LFSM / LFSD /
路线文件，逐个核对摘要、长度，再执行第二次重建的逐字节比较。这里不检入生成的大型载荷。

当前夹具来自 `laneflow-urban-generator-v2` / `cn-urban-template-v2`，没有随机编制
seed。共同模块在所有规模具有相同字节，topology 仅导入该共同模块。

`10k/` 与 `100k/` 是 2026-10-22 在 #819 资源预算校准后重跑的结果。相对 2026-10-04
多车道基线，三个规模的 manifest 都只有 `compiler_controlled_peak_bytes` 一项改变，
七个载荷的长度与 SHA-256、路网修订号和拓扑计数全部相同。旧报告保留在 git 历史，
#707 等研究目录中的历史证据副本没有改。

### #819 预算下降的来源

旧前端把 Typed AST record、reference 和 relation 的总和统一乘以最大
`TypedAstDeclaration` 的尺寸，100k 仅来源保留模型就计入 2,752,172,969 bytes。
现在按真正拥有的外层 enum、嵌套数组和独立 Box 计量，内嵌引用和来源位置不再重复
视为完整声明。共享字符串、owner 地址与位置 context 的保守上界保留；alignment
临时树、显式曲线段和 cubic 来源 Box 仍计入几何编译期间的 live base。输入冲突区域
的 `f64` ring 与编译输出的 `f32` 点表分开计量。

HIR 冲突阶段原来把整个编译单元的声明总数用作 Junction / ManeuverPath /
ManeuverGate 三张查找表的容量；现在使用各自实体计数，保留每项八桶的保守倍率。
100k 峰值仍落在 HIR 构建及策略绑定的保守模型上；release 构建读取本次接受的
来源后，私有计划统计与完整生成的 manifest 相互吻合：

| HIR 峰值组成（bytes）           |        校准前 |        校准后 |
| ------------------------------- | ------------: | ------------: |
| 已接受来源 / Typed AST 保留上界 | 2,752,172,969 |   796,709,801 |
| HIR 持久记录                    |   364,711,360 |   364,711,360 |
| HIR 查找预算                    |   467,524,305 |   467,524,305 |
| HIR 互斥阶段 scratch 峰值       |   338,371,888 |    41,380,184 |
| 策略绑定追加预算                |     7,735,528 |     7,735,528 |
| 合计                            | 3,930,516,050 | 1,678,061,178 |

来源模型减少 1,955,463,168 bytes，HIR 暂存模型减少 296,991,704 bytes，合计
2,252,454,872 bytes。准入峰值为 876,436,933 bytes；它包含临时 authoring 几何及
编译输出共存，低于上表的 HIR 峰值。HIR、MIR、LIR 与源映射的实际容器和释放顺序
没有变化，输出逻辑字节保持
111,116,294。前后 100k 编译阶段的实际累计分配请求均为 2,170,986,627 bytes、
净存活请求变化均为 368,079,937 bytes。这次减少的是模型的过度预留，不能解释为
实际堆峰值下降；#374 的完整分配器账本仍未由本任务完成。

## 共享根修复与验收边界

正式多流让行模板在原基线上能够编译并通过后发射检查，但共享根以
`Policy { policy: 0, violation: Reference }` 拒绝合法 LFCA。原因是加载器用 typed ordinal
数值顺序检查 classes / yield 集合，而
[规范格式合同](../../../../docs/design/portable-canonical-artifact.md)要求按被引用
StableId 字节序排列。修复只校正这两个集合的排序校验，保留越界、重复和逆序拒绝；
没有改公开 API、格式语义或资源上限。完整小型夹具覆盖真实多目标让行关系，另有
有限的顺序/重复/越界回归测试；共享根 39 项、编译器路权相关 69 项测试通过。

本基线只证明 #542 的静态交付。没有执行活跃车辆固定步进、七项需求计划、真实
parked 个体分配、Adapter、恢复或跨修订切换；这些状态不能由空世界的容量配置或
停车空容量代替。#304 的完整完成条件仍由对应后续切片满足。
