# 停车离场命令与活动集合研究

关联 #678；生产检查基线 `e048b8104d334f012109c7d2028b921041277b14`。
本目录交付测量入口、工作量证据及等价优化边界，不修改生产规则、公开 API、格式、
依赖或运行时索引布局。生产路径的新增观测点全部受 `cfg(test)` 约束。

## 结论与最小切片

三类成本需要分别处理：后车验证访问 Active；连续成功导致 Occupancy 重建；成功
park/leave 从 live 重建 Active 顺序。重复拒绝复用 Occupancy 已有效，不重复修复。

最小实施切片已单列为 [#696](https://github.com/illusion-tech/laneflow/issues/696)。
优先保留现有 Active 向量，对停车状态变更做保序插入/移除，并复用可失效的顺序
定位。它只解决成功命令的 live 扫描，不承诺解决后车扫描或占用重建。内部缓存若需
按槽位保存 `u32` 定位，另有约 `4 × slot高水位` B 的预算，不能拿下面不含身份定位
的有序整数模型冒充最终内存成本。第一次建表、零/连续/交错成功、槽位复用和
spawn/despawn/replace/step/restore/cutover 都须进入后续正式 A/B 和失败注入。

位图和分块结构能减轻 live 扫描，但保留 Active Vec 消费方式时仍需物化和复制，
改动面及额外存储较大，本轮不选择它们作为第一实施切片。若采用惰性顺序定位，
park/leave 不应只因状态序号变化而重建定位；真正的 live 顺序改变必须维护或失效。
可选缓存预留失败回退完整计算，不新增领域错误或部分提交。

Occupancy 局部桶更新/覆盖层只作为后续方向。不能由简化模型的加速倍数推导真实
`leave_parking` 收益。生产索引还包含按车辆排除的 suffix minima、跨边车身片段和
稳定顺序键；在 Active 中间插入后，旧记录的稠密 update sequence 不再能直接与
新记录比较。实施前必须解决顺序键、事务预留、删除/重绑定/slot世代及完整缓存
来源标记。覆盖层若无限增长，会把重建成本转移到每次查询；当前模型不替它证明
压实阈值和失败原子性。下一步应先对比有限覆盖层与局部桶的完整查询/内存，而不是
直接全局替换 step 的 CSR。

后车剪枝尚无可采纳的局部索引方案。现行谓词沿每个 follower 的已选 route 判定，
出口边上没有车不代表无上游 direct follower；循环出现项、合流所有分支和跨边
车身必须完整覆盖。静态 predecessor 一层查询不足，任意固定 hop 截断也不足。
若另做反向出现项索引，须量化动态路线后缀关联数、失效成本与保守距离界，并保持
原 stable order 的首个不安全 follower。没有证明时保留全扫描。

长期约束同步至 [停车设计 §9.1](../../docs/design/parking-system.md#91-命令批次成本与等价优化边界)。
以上是最小切片选择与后续实施边界，不是这三条生产优化已经交付。

## 生产测量口径

- AMD Ryzen 9 9955HX，Windows 11 Pro Insider 29661，Rust 1.98.0 MSVC。
  release opt-level=3、debuginfo=1、CARGO_INCREMENTAL=0，固定逻辑 CPU16、普通优先级。
  未独占物理核心、未停用其他应用；无 WPR、无并行 Cargo 构建。不是机器无干扰保证。
- 65 条边、64 个互不相交的退出路线、一个虚拟池。保持每批初始 Active 为128/1024，
  Parked 为64/4096，改变实际 API 次数1/16/64与成功比例0/50/100%；一次命令不构造
  不可能的50%比例。另测64次半成功的成功在前/拒绝在前排列，总计34个场景。
- 每个出口路线保留一个移动 follower：允许离场时位于10 m，不安全时位于61 m；
  出口70 m，车长4.5 m、速度10 m/s。其余 Active 在独立背景道路上。请求目标车辆
  在 live 顺序最前，移动 follower 在背景 Active 后面；明确测到的是这个首错位置，
  不是所有可能排序的平均值。成功后实际 Active 增长，初始 Active/live 跨比例固定。
- 每场景重新安装相同世界，先2批预热，再16批测量；三次独立进程。共102个场景
  实例、1632个测量批次、52608次实际计时 API 调用，全部样本保留。注册、生成、
  snapshot、断言、摘要和输出均在 API 计时外。
- `batch` 是该批逐次 API 耗时之和，不是包住断言/循环的总墙钟。每个新批次的首次
  查询包含冷 Occupancy 构建；预热暖的是代码/分配器，不在不同批次间保留车辆世界。
  每进程先算 nearest-rank 分位数，再取三进程中位数；max取三进程最坏值。每场景
  仅16批，批次p95/p99都退化为该进程max，不作尾延迟认证。命令分位数混合了该批
  所有调用，分析JSON另列成功/拒绝分组。
- 全部相同场景的最终完整 snapshot 摘要跨进程一致；工作量构建的摘要也与生产
  构建相同。拒绝结果核对精确 follower，全部拒绝场景完整 snapshot 不变。
  这是一套合成命令基线，不是城市 workload、10万车辆测试或产品认证。

## 完整性与失败边界

- 新增双上游合流定向用例：仅看出口边会漏掉两侧移动direct follower。删除/复用
  一个槽位后，首错必须仍按live顺序落到另一侧车辆；全部移除后成功离场，下一辆
  立即以第一辆为物理重叠blocker，失败不改snapshot。
- 既有 `leave_overlap_detects_cross_predecessor_and_repeated_occurrence_geometry`
  覆盖跨前驱车身与重复物理边；1 mm emergency边界与失败原子性用例继续运行。
  这些是必须保留的反例，不是所有未来候选索引完整性的形式证明。
- 所有结构模型对每个插入前缀核对全量参考；占用模型覆盖分散/单桶聚集，活动模型
  覆盖高/低活动率与逆序插入。模型未实现删除、compaction或内存失败，不能直接
  进入生产；这些属于后续实现的必需验收。
- 本地Runtime全套：370个非忽略单元测试，以及全部非忽略集成/文档测试通过。
  工作量矩阵、三轮无插桩生产测量和最终三轮结构实验单独执行。首个夹具因背景
  边长超过正式10000000 mm上限被编译器拒绝，修正为合法长度后才产生正式数据。
