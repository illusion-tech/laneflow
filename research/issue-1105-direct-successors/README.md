# 无内边直连后继声明修复的回归证据

本轮修复 LuST 转换器漏发普通段间后继的问题。`sumo:-20604` 与 `sumo:-22774`
的完整信号闭包分别包含 4 条、6 条关联路径，均通过生产编译、LFCA 发射及后发射检查。
原成功的 16,265 条边完整 f64 程序与规范 f32 点保持逐位相同，完整转换拓扑、控制器、
相位、机动门、停止线与 8,230 条原失败诊断也保持不变。

这只关闭 [#1105](https://github.com/illusion-tech/laneflow/issues/1105) 的拓扑发射缺口。
没有扩展 S1 算法或预算，也不构成 S1 生产 G1 接受、连续误差认证或 LuST 全网转换成功。

## 设计与实现边界

[G1](https://github.com/illusion-tech/laneflow/issues/1105#issuecomment-6443917513) 与
[G2](https://github.com/illusion-tech/laneflow/issues/1105#issuecomment-6443948374)
在实现前记录。现行权威见[道路编辑前端 §9.3.1](../../docs/design/road-editing-source-and-geometry-frontend.md#931-拓扑几何-lowering-闭包)
与[真实路网工作负载 §3.1](../../docs/design/real-road-workloads.md#31-lane-graphid-与-route)。

生产变更仅位于转换器 `output/emit.rs`：从已经归一化且内边列表为空的路径收集
entry → exit 后继，按发射边键排序并去重。含内边的转换继续由路径独占；既有路径和
控制信息不删改。回归入口复用同一个后继声明函数，编译器及生产几何实现没有修改。
无内边路径也必须继续通过端点与方向检查，不能靠补后继跨过真实空间断缝。

## 固定 84 条路径的结果

使用 [#1103 的原始队列及候选](../issue-1103-s1-recovery-budget/README.md)。没有重新搜索
候选；从保存的完整 f64 位模式重建原候选，并验证重建结果逐位相等。32,768 与
262,144 两档均沿用原候选池和前 128 次共享赋值的顺序。

| 检查范围                             | 修复前 | 修复后 |
| ------------------------------------ | ------ | ------ |
| 原程序完整路径接受                   | 22     | 24     |
| 原程序跨边方向拒绝                   | 3      | 3      |
| 原程序缺少真实几何                   | 57     | 57     |
| 原程序缺少后继导致拓扑拒绝           | 2      | 0      |
| 两档固定候选各自最佳共享赋值的接受数 | 23     | 25     |
| 两档固定候选各自缺少真实几何         | 56     | 56     |
| 有信号目标接受                       | 0 / 31 | 2 / 31 |

两条目标的变化分别代表整个控制器闭包通过，不能把目标数与关联路径数混用。
其余 82 条目标的完整结果与原证据相同，包括原已接受路径的全部边长、控制锚点和
关联路径。原有 14 条多内边目标仍有 3 条接受；本修复没有带来新的几何候选。
31 条有信号目标中的其余 29 条仍在真实程序缺失阶段停止。

## 两处生产信号闭包

另用公开生产入口 `compile_network_lfca` 独立编译两处原始源形状及完整控制器闭包，
没有通过研究候选替换几何。两次后续运行生成的 LFCA 均逐字节相同。

| 路口          | 边  | 关联路径 / 机动门 / 停止线 | 控制器 / 组 / 相位 | LFCA 字节 |
| ------------- | --- | -------------------------- | ------------------ | --------- |
| `sumo:-20604` | 8   | 4 / 4 / 4                  | 1 / 1 / 4          | 53,959    |
| `sumo:-22774` | 12  | 6 / 6 / 6                  | 1 / 1 / 4          | 63,940    |

闭包单独编译会依据该闭包重建几何钳制，因此将其修复前后的完整程序另存并比较；
同时独立比较全网原成功边的完整程序。两组比较均通过，不用局部重建代替全网不变性。

## 完整不变性与确定性证据

修复前源提交为 `4d377ff3`，修复后源提交为 `4ebd388b`；完整 SHA、可执行文件摘要及
运行状态见 [protocol.json](protocol.json)。固定输入为 LuST
`c4bd5bd3751d426d42a9a1749c815e47ea188549`，输入文件经过现有验证器校验。

每次运行先捕获真实生产发射结果，再保存下列完整内容。修复后的两次独立进程均用
Rust 逐行比较完整基线，导出时又用 Windows `fc.exe /b` 独立比较全部字节。

| ---------------------------- | ---------- | ---------------------- |

不变性结论依据完整值和完整字节比较，不依据摘要相等推断。
原始文件及两个可执行文件保留于 `protocol.json` 指定的本机证据目录；大体积完整几何
不重复纳入 Git。复现时可从上述两个冻结提交重新生成并比对。

- [baseline-results.json](baseline-results.json)：修复前完整路径与生产闭包拒绝证据。
- [results.json](results.json)：修复后全部目标、控制闭包、候选赋值及生产闭包结果。
- [comparison.json](comparison.json)：比较计数、完整文件字节数与摘要。

## 复现与检查

在两个冻结提交各自的工作树使用 Rust 1.99.1 release 测试构建，并运行
`output::emit::s1::recovery_coverage::successors::pinned_lust_direct_successor_regression`。
该测试为显式 `ignored` 入口，需使用 `--ignored --exact --nocapture --test-threads=1`。

| 环境变量                        | 内容                                           |
| ------------------------------- | ---------------------------------------------- |
| `LUST_SOURCE_DIR`               | 上述钉版 LuST 源目录                           |
| `DIRECT_SUCCESSOR_OUTPUT_DIR`   | 每次运行均不存在的新输出目录                   |
| `DIRECT_SUCCESSOR_BASELINE_DIR` | 修复前运行不设置；修复后指向修复前完整输出目录 |

固定候选及队列直接从仓库原始证据读取，不接受替换样本或搜索参数。修复前程序会断言
结果与 #1103 原始证据相等；修复后程序会断言恰好两处原拓扑拒绝转为接受。

本地 `cargo test --locked -p laneflow-lust-converter` 与 release 版本均为
218 passed、0 failed、16 ignored；本轮完整回归入口另显式执行三次且全部通过。
`cargo check --tests`、Clippy 全 targets 的 `-D warnings`、rustfmt 及差异空白检查通过。
四项新增常规回归覆盖重复目标、输入顺序、内边权威、混合路径的完整信号闭包与空间
断缝拒绝。这里的运行时间仅用于诊断，没有性能比较结论。
