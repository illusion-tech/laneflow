# 实际整数内存页注入与取证底座

关联 [#963](https://github.com/illusion-tech/laneflow/issues/963)，设计依据为
[完整性设计](../../docs/design/traffic-runtime-state-integrity.md) §2.5 / §4.2 / §5、
ADR 0032 与[验证矩阵](../../docs/reference/validation-matrix.md)的页指纹判读口径。
实现为 [static-network 测试模块](../../crates/laneflow-static-network/src/page_injection_tests.rs)，
只进入测试二进制，无生产 API、数据格式或默认认证行为变更。

## 实际覆盖的内存

父进程经 Compiler 发射含 4,096 条不同长度车道边的合法 LFCA，再经真实 reader / builder
建根并要求健康认证 `Pass`。引用从仍健康的来源 reader 冻结，不从待改写修订反向提取。
每个修订子进程独立读入同一 LFCA、重新建根，并在改写前再次要求健康认证 `Pass`。

目标是实际分配的 `lane_lengths_millimetres`：4,096 个 `u32`、16,384 B。先读取系统页大小，
再按实际分配地址找到三张完整页，选择中间页，使两侧各有一张完整供体页。
只接受已确认的 4,096 B 系统页；其他页大小、范围不足、地址溢出或非整数对齐均拒绝，
不记页覆盖。页大小来自仅供测试的
[`page_size::get`](https://docs.rs/page_size/0.6.0/page_size/fn.get.html)；该依赖与其平台依赖
纳入 cargo-deny，未增加仓库手写 `unsafe` 或放宽源码审计。

在 `Arc::get_mut` 确认唯一拥有、且没有活动借用时，用安全整数切片写入该完整页；
随后结束可变借用，调用真实认证入口。没有替换候选或实际侧读取视图，也不伪造认证结果。
页内只包含任意位模式都有效的 `u32`，不写指针、引用、枚举、`bool` 或 `Vec` 元数据。

这里证明的是实际分配内、系统虚拟页对齐的受控软件写入。虚拟地址不证明物理页帧归属、
物理连续性或真实 DRAM 故障，也不证明运行中持有不可变借用时能以同样方式注入。

## 内容、认证与控制组

| 请求       | 对实际目标页的操作       | 修订侧认证                                  | 按读回内容判读            |
| ---------- | ------------------------ | ------------------------------------------- | ------------------------- |
| 健康       | 不改写                   | `Pass / None`                               | `Unchanged`，只计健康对照 |
| 零页       | 全页整数置零             | `Mismatch / SharedStaticRoot / DisableRoot` | `Zero`                    |
| 整页替换   | 全页填入不同的整数值     | 同上                                        | `Replaced`                |
| 负一页供体 | 复制同一分配内前一完整页 | 同上                                        | `Shifted(-1)`             |
| 正一页供体 | 复制同一分配内后一完整页 | 同上                                        | `Shifted(1)`              |
| 局部变化   | 页内首个整数翻转一位     | 同上                                        | `Partial`，不计整页替换   |

每种请求分别运行修订组和普通整数控制组，共 12 个独立子进程。控制组使用独立确定性
整数序列，不读 LFCA、不建根、不调用认证；它验证同类分配、页范围、内容变换与判读。
这不是故障机硬件归因，也不是两种独立物理访问路径的环境 A/B 证据。

子进程保留改写前、改写后及认证返回后的整列原生端序字节。父进程另从健康来源重建
期望列，核对全部字节与未改写区域，验证前后分配地址没有移动、页范围确实位于整数列内，
并按完整证据核对失配阶段、component、表、entity kind、序号、字段、期望值与实际值。
认证返回后的读回必须仍与改写后内容一致。

指纹由读回内容计算，不直接复制请求名称：先判未变与全零页，再逐字节比较相邻供体页；
之后按验证矩阵 §8.1 判近零页：非零字节至多 16 个，且至少 256 个原非零字节被清零，
两项同时成立才记 `Zero`。精确供体匹配仍优先记 `Shifted`。
余下情况将页均分 16 段，至少 12 段不同才记 `Replaced`，否则记 `Partial`。
首个分歧偏移和差异字节数单独留档；首个分歧不一定恰落页首，不能用它替代整页判读。

## 近零内容判读回归

[内容回归](../../crates/laneflow-static-network/src/page_injection_tests/fingerprint_tests.rs)
与 [digest-probe 回归](../../xtask/src/digest_probe.rs) 对照同一近零阈值：

- 原页一半非零或全页非零，改后只剩 1 B 非零，均识别为 `Zero`。
- 改后非零字节数 15 / 16 / 17，与被清零的原非零字节数 255 / 256 / 257 交叉组合，
  核对两项阈值须同时成立且包含边界。稠密页残留 17 B 时不判 `Zero`。
- 原页仅 40 B 非零、局部清除其中 30 B，仍为 `Partial`；不能只根据改后零字节比例判近零。
- 未变化（含全零未变）、全零变化、正负一页精确供体各保留原有优先级；
  digest-probe 另确认不足一整页的近零片段仍为 `Fragment`。

这些测试直接调用真实分类函数，但输入是独立拥有的字节数组，不提供实际地址或认证证据。
新增近零规则只补齐当前仪器的内容判读，不新增固定矩阵请求，也不重写下述冻结仪器的
12 个历史样本。两端供体搜索范围仍各按自身仪器定义：本模块只核对相邻页，
digest-probe 在原文件中核对前后 64 页；本次对齐的是近零阈值及其判读优先级。

## 完成性与留档

每个子进程限时 30 秒，输出重定向到本次目录内的文件，父进程超时或退出时回收自有子进程。
开始时先写 `Incomplete`；子进程退出成功并交付响应后，父进程核对独立 PID、协议、页范围、
三份完整读回与真实认证证据，全部成立才更新为 `Complete`。
退出失败、超时、证据缺失或截短、错误进程身份、范围错误、无实际内容变化均不能计覆盖。
已有根目录或用例目录拒绝后不改写原记录。

每份成功记录包含页地址、分配范围、系统页大小、原生端序、三个完整内容文件、父子 PID、
请求、响应、内容判读、完整逻辑失配证据与 stdout/stderr。`source.json` 登记既有 LFCA
revision / digest / exact length；这些保持现行来源身份角色，不新定义持久摘要协议。
证据文件是研究留档，不承诺断电耐久或物理持久化；读取对照不构成另一套通用写后读回实现。
#954 的写入能力仍由城市浸泡链路复用，本模块不复制其故障注入或重试机制。

自动回归成功后清理临时目录，失败保留目录。手工留档使用测试入口
`page_injection_tests::collect_page_evidence`（默认 ignored）：先构建 static-network 测试
二进制，再设 `LF_PAGE_OUTPUT` 为不存在的绝对目录、`LF_PAGE_COMMIT` 为冻结源码提交，
用 `--ignored --exact page_injection_tests::collect_page_evidence --nocapture` 运行。
每次使用新目录；原件默认保存在本机，不承诺远端可恢复。

两项依赖成功采集的普通回归在宿主不支持时输出 `SKIP` 提示并提前返回；Rust 测试框架
可能显示通过，这不代表页覆盖。手工采集入口仍明确拒绝，并在生成来源或启动子进程前
保留 `Incomplete / unsupported`。另用 8 / 16 / 64 KiB 参数验证拒绝预检与无来源产物，
这些参数化负向测试不冒充在相应页大小机器上采集过证据。

## 保留的边界

本轮只覆盖建根后、没有在途消费者时的完整整数虚拟页。真实物理共页、候选与根的共因
页事件、不可变借用期间的实际改写、运行中消费者与具体页故障重叠、Rust 有效性破坏、
故障机自然取样和长期归因仍未验收。控制组通过不构成机器健康证明；软件注入检出也不
构成产品保证。不据本切片关闭 #963 或启动运行中保护 G1。
