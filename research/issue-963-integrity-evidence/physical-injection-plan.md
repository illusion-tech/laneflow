# 物理注入可行性与验收方案

关联 [#963](https://github.com/illusion-tech/laneflow/issues/963)。本文是 2026-10-26 的研究方案，
没有执行新的注入，不增加已覆盖样本。依据为
[ADR 0032](../../docs/adr/0032-runtime-state-integrity-and-distortion-disposition-authority.md)、
[完整性设计](../../docs/design/traffic-runtime-state-integrity.md) §2.5 / §3 / §4.2 / §5 / §9
和[逐项验收证据](acceptance-evidence.md)；不改变产品合同或二期准入条件。

## 可行性结论

已有[整数页注入](page-injection.md)能在唯一拥有、没有活动借用时改写真实整数分配；
[在途重叠矩阵](README.md#在用审计与在途步进)能验证逻辑故障下的宿主处置。
两者都不能证明候选修订与在用修订物理共页，或消费者实际读取了被外部改写的 backing。

后续可推进的是**有界的布局取证与指定二进制外部扰动实验**。工具有文档支持，但尚未
证明当前平台、实际分配和时序满足实验条件；不能直接承诺补齐两个物理缺口：

- 物理共页须同时证明真实对象、同一物理页帧、完整写入范围和两侧变化，只有虚拟地址或
  相同内容不够。实际页混有分配器元数据或未知对象时，整页改写方案不成立。
- 活动共享借用期间改写普通不可变 backing 超出现行 Rust 程序语义的保证范围。即使
  内容是 `u32`、目标暂停、外部写入后成功返回，也只能保存该二进制的机器级观察，不能
  作为合法 Rust 并发测试或跨编译版本保证。完整边界见下文。
- 虚拟机适合先验证工具链；客户机物理页不是宿主 DRAM 页帧。若要补齐裸机物理页证据，
  必须在明确的裸机实验目标上重新验证。软件物理地址写入也不是自然硬件故障。

本方案完成不代表注入矩阵完成。24 小时取证留档继续有效，原件和备份保留；无需重测。
受控注入不增加设计 §9 所需的自然运行中失真证据。

## 工具与平台条件

优先路线是控制端与可丢弃实验目标分离：先用隔离 Windows 虚拟机预演，随后按需要选择
专用裸机。控制端保存原件，目标只运行冻结的 LaneFlow 测试二进制；不对日常开发进程注入。

| 工具 / 能力                                  | 用途与权限                                                     | 证据限制                                                 |
| -------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------- |
| 既有安全整数页夹具                           | 健康、单侧改写和指纹判读基准；无系统配置变更                   | 不覆盖活动借用、共页或物理页帧                           |
| `VirtualQueryEx`、`ReadProcessMemory`        | 控制端持目标查询 / 读取权限，读取映射属性与完整字节            | 虚拟内存视图，不返回物理页帧身份                         |
| `QueryWorkingSetEx`                          | 记录驻留、共享属性等辅助信息                                   | `Shared` / `ShareCount` 不是两地址同物理页的证明         |
| `WriteProcessMemory` 或调试器虚拟地址写入    | 有目标写入权限时验证外部写入与读回链路                         | 仍是虚拟地址写入；需检查写时复制，不作为物理共页注入替代 |
| WinDbg / KD 的 `!pte`、`!vtop`、物理内存读取 | 正确进程地址空间中的页表、物理地址和内容互证                   | 必须有受支持的内核调试目标、匹配符号及目标地址翻译上下文 |

## 布局证明

先完成只读布局取证，再决定是否允许一次写入。每次重新启动、重建候选修订或重新分配，
均重新获取布局，不能沿用前一进程的地址或页帧号。

1. **固定身份**：保存源码提交、二进制与符号身份、Rust 版本、目标架构、优化 / LTO /
   panic 配置、OS 与调试器版本、目标 PID / 创建时间及控制端 PID。冻结健康 LFCA 的
   既有 revision / digest / exact length，并从健康来源独立构建期望内容。
2. **定位真实对象**：记录在用 `Arc<SharedNetworkRevision>`、本次认证真正构建的候选
   修订及目标列的地址、长度、元素宽度、字节范围与生命周期。当前
   [长度列](../../crates/laneflow-static-network/src/traffic.rs)是 `Box<[u32]>`；
   不从 `Arc` 或 `Box` 头部地址推断 backing，不以独立替换视图冒充本次候选。
3. **确认映射**：读取系统页大小、区域边界、提交状态、保护属性；首轮限定普通 4096 B
   页。全部目标范围必须在活分配内，地址计算无溢出。对目标页选择相符的缓存访问方式，
   不靠改缓存属性、解除保护或重新映射来凑实验条件。
4. **确认物理身份**：在冻结目标的同一停止窗口，保存进程地址空间 / 页表上下文、原始
   PTE 及翻译结果，逐页对照虚拟与物理读回。`!pte` 的解释以
   [目标架构文档](https://learn.microsoft.com/en-us/windows-hardware/drivers/debuggercmds/-pte)
   为准，不把示例地址或另一进程的翻译结果套用到本次目标。虚拟机另标客户机物理地址，
   不称为宿主物理页帧。
5. **确认共页关系**：共页可以是同页内不相交的两段 payload，也可以是不同虚拟页的物理
   别名，两者分别记录。前者须证明对应字段与页内偏移，后者须证明相同物理页帧及映射
   关系；两种情况都核对故障前内容与独立健康期望。地址接近、同一虚拟分配区域或两页
   字节相同均不能替代该证明。共享映射发生写时复制后可能分离，必须再查页表。
6. **确认全页归属**：整页零化要求覆盖页内每段的所有权清单，只允许已识别、已初始化
   的普通整数 / 字节 payload 或专用试验缓冲。页内存在指针、对象头、分配器元数据、
   未识别间隙或其他对象时停止该用例。只改两个字段必须记局部改写，不能算整页零化。
7. **复核稳定性**：在写前、写后且恢复目标执行前、目标读取时及销毁对象前重新记录身份、
   映射和内容；发生页帧变化、写时复制、释放重用或迁移时不得继续使用旧物理地址。
   [VirtualLock](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtuallock)
   可辅助驻留，不提供本方案所需的页帧恒等或两对象共页证明。

普通堆分配没有本研究要求的共页与全页归属保证。先观察自然布局；无法同时满足第 5、6
步即记录布局不支持。为了成功而更换生产分配器、重排生产对象或引入共享映射，会改变
被验证对象，须另评估；专用页布局夹具只能证明夹具自身。两个顺序虚拟写入也不能替代
一次作用于同一物理页范围的故障事件。

## 注入时点与最小矩阵

每一行在执行前固定目标、预期改写字节和阶段。使用有界握手 / 调试停止事件；不以 sleep、
日志打印顺序或“两个线程都启动了”证明重叠。保存阶段序号、线程、指令位置和单调时间。

| 用例                    | 停止与改写时点                                                        | 必须观察的结果与边界                                                                                                      |
| ----------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 健康对照                | 相同断点、读回和恢复流程，不写入                                      | 健康认证 `Pass`、正常 step；排除工具本身造成的差异                                                                        |
| 单侧实际页对照          | 建修订后、安装前，取得唯一所有权且所有共享借用结束                    | 对照既有整数页五类改写及完整认证证据；单独复核物理映射，不把历史虚拟页样本升级                                            |
| 认证期共页零化          | 真实候选已构建、对应列尚未比较；冻结目标，确认两侧同页后作用于该页    | 两侧同值损坏、其他比较输入与来源未变时，`Pass` 是设计 §5 第 16 条的声明漏检观察；若实际返回不同则保留完整差异，不强改预期 |
| 分离页对照              | 同一认证阶段，先证明候选与在用修订位于不同物理页，仅改在用侧          | 来源保持健康、同一失配复现时应观察 `Mismatch / SharedStaticRoot / DisableRoot`；与共页结果对照                            |
| 来源实际 backing 变化   | reader 完成验证 / 同修订判据后，builder 下一次读取目标字节之前        | 证明 builder 读到变化，记录来源复核与真实分类；失败须按 Source / 操作失败 / Untrusted 的实际路径记录，不能预置认证结论    |
| 在用修订实际变化与 step | step 进入后、选定消费者下一次实际读取目标列之前；认证与该调用保持重叠 | 单、双工作线程分别证明消费者读取了改后值，再记录审计结论、停止新调用、在途返回或异常，以及输出处置                        |

共页用例在初次比较相等时不会当然触发复算。分离页用例若进入第二次认证尝试，新候选
必须重新定位；不能把第一次候选的地址当作第二次候选。发生额外差异、panic 或未完成
复算时按真实路径记录，不能只凭注入请求名称推导 `Mismatch` / `Untrusted`。

单侧页对照的合法软件基线仍由目标自身通过 `Arc::get_mut` 取得可变切片并安全写入。
用外部工具改写同类对象是另一份机器级观察，不能仅凭“没有消费者”或“唯一 Arc”就
省略借用、绑定可变性和分配有效性审查，更不能把两种执行方式混成同一份样本。

来源用例要保留改写前、reader 已验证、builder 实际重读、来源复核四个内容时点，分别
登记持续变化和 `A → B → A` 的恢复时刻；恢复前像来自控制端的健康副本。返回 `Pass`
只说明该次观察，不消除设计中短暂变化未被发现的边界。

在用修订用例分别计划持续失配、首次比较失配后恢复、复算改为另一位置失配三种变化；
在单、双工作线程下各执行。恢复或第二次改写必须在首次证据已经形成、复算读取之前，
保存两次比较的真实内容与位置。`SharedStaticRoot` / `Untrusted` 是对照既有分类的
预期，仍以完整流水线实际返回为记录，未命中阶段时不能借用逻辑夹具的结论。

源码定位依据为
[认证流水线](../../crates/laneflow-static-network/src/attestation.rs)的
`SameRevisionCriterionChecked` → `build_shared_network_revision` 和
`CandidateRootBuilt` → `RootComparisonStarted`。这些 trace 名称帮助定位，**本身不是
已交付的物理注入握手点**。现有
[重叠测试](../../crates/laneflow-runtime/src/admin/tests/audit_step_overlap.rs)的
`before_next_commit` 位于准备结束后，只能证明调用尚未返回；该拍可能早已读完目标列，
不能据此宣称消费者读到了故障内容。

消费者用例因此需要两个不同位置：先在目标 load 前停止、改写并观察该 load；再利用
提交前握手保持 step 在途，让审计线程完成认证与宿主停用，最后释放原 step。不得在
全部目标线程仍被调试器暂停时等待审计线程完成，也不得把注入后另起的一拍算成原调用。
如消费者提前异常、无法到达第二个握手点，就保留异常并将重叠处置链记为未完成。

后续仪器须在冻结二进制中定位具体的目标内存 load，保存该指令、地址、读入值及阶段
关联，或提供经审查的等效消费证据。优化使读取提前、合并、消除或只用寄存器旧值时，
本次不具备目标消费覆盖，不能为凑结果关闭优化而沿用原二进制标签。新增测试同步点
必须默认关闭、只用于观察 / 握手，不替换比较视图；改动后重新冻结二进制身份。

写入期间停止全部目标执行线程，避免将半页写入当完整页事件；恢复后在同一目标读取处
再次核对映射与读入值。控制端的一组顺序写指令只构成一次有起止范围的受控扰动窗口，
不称为硬件原子故障；无法排除其他写入者、无法证明停止窗口或读入时点时，停止计覆盖。

## Rust 有效性与结论边界

必须分别审查值、所有权 / 借用、并发访问以及分配器 / 对象不变量，不能只检查字段类型：

- **值有效性**：已初始化的 `u32` 任意位模式有效，但错误长度 / 序号仍可能造成语义错误
  或越界。指针、引用、枚举判别值、`bool`、`char`、`NonZero` 以及分配元数据不列入本轮
  可写清单。完整性设计 §2.5 对标量的保证收窄不是活动共享借用可写许可。
- **借用与并发**：Rust Reference 将违反别名规则、改写共享引用所指不可变字节和数据
  竞争列入未定义行为；`unsafe` 本身不豁免。目标暂停不等于引用生命周期结束，外部
  调试器 / OS 写入也不为原 Rust 程序建立合法的可变访问。
  依据：[Rust 未定义行为](https://doc.rust-lang.org/reference/behavior-considered-undefined.html)。
- **常见替代仍有边界**：`UnsafeCell` 不自动解决数据竞争，把它产生的指针转成普通
  `&T` 后仍有不可变约束；堆分配内的 `read_volatile` 也须满足通常访问规则且不是原子
  同步。依据：[UnsafeCell](https://doc.rust-lang.org/std/cell/struct.UnsafeCell.html)、
  [read_volatile](https://doc.rust-lang.org/std/ptr/fn.read_volatile.html)。不能给仪器加
  `volatile` 就声称修复了生产读取的别名问题。
- **可保存的结论**：唯一所有权下的安全改写继续作为有效软件回归。活动不可变 backing
  的外部扰动只作为精确编译产物、平台和注入窗口上的机器级观察；即使完整返回也不能
  推广成无未定义行为、所有优化构建均检出或生产内存安全保证。进程崩溃可保存为观察，
  不伪造 Runtime 的 `Untrusted` / `Mismatch` 报告。

以上是对官方约束与当前不可变布局的研究判断。改变生产 backing 为原子、锁或内部可变
存储会影响 ADR 0032 的不可变、无原子基线，须另回 G1；不为完成注入实验引入该变更。
若物理证据最终成立，只按已验证平台与对象范围更新覆盖，Rust 模型之外的限制仍随证据
保留，不能由实测全绿撤销。

## 原件与失败判据

沿用现有研究的 `Complete` / `Incomplete` 完成性概念，不新增产品协议或摘要算法。
每个用例先登记 `Incomplete`，控制端保管独立健康前像和原始记录；结束后分别裁定
**取证完整性、注入成立、覆盖主张、实际行为**。`Complete` 只表示声明所需原件齐全，
不表示认证成功或整个 #963 验收通过。

每份记录至少包括：冻结身份与配置；用例、工作线程数和预算；原始地址翻译 / 页表 / 归属
清单；完整改写范围及前后页、相邻保护范围和相关列读回；控制端原始操作记录和实际写入
字节数（工具提供时）；阶段握手与消费证据；真实认证 trace、首次及复算失配证据；
退出 / 异常记录；
宿主新调用计数、在途结果和已发布 / 隔离输出。摘要清单用于原件一致性校验，不能代替
完整字节、物理映射或目标身份。双路径读回仍可能共享缓存，不称为独立硬件通道认证。
调试器没有字节数回执时保存逐条命令、请求范围和完整读回，分别报告请求写入字节数与
实际差异字节数，不虚构 API 回执或把差异字节数等同所有写入字节数。

| 情况                                                                    | 裁定与动作                                                                                                           |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 工具缺失、权限拒绝、无调试目标、符号 / 二进制不匹配                     | `Incomplete`，注明具体前置条件；不试写未知地址                                                                       |

| 完整同页同值受损而比较 `Pass`                                           | 声明漏检的机器级观察；不计“无漏检”，不扩展到未测对象                                                                 |
| 完整单侧故障得到预期非 `Pass` 且宿主处置成立                            | 仅计该样本的检测 / 处置观察；同时保留 Rust、平台与时序边界                                                           |

一份记录可以完整证明“布局成立”却缺少“消费者读入变化”。此时只保留前一项子证据，
不能把整个重叠用例标成完成。对外按各自分母报告健康、已成立注入、声明漏检、异常和
不完整数，不从成功样本中推算未执行部分。

## 后续实施顺序与停止条件

1. **平台与只读布局探针**：先固定目标为虚拟机还是裸机、地址层级、工具版本、权限、
   符号和证据目录。只读获取真实候选与在用修订布局、页表和归属；不改变生产分配。
   新增仪器优先用 Rust，沿用源码审计与依赖审查；如果需要手写 unsafe、非 Rust 实现
   或变更源码审计边界，先提交具体方案，不把本研究文档视为实现豁免。
2. **工具链对照**：先完成健康对照、独立普通整数缓冲和单侧页对照，核对写入、读回、
   缓存属性及地址稳定性。虚拟机结果只用于客户机层预演；未完成裸机验证不提高其层级。
3. **逐项物理实验**：布局成立才进入共页 / 分离页对照，再进入来源时序及消费者读取
   实验。在用 step 用例固定单、双工作线程。每个组合首轮只跑一次；原件独立复核后，
   再用新目标进程复现一次，不用同一损坏进程连续积累“重复成功”。
4. **有界停止**：首轮每组合最多三次只读布局尝试，每次新进程；每个自动握手最多
   30 秒、单次试验最多 120 秒，包含调试暂停。人工平台配置不计该窗口；如工具需要
   更长预算，须在启动前写入本次计划，不在超时后改标签。控制端超时只回收自己创建的
   测试目标，不能为清理而重启工作主机。所有失败尝试保留；重复相同阻碍即停止该组合，
   不增加压力或无限重试寻找共页。
5. **复核与范围裁定**：另一独立复核过程从原件重算字节、地址范围与顺序，再对照真实
   报告和宿主处置。瞬态恢复只是用例内预先声明的注入步骤；用例结束后销毁测试目标，
   不把原地修回后的进程复用于下一样本。新目标从健康来源重建并重新认证。只有布局、
   注入、时序与结果均可核对的范围才可提交覆盖更新。

本方案的交付验收是：工具依据可定位；平台已知与未知分开；两类缺口各有布局和时序
证据要求；Rust 限制与可宣称范围明确；不完整和反例有去向；后续实施有明确先后和停止
点。**本轮只完成方案与只读盘点，以上实验均未执行**。物理缺口继续单列，不修改历史
整数页样本、24 小时报告、原件或备份，不据此启动运行中保护 G1。
