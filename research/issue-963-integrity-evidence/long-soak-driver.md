# 长期浸泡驱动与安全暂停恢复

本页定义 #963 的 Rust 测试仪器操作与证据判读。代码入口是
[`integrity_soak`](../../tools/laneflow-urban-harness/src/integrity_soak.rs)，只进入
`cfg(test)`，不改变 Runtime 生产 API、LFCA / LFRS 或 Adapter 协议。仪器支持长期运行，
不等于已经完成故障机长期验收，也不构成运行中保护的二期 G1 证据。

## 启动与配置

先约定主机、采集时长与资源范围，再构建并冻结测试二进制：

```text
cargo +1.99.1 test --release --locked -p laneflow-urban-harness --lib --no-run
```

使用 Cargo 实际输出的测试二进制路径。`LF_SOAK_OUTPUT` 必须是新的绝对目录；目录已存在、
时长非法、配置超限或创建竞争均拒绝，不改写原证据。设置 `LF_SOAK_COMMIT` 与
`LF_SOAK_BINARY_SHA256` 记录冻结源码和二进制的既有 SHA-256 来源引用角色；字段只作来源
记录，不替代对实际源码、二进制和原件的独立核对。

- `LF_SOAK_SECONDS`：必填，排除暂停的有效运行秒数，范围 1–604800（最长七天）。
  有效运行包括推进、存档、认证和独立回放，不是纯推进计时或性能样本。
- `LF_SOAK_WALL_SECONDS`：含生成、启动、暂停及看护的总墙钟上限；默认有效秒数的四倍
  加 300 秒，合法范围为有效秒数至 2592000 秒（三十天）。暂停也会耗尽此预算。
- `LF_SOAK_MAX_MEMORY_BYTES`：看护、驻留世界、回放及观察到的后代进程的工作集采样
  合计阈值，默认 2147483648 字节（2 GiB）。
- `LF_SOAK_MAX_DISK_BYTES`：输出目录证据容量采样阈值，默认 2147483648 字节（2 GiB）。
  上述两个字节阈值范围均为 1–68719476736（64 GiB）。
- `LF_SOAK_BATCH_TICKS`：每段最多推进的 tick 数，默认 1024，范围 1–4096。
  暂停或停止请求可在下一拍之前缩短当前段，随后仍须完成该段的独立回放。
- `LF_SOAK_REPLAY_SECONDS`：每个独立回放子进程的墙钟上限，默认 30 秒，范围 1–120 秒。

启动命令只运行指定入口：

```text
<test-binary> --ignored --exact integrity_soak::bounded_soak --nocapture
```

测试进程担任独立资源看护，另启驻留世界进程；每段再启认证后恢复存档的独立回放进程。
原世界始终留在驻留进程，运行时工作线程固定为一个，推进按每拍至少 16 毫秒节流。
负载沿用 Fixture 城市与 `SUSTAINED-ACTIVE`，不扩大车辆规模或改变交通语义。

看护通过 sysinfo 安全接口约每秒记录一次工作集及证据容量，并核对总墙钟。
工作集合计可能重复计入共享页，是采样合计最大值，不是匿名堆峰值或物理失真归因。
每次记录 `memory_sample_complete`；启动阶段读不到的样本单列不完整，不把它当零。
最终记录完整采样数；没有完整样本时峰值为 `null`，不以零字节占位。
存活看护或驻留进程超过三秒仍不可测、或整轮没有有效驻留工作集样本时拒收为 `Incomplete`。
阈值不属于 OS 硬配额，瞬时峰值和两次采样之间的超量可能未被观测；检测、调度与清理也
可能产生滞后。超限、读写失败、子进程失败或超时均结束本轮，保留 `Incomplete`。

## 暂停、恢复与结束

另一个终端设置同一 `LF_SOAK_OUTPUT`，将 `LF_SOAK_COMMAND` 设置为 `status`、`pause`、
`resume` 或 `stop`，然后运行：

```text
<test-binary> --ignored --exact integrity_soak::control_soak --nocapture
```

`pause` 只表示请求已写入。以 `status.json` 的 `state = Paused` 为安全暂停确认：此前
正在推进的段已经停止于拍边界，完成修订认证、独立进程回放、比较与证据写出。若该段失败，
采集终止而不会确认暂停。请求具有采集标识与连续序号；前一请求未确认时不接受下一请求。

确认暂停后，不再推进世界、存档、周期认证或派生回放进程，只保留低频控制轮询与资源看护。
原世界及其分配继续驻留内存，因此暂停不会释放内存。需要安静计算窗口时应等到暂停确认；
此功能不声明整台主机零后台开销。

`resume` 仅在已暂停时接受。驱动读回暂停检查点，与驻留进程保留的原检查点对比，再以冻结
发布引用认证在用修订，核对原世界的 world_id、tick、命令游标、直接状态摘要及宿主摘要。
任一操作失败或内容失配均结束本轮，不自动恢复或重建原世界。通过后仍推进原驻留世界，
不在父进程执行 `Harness::resume`。

暂停、恢复事件与检查点逐次留档。暂停墙钟、有效运行时间、运行阶段墙钟及含启动的总墙钟
分别记录；暂停期间不计入有效时长，单列为未采样间隔。恢复检查只检测端点保留的变化，
不能证明暂停期间不存在瞬时失真或控制状态共因失真。

`stop` 在完成当前段后结束；暂停时可直接结束。已完成段保留其真实分类，整个未完成的
采集记 `Incomplete`，不能用已完成的前缀宣称达到目标时长。主动结束后看护入口以失败状态
退出是预期行为，以记录中的 `user stop` 区分。`resume` 不适用于已停止、失败或关闭的进程。

关闭后必须用新目录开始新一轮，不能把恢复存档当成原匿名堆持续驻留。不要用 OS 挂起
进程代替安全暂停：它不能给出完成审计和落盘的确认。

## 证据布局与中断语义

- `config.json`：冻结配置、采集标识及看护 PID。`collection.json` 在创建时先标记
  `Incomplete`；完整结束必须另有本轮的最终 `supervisor.result.json`。
- `segments/000000/` 等：每段自己的存档、请求、原世界期望、独立响应、双路径环境对照及
  stdout/stderr。`request.result.json` 在开始前为 `Incomplete`，完成后原子发布真实结论；
  已完成段不回写。只有完成性判据满足的 `CompleteMatch` / `Diverged` 段有审计覆盖。
- `events/`：独立的暂停检查点、暂停、恢复和结束记录，不把暂停间隔算为连续采样。
- `resources/`：每六十次采样一份记录；当前文件写后读回再原子更新，封存后不再改写。
  `watch.json` 提供最新采样；暂停时 `status.json` 的时间是确认时快照，最新总墙钟看采样。
- `status.json` / `control.json`：驻留进程确认状态与待处理请求。`control.lock` 防止并发
  写命令；异常遗留锁不自动接管，应先读状态并确认原控制进程已结束。
- `summary.json`：驻留进程正常返回时的覆盖与时长摘要。资源看护另核对最终预算和退出状态，
  所以单独看到 summary 的 `Completed` 还不能判整轮完整。
- `supervisor.result.json`：本轮看护结论、资源采样数、采样合计峰值、总墙钟与后代清理结果。
  看护独立核对目标时长、有效时间与暂停时间不超过自身墙钟、实际驻留 PID、执行模式和 tick
  覆盖计数；过早退出或不完整摘要不能仅凭自报 `Completed` 通过。
  看护、驻留进程及已观察后代按 PID 与启动时间追踪；清理未确认时如实记未确认。
- `failures/<pid>.json`：各进程的原始失败；`failure.json` 只是最近失败的入口。

看护和回放进程使用有界清理。看护异常退出时，独占 stdin 管道断开，驻留进程在下一次
控制检查时停止；回放最多受自己的超时限制。看护被强制杀死时无法保证写出最终看护记录，
未完成段及最初的 `Incomplete` 仍保留。进程清理覆盖观察到的后代，不声称提供 OS Job / cgroup
隔离或捕获未观察到的瞬时派生进程；挂死调用及系统调度可能延迟协作退出。

正常结束只说明所存段在对应检查点、宿主记录流与环境对照下的结果。初始安装及第一拍、
暂停间隔、检查点之间的瞬时变化、物理页帧与匿名堆归因、故障机长期验收继续单列未覆盖。
本次驱动扩展没有启动新的长期采集；实际长期样本另行冻结身份、资源范围与验收记录。

墙钟预算回归先让真实城市世界确认暂停，再受控推进看护时钟，验证暂停状态下总预算仍会
耗尽；避免把城市初始化和暂停确认挤进很短的真实超时窗口。该时钟只由回归直接传入，
正常 `bounded_soak` 入口始终使用单调时钟的实际经过时间；不将受控时钟用例当实测时长。
