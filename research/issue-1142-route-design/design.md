## 1. 承接：A0/A1 已完成的工作

### 1.1 已核实的事实（A0，`kimi-806-a0`）

- 失真回归测试已替换为真实 B0/B1 反例：`A0/B0/B1/C0`，`P1=[A0,I1,B0]`、
  `P2=[B1,I2,C0]`，缺口输入无 `B0→C`、无 `B0→B1`。
- 直接路线阶段与组合 fail-fast 均返回 `Error::SumoModel`，内部消息
  `no complete lane-level path for road route ["A", "B", "C"]`；连续对照精确物化为
  `[sumo:A_0, sumo::J1_0_0, sumo:B_0, sumo::J2_1_0, sumo:C_0]`。
- 来源错误分域成立：unknown lane/unknown road/DUE 直接引用 internal edge 各自在
  归一化或路线边引用校验阶段拒绝，不与路线缺口混淆。
- 缺失道路 hop 与 lane 缺口共用同一正式错误文本（A0 不新增生产分类）。

### 1.2 已核实的事实（A1，`kimi-806-a1` / #1085）

- converter 内部诊断已可区分 `SourceValidation`、`Normalization`、
  `RoadHopMissing`、`LaneContinuityGap`、`MaterializationFailure`、`Unclassified`，
  并按零基 occurrence 记录可达 lane 集合与所需 `from_lane` 对。
- 连续夹具的**组合静态转换实际失败在路线成功之后的几何修复阶段**：
  `sumo::J2_0_0`（chord 5.0000 m）在量化焊接预算下曲率不可行
  （`2 pieces (chord floor) each turn 3.75 deg > 1.90 deg`）。该失败是几何发射
  问题，不得改写为路线物化失败。**推导**：任何以 A0/A1 夹具几何为底本的最小闭环
  样本都必须显式处理这一已知发射风险（见 §6.2）。

### 1.3 问题定位（事实 + 推导）

当前展开器（`can_complete` / `materialize_path`）要求下一跳的 `from_lane` 等于
已到达 lane；`A→B` 只有 `P1=[A0,I1,B0]`、`B→C` 只有 `P2=[B1,I2,C0]` 时，搜索在
道路 `B` 停在 lane 0，无法完成。这不是 `B1` 不存在，也不是道路级不可达，而是
**缺少从 `B0` 到 `B1` 的已证明可执行横向转移**。四个结论层级不能混用：

| 层级         | 含义                              | 现状                             |
| ------------ | --------------------------------- | -------------------------------- |
| 道路可达     | 道路对投影上有来源 connection 链  | A→B、B→C 均可达                  |
| 路径物化     | 车道级完整边链可生成              | 缺口处失败（严格合同，正确行为） |
| 运行时可注册 | `register_route` 静态序列合同通过 | 只证明静态序列，不证明安全       |
| 多车安全执行 | 动态占用、间隙、仲裁、清空、重放  | 属于 #237 最小子合同，尚未交付   |

**结论（推导，承接修订稿 [C1]/[R1]）**：仅放宽 `can_complete` 让搜索通过、而
`materialize_path` 不放宽，只会造成搜索与物化合同不一致；两处同时放宽会拼出没有
对应连接或没有完整机动路径的边链。任何"搜索放宽"都不产生可执行路线。

## 2. 边界设计：路线展开负责"找到并物化"，#237 最小换道负责"证明可执行"

### 2.1 总原则

**路线展开（converter 侧）不产生横向转移，只消费它们。** 展开器在给定最终拓扑
上把道路级需求物化为完整车道级边链；当且仅当横向转移以真实拓扑/材料形式存在
（见 §2.3）时，物化可以跨越该转移。缺少转移材料时，展开器必须按现行严格合同
失败关闭并给出 `lane-continuity-gap` 类缺口定位（A1 诊断），**不得**改选 lane、
拼接无连接边链或从候选尾部补位。

**#237 最小换道能力（运行时 + 编译材料）负责让一次固定、预制的横向转移可被
证明执行安全。** 它不改变路线权威，不承担选路，不引入自由在线选道。

### 2.2 路线展开职责清单（本设计冻结的边界内侧）

事实依据：`real-road-workloads.md` §3.1、`route-system.md` D1–D8、ADR 0029。

1. 来源准入：XML、lane/connection 引用、人口记录合法性（来源错误域）。
2. 道路 hop 可达：固定道路序列每个相邻道路对的来源路径存在性。
3. 当前 lane 连续性搜索：稳定定位首个不可完成 occurrence，输出可达 lane 集合
   与所需 `from_lane` 对（A1 诊断已具备）。
4. 完整路径物化：入口、内部边、出口完整展开，重复 occurrence 与稳定选择结果
   确定；最终边链按完整 `ManeuverPath` 对应（registration-time compiler 必须在
   每个路口 occurrence 唯一匹配同一 ManeuverPath）。
5. 目录与人口绑定：相同 lane occurrence sequence 归一化为同一 catalog entry，
   人口身份、ordinal、顺序稳定；失败记录不删除、不补位。
6. 失败关闭：无完整路径、零/多 path 匹配、unknown/internal 引用、物化不完整
   都是 fatal error；不发布删减/补位后的 `routes.toml`。

展开器**不负责**：横向转移的许可、间隙、安全证明、占用投影、进入仲裁、清空；
也不负责在两条执行方案（默认换道方案 / 固定受控连接区）之间选择或静默切换。

### 2.3 #237 最小子合同（本设计冻结的边界外侧，首版最小内容）

承接修订稿 §5.1 的必要合同矩阵；消费 `cross-section-access.md` §14 的冻结
保证（相邻事实源、整边界锚点、overlay 模式、物理/policy 分层），#237 的 G1
只做契约校验，不得重复冻结：

| #   | 合同                   | 首版最小内容                                                                                                                                   | 事实源与缺口                                                                                                   |
| --- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 1   | 物理相邻               | 同向 lane 稳定链身份、共同纵向范围、实际相邻边界                                                                                               | `RoadSection` ordered lanes + `RoadCorridor.elements` 顺序是唯一事实源；不得按 ID、SUMO index 或空间接近猜邻接 |
| 2   | 跨越许可               | 边界标线事实与 policy 许可分开；未知/拒绝失败关闭                                                                                              | AccessRule 可复用组合模式；标线是物理事实，许可在 policy 层                                                    |
| 3   | 单一路线权威与固定过渡 | 出发前确定完整实际边链；预制过渡有连续几何、明确边界、最终长度；首版不支持活动车改 Route                                                       | `Route` 与游标继续拥有实际遍历（ADR 0029/0017）；过渡若为带中心线的真实边可复用 lane-pose                      |
| 4   | 源/目标物理占用        | 换道期间同一车辆、同一位姿在源和目标车道有明确占用投影；车身扫掠区、重复 occurrence、长车跨边均有定义；不重复计数车辆                          | 当前占用按物理边分桶，车身仅沿本车路线回溯；不同边几何相交不自动共享占用                                       |
| 5   | 目标前后车与源后车     | 进入前证明目标 leader/follower 领先与滞后间隙、制动与最小间距；考虑尚未进入共享边的接近后车；保护源车道后车直到车尾清空                        | 当前 Following 不搜索未选分支或其他 incoming branch；生成准入的双方向证明可参照但不等价                        |
| 6   | 进入仲裁与硬停         | 固定边界前设可停住的进入点；原子取得源/目标所需资源；同拍竞争按稳定顺序裁决；与 Following、Signal、Waiting、Conflict、Parking 同一安全求解顺序 | 普通无门 hop 当前直接允许通过；不得用普通 successor 充当换道准入                                               |
| 7   | 原子提交与车尾清空     | 车辆状态、资源持有与事件同一提交生效；拒绝保留已提交旧状态；源/目标资源持续到相应车尾清空                                                      | Conflict 的 committed + earlier-staged claim 与真实车长清空判据可复用，不得另建安全权威                        |
| 8   | 保存、恢复与重放       | 过渡阶段、路线位置、资源预约、等待、清空事实用稳定引用完整保存/重建；恢复不重复 grant/事件；重放得到相同状态摘要                               | 路线已按 `StableId128` 序列保存；新增换道状态的快照/恢复/摘要/版本影响由 G1 决定                               |

**首版明确排除**：潮汐/可逆车道、动态 lane-use 全集、自由在线选道、活动车改
Route、任意位置材料化、全量 `ResolvedLanePlan`。若未来需要运行中改计划，另立
设计路线替换与状态迁移。

### 2.4 固定预制过渡的物化形态（建议，默认方案）

**建议**：保留原 LuST 道路/路口/连接语义与原车道连续流，在真实过渡边界把
双车道路段切成上游/过渡区/下游，过渡是带中心线的真实 `LaneEdge`：

```text
B0_up ──(普通 successor)──> B0_down        直行流，保持原车道连续流，无新增门
B1_up ──(普通 successor)──> B1_down        直行流，同上
B0_up ──T01──> B1_down                     固定预制过渡（#237 子合同承载）
```

- 拆分必须同时切开两条 lane（`cross-section-access.md` §3.2 lane 纵向共延伸
  不变量：lane 中途起止处必须是 section 边界）；拆分、删除、合成边给出稳定身份、
  方向、整数毫米长度与来源映射。
- 过渡 `T01` 的边界完全落在显式 section 边界内，**不依赖共享 stationing**，
  因此不需要 #273（段级锚定整体推迟到横向几何 G1；#237 首版按整边界语义）。
- 改变车辆的路线边链物化为 `[A0, I1, B0_up, T01, B1_down, I2, C0]`；直行车辆
  保持 `[A0, I1, B0_up, B0_down, …]` / `[…, B1_up, B1_down, I2, C0]`，与现状
  同构。展开器只消费 T01 存在的最终拓扑，不感知"换道"语义。
- **注册成功仍不等于安全证明**：`register_route` 只做静态序列与出现项合同
  （`route-system.md` D4/D11、`road-junction-model.md` §3.4）；T01 的安全义务
  全部由 §2.3 子合同 4–8 在运行时履行。

**与备选（固定受控连接区）的分界（事实 + 建议）**：备选把固定区两侧 lane 全部
切成 `*_up/连接区/*_down`，所有直行与斜向流都进入门、冲突和下游清空合同
（`road-junction-model.md` §17.4：merge/diverge 的 gap/priority/lane availability
是独立 G1 范围）。它会改变排队、容量、等待与行程时间语义，构成派生负载。**两案
不得混用材料、不得静默切换**；只有在独立 G1 接受派生负载变化、完成全部冲突覆盖
证明后才可选备选。

## 3. 衔接列明

### 3.1 与编译器（converter / 网络编译器）的衔接

| 接口         | 编译器侧责任                                                                                                                       | 路线展开侧消费                                                                                           | 失败关闭条件                            |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| 最终权威拓扑 | 归一化只发布一份最终权威 `NormalizedTopology`，同时供路线展开与静态发射消费（现行两阶段各自归一化不证明拆边后一致）                | 每个道路 occurrence 按来源 road/lane → 最终 `LaneEdge` 链的显式映射物化                                  | 零/多义映射失败关闭                     |
| 完整机动路径 | 每个保留 source connection 对应最终入口、完整有序内部边、出口与路径身份；共享边唯一归属                                            | 只选择完整路径，不覆盖入口/出口，不从信号或名称反推                                                      | 零/多 path 匹配拒绝                     |
| 长度与可用段 | 最终规范中心线、编译提交的整数毫米边长、两端被路口/改造消耗范围、剩余可用段、固定过渡边界                                          | 不用旧 SUMO `length` 或长度百分比换算；边界不足或重叠拒绝/保留未决                                       | 边界不足、重叠                          |
| 横向过渡材料 | 合法相邻边界、许可依据、T01 端点/边链、源/目标占用映射                                                                             | 诊断发现的 lane pair 只是需求，不自动成为可执行过渡                                                      | 缺材料 = `lane-continuity-gap` 保持失败 |
| 控制锚点     | `StopLine` 所在最终边、`ManeuverGate` 的最终 path/`transition_index`、信号组与来源 link、Waiting/Conflict entry/clearance 重新绑定 | 不沿用旧 gate index 或停止线；split 后不按百分比搬移停车位置                                             | 缺失、歧义、绑错边拒绝                  |
| 修订与制品   | 同一最终拓扑产生 LFCA/`SharedNetworkRevision`、`NetworkRevisionId`、digest/length 与合同版本                                       | 路线目录、人口、Runtime 与 Spatial 消费同一最终修订；需要同一 `Arc` 的场合不能只比较 `NetworkRevisionId` | 旧修订证据不得替代                      |

**事实**（`network-compiler.md`）：编译器不预编译路线；路线出现项只在
`TrafficWorld::register_route` 编译（ADR 0029）。路网制品不声明路线，场景
catalog 拥有示例边序列。因此"路线展开"产物（`routes.toml` 车道 id 序列）属于
转换器/场景层出行清单，不进入 LFCA。

**推导**：#790 可能移动入口/出口并改变可用边界；过渡边界与拆边必须与 #790 的
最终拓扑汇合到同一修订后才能落地，本设计不预设 #790 结果。

### 3.2 与路线系统的衔接

- 输入契约不变：`register_route` 只接收共享静态路网 `LaneEdgeOrdinal` 有序非空
  序列（ADR 0029/#498）；调用方持有 catalog `route_id` ↔ handle 对照。
- 相邻边校验为"车道后继或机动转移候选"（`route-system.md` D4）；T01 在最终拓扑
  中以真实边 + 普通连接进入该校验，**不需要**为换道新增注册校验类别。
- 出现项编译规则不变：完整 `ManeuverPath` 匹配、内部边覆盖、首末边不得落内部
  边、末边不得带 StopLine、hop 半开区间不相交（ADR 0029 §2）。
- 显式 loop、重复 edge 继续由 `route_edge_index` 区分；拆边后同一物理道路的
  occurrence 计数与稳定选择按最终边身份重新物化。
- 路线仍是每世界可变状态，经唯一 `register_route` 入口；不恢复 `StaticRoute`、
  不造第二套路线权威、不让 Runtime 做寻路（`route-system.md` D8）。

### 3.3 与运行时的衔接

| 运行时机制         | 现状（事实）                                               | 换道承载方式（#237 子合同）                                   |
| ------------------ | ---------------------------------------------------------- | ------------------------------------------------------------- |
| 占用索引           | 按物理边分桶，车身沿本车路线向车尾展开                     | 子合同 4：过渡期间源/目标双向占用投影；不重复计数             |
| 跟车 / leader      | 只沿 follower 路线前视；不搜未选分支与未进入共享边车辆     | 子合同 5：目标前后车与源后车显式证明                          |
| 门与信号           | 无门 hop 直接允许；缺 policy/规则 `DenyAndStop`            | 子合同 6：T01 进入点前硬停 + 原子资源取得；普通直行流不新增门 |
| Waiting / Conflict | 组合资源 + committed/earlier-staged claim + 车尾清空可复用 | 子合同 6/7：复用其仲裁与清空原语，不另建安全权威              |
| 固定步进           | 串行 P0–P8、失败原子、确定性事件顺序                       | 同拍竞争按稳定顺序裁决，与领域算法同一求解顺序                |
| 快照 / 恢复 / 重放 | 路线、机动、Waiting、Conflict 状态有稳定引用持久化         | 子合同 8：新增过渡阶段/预约状态由 G1 决定快照与版本影响       |

**边界结论**：路线展开的交付止于"完整、可注册的最终边链"；运行时可注册不是
安全证明；安全证明由 #237 最小子合同的运行时实现与其验收矩阵提供。两者的验收
不得互相替代。

### 3.4 跨层共同输入（统筹复核：**附条件通过**，2026-10-29）

以下接口需要与几何/编制线（#790）共同冻结后才能进入实现。统筹（lead）已复核
清单本身，结论为**清单成立、附条件通过**：可作为路线侧消费契约**草案**，
实现切片落地时按下列条件转正式 schema，逐项引用权威来源：

1. 来源与最终边链映射（拆分/删除/合成边的身份、方向、边界角色）——**条件**：
   "稳定身份"不得强于现行编译器/修订模型实际提供的保证；若模型只保证**逐修订
   身份 + 文档化映射**，合同照此写，不得发明跨修订稳定 ID 语义。
2. 每个保留 source connection 的完整机动路径（含共享边唯一归属）——与现行
   ManeuverPath 契约及共享边唯一赋值语义一致，无附加条件。
3. 最终整数毫米边长、可用段与固定过渡边界（不用长度百分比、不共享 stationing）
   ——与编译器 `length_mm` 口径一致，纪律正确，无附加条件。
4. 横向过渡材料（相邻边界、许可依据、T01 端点/边链、占用映射）——**条件**：
   "许可依据"必须引用现行规则权威文档（`cross-section-access.md` §5/§6
   AccessRule 组合模式），不发明新许可语义；T01 端点/边链定义随 #237 子合同走。
5. 控制锚点重绑（停止线、Gate `transition_index`、信号组、Waiting/Conflict
   锚点）——**条件**：必须与现行锚点绑定语义一致；各轮锚点核对口径即其验证面。
6. 修订与制品绑定（同一最终拓扑的 LFCA/`SharedNetworkRevision`/digest/合同
   版本）——**条件**：锚定 ADR 0025（受检规范路网与共享静态路网）与
   ADR 0033（摘要角色与摘要算法选型权威）的现行权威，不另立绑定口径。

**落地条件（统筹复核结论）**：实现切片把六项落为类型化/文档化契约且逐项引用
权威来源；凡现行模型不提供的保证，记入「生产 G1 缺口清单」由统筹在收口批汇总
（协调章程 §7），**不在设计里静默假设**。统筹同时确认：T01 用中心线真实边物化
（整边界锚定、不依赖 #273、不与固定连接区方案混用）与"设计接受前不放宽生产
路线行为"边界一致；A1 几何修复失败按 §6.2 处置正确。

## 4. 最小闭环样本定位

[sample/](sample/README.md) 给出合成、钉版的最小闭环输入：双车道路段 + 固定
预制过渡 + 四角色受控输入 + 下游信号化路口 + 场景阶段与期望断言。它同时钉住：

- 缺口输入（`P1=[A0,I1,B0]`、`P2=[B1,I2,C0]`）与连续对照（增加 `P0=[B0,I0,C0]`）
  ——与 A0/A1 夹具同构，便于对拍；
- 固定过渡的几何、拆边、整数毫米长度与占用映射草案；
- §2.3 子合同 4–8 的验收输入（目标前车、目标快速后车、源后车、同拍竞争、
  下游阻塞、长车尾、快照/恢复/重放）。

样本是**设计材料**：当前生产入口无法表达过渡语义，样本中的执行断言归属后续
实现切片；样本不构成任何运行结论。

## 6. 未决问题与风险

### 6.1 未决问题

1. T01 物化形态最终由 #237 G1 定夺：真实边 + 普通连接（本设计建议）需要确认
   与 `road-junction-model.md` 的 ManeuverPath 覆盖规则兼容——T01 若被纳入
   某个 Junction 的 path，须给出完整 entry/internal/exit 声明，不能只画斜线。
2. 过渡期间源/目标双占用投影与 `vehicle-following.md` §6.4 overlap 判据的
   组合顺序需要 G1 明确（不得把双占用误判为非法重叠，也不得借此合法化真重叠）。
3. 诊断分类（`lane-continuity-gap` 等）是否升格为稳定机读输出/公开诊断格式，
   需另行评审（A1 保持内部）。
4. #790 最终拓扑与本设计的拆边/边界方案汇合方式（§3.1 推导）。
5. §3.4 六项中凡现行模型不提供的保证（如超出逐修订身份 + 文档化映射的稳定性
   诉求），随实现切片记入「生产 G1 缺口清单」交统筹汇总，不在本设计静默假设。

### 6.2 风险

1. **几何发射风险（已实测）**：A1 连续夹具在几何修复阶段失败
   （`repaired curve sampling exhausted: 9 pieces breach the quantized weld
   budget` / `2 pieces (chord floor) each turn 3.75 deg > 1.90 deg`）。最小闭环
   样本与后续实现切片的夹具几何必须以"发射可通过"为设计输入（内部边加长、
   转角放缓），或如实记录发射失败为独立几何问题，不得"修绿"几何代码或改写
   为路线失败。
2. merge/diverge 的 gap/priority/lane availability 仍是独立 G1 范围
   （`road-junction-model.md` §17.4）；若选备选固定连接区，不得复用"现有
   Conflict 原语可复用"推断端到端安全已交付。
3. 排队/容量/行程时间会因 T01 进入前硬停与间隙等待改变；不得把源/目标双投影
   记为两辆车或两份容量（修订稿 §4.3 口径）。
