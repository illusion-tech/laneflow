## 0. 计划定位

- 本计划只给**切片分解与验收标准**；每个切片另立 Issue，一 Issue 一 PR，
  生产行为变更在实现前走 G1（`development-gates.md` §4）。
- 生产 S1 G1 保持 Proposed；本计划不批准任何生产行为变更。
- 验收以[最小闭环样本](sample/README.md)的钉版输入与下述矩阵为准；样本中标注
  `needs-237-subcontract` / `needs-g1` 的期望在对应能力落地前不得宣称通过、
  不得以「不适用」替代缺失证据。
- 陈述纪律同设计方案 §0：未运行的验证一律标注，不以推导充当运行结论。
- 方向裁决（2026-10-29）选项 3 采纳后，本计划按裁决口径补修（保证三段边界、
  数值口径、落地两道门槛、#237 范围、待冻结项、完整选取集合验收）；方向成立
  ≠ G1 Accepted。

## 2. 切片详情

### S0（已完成）：真实反例与内部阶段诊断

- **证据**：A0 修正失真测试、真实 B0/B1 反例、精确错误文本、连续对照、来源
  错误分域（11 案例）；A1 六类内部诊断、逐记录定位、连续夹具组合静态实测
  （几何修复阶段失败，如实保留）。
- **不再补做**：不重跑全量人口。当前人口 v2 基线为 **9,344/10,000 条不可展开**
  （`research/issue-1053-lust-population-v2/README.md`）；**9,350/93.5% 为旧选取
  口径**（旧 SHA 对照），两者差值不得写成修复效果。

### S1：展开合同收口与过渡感知扩展（converter）

**目标**：让路线展开在**声明的过渡材料存在**时跨越过渡完成物化；材料不存在时
行为与现状严格一致。这是对 `can_complete` / `materialize_path` 成功条件的
生产行为变更，**必须先接受本设计并走 G1**，在此之前红线保持（不放宽）。

**范围**：

1. 过渡声明输入：来源 lane 对 + 过渡边界 + 最终边链（跨层合同 §3.4 第 4 项）；
   展开器把「当前来源 lane」在声明边界处按声明转移，其他位置保持
   `from_lane == 到达 lane` 的严格语义。
2. 错误语义保持：无材料的 lane 缺口仍失败关闭，错误定位（`lane-continuity-gap`）
   与阶段分域不变；A1 诊断分类按评审结论决定是否升格稳定机读输出（另行评审，
   不与本切片混做）。
3. 契约同步：`real-road-workloads.md` §3.1 车道级展开条款随 G1 修订（措辞从
   「禁止边内换道」改为「仅在声明过渡材料处允许来源 lane 转移」），并明确
   `routes.toml` schema 不变（lane id 序列）。
4. 可选（随 #806 实现排期）：PR #261 遗留 pinned 静态断言补齐。

**验收（接受）**：

- 样本 `s1` 三拓扑变体成立：gap（无 `T01`/无 `I0`·`P0`）`lane-continuity-gap`
  （可达 `{0}`、所需 `{1}`）失败关闭；continuous-control（无 `T01`/有
  `I0`·`P0`）物化 `[A0, I1, B0_up, S00, B0_down, I0, C0]`；transition（有
  `T01`/无 `I0`·`P0`）物化 `[A0, I1, B0_up, T01, B1_down, I2, C0]`，与 A0/A1
  结论对拍。
- A0/A1 全部既有测试等值通过（反例、连续对照、来源分域、人口身份/顺序/绑定、
  重复构建确定性）。
- 负例分域：unknown lane/road、DUE internal edge、缺失道路 hop 仍留在原错误域。

**验收（必须拒绝/不得误判）**：任意 `Err` 冒充阶段断言；`B1` 不存在；把
unknown/internal 引用归类为换道缺口；跳过失败人口或从候选尾部补位；在无材料
处拼出边链。

**明确不做**：自由在线选道、任意位置转移、活动车改 Route、`ResolvedLanePlan`；
不改人口选取/排序/截断/绑定。

### S2：#237 最小子合同 G1 冻结（设计切片）

**目标**：把设计方案 §2.3 的 8 项子合同冻结为 #237 首版 G1 输入，消费
`cross-section-access.md` §14 已冻结保证（只做契约校验，不重复冻结）。

**必须回答的未决项**（设计方案 §6.1；第 1、2、7 项**保持待冻结**——方向裁决
选项 3 只确立职责边界与材料化方向，不使任一项获得 G1 通过）：

1. `T01` 物化形态：真实边 + 普通连接（本设计建议）与
   `road-junction-model.md` ManeuverPath 覆盖规则的兼容性；merge/diverge
   独立 G1（§17.4）的适用边界。
2. 源/目标双占用投影的精确公式，与 `vehicle-following.md` §6.4 overlap 判据的
   求解顺序（双占用不误判为重叠，也不合法化真重叠）。
3. 进入仲裁与 Following/Signal/Waiting/Conflict/Parking 的同一安全求解顺序落点。
4. 过渡状态的快照形状、恢复、摘要与版本影响（交 S5 消费）。
5. 明确排除清单冻结：潮汐/可逆车道、动态 lane-use 全集、自由在线选道、活动车
   改 Route、任意位置材料化、全量 `ResolvedLanePlan`；#273 仅在任意纵向位置
   材料化或共享 stationing 成为必要输入时登记为真实依赖。
6. 跨层合同落地条件（统筹复核结论，2026-10-29）：设计方案 §3.4 六项落为
   类型化/文档化契约并逐项引用权威来源——边链身份按**逐修订身份 + 文档化映射**
   口径（不发明跨修订稳定 ID）、许可依据引 `cross-section-access.md` §5/§6
   AccessRule 权威、锚点对齐现行绑定语义、修订/制品绑定锚定 ADR 0025/0033；
   凡现行模型不提供的保证记入「生产 G1 缺口清单」（统筹收口批汇总）。
7. 执行能力检查（裁决口径）：静态材料可先验证；**生产执行必须有能力检查并在
   不支持时拒绝**。检查位置（注册期 / 车辆准入期 / 执行入口）与拒绝语义由 G1
   定案；T01 承载形式、占用映射与本检查在冻结前不得视为可用能力。

**验收**：G1 记录链接到正式设计证据；若改变 Route 权威或引入动态拓扑，必须
显式 supersede ADR 0017（默认方案预期不需要）；与 #234/#262 冻结保证逐条
校验通过或明确回修。

### S3：过渡材料化与静态发射（compiler / authoring）

**目标**：让合成编制输入（或道路编辑来源）能声明「双车道路段 + 固定预制过渡」，
经唯一最终权威拓扑发射静态制品，供展开与运行时消费。

**范围**：

1. 必要分段：`B-up`/`TZ`/`B-down` 的 lane 共延伸切分、`T01` 真实边（连续
   几何、明确边界、整数毫米最终长度）、来源映射与稳定身份。**来源保真**：T01
   若为经授权规则派生的编制材料，保存来源映射与构造依据，**不得冒充原 SUMO
   connection**。
2. 控制锚点：`sl-t01` 进入点停止线、J2 的 `sl0/g0`、`sl2/g2` 重绑到最终边；
   不沿用旧 gate index，不按百分比搬移停车位置。
3. 静态发射：LFCA/`SharedNetworkRevision`/`NetworkRevisionId`/digest 与合同
   版本随同一最终拓扑产出；编译器仍不预编译路线（ADR 0029）。
4. **几何发射预算实测**：按样本几何验证发射；若失败，按 A1 口径如实记录为
   独立几何问题（不修绿几何代码、不改写为路线失败、不提高预算）。

**验收（接受）**：样本 `network` 发射通过；`s1` 三拓扑变体在最终拓扑上成立；
过渡路线与直行路线经 `register_route` 注册成功（静态序列合同，含完整
ManeuverPath 匹配与内部边覆盖）；锚点绑定与 §3.4 逐项一致；边链身份按逐修订
身份 + 文档化映射口径（不发明跨修订稳定 ID），许可依据引用现行 AccessRule
权威。

**验收（必须拒绝）**：缺失/歧义/绑错边的锚点；边界不足或重叠的过渡；旧修订
证据复用；只比较 `NetworkRevisionId` 而需同一 `Arc` 的场合。

**明确不做**：不改生产采样与阈值；不把 LuST pinned 基线的成功几何/拓扑/锚点
改动；不实现 #237 运行时安全。

### S4：运行时最小换道执行（runtime）

**目标**：实现子合同 4–7（占用投影、目标前后车与源后车、进入仲裁与硬停、
原子提交与车尾清空），在最小闭环上证明可执行。

**验收（接受）**：样本场景 s2–s8、s11 全组成立——单车基线、目标前车/快速后车/
源后车停让与恢复、同拍稳定裁决、下游阻塞预检、长车尾清空、结构负例失败关闭；
确定性（同输入同规范结果，不同 worker 配置一致）；执行入口能力检查生效，不
支持的过渡被拒绝（拒绝语义按 S2 G1 结论）。

**验收（必须拒绝/不得误判）**（对应验收矩阵）：只检查目标前车；进入共享区后
才感知目标后车；以未提交位移充当其他车位置；以遍历先后/worker 调度决定裁决；
车头离开即释放资源；把正常等待记为非法路线；放宽注册/安全距离/冲突覆盖使夹具
通过。

**明确不做**：潮汐、自由选道、任意位置横向轨迹、全网推广。

### S5：过渡持久化 / 恢复 / 重放（runtime admin）

**目标**：子合同 8——过渡阶段、路线位置、资源预约、等待、清空事实的稳定引用
保存/重建；恢复不重复 grant/事件；重放一致。

**验收**：样本 `s10` 三捕获点（pre-entry / mid-transition / clearing）恢复后与
连续运行、重放的规范状态摘要与事件一致；快照不含进程内句柄（ADR 0029 §6
口径）；版本影响按 S2 G1 结论登记。

### S6：全网物化与 TOPO/DEMAND 验收（#790 汇合）

**目标**：在 #790 形成的同一最终 LFCA/`SharedNetworkRevision` 上做全网确定性
物化、逐条注册与真实 TOPO/DEMAND 验收。

**验收**：验收条件按**四层分列**——材料覆盖（可物化）/ 几何发射 / 可注册 /
执行（按既定 workload 窗口完成），逐层计数与失败原因分别保留，上层通过不推断
下层；正式 convert 按**完整选取集合**（10,592 候选 → 10,000 入选）验收，
**失败人口不删除、不从候选尾部补位、不跳过**；不以 S0 诊断数量或 S4 小夹具
结果替代。当前基线为 9,344/10,000 不可展开、9,350/93.5% 为旧选取口径，两者
差值不得写成修复效果，也不得写「放宽即消除失败率」——修复效果只能由新合同下
完整选取集实验给出；两口径收益分列（协调章程 §1）。

**排程**：重构建/全量实验初始并发 ≤2（协调章程 §3）；正式耗时/堆峰值比较单独
排时段；结果 JSON 不含计时字段。

## 3. 验收矩阵映射

验收条件按材料覆盖 / 几何发射 / 注册 / 执行四层分列，不得跨层推断（数值口径
见 S6）。

| 验收组           | 主责切片             | 样本场景   | 一句话接受条件                                          |
| ---------------- | -------------------- | ---------- | ------------------------------------------------------- |
| 反例与对照       | S1                   | s1         | 精确路线错误 + 连续边链，人口/顺序稳定                  |
| 注册与原子性     | S3                   | s1、s11    | 完整路径注册成功；失败前后注册表不变；注册成功≠安全证明 |
| 单车与位姿       | S3/S4                | s2         | 完整最终边链连续到达；停止线/门正确；不凭空换 lane      |
| 目标与源车道安全 | S4                   | s3、s4、s5 | 三方间隙不足进入前停让；安全后前进                      |
| 同拍与多车       | S4                   | s6、s9     | 稳定裁决、资源不足等待、恢复继续、无重叠                |
| 车尾与下游       | S4                   | s7、s8     | 车尾清空释放；下游阻塞不进入；无残留                    |
| 持久化与确定性   | S5                   | s10        | 三捕获点保存/恢复/重放一致；无重复 grant                |
| 结构负例         | S1/S4                | s11        | 缺材料失败关闭；不得靠放宽通过                          |
| 固定连接区专项   | （仅备选启用时另立） | —          | 全流门/停止线/冲突/清空覆盖 + 派生负载接受              |

## 4. 依赖、排程与治理

- **无跨路代码依赖**：S1–S6 与 A–E 各路并行（协调章程 §6）；共享代码只由 E
  修改，本路不触碰共享助手。
- **跨层合同**：设计方案 §3.4 的 6 项共同输入已由 lead 复核（2026-10-29，
  **附条件通过**；条件见 `design.md` §3.4）。S1/S3 落地时按条件转正式 schema
  （类型化/文档化契约逐项引用权威来源）；与 #790 几何/编制线的入口/出口移动
  问题同步澄清；现行模型不提供的保证汇入「生产 G1 缺口清单」。
- **落地两道门槛（裁决口径）**：(a) 先最小合同（S2 冻结），再并行 S1（展开器）
  与 S3（过渡材料化）；T01 可为经授权规则派生的编制材料，须保存来源映射与构造
  依据，**不得冒充原 SUMO connection**。(b) 静态材料可先验证；生产执行必须有
  能力检查并在不支持时拒绝——检查位置与拒绝语义 G1 定案（S2 未决清单第 7 项）。
- **治理**：每切片建 Issue（原生 Type + `area:*`）→ G0/G1 分别记录 → G2
  「设计/依赖就绪」分别记录 → 实现/实验 → PR（`Closes #<issue>`）→ lead
  收口入队（Merge Queue，`--match-head-commit <H_pr>`）。本批设计材料的
  跨层合同由 lead 复核，设计接受（G1）另行记录。
- **提交纪律**：trailer 按实际 Harness/Model；AI 参与不写 `Co-authored-by`。

## 5. 全局明确不做

1. 设计接受前放宽生产路线行为（含 `can_complete` / `materialize_path`、错误
   路径、人口绑定、`routes.toml` 口径）。
2. 本批改生产代码、生产采样、compiler、数据格式、Adapter API、依赖或阈值。
3. 把城市经济、出行需求、路线选择策略或游戏规则放进 Traffic Runtime；把
   换道特化提升为所有交通参与单元的终态公共基类。
4. 用注册成功、小夹具完成或诊断数量冒充多车安全或全网可执行证据。
