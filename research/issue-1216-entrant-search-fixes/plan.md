# Issue #1216 方案稿：S4 潜在进入者距离裁剪与循环路线出现项查询

基线：main@45263887（审计 P1×1/P1×2）。范围：conflict_tick.rs 潜在进入者枚举的
距离裁剪与出现项定位；不动持久化面（#1217）、不动性能面（#1219）。G2 在本稿
获批后记录。

## 1. 缺陷一：距离裁剪（conflict_tick.rs 7046-7076）

### 1.1 现机制与错误轴

- 游走结构（7047-7076）：从 `interval_edge` 起沿 lane-graph 上/下游分环扩张，
  `neighborhood` 去重，`depth_mm` 为**单一全局标量**。
- 错误轴三条：
  1. **全局深度**：`depth_mm` 在邻居入列时累加该邻居全边长（7062-7068），
     是所有分支共享的一个标量。`while depth_mm < MAX_STOP_REACH_MM`（7051）
     在环顶判一次——任一长分支一次入列就把预算耗尽，其余分支的后续环
     整体不再展开。
  2. **全边长计距**：入列即计全长，不区分边上实际位置；边内剩余距离（车在
     边首 vs 边尾差整边长）不在搜索口径内。
  3. **常量无据**：`MAX_STOP_REACH_MM = 250_000`（7046）无输入上界支撑——
     受检 profile/步长组合（如 100m/s、0.5m/s²）制动距离可达 10km 量级，
     250m 不是任何合法输入的包络。注释里"250m 包络任意档案最坏 d_stop"
     的断言不成立。
- 反例（issue）：分支上一边 D=300m，入列即令 depth_mm=300k≥250k，环止；
     另一分支上距保护区 8m 的车所在的边在第二环，永未入列——8m 车从
     枚举中消失，P4 少证一个真实潜在进入者，错向放行。

### 1.2 修案

- **各分支路线距离**：环扩张改为逐条目深度。frontier 条目=(edge, depth)，
  depth=保护区入口沿该分支到 edge 近端的路线距离；扩张到邻居 n 时
  `depth(n) = depth(c) + len(c)`（跨当前边的实距），条目独立、互不共享。
- **边内实际剩余距离**：剪枝只用近端距（`depth(n) <= reach` 即入列——边上
  存在可达点）；车在边上的实际距离由既有逐进入者测距给
  （`distance_to_occurrence_progress` 已含 progress）。即：搜索剪枝按
  近端距（不漏），证明判据按实际距（不松）。
- **搜索范围导出（禁增常量）**：`reach = max_{profile in revision}
  stop_distance_millimetres(max_speed_limit, fixed_delta_time_ms,
  comfort_decel*1000, min_gap)`——受检 profile 与步长导出；对该 reach 之外
  的任何车（d_stop <= reach < distance）逐进入者证明恒成立（yieldable），
  剪枝不漏（I-B1 方向保持：枚举域 ⊇ 一切证不出来的车）。
  - `comfort_decel == 0` 的 profile 使 stop_distance 返回 u64::MAX：该类车
    永不可证，枚举域=整可达分支（有限图 visited 集天然终止）；此为正确
    保守向，性能归 #1219。
  - 备选"逐进入者可达证明"（先枚举全车再逐个证）否决：占用索引按边组织，
    全车扫描是 O(vehicles) 且与既有 edge_vehicles 枚举形态相悖；导出范围
    保持边局部枚举不变。
- **删 `MAX_STOP_REACH_MM`**（验收项：常量删除/替换记录）。

## 2. 缺陷二：循环出现项首现误选（conflict_tick.rs 7080、7087、7254-7262）

### 2.1 现机制与错误轴

- 两处 `route_edges.iter().position(...)`（7080 区间目标、7087 边界目标）
  从路线头起取**首个**同值出现项。循环路线 [X,D,Y,B,D,Z]（D 为边界边，
  游标在 B=下标 3）：真目标是下标 4 的 D（前方），position() 选中下标 1
  （身后）。
- 后果链：`distance_to_occurrence_progress(…, target=1, …)` 对身后目标返
  `None`（7254 注释"身后目标不构成到达"）→ `best` 保持 None → 7257-7262
  `continue`"已过区间/不可达跳过"——把**选错目标**误判成**已过区间**，
  真实前方的 D 从未被度量，进入者被跳过，P4 少证。

### 2.2 修案

- **注册期出现项表**：`compile_route` 构建
  `edge_occurrence_index: Box<[(LaneEdgeOrdinal, u32)]>`——(边序数,
  路线下标) 对按 (边序数, 下标) 排序；每路线一份，注册期一次。
  - 存储记账：约 8 字节/路线边，入 `retained_logical_bytes` 与分配账
    （会计钉如位移按测试夹具面重钉，差异记录）。
- **游标定位**：查边 e 的出现项区间（二分到该边的连续段）后
  `partition_point(|idx| idx < cursor)` 取**首次不早于游标**的出现项；
  无 ≥ 游标者=真在身后。7080（区间目标）与 7087（边界目标）同修。
- **skip 分支语义**：7257-7262 的 `best=None` 跳过在定位修正后只在"全部
  目标真在身后"时成立，语义与注释对齐；表查失败（边不在表=数据前提缺失）
  维持既有 fail-closed 归口（上方 state/compiled 分支）。
- **T 与边界边同修**（issue 要求）：interval_edge 的目标选位（7080）与
  first_ring 边界目标选位（7087）走同一表同一 partition_point 口径。
