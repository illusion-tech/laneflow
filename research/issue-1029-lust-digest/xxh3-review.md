# LuST 确定性派生与 XXH3 复核

关联 [#1029](https://github.com/illusion-tech/laneflow/issues/1029)；测量日期：2026-10-25。
这是固定输入的非生产实验。规则修订提案在 [#1051](https://github.com/illusion-tech/laneflow/issues/1051)，尚未接受。

## 结论

这两处实际用途是确定性排序与位置比例派生，不承担输入真实性、对象身份或完整性
相等证明；“结果持久化”本身不构成必须采用密码学哈希的技术理由。现行 ADR 0033
仍按间接持久化规则将其归入内部完整性摘要，因此生产 SHA-256 合同保持有效。
本复核建议另行 G1 明确确定性派生角色，允许在满足具体要求后采用非密码学算法。

在本机同批真实输入上，XXH3-64 相比 SHA-256 的候选哈希快 11.16–11.83 倍，带前缀
的 `q` 派生快 4.76–4.80 倍；每次构建分别节省约 0.41–0.43 ms、0.37–0.38 ms。
这是持续发生的单项收益，但没有证明转换器或 DEMAND 端到端提速。完整选取的摘要
成本不是本次证据显示的主要耗时；两处都不在稳态 tick 内重复计算。

XXH3 是值得进入 G1 的候选，不能由 SHA/BLAKE3 两项比较排除。这里也不直接决定
生产迁移：角色是否应修正与当前规模是否值得迁移，应分别作决定。一次性人口/证据
重建成本可承担，不作为长期保持原算法的唯一理由。

- `sha2 0.11.1`、`blake3 1.8.7`、`twox-hash 2.1.3`。XXH3 只在 converter 的
  dev-dependencies 中启用 `std` / `xxhash3_64`，关闭默认 features；复用原 lockfile
  已有版本，不升级既有 `ruzstd` 依赖。两项测试依赖纳入根 cargo-deny 约束。
- 默认测试跳过本项；运行命令与第一阶段相同，当前源码一次输出三种算法。常规
  release 单测 159 passed / 8 ignored；三个显式真实输入实验各 1 passed。

候选 XXH3 调用 `XxHash3_64::oneshot_with_seed(0, id.as_bytes())`，使用实现的默认
secret；按无符号 `u64` 升序，原始 ID 字节作为次键。数值升序等价于该结果大端
字节的字典序，不能改用机器原生端序字节比较。SHA/BLAKE3 主键是 32 字节，XXH3
是 8 字节，普通完整选取还包含键宽与排序存储成本变化。

位置实验保持 `LF-REAL-LUST-DEMAND-v1\0 || UTF-8(ID)`，用 64 字节栈缓冲区拼接，
测量包括拼接与边界检查；XXH3 结果右移 11 位得到 53 位分子，再除以 `2^53`。
没有使用 Rust `Hash` trait 编码、进程随机 seed 或可变 secret。保留旧前像只为隔离
算法变量，**不是已经接受的迁移前像**；真实迁移须另定域分隔和派生版本。

计时不含来源验证/XML 解析/路线展开/编译/写文件；完整选取含输出释放。`q` 测量
固定使用原 SHA 人口，未计算实际首 route edge、`progress` 或运行 DEMAND。
每样本先校准至约 40 ms 或 256 次上限；快速 XXH3 项会先达到 256 次，批次实际
约 10 ms（候选）或 25 ms（位置），没有宣称全部批次都达到 40 ms。

量级对照，不是精确阶段归因。

## 语义与分布观察

以下结果三进程完全相同，来自同一固定数据集，不是三次独立抽样：

- XXH3 与 SHA 人口共有 9,441 条，移出/移入各 559 条（5.59% 人口被替换）；
  共有条目的名次全部改变。XXH3 人口需复制 375,865 个路线 edge 字符串，SHA 为
  377,108 个，所以普通选取比较含人口变化；固定人口对照保留相同 SHA 排序及负载。
- 原 SHA 人口的一万条 53 位分子全部改变，`q` 平均绝对差为 `0.333761744`。
  该差值不是米数；退化区间与浮点舍入之后的真实位置变化没有测量。
- 三种算法在 10,592 个候选主键上均为零碰撞，在一万条位置分子上也均为零碰撞。
  这只是固定样本观察，不是 XXH3 的抗碰撞保证。
- 真实输入实验断言 SHA 测试实现逐字段等于生产输出，预计算键也相同；反转候选
  输入后 XXH3 顺序相同。另将所有候选主键强制设为零，确认仍保留 10,000 条并按
  原 ID 字节严格升序，主键碰撞不会被误当作车辆相同。
- 新人口的车道级可展开性、`progress` 合法性与实际交通质量未验证。

| 算法    |  `q` 最小值 |  `q` 最大值 |    `q` 均值 | 16 箱中最少/最多 |
| ------- | ----------: | ----------: | ----------: | ---------------: |
| SHA-256 | 0.000093418 | 0.999988179 | 0.500743547 |        586 / 689 |
| BLAKE3  | 0.000001777 | 0.999939682 | 0.498745957 |        564 / 702 |
| XXH3-64 | 0.000019713 | 0.999954375 | 0.502933819 |        588 / 675 |

箱为 `[k/16, (k+1)/16)`，均匀模型下每箱期望计数为 625。XXH3 的箱计数为
`[607, 633, 599, 588, 618, 628, 613, 675, 654, 643, 626, 602, 593, 631, 651, 639]`。
这些描述值未显示空箱或集中在狭窄区间；**没有进行普适均匀性、独立性或交通代表性
认证**，也不能排除 ID 结构上的相关性。确定性不等于均匀，更不等于不可预测。

## 技术要求与规则调整建议

固定源文件的长度、SHA-256 与 commit 校验负责检查“消费的字节是否等于冻结输入”；
它们不能证明数据本身真实或有代表性。候选哈希只提供顺序，位置哈希只提供比例。
两者都没有从“哈希相同”得出“对象或内容相同”的判断，因此无需沿用完整性摘要的
证明能力来论证正确性。该结论由本仓库的消费方式得出，不是对所有采样器的建议。

允许非密码学派生需要同时满足：

1. 角色独立：不得复用为身份、去重、签名、制品摘要或 Runtime 完整性证明。
2. 结果可重建：冻结算法变体、seed/secret、原始 UTF-8 字节、域分隔与字段边界、
   比较顺序、位提取、派生版本；迁移前增加跨实现 golden vectors。此次只在一台
   x86_64 主机运行，不宣称已经完成跨平台验证。
3. 碰撞有明确语义：人口排序继续以完整原始 ID 打破平局；若某用途需要唯一身份或
   摘要相等证明，不可据此沿用 XXH3-64。位置分子可以重复，不要求每辆车得到独占值。
4. 分布按用途验收：描述统计只能发现明显异常；实际迁移还要验证新人口路线、
   合法位置和 workload/replay 基线，不能把换样称为质量提升。
5. 威胁模型写清：本实验处理冻结来源，不防外部参与者挑选 ID 获得有利位置。公开
   固定 SHA 同样不能防止反复试 ID 操纵排名；如果需要抗操纵、公平抽签或不可预测性，
   须另行设计带密钥/承诺等机制，不能仅换一个哈希名称。

[xxHash 官方规格](https://github.com/Cyan4973/xxHash/blob/dev/doc/xxhash_spec.md)明确
不提供抵抗刻意碰撞或指定摘要构造的能力；
[twox-hash 2.1.3 文档](https://docs.rs/twox-hash/2.1.3/twox_hash/)给出原始字节接口与
feature 选择。本报告对确定性派生的适用判断仍以以上用途和限制为条件。

G1 提案 #1051 应修正“任何影响持久结果的哈希都必须密码学化”的过宽归类，同时保留
现有四类角色的安全约束与稳态 tick 禁止哈希。若接受 LuST 迁移，再在后续实现中提升
受影响 workload ID、更新派生版本、重建验收基线，直接采用一套当前合同。
