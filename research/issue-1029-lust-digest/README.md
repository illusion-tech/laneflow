# LuST 短前像摘要成本复核

关联 [#1029](https://github.com/illusion-tech/laneflow/issues/1029)；测量日期：2026-10-25。

## 结论

在本次机器、依赖版本和固定 LuST 输入上，保持候选排序与 `departPos` 派生的 SHA-256。
实测 BLAKE3 对短输入更慢；完整选取没有可复现的提速。迁移及重建基线主要是一次性
成本，不能单独证明应长期保留原算法；这里的保持结论由实际候选算法成本支持。
若目标机器、实现或输入分布改变，应重新测量，不把本机结果推广为 SHA-256 普遍更优。

## 方法

每个项目先用校准批次预热，迭代数逐倍增加至约 40 ms 或上限 256 次，随后保持该
迭代数测 11 个样本。CSV 的 `ns_per_call` 为批次墙钟除以迭代数；每个 call 处理
下表所列的完整记录集合，不是单条记录耗时。样本内轮转项目起点并交替方向；摘要
结果使用 `black_box` 消费。计时器位于整批操作外，不插入单条摘要计算。

| 项目                                 | 一次调用内容与边界                                                                                          |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `candidate_hash`                     | 对相同 10,592 个候选 ID 逐条计算摘要；不分配结果表                                                          |
| `select_and_drop/production`         | 原生产函数：对全部 215,526 条已解析记录筛选、缓存键排序、截断、校验、复制一万条输出，再释放输出             |
| `select_and_drop/sha` / `blake`      | 测试专用选取实现，保留相同筛选、排序次键、截断、校验和复制步骤，只更换主摘要键                              |
| `select_and_drop/precomputed_sha`    | 同测试实现，用来源序号索引预先计算的相同 SHA 键；包含索引读取成本，作为移除摘要计算的估计对照               |
| `select_and_drop/fixed_population_*` | 两项均额外计算并消费相应算法摘要，再使用相同预计算 SHA 键；固定最终集合、排序和复制负载，避免新人口造成混淆 |
| `depart_fraction`                    | 对相同 SHA 入选的一万条记录，用现有前缀逐条摘要并取前 53 位得到 `q`；不构造实际 `progress` 或运行 DEMAND    |

实验开始时逐字段断言测试 SHA 实现与生产输出相同、预计算键输出与生产相同。
测试实现针对完整固定候选集，失败诊断没有复制生产错误文本；不声称覆盖任意坏输入。
BLAKE3 对照保留现有前像，仅隔离算法变量；这不是已经冻结的迁移前像或新派生版本。

## 测量结果

下表为每轮 11 个样本的中位数，单位均为 **ms / 整次调用**。

| 项目                       |  第 1 轮 |  第 2 轮 |  第 3 轮 |
| -------------------------- | -------: | -------: | -------: |
| 10,592 次候选摘要：SHA-256 | 0.472688 | 0.549420 | 0.465164 |
| 10,592 次候选摘要：BLAKE3  | 0.845513 | 0.985456 | 0.841275 |
| 生产选取及输出释放         |  66.9092 |  76.2208 |  81.0400 |
| 测试选取 SHA               |  68.0439 |  73.5879 |  79.4640 |
| 测试选取预计算 SHA         |  68.2571 |  73.8126 |  77.9170 |
| 测试选取 BLAKE3            |  70.0905 |  73.7960 |  80.5693 |
| 固定人口，计算 SHA         |  67.1696 |  74.5876 |  80.2275 |
| 固定人口，计算 BLAKE3      |  65.9850 |  75.1310 |  80.1444 |
| 一万次 `q` 派生：SHA-256   | 0.499524 | 0.538233 | 0.517290 |
| 一万次 `q` 派生：BLAKE3    | 0.930469 | 1.005211 | 1.002900 |

候选摘要中，BLAKE3 每批多用 0.373–0.436 ms，为 SHA 的 1.79–1.81 倍；`q` 派生
每批多用 0.431–0.486 ms，为 SHA 的 1.86–1.94 倍。这些是本次短输入批次的结果，
不是长缓冲区吞吐结论。

单独 SHA 候选摘要批次耗时与生产选取及输出释放耗时的比值为 0.57%–0.72%，只作
成本量级参照；两者独立计时、缓存与调用上下文不同，**不是精确的阶段归因比例**。
更直接的预计算键对照中，“测试 SHA − 预计算 SHA”的三轮中位数差为
−0.2132、−0.2247、1.5470 ms，方向不一致；不能据此声称摘要零成本或精确占比。
固定人口对照中的 BLAKE3 也没有跨轮一致的提速，因此不报告完整选取收益。

## 语义变化

三轮完全一致：

- 两种选取共有 9,440 条记录；移出 560 条、移入 560 条，即 5.6% 人口被替换。
- 共有记录中 9,440 条名次全部改变，没有保持相同名次的记录。
- SHA 人口需复制 377,108 个路线 edge 字符串，BLAKE3 人口为 376,346 个，因此
  直接完整选取对比本身包含复制负载变化；固定人口对照用于隔离这一因素。
- 对原 SHA 人口的一万条记录，前 53 位分子全部改变，`q` 的平均绝对差为
  `0.332742114`。这是相对合法区间的比例变化，不是米数；未构造实际首 route edge。
  `high == low` 的退化区间不会改变 `progress`，浮点舍入也不在本项统计中。
- 未验证新人口的车道级可展开性，不把这次换样解释为质量改善；旧有路线 / 几何缺口
  没有在本实验中解决。

按设计 §7，真实迁移须提升受影响的工作负载 ID、更新派生版本并重建基线。这是可
承担的一次性工作；本次不迁移的性能依据是候选算法没有提供持续收益，而非拒绝改变
历史结果。两处按 ADR 0033 的间接持久化规则归类，角色结论不因测量改变。

变化、样本及中位数；常规测试默认跳过此证据测量。
