# 空区间短路的验证与采用边界

## 结论

候选在固定长路线的普通整步测量中有重复收益，且不增加内存；正确性回归通过。
采用依据是这项针对性结果。城市两轮六组对照未重现第一轮第三组的 12.67% 倒退，
但仍有明显时间漂移，不能宣称固定的城市加速百分比或 p95 改善。
这属于 1.0 前内部优化，不是 #707 正式性能认证，也不证明稳定十万 Active。

## 空区间证明与正确性

1. 非资源 Gate 定稿保留完整车辆和路线查找，先依旧规则计算零进度回看的
   `first_hop`。只有它等于 next cursor 且 next 的毫米进度小于该边长度，才提前
   返回：区间中的 hop 只能等于 next cursor，而原循环在该位置首先 break。
   同边旧进度为零的回看、恰好到边尾、多边跨越均不被误短路。
2. GateCrossed 只有 `first_hop < next cursor` 才可能有元素。`first_hop` 仍包含
   prepared grant 的最小 hop，不能直接用 old/next 相等代替此判据。
3. Maneuver completion 在 old/next cursor 相等且旧 traversal 不是 Clearing 时
   为空。旧 Clearing 继续原路径，包括出口早已越过、本拍车尾净空的延迟完成。
   资源 acquire/release、passage enter/clear、Waiting 事件和统一排序未被短路。

新增三个测试：每条边的 old/next 与零/非零 carry、下一位置边首/边内/边尾、
Clearing/非 Clearing 的逐项扫描预言机；同 cursor 的 prepared grant 回看；
空区间仍拒绝缺失路线。该矩阵是投影层边界测试，资源合法性由真实整步夹具验证。

完整 runtime 回归 **523 passed / 18 ignored**，包含固定历史摘要的阶段等价、
AfterGrants/AfterTransitions 失败与同拍重试、快照续跑、Waiting/Conflict 资源生命周期、
句柄代次复用及 worker 1/2/4/8/16 的既有矩阵。新增测试未重写固定预期。
Clippy（all-targets、placement-fixtures、`-D warnings`）通过。Rust 采集器六项测试
通过，包括缺失/重复/损坏长路线样本的拒绝测试。

两轮城市、两个规模共 48 个进程，同一规模的 `commands.jsonl`、`events.jsonl`、
`ticks.jsonl` 在 A/B 间分别只有一个 SHA-256；这覆盖此次固定输入，并非普遍行为证明。

## 机制、内存与环境限制

独立诊断在所有长路线轴上每车每拍从 16 次二分降为 11 次，省去非资源 Gate 定稿
两次和事件区间三次。其余 11 次包含两次空降速表查询。仍然是 `signal_stop_distance`
的 Gate 解释为零，不能写成整个 step 不做 Gate 策略解释。

路线 8/128/2048 圈时 world-owned retained bytes 分别为
**717341 / 755741 / 1370141**，与 #679 固定基线一致。无新增字段、heap owner、
索引或失效维护成本；查询预言机和计数器只存在于测试。

采样前无已知 cargo/rustc/Clippy/城市研究进程，采样与编译串行。首轮前 CPU 总占用
8.70–22.37%，补测前 11.53–21.12%；没有把桌面系统视为隔离机器，也没有证明采样
全程不存在背景负载。Windows 调度与背景活动未被隔离，不能把城市漂移归因到某个
确定进程。源码、二进制与输入的前后身份核验通过，所有 raw 复算通过。
