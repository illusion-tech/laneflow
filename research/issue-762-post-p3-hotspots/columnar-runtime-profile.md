# 列式运行时当前头诊断

Refs #814。laneflow-columnar-runtime-research 的 detail 导出在受检源码副本中
注入探针，普通 release 不注入。计数先在线程内累加，P2/P3 输出块、P5 物理块
结束时归约；协调器在完整 join 后收取并清空，禁止逐车更新全局原子计数。

prepare-detail-at <完整源码提交> <新 builds 目录> 允许新冻结诊断工具定位旧头。
源码必须为当前干净工作树的可达祖先；工具、被测源码、导出文件与实际 EXE 各自
绑定身份。它不能让旧 EXE 借用新源码凭据。两臂须由同一工具、环境和工具链构建。

原有 LF762 保存协调器阶段墙钟；LF814 保存 20 项工作量与三项布局。
LF814_PIPELINE 每拍保存 28 项耗时和相应计时次数、40 项工作量。
LF814_BLOCK 是相同记录的五项汇总：准备、数值、限速、行走、收尾。
并行块耗时可以重叠，不能当作线程 CPU 或相加解释整拍回归。

P2 的逐行细分只采样 update_sequence % 32 == 0；缓存写入采样
cache_index % 32 == 0。P5 的逐行细分只采样 start % 4096 == 0 的块。
这些采样行并非随机代表样本；报告实测耗时及次数，不外推成整拍独占成本。
其余粗粒度计时覆盖所有相关调用，工作量计数不采样。诊断时钟和计数仍会扰动
执行；净收益只能用不带这些探针的普通 release 证明。
