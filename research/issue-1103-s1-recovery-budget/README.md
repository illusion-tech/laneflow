# S1 恢复覆盖与搜索预算定界

任务：[#1103](https://github.com/illusion-tech/laneflow/issues/1103)，父议题
[#790](https://github.com/illusion-tech/laneflow/issues/790)。本轮只增加 `cfg(test)` 研究入口
和证据，生产采样、拓扑发射、阈值与锁定失败清单不变。生产 S1 的 G1 **尚未接受**；
待评审建议见 [G1 决策材料](g1-proposal.md)。

## 结论

提高划分预算没有增加本轮恢复数。原六条截断样本在 1 / 2 / 4 / 8 倍预算下均为零候选；
固定 17 条样本的搜索耗时中位数由 0.404 秒升至 2.408 秒，约为 5.96 倍。
8 倍预算下，三条仍被预算截断，另三条已耗尽当前有限候选族。

随后冻结的真实覆盖队列包含 17 个分层起始样本，连同共享边关联路径、信号控制器闭包
和原 34 条路径，共检查 84 条目标路径。基线 22 条接受，候选赋值后 23 条接受：
新增的仍只有此前已恢复的 `sumo::-10004_5_1` 所在路径。两档覆盖预算的全部候选与赋值
结果相同。14 条多内边目标路径有 3 条接受，但没有新增同时恢复；31 条有信号目标路径
没有接受结果。不能把六条边获得候选解释为六条完整路径恢复。

两次独立进程的完整结果和输入逐字节相同；每次都重放全部 16,265 条原成功边，逐项比较
完整 f64 程序、画布选择键和全部 f32 规范点。原成功程序没有被候选替换。

## 四档预算实验

输入沿用 [#1093 的完整 17 条输入](../issue-1093-s1-efficiency/inputs.json)，只提高原六条
`partitions` 截断边的预算，另 11 条对照保持 32,768。候选顺序、2–2,048 片有限族、
512 步累计切向扫描、1.95° sink 与 0.95° 完整边端弦约束均不变。

| 单边划分上限 | 正式进程数 | 17 条样本搜索中位数 | 最小—最大 | 相对默认耗时 | 六条中新候选边 | 仍截断 / 有限族耗尽 |
| --- | --- | --- | --- | --- | --- | --- |
| 32,768 | 4 | 0.404344 s | 0.402961–0.420875 s | 1.00 倍 | 0 | 6 / 0 |
| 65,536 | 4 | 0.789273 s | 0.781723–0.806692 s | 1.95 倍 | 0 | 6 / 0 |
| 131,072 | 4 | 1.482730 s | 1.473633–1.497243 s | 3.67 倍 | 0 | 4 / 2 |
| 262,144 | 4 | 2.408179 s | 2.403371–2.457660 s | 5.96 倍 | 0 | 3 / 3 |

release 构建使用 Rust 1.99.1、`opt_level=3`。源码冻结为
`5388d19f58f51b8466331c3e542f10a76107e453`；二进制 SHA-256、构建 profile 和顺序见
[protocol.json](protocol.json)。预热各档一次，正式顺序为 `ABCDDCBAABCDDCBA`，
每次启动新原生进程。计时覆盖搜索及候选诊断构造，排除源数据准备和旧程序重放；
进程墙钟与 CPU 时间另存。该实验用于预算成本比较，不能外推为全转换器或交通运行时性能。

机器为 AMD Ryzen 9 9955HX、32 个逻辑处理器。每次前后均确认 AC 在线、OEM
`OperatingMode=2`，Windows 电源计划不变。按用户明确要求，背景负载只记录、不作为
停止条件。16 个正式区间的背景 CPU 中位数为 3.61%，范围 2.10%–8.45%；这是区间
平均值范围，不是瞬时峰值。采用 Windows `Processor(_Total)/% Processor Time` 原始
`CounterSample` 对，减去被测进程 CPU；残余包含监督进程开销。本轮没有单独测量监督
开销，也不作为安静环境认证。

同档五次输出逐字节一致。默认档以及其余 11 条对照与 #1093 的完整候选、跨度参数和
指标相同，另用 Python JSON 读取独立复核。第一次预热因 Rust 内存 f64 诊断值与已读取
JSON 的末位舍入差异而停止，正式进程数为零；修正为同一 JSON 读取路径后重跑。
程序和控制点使用整数位表示，仍精确比较。旧二进制与失败日志保留，摘要见
[budget-comparison.json](budget-comparison.json)。

## 真实路径覆盖

固定 LuST 数据共有 24,495 条边、14,098 条路径、201 个控制器；原发射成功 16,265 条，
失败 8,230 条。先完成清单，后按路径 ID 字典序冻结选择，再运行搜索和编译。

分层为多内边、共享内边、共享进出边、有信号路径，各按完整控制器闭包缺失 0 / 1 /
至少 2 条程序分组，每组取两个不同闭包。单闭包至多 64 条路径、128 条边、8 条缺失边；
新增恢复边并集至多 64 条。共享进出边还纳入使用这些边的全部路径及其信号闭包。
真实清单没有共享内边，保留该空分层；在任何搜索和编译前补入共享进出边分层。
各层总体数、筛选上限、具体 ID 和扩展关系全部保存在 [cohort.json](cohort.json)。
这是有界确定性选样，不是全城恢复率的统计抽样。

最终搜索原九条失败样本和队列新增失败边的并集，共 43 条。两档覆盖预算分别为默认值
和 262,144；原样本中非截断的三条失败对照仍保持默认值。完整路径验证源码冻结为
`4bb1f89d0b351bb9dde68219bc0c053eb2bbb098`，完整身份见
[protocol.json](protocol.json)。两次新进程执行，计时仅作诊断。

| 检查层级 | 原程序基线 | 默认预算候选 | 8 倍预算候选 |
| --- | --- | --- | --- |
| 有候选的失败边 / 搜索边 | 0 / 43 | 6 / 43 | 6 / 43 |
| 完整目标路径接受 | 22 / 84 | 23 / 84 | 23 / 84 |
| 目标跨边方向拒绝 | 3 | 3 | 3 |
| 发射前置缺失，未到编译检查 | 57 | 56 | 56 |
| 编译器拓扑拒绝，未到目标几何检查 | 2 | 2 | 2 |
| 多内边路径接受 | 3 / 14 | 3 / 14 | 3 / 14 |
| 有信号目标路径接受 | 0 / 31 | 0 / 31 | 0 / 31 |

两个信号正向对照具备全部真实几何，却在编译阶段得到
`LF-COMP-DISCONNECTED-MANEUVER-PATH`：`sumo:-20604` 与 `sumo:-22774` 的无内边直连
路径。生产 [add_edges](../../tools/laneflow-lust-converter/src/output/emit.rs#L358)
对所有边写入空后继；编译器 [hir/junction.rs](../../crates/laneflow-compiler/src/hir/junction.rs#L799)
要求没有内边的普通段间转接仍有声明后继。研究入口沿用当前声明方式和生产 `add_junctions`、
`add_signals`，没有为通过检查补造连接。这是独立的基线拓扑发射缺口，不能归为 S1
几何失败，也不能靠增大采样预算消除；本轮未修改它。

31 条有信号目标覆盖 12 个控制器，保留全部原始相位、组、机动门、停止线和控制器
关联路径。其余 29 条有信号目标被缺失程序挡在前置阶段。这里的“覆盖”表示纳入真实
检查，不表示控制器通过了编译。完整闭包数据与每条诊断见 [results.json](results.json)。

六条候选边各保留 8 份程序，共 48 份；除旧的 `sumo::-10004_5_1` 外，新增候选边为
`sumo::-10034_0_0`、`sumo::-10130_16_0`、`sumo::-10130_18_0`、
`sumo::-10130_8_0`、`sumo::-29388_3_0`。新增五条候选边所在完整闭包仍有其他缺失程序，
因此没有新增完整路径恢复。两档全部 48 份程序和指标一致。

### 共享赋值的保证与不足

每轮先按边 ID 给所有路径赋同一份候选，再检查全部目标。保留原路径在原所有者内的
序号和原进出边角色，任何缺失边都不使用占位几何。全局候选空间为 `8^6 = 262,144`；
按固定字典序只试前 128 次，**没有穷尽**。前三条候选边仅试索引 0，第四条试 0、1，
最后两条试 0–7；不能把这一过程解释为六边组合均已验证。

只在完整依赖候选索引相同时复用路径结果；若仍有任何无候选的缺失依赖，所有赋值都
返回同一前置缺失。每档实际 84 次不同路径求值，10,668 次相同依赖缓存命中。
这些是研究验证器计数，没有宣称生产性能收益。回归使用两个候选维度验证相关索引改变
会重新编译、不相关维度才复用结果。所有 128 轮均只有 23 条接受，保留的最佳部分赋值
不等于 84 条目标整体接受。

## 资源、几何和长度边界

固定硬上限为每边 32,000,000 个工作计数（新候选点使用、切向求值、重放前缀点使用）、
8 份候选、256 个扫描 cubic / 回溯帧、262,144 个规范去重键点和 262,144 个已选前缀点。
全局赋值上限 128。它们是研究限额，不是已接受的生产资源预算。

43 条边的划分次数从 889,341 增至 4,382,675；有限族耗尽从 13 条增至 25 条，预算截断
从 24 条降至 12 条，候选池填满始终为 6 条。单边各项最大值为 6 张扫描表、3,078 个
累计值、12 个帧、77 个前缀点；去重键点最大值从 759 增至 1,779。候选池合计保留
2,438 个程序点。独立最大值不能相加成同时峰值；容器容量、JSON 指标及分配器开销均
未计量，**没有实际堆峰值结论**。完整计数见 [resource-counts.json](resource-counts.json)。

192 条候选跨度记录中的九点网格到对应弦偏离最大约 0.010183 m，f64 控制包络估计
最大约 0.015942 m。全部标记 `certified_continuous_bound=false`，不能当作连续几何
误差证明或完整认证；也没有覆盖源折线到拟合曲线的全部偏离。

23 条接受路径涉及 62 条不同边，全部编译后规范点匹配预期。编译长度相对 SUMO 源
声明长度的差值范围为 -5.003 至 +3.337 m；该范围包含原成功边，不能归因于 S1。
长度差、采样偏离、连续误差认证是不同问题。本轮没有修改长度权威或阈值。
