| 模式 | 与 global 参照的差异 |
| --- | --- |
| local | 跳过不会被查询的 cell，按目标全部读者中的最大需求时窗保留结果，沿用 directed ETA |
| approx | 上述查询目标与局部时窗，ETA 改普通 f64 加速运动估计 |
| queue2/4/8 | 每条物理边只取前 K 辆 Active，排除跨边车尾；只预测最近 conflict entry 的 passage，使用近似 ETA |

Queue 模式仍复用当前 P3/P4、占用与资源许可。它是入口参与者缩减原型，
还不是完整的新入口队列调度、局部许可或多频率模型。对无信息目标的行为沿用
当前裁决；省略后车预测可能改变通行结果，不能由局部单测推导为交通安全。

所有目标时窗都由**读取目标的流**决定；不是读取目标自身 gap。
局部时窗之外跳过当前 cell，只有超出全局可达距离才退出路线扫描，避免遗漏
后方具有更长时窗的目标。共享目标多读者 max 有单元测试，城市夹具仍没有
多 profile 共同读取同一个目标的真实覆盖。

## 结果与判断

首轮筛查，100k 混合生命周期、4 workers、tick 65–512（448 拍）：

| 模式 | Core 均值 ms | Core p95 ms |
| --- | ---: | ---: |
| global | 68.545 | 76.816 |
| local | 58.042 | 64.614 |
| approx | 53.957 | 60.228 |
| queue2 | 52.594 | 59.587 |
| queue8 | 55.362 | 61.638 |

这是按表中顺序执行的单轮筛查；approx 与 queue2 的小差异尚不能认证。
三种 10k gap 分布各六臂也已运行 512 拍。短前缀各模式的聚合行驶距离、
停车比例相同，不能据此声称后车预测省略对所有交通结果无影响。

随后独立进行 A-B-B-A（global / queue2 / queue2 / global）复测：

| 顺序 | 模式 | Core 均值 ms | p95 ms | p99 ms | 最大 ms |
| --- | --- | ---: | ---: | ---: | ---: |
| A1 | global | 94.026 | 103.849 | 107.562 | 113.113 |
| B1 | queue2 | 62.710 | 77.020 | 80.383 | 82.554 |
| B2 | queue2 | 70.372 | 80.531 | 84.914 | 87.571 |
| A2 | global | 91.191 | 101.565 | 105.054 | 112.490 |

复测内两轮均值为 92.609 → 66.541ms，下降约 28.1%；首轮筛查下降约 23.3%。
**只据此确认缩减工作有值得继续的收益，不认证固定比例或稳定绝对耗时。**
复测与首轮之间波动很大，Harness observation 也从约 85ms 增到 97–111ms；
没有 CPU 频率与线程 CPU 时间，不能将全部差值归因于算法。没有反转起始模式
再补 B-A-A-B，approx 与 queue2 的增量收益仍未做平衡复测。
完整逐拍数据、各轮分位数和峰值保留在 `summary.json` / `timing.csv`。

较长窗口使用 `movement_mixed-10k` 的新 8448 拍 probe 计划，实际运行前
8192 拍，即 131.072 秒仿真时间。新旧模式共用该计划及相同输入；它不是
原 512 拍计划的状态恢复，也不改旧计划。最长信号周期由
`2 × (60 + 8) + 2 × (40 + 8)` 个 528ms quantum 构成，为 122.496 秒。
该窗口覆盖至少一轮信号周期，但仍远早于正式生命周期后段。

独立 audit 二进制，两臂各 512 拍，下表统计 tick 65–512；插桩成本包含在
本表耗时中，不能和无插桩数字混合成一次运行，也不能据此测插桩净开销。

| 每拍均值 | global | queue2 |
| --- | ---: | ---: |
| Active | 70105.54 | 70105.54 |
| frontier 参与车辆 | 70105.54 | 15861.95 |
| 扫描 passage（含退出检查） | 132168.16 | 53068.52 |
| 距离计算尝试 | 132168.16 | 4399.58 |

| Core ms | 69.096 | 53.661 |

frontier 约减少 80.2% 的耗时，距离计算约减少 96.7%。它不再是唯一的大头。
候选仍有 P3 准备/分发/消费 2.072 / 3.525 / 4.629ms、Waiting prepare
9.553ms、Motion 6.831ms、Conflict finalize 5.732ms、Waiting outputs
5.188ms、preflight 4.281ms、occupancy 3.303ms。
P4 仍只有约 0.905ms，不优先做 P4 并行。

仅作成本算术：即使候选余下 frontier 完全免费，Core 仍约 49.918ms；
即使整个 Conflict prepare 免费，仍约 37.905ms。达到 33ms 必须减少其他阶段
的工作，16ms 更不能靠此原型宣称可达。生产命令/发布/宿主积压尚未测量。

## 本轮决策与下一切片

1. **继续查询目标过滤、局部时窗和入口参与者缩减的方向**，保留本轮完整对照。
   queue2 已证明组合原型能减少大量工作；尚不能认定 K=2 是充分的产品规则，
   也不能把它相对于 approx 的单轮小优势当成已确认收益。
2. **下一代码热点推进到 P3 的候选发现、报告消费与 Waiting 工作范围**。
   让确实接近入口或发生状态变化的车辆触发计算，再研究低频更新；当前 prototype
   每拍仍更新，没有完成多频率模型。不要继续把全部路线压在 frontier 上。
3. **下一夹具优先补“能区分模型”的案例**：同一目标被 short/long 多读者读取，
   临界到达时间两侧、不同转向的队首/后车、密集入口连续放行与尾部释放。
   用公共输入和接口构造，检查预期方向、冲突占用、最长等待及吞吐；不以旧摘要
   为 oracle。三种 profile 的覆盖和完整信号周期仍不能替代这些场景。
4. 对候选增量收益用 approx/queue2 平衡复测；等模型与质量筛查收敛后再实际
   演进到代表性后段。此次不继续数小时正式认证，不批准产品合入。
