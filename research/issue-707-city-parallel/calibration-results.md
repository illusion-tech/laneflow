## 1. 覆盖

本拍 frontier 用的是上一拍运动准备写下的近门和失效名单。名单对不上的车要到
下一拍才整段重走。对不上包括：没有有效槽位、句柄 generation 不同、路线序号
或路线 generation 不同、所在边不同、进度回退。新进入 Active、路线替换和
句柄复用都属于这里。`world_id` 与已建立名单不一致时，这一拍退回全量重建，
不沿用旧名单。

自己的门候选仍按活动车辆求值。缺的是别的车本拍的让行查询：这辆车还没有
被写成接近来源时，查询可以把它看成视野外。

短窗重叠为 0 只说明同边车身没有相交，不说明让行看见了这些车。

计数只在 `LF707_AUDIT=on` 时发生，不改变决定。一次 100k 长尾、4 workers、
33 ms、256 拍。环境与封存 best 相同，另加审计开关。不开阶段计时。
第一拍建立名单时不计入。次数是整个 256 拍前缀，不是 tick ≥ 65 的均值。

| 项 | 次数 |
| --- | ---: |
| 名单建立后没有槽位记忆 | 5257 |
| 其中句柄 generation 不一致 | 151 |
| 其中两倍步长内够到非受保护 Candidate 门 | 0 |

没有槽位记忆平均约每拍 20.6 次。151 次是其中槽位还在、但 generation
已经不同的次数。其余 5106 次没有再拆成新 Active、路线替换、换边或进度回退。

两倍步长内够到非受保护 Candidate 门的次数是 0。这个短窗里，漏进下一拍的车
没有落在这种门的两拍可达范围里，151 次 generation 不一致也没有。0 不说明
路线替换、句柄复用或修订切换在别的窗口也不会漏。门规则写成拒绝停车时，
这个计数也不增加。重叠为 0 仍然不是让行覆盖的证明。

值得以后补的做法是：上一拍预测集合，加上本拍命令和生命周期产生的增量。
这一片没有实现它。

这次的 `quality.csv`、`ticks.jsonl`、`events.jsonl` SHA-256 与 M3 短窗相同。
最后一拍重叠对数是 0。

## 2. 拒绝

同一前缀、同一审计。每个冲突候选在推入时记一次预检原因，仲裁结束再记
最终决定。连续段按车辆下标累计，不按 generation 切开；下标被复用时，
相同原因会把前后两辆车接成一段。

全窗 135447 个候选。推入时已经拒绝 134099 个，占 0.990。无预检拒绝的
1348 个全部在结束时授予。没有任何一个预检拒绝在结束时变成授予。

| 推入时的原因 | 次数 |
| --- | ---: |
| 无预检拒绝 | 1348 |
| 冲突占用 | 46936 |
| 前导间隙 | 10798 |
| 下游存储 | 76365 |
| 等待容量、等待存储、等待环、滞后间隙、接近不可证明、下游冲突 | 0 |

| 结束时的决定 | 次数 |
| --- | ---: |
| 授予 | 1348 |
| 冲突占用 | 91069 |

| 下游存储 | 37130 |
| 其余拒绝原因 | 0 |

推入时和结束时不是同一列。44133 个在推入时记为下游存储或前导间隙的候选，
结束时记为占用。让行查询共 110202 次：接受 27254，占用 60336，前导间隙
22612，滞后间隙和接近不可证明是 0。候选级拒绝约占 0.990，但让行查询里
仍有 0.247 是接受。一个候选可以在某些 cell 上被接受，再因别的原因被拒绝。
拒绝经常是这些查询做完之后才知道的结果。

先前 tick ≥ 65 的需求比例是另一份构建上的 0.990，192 拍里 18 拍有授予，
单拍最多 440。这次全窗 256 拍也是 18 拍有授予，单拍最多 440。每拍候选
次数不能和那次的 680 直接对照：这次把暖机算进去了，构建也不同。

这个窗口里的拒绝主要是下游存储、占用和前导间隙，而且很多段很长。
等待、滞后间隙和接近不可证明一次都没有出现。红灯停止线 ETA 仍是 0 的
问题没有在这次被分开，所以这 0.990 不能当成可以缓存的正确结果。
占用和下游存储会随资源释放变化；没有对应的提前失效条件时，把拒绝留下
去会把已经该放行的车继续堵住。这一片不开始拒绝有效期，也不开始把预检
拒绝的候选从仲裁顺序里拿掉。

## 3. 分辨

只跑封存的 `harness-m16-plain.exe`，不重新编译。环境与封存 best 相同。
连续四次，每次 256 拍、4 workers。统计 tick ≥ 65 的 192 拍，`public_step_ns`
线性插值分位数。单位是毫秒。

| 次 | 均值 | 样本标准差 | p95 |
| --- | ---: | ---: | ---: |
| 1 | 28.415 | 2.900 | 33.288 |
| 2 | 28.718 | 2.616 | 33.230 |
| 3 | 28.316 | 2.161 | 31.956 |
| 4 | 28.546 | 3.922 | 34.437 |

四次均值的平均是 28.499 ms。极差是 0.402 ms。四次均值的样本标准差是
0.174 ms。四次的 `quality.csv`、`ticks.jsonl`、`events.jsonl` SHA-256
都与 M3 短窗相同，最后一拍重叠对数都是 0。

这一批里，运行均值之间小于 0.402 ms 的差，不能当成稳定收益。
“两次 after 都低于两次 before”仍然是选用规则。规则没过，只说明这次
没有把收益和负载分开，不是证明收益为零。延迟物化那次 after 均值少
2.542 ms，大于这里的 0.402 ms，但那一批 before 自己的极差有 1.885 ms，
所以保留线没有成立。这次 A/A 不把那一轮收回 best。

同一封存程序在车道块、投影、延迟物化三批里的 best 均值大约是
35.261、27.934、36.877 ms。那是批与批之间的负载，比这一批内部的
0.402 ms 大得多。以后的候选轮仍要把封存程序放进同一批。
这一批的 28.499 ms 不改写封存的 28.462 ms。

## 4. 证据边界

三轮已经记过的结论，边界是：

- held 可以漏一拍接近来源。第 1 节的 0 只覆盖这次短窗里、两倍步长够得到
  非受保护 Candidate 门的那些漏记。
- 车道块是快路径没有命中。它没有量到混合车长下快路径真正执行时的布局。
- 延迟物化不进入 best。稳定收益尚未分辨，而且它延迟的是接近记录，
  不是预检拒绝的候选。

投影那一轮停止的是无前车预测再加全量硬投影。排序用拍初占用后杠；
缩短用的是前车已经写下的下一状态后杠。收到拍初位置时速度为 0，否则
速度不超过这段位移除以步长。不另加补偿层。
