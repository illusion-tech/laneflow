  0.0344ms、最大 0.4668ms。记录器记账等少量成本在残差内，不强制抹平。

  差异、阶段缺失、耗时越界、混入下一边界事件。原计划摘要和矩阵完成性也受检。

## 3. Core 成本已经分解到具体阶段

下表是插桩开启臂 tick 65–512 的均值，单位 ms。只将互斥父阶段求和；

| Motion（包含 P5） | 17.672 | 6.735 |

| 嵌套成本 | 4w 均值 ms |
| --- | --- |
| frontier 重建 | 18.764 |
| P4 获取/裁决（包含依赖准备） | 1.001 |
| P3 准备 / 分发 / 消费 | 2.167 / 4.155 / 4.996 |
| P2 准备 / 分发 / 消费 | 0.614 / 6.812 / 0.987 |
| P5 准备 / 分发 / 消费 | 0.911 / 5.068 / 0.754 |
| occupancy count / layout / fill / sort | 1.161 / 0.139 / 1.598 / 0.694 |

分发是协调器等待完整 join 的墙钟，包含调度和并行执行，不是纯调度开销。
准备包含发现、槽位和闭包构造；回退时其作用域可能包含融合求值。本窗口 4w
大工作集走分发，1w 这些子项没有调用，零值不代表融合计算免费。

4w 最慢 5% Core 拍（23 拍）中，同拍 Core 均值 89.734ms，Conflict 准备
39.182ms，其中 frontier 22.954ms、P3 消费 5.662ms、P4 1.274ms。
这是同一批慢拍的条件均值，不是各阶段 p95 相加。

由此调整优先级：

1. **Core 主线先查 frontier**：它在早期平均已占约 18.76ms，且最慢 Core 拍
   仍突出。源码有 live 扫描、逐 Active 路线定位、ETA 求值及 owner 合并；已有
   horizon 提前终止。后续允许缩减证明对象、近似和重设检查，以性能及实际交通
   结果判断取舍；不再以保全旧模型义务为前提。
2. **其次查 P3 消费及后处理**：P3 消费约 5ms；Conflict finalize + Waiting
   outputs 约 11.69ms。按输入/报告/更新数量解释成本后选择可消除的重复工作。
3. **P3 投影计数快路径降为小候选**：整个准备段才约 2.17ms，省掉一遍计数
   的收益上界更小，不可能单独解释 16ms/33ms 差距。当前没有实现或测得该收益。
4. **P4 并行不是首选**：本前缀 P4 约 1ms；此结论不外推到其他争用状态。

仅作为当前成本结构的算术示例：即使将整个 Waiting 准备和 Motion 两项成本
同时归零，4w 本前缀均值仍约 54.79ms。这不是算法理论下限，但说明继续只扩大
现有 P2/P5 并行，无法填平当前差距。需要削减其他工作或改进组织方式。

这些是一次顺序运行中插桩与环境/时序变化的合成差异，**不能称为纯插桩开销**。
首轮已完成开关对照，但尚未隔离可用于小收益验收的扰动上界。下一项优化的收益
若与该量级接近，必须补平衡次序重复及无插桩 release 对照，不能直接宣布有效。

off-w4 原 observation 均值 78.458ms；公共命令均值 1.927ms，Core 均值
68.511ms，iteration 均值 152.400ms。三项旧计时不覆盖所有 caller、摘要和 writer。
iteration 包含缓冲语义输出，但不包括最终 flush、checkpoint、诊断 CSV 写出、
初始化或汇总；不是整进程墙钟，也不是生产 `command + Core + publish` 服务时间。

## 5. 生命周期机制验证

定向夹具通过公共接口构造；先正常 step 到 Completed，再发起重试/替换。
两种 live 规模为 256 和 4288，包含 64 或 4096 个停放车辆，三轮独立建世界。
该夹具无 Conflict/Waiting 权威，不能冒充城市后段或 100k 性能。

在 live=4288 的插桩臂第 2/3 轮中：128 次 Blocked 重试的定位耗时分别为
0.4904/0.4947ms，整个批次为 0.5470/0.5514ms；旧句柄在 live 尾部，源码
因此每次访问全部 4288 项。定位确为该定向重试场景主要成本。
64 次成功替换的提交阶段分别为 0.5608/0.5513ms，整个批次约 0.8460/0.8493ms；
提交阶段含 Active 全量重建，尚不能把全部提交耗时都归于该重建。

未 Completed 拒绝约为微秒级批次；Harness 通常直接延期，不进入公共替换 API。
因此不能把所有 retry 次数乘以定位扫描成本。

生命周期后续候选拆开验证：B1 复用现有 LiveOrderIndex 缩减 Blocked 定位；
B2 处理成功替换后的 Active 维护及索引失效。验证句柄有效、车辆守恒、资源释放
与新失败处理；允许调整 live 顺序、回滚和日志组织，不要求复现旧行为。
两者均尚未实现，不能报告加速。
