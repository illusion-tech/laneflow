# #707：本拍准入需求占当前构造的比例

2026-09-22。承接 [按车道边成批](motion-lane-batch-results.md) 之后的方向调整。
状态：实验已完成。结果见 [需求比例](demand-ratio-results.md)。下文是跑数前的合同。
本轮只计数，不改交通计算，不开始新的调度原型。

保留组合仍是 B1 + H1 + 屏障跳过 + 稠密 binding + frontier 按 hop 记住。
源码从 `target/issue707-m8-source` 复制到 `target/issue707-m13-source`。
M8 带阶段计时的 `LF707_COAST=on` 已经给出 frontier 均值 4.304 ms、
p3 准备均值 3.258 ms。那两个数仍是这段的参照。本轮二进制多了计数，
绝对毫秒只用来看计数有没有把阶段撑大，不替换 M8，也不替换 M3 dense
的 29.334 ms。

## 要回答的问题

当前 frontier 仍对全部 Active 车构造多秒时窗里的接近记录。P3 仍为通过
范围筛选的车整理 cell 和下游声明。本轮量两组比例：

1. 本拍让行查询真正读到的 frontier，占本拍插入的多少。
2. 已经物化的候选里，有多少在进入仲裁前就带着拒绝，以及最终授予了多少。

让行查询发生在候选整理期间，早于授予。比例可以用查询结果，因为这是在
观察现有流程，不是用最终授予去决定构造哪些记录。

一拍可达插入另记一列。它表示“这辆车自己本拍够得着这条冲突”。远处的车
仍可能给别人的让行提供领先间隙，所以这一列不参与收口。

## 计数

分母：

- 插入次数：写入某个 cell 的接近记录条数。
- 插入过的 cell 数：本拍至少插入一次的 cell。
- 候选数：本拍推入的冲突候选。

分子：

- 落在本拍被让行查询读过的 cell 上的插入次数。
- 既被插入、又被让行查询读过的 cell 数。
- 推入时已经带 `preflight_no_grant` 的候选。
- 本拍实际授予的候选。

一拍可达的距离上界与屏障跳过相同：`速度 × dt + 0.5 × 最大加速度 × dt² + 50 mm`。
比较的是该冲突入口的剩余距离。

另外记下：Active、缓存命中、整段重走、有插入的车、有一拍可达插入的车、
让行查询次数、被查询的 cell、预约跳过、范围跳过、进入 Gate 求值的车、
候选 cell 条数、下游声明条数、仲裁访问次数、空 cell 的等待候选、
因预检而没有下游声明的候选。

## 运行

100k 长尾、4 workers、33 ms、256 拍、一次运行。
`approx/both/combined/boundary=on/decision=every`、`LF707_OBSERVE=fused`、
`LF707_BARRIER=skip`、`LF707_BINDING=dense`、`LF707_COAST=on`，
并打开阶段计时和本轮计数。统计 tick ≥ 65 的 192 拍。不做 ABBA。

短窗 `quality.csv`、`ticks.jsonl`、`events.jsonl` 必须与 M3 的 SHA-256
前缀一致，重叠对数为 0。不一致则这次计数改了行为，结果作废。

## 收口

下面都用 tick ≥ 65 的均值。

Frontier 按需构造：

- `被查询的已插入 cell / 插入过的 cell ≥ 0.80`，并且
  `落在被查询 cell 上的插入 / 全部插入 ≥ 0.80`：本拍证明已经覆盖当前构造。
  这条按需构造收口，不写反向索引。
- 上面两个比例有一个 `≤ 0.50`：缺口够大，方向保留。本轮仍不写原型。
- 落在中间：只记录，不开始原型。

P3 延迟物化：

- `推入时已拒绝的候选 / 候选 ≤ 0.20`，并且 `授予 / 候选 ≥ 0.80`：
  物化的候选大多会进入真正授予。延迟物化收口。
- `推入时已拒绝的候选 / 候选 ≥ 0.50`，或 `授予 / 候选 ≤ 0.50`：
  方向保留。本轮仍不写原型。
- 落在中间：只记录。

阶段时间相对 M8 的 on 均值：frontier 4.304 ms，p3 准备 3.258 ms。
本轮 frontier 均值若比 4.304 ms 高出超过 1 ms，说明计数把阶段撑大了，
不把这次的绝对毫秒写成新预算。比例仍然有效。

16 ms 目标不在本轮完成。车道工作集和约束投影不在本轮。
