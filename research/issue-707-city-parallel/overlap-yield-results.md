# 重叠检查处让出、由占用记录并行填出重叠索引：结果

**日期**：2026-10-11；Refs #861，父任务 #707 继续开放。设计见
[`traffic-runtime-vehicle-placement.md`](../../docs/design/traffic-runtime-vehicle-placement.md)
第 9 节。

## 1. 结论与交付范围

执行资源支持协调器并行时，生成、替换与驶离停车走到重叠检查、生成重叠索引已过期，
就让出：活动世界在一次执行作用域里并行重建过期的占用索引，再按边分块由占用记录
填出重叠索引，然后重新执行命令。占用索引重建失败时两份索引都保持原状，命令在原位置
串行重建。调度线程少于 4 时行为不变。不改规则、公共 API、错误分类、格式或资源所有权。

普通 ABBA 观察窗公共命令合计下降 43.7%–46.3%，命令 p95 下降约 51%–52%，p99 下降
约 23%–24%，最大值下降约 11%；step 分位无一致方向。四次运行的交通文件逐字节一致。
本交付不宣称 16 ms 达标或 #707 完成认证。

## 2. 依据

计数探针（不合入，#871 实现之上；交通文件与未插桩运行逐字节一致），观察窗 132 批
命令：

| 观察                                 | 结果                                      |
| ------------------------------------ | ----------------------------------------- |
| 每批生成重叠索引重建                 | 正好 1 次（132/132），每次遍历约 10 万辆  |
| 每批重建耗时                         | 4.1–5.6 ms，中位数 4.6 ms，合计约 0.61 s  |
| 占观察窗命令时间                     | 约 44%                                    |
| 被挡替换除重建外的检查               | 每次合计约 2 µs；重叠查询平均看 10 辆车   |
| 被挡替换与上一批某次被挡输入相同     | 0 / 17,243                                |

同一探针里，成功替换的准入平均约 50 µs（合计约 0.30 s），成功替换的提交平均约
42 µs（合计约 0.24 s）。

## 3. 实现与正确性

见设计 9.2–9.4 节。要点：

- 两份索引对活动车用同一个车身展开，每条边上的车辆多重集相同；重叠查询结果与桶内
  顺序无关，所以由占用记录填出的重叠索引与串行重建的查询结果相同；
- 两份索引维护方式不同（重叠索引逐车修补删车、停车与驶离，并供切换事务可失败重建），
  不合并；
- 让出点就是现行的重建点；让出前命令没有提交任何东西，重新执行得到同样的结果。

验证：

- 替换在单 worker 与 16 worker 世界逐次比较：先被挡、后成功，结果、重叠索引与最终
  状态相同；只在第一次重叠检查处让出一次、填桶一次；
- 第 8 节的让出测试加上重叠索引比对，并断言每批的让出发生在重叠检查处、填桶次数
  等于让出次数；占用索引并行重建失败时不填桶，退回串行，结果相同；
- 变异检查：填桶不写入车辆时，两个直接相关的测试失败；
- Rust 1.98.0：Runtime 默认与 `placement-fixtures` 两种配置全量测试通过；Clippy 两种
  配置 `-D warnings` 通过；`fmt` 通过。
