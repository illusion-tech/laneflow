# #707 M1：Motion 四段成本

2026-09-22。状态：**测量完成。** 最大的一段是约束查询；其中非前车查询占多数。
预注册的三条采用线没有全部通过，因为计时扣减相对校正值偏大；名次本身在
三次运行、原始周期和校正周期、以及全部采样拍上都一致。本轮没有原型，
没有改交通计算，没有创建 PR。16 ms p95 仍未达到。

口径见 [测量合同](motion-phase-plan.md)。保留组合仍是 B1 + H1。

## 1. 测到的名次

100k 长尾夹具、4 workers、33 ms 步长、每臂 256 拍。统计记录 tick ≥ 65 的
采样拍，每臂 48 拍（68、72……256）。下表是四名 worker 的 CPU 时间之和，
不是墙钟，也不能相加后当成 Core。

校正值已减去每个区间一次空转计时。空转中位数在全部采样拍上都是 100 个
TSC 周期；TSC 频率约 2.4953 GHz。

| 段 | diag-a | diag-b | diag-c |
| --- | ---: | ---: | ---: |
| 约束查询 | 21.571 | 21.222 | 21.113 |
| 其中前车查询 | 6.663 | 6.547 | 6.495 |
| 其中其余约束 | 14.908 | 14.674 | 14.618 |
| 输入读取 | 11.893 | 11.662 | 11.632 |
| 跟车求解 | 6.009 | 6.008 | 5.966 |
| 下一状态构造 | 3.619 | 3.592 | 3.591 |
| 边界推进（旁路） | 1.694 | 1.669 | 1.656 |

单位是毫秒 CPU。三次运行的校正名次都是约束、输入、跟车、下一状态。
原始周期的名次都是约束、输入、下一状态、跟车：跟车和下一状态互换，
最大段没有互换。144 个采样拍的原始名次和校正名次全部是约束查询。

约束查询相对输入读取的校正领先为 9.678、9.559、9.481 ms，跨次极差
0.197 ms。段内标准差约 0.97–1.31 ms，p95 为 23.446、23.372、22.674 ms。

其余约束约占约束查询校正时间的 69%，前车查询约占 31%。10k 长尾的
一次 256 拍对照保持同一顺序：校正后约束 1.888、输入 1.081、跟车 0.593、
下一状态 0.366 ms CPU；前车 0.568，其余约束 1.320。Active 为 7,312–7,500。

其余约束在实现里包含等待停止、冲突停止、路终、信号停止、停车停止、
停止点合并、资格判断中的门控，以及硬边界和它的 hop 许可。运动缓存探测和
决策尝试的构造也留在调用方的这一段里，没有单独计时。这段没有再拆开，
所以还不能指定其中哪一次查询占 14.6–14.9 ms。

下一状态的校正值小于被减去的计时开销的两倍，原始名次又和校正名次对调。
这一段和跟车求解的高下还没有分开。两者都明显小于约束查询和输入读取。

## 2. 和未插桩墙钟的关系

同一诊断二进制里，未采样拍不读 TSC。这些拍的 Motion 并行墙钟是：

| 墙钟 | diag-a | diag-b | diag-c |
| --- | ---: | ---: | ---: |
| 并行求值 | 9.161 | 8.908 | 8.801 |
| 输入表收集 | 0.826 | 0.774 | 0.832 |
| join 后串行消费 | 1.786 | 1.732 | 1.792 |
| 三段合计 | 11.776 | 11.416 | 11.427 |

采样拍的并行墙钟约为 20.7–20.9 ms，比未采样高约 11.6–12.0 ms。
Core 也高约同样的幅度，说明开销留在并行求值里。输入表收集和串行消费在
采样与未采样之间几乎不变，分别约 0.8 ms 和 1.8 ms 墙钟。

未采样 Core 与当天封存 H1 二进制处于同一波动带。稳态 192 拍：

| 运行 | Core 均值 | 标准差 | p95 | 最小 | 最大 |
| --- | ---: | ---: | ---: | ---: | ---: |
| H1 参照 | 32.872 | 2.667 | 38.060 | 29.192 | 44.143 |
| diag-a 未采样 | 33.311 | 2.835 | 39.288 | 29.363 | 43.945 |
| diag-b 未采样 | 32.870 | 2.624 | 38.295 | 28.389 | 41.104 |
| diag-c 未采样 | 32.922 | 2.482 | 37.589 | 28.799 | 43.470 |

H1 参照的 iteration 均值 106.198 ms，observation 均值 70.322 ms。
这是当天的快端，落在此前保留基线大约 33–37 ms 的带内，不是一次异常慢的运行。
采样拍 Core 均值 44.699、45.399、44.905 ms，只说明插桩开销，不能拿来
和 16 ms 或 33 ms 比较。

校正后的四段加边界，diag-a 合计 44.786 ms CPU。按 4 个 worker 平均约
11.2 ms，高于未采样并行墙钟 9.161 ms。绝对毫秒因此略高于未插桩墙钟；
名次用的是同一套时钟下的份额。把约束查询约占归因 CPU 一半的份额，摊到
大约 9.2 ms 的未采样并行墙钟上，对应约 4.4 ms。这是份额草图，不是删除
这段之后会少掉的墙钟。

未采样 Core 均值约 33.0 ms，Motion 准备合计约 11.5 ms。即使这段准备变成
零，其余 Core 仍约 21.5 ms，仍高于 16 ms。约束查询只是 Motion 里最大的
一块，不是 Core 的全部。

## 3. 预注册门槛

三条线里：

1. 三次运行的最大段在原始和校正下都是约束查询。通过。
2. 校正领先大于这三次领先的跨次极差。通过。
3. 校正均值至少为被减计时开销的两倍。未通过。diag-a 的约束查询原始
   33.019 ms、校正 21.571 ms，开销 11.448 ms，两倍是 22.896 ms。

因此 `summary.json` 的 `primary_target` 为空。第 3 条拒绝的是“把校正毫秒
当成已经量准的预算”，不是名次。144 拍全部指向同一段，领先约 9.5 ms，
段内波动约 1 ms，跨次极差不到 0.5 ms。下一轮可以针对这一段减少工作；
不能把 21 ms CPU 写成预期墙钟收益。

## 4. 场景与路径

三次 100k 的 Active 都是 70,761–74,392。进入运动原语的车辆均值 72,737，
其中完整求值 70,978，预览复用 1,759（约 2.42%），硬停提前返回 702。
48 个采样拍全部走 4 worker 分发。稳态停车车辆约占 Active 的 4.53%。
这只说明测的是完整求值路径，不是交通质量验收。红灯停止线 ETA 与长等待
没有在本轮处理。

10k 冒烟 80 拍先核对了周期之和等于区间跨度，随后才跑 100k。那次运行
进程退出码因 `WaitForExit(int)` 未发布而为 null；`prefix-result.json` 为
80 拍完成。运行脚本已补上无参 `WaitForExit`，正式五臂都由脚本判定成功。

## 5. 下一轮

下一轮原型减少每辆车的非前车约束查询：等待停止、冲突停止、信号、停车和
路终距离、资格门控，以及硬边界 hop。允许改算法、近似和数据组织，用短性能
对照和交通结果验收。前车查询是同一段里较小的部分；C1 已经看到它几乎不
重复，静态门控规则表也保持淘汰。

输入读取是稳定的第二段，约 11.6–11.9 ms CPU，大于跟车求解。它留到约束
查询有结果之后，不和本轮原型混在同一次对照里。H2 观测降频和红灯 ETA
模型仍各记各的账。

候选稳定之前，不整合正式实现，不改权威设计，也不把这次诊断 Core 写成
性能收益。
