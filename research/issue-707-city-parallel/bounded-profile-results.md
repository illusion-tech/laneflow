# 持续十万负载的准入、观测与慢拍剖析

2026-10-07。Refs #826、#707。承接[持续负载准入报告](sustained-admission-results.md)。
本次只定位成本并提出下一优化方案，没有改动正式 Runtime 算法，也不作性能认证。

## 结论

公共准入的主要成本是 `placement.rs::rebuild_spawn_contenders`：观察期 132 次重建，
累计 **15.0050 秒，占公共准入 69.07%**。成功调用承载大部分重建成本；
入口阻挡拒绝虽有 17243 次，累计只占 2.55%。因此优先研究准入候选缓存重建的
保守筛选，保留精确安全求值与拒绝语义，暂不继续调整调用方入口尝试顺序。

观测最大项是 `observe::state` 的全量状态与摘要（26.1234 秒），其次是
`observe::events`（10.9858 秒）。step 中 `prepare_conflict_step` 最大；最慢 5%
样本相对其他样本的平均增量也以它为主，但单次尖峰还出现在 Waiting 准备、Motion 和
预检。本次未采集操作系统调度栈，不能把尖峰全部归因于算法计算。

## 范围、方法与失败保留

基线为已合并的 `9d61f8d2b0d2ccceb22580a346b1031fdc153022`，16 workers，
十万道路机动车，512 拍暖机加 1024 拍观察。普通、第一版插桩、修正版插桩依次运行；
第三轮的唯一理由是补齐跨线程计数，不追加第四轮或正式长测。

普通二进制复用此前冻结的 `6c3f5d2d` 构建，已通过 Git 核对该提交与本次基线的
`crates/`、`tools/`、Cargo 配置、锁文件和 `.cargo` 全部相同。研究目录与报告提交不
属于该普通二进制的构建源码。插桩二进制由相同生产基线应用冻结补丁构建；运行时先
恢复生产源码，因此诊断中的运行目录 commit 不能单独代表插桩二进制身份，须同时核对
补丁、模块及二进制摘要。

第一版使用线程本地计数器，记录到了调用线程的准入和观测，但漏掉池内协调线程的
step 区间。原始日志、二进制、模块、补丁和冻结记录全部保留；其 step 阶段计数为零
表示**未测到**，不是零成本。修正版改为粗粒度区间结束时原子累加，只在同步调用返回、
全部 worker join 后读出和清零。独立测试覆盖八线程合计 8000 次记录，以及结果分类
差分、跨拍清零。最终审计要求每个 step 阶段每拍恰好一条，并核对外层逐拍耗时与
原 diagnostics 的排序样本完全一致。

所有区间为包含式墙钟；嵌套项不相加。Motion 分发含 join 等待，不是各 worker CPU
时间。未给逐车求解循环插入计时，也未测最长 worker 块、CPU 栈或实际并发参与数。
插桩输出在原有观测计时结束之后写入 stderr，其成本仍影响端到端墙钟。

包括候选、请求与诊断记账，不能把它也算成公共 Runtime 调用。

| ----------------------------- | ----- | ------- | ---------- |
| rebuild_spawn_contenders      | 132   | 15.0050 | 69.07%     |

| ensure_current_occupancy      | 5971  | 0.9239  | 4.25%      |
| overlap_blocker               | 23214 | 0.5842  | 2.69%      |

| ensure_spawn_downstream_index | 5971  | 0.0862  | 0.40%      |

`fresh_motion_admission` 共 20.7897 秒，包含上表重建、自身运动和索引准备，不能重复
累加。`admit_direct_followers` 仅 0.0049 秒；不能因错误名为 `unsafe-follower`，
就把该结果类别的整段耗时归给后车循环。

源码 `placement.rs::ensure_spawn_contenders` 按世界世代和观测状态序号检查缓存。
本窗口 132 个有回收的边界各触发一次重建，后续成功插入用增量刷新；132 次重建的
单次平均为 113.67 ms。`rebuild_spawn_contenders` 遍历 `live_order`，调用
`add_spawn_contender`，其中有逐车运动预览和接近记录构建。按固定十万 live 与源码
循环计算是 1320 万个 live 槽位访问；这是源码推导，不是另行采集的硬件或逐车计数。
首版调用线程计时得到 15.1887 秒，修正版得到 15.0050 秒，主导位置一致。

尖峰。本切片到此完成函数/阶段定位；进一步拆 P2/P3/P4、线程调度和长尾需独立范围。

## 下一优化方案

建议下一切片只做 **准入缓存重建前的保守候选筛选**：从当前已提交车辆、编译路线和
配置计算保守可达上界，只有能证明在证明时窗内没有相关冲突接近记录、下一拍也不可能
触及相关门/等待入口、且无既有需要维护的权利或状态时，才跳过该车的完整运动预览。
不能证明时继续现有精确路径。优先核对 `entry_frontier` 已有可达边界算式能否复用，
不能直接信任上一拍缓存，因为 step 和同一边界的成功命令均可能改变序号与邻车状态。

这是待验证设计建议，**本切片未实现**。开工前须在独立优化任务中冻结筛选证明与
设计影响；验证应包括：筛选关闭参考与筛选后逐项 contender/命令错误/已提交状态
一致，近门恰好可达、零进度/跨边/重复 occurrence、Waiting 和既有冲突权利、
生成/替换/移除、句柄代次及换根、分配失败与重试。不得跳过候选自身、前后车或重叠
安全检查，不改变成功后增量维护，不引入常驻第二套交通语义。

收益验证先用本窗口做正常 release 的平衡 A/B，再按风险决定扩大窗口；同时检查
准入墙钟、重建次数/候选数、分配与保留内存、全程墙钟及 step 分布。15 秒是当前热点
规模，不是承诺能全部省掉；优化准入不等于达到 16 ms 的 Core 整步预算。若相同语义下
收益不足或资源成本上升，应保留结果并停止该候选，不顺带扩大到其他算法。
