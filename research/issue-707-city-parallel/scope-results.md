# #707 P3 / Waiting 工作范围实验

2026-09-21。Refs #707。研究原型与有限窗口筛查；不要求与旧算法逐拍等价。

结论：保留 P3 与 Waiting 工作范围缩减原型。100k 平衡复测 Core 均值
52.750 → 44.038ms（约 -16.5%），仍未达到 33ms。新增夹具证实固定队首 K
会改变混合转向决策，其中已测案例有合理收益；城市长窗则暴露出共同的严重
长等待现象，不能据此宣布交通质量已合格。

## 本轮原型

`LF707_SCOPE=all/p3/p2/both` 在安装时读取，仅用于研究对照：

- **P3**：输入发现阶段只处理按当前速度及最大加速度，本拍可能触及 Gate 的车辆。
  保留已有 reservation 的处理；空输入不分发，非空使用原 worker 独占槽位。
  同时去掉这条路径上的一次全量候选预数扫描。不保留旧版 eligibility 输出作为门槛。
- **P2**：对本拍到不了 Waiting entry 且没有 Waiting membership 的车辆跳过完整
  Waiting 预览；保留紧凑缓存位置。运动仍由 Motion 计算，可能出现成本转移，
  以整拍 Core 的净收益作判断。
- 不跨拍复用结果，本轮没有加入低频决策或通用恢复系统。

## 能区分行为的新夹具

通过公开编译、安装、路线、spawn/step 接口构造。入口长 130 米，同一被查询
冲突目标实际绑定三类读者；三类车辆的物理参数相同，只改变 gap：lead
1500/3000/5000ms，lag 500ms。仿真步长 100ms，初速 10m/s。

| 优先来车距入口 | 短 gap | 中 gap | 长 gap |
| --- | --- | --- | --- |
| 5 / 15 米 | 等待 | 等待 | 等待 |
| 30 米 | 放行 | 等待 | 等待 |
| 60 米 | 放行 | 放行 | 等待 |
| 90 米 | 放行 | 放行 | 放行 |

这是不同规则实际作用于同一目标的判别证据，不只是 profile 声明或 max 辅助函数测试。
断言长 gap 不会在同条件短 gap 拒绝时独自放行，并要求出现放行与 LeadGap 两类结果。

混合队列加入有真实曲线、movement 与 gate 的转弯路线；入口前 0/2/4 辆车转弯，
随后一辆车直行进入被查询冲突区。固定物理车道前 K 辆的模型出现如下变化：

| 转弯前车数 | 全候选近似 ETA | queue2 | queue4 |
| --- | --- | --- | --- |
| 0 | 等待 | 等待 | 等待 |
| 2 | 等待 | 放行 | 等待 |
| 4 | 等待 | 放行 | 放行 |

这证明固定 K 会遗漏后方不同 movement 的来车。它不是旧轨迹等价要求：是否应
接受这种更积极的放行，要看真实通行间隔、优先车辆延误、冲突占用和排空结果。
不能把上一轮城市聚合值相同当作固定 K 普遍充分的证明。

进一步观察表明，这里提前放行并非已证实的退化。两辆转弯前车时，queue2 将
让行车最长停车从 7.5 秒降到 0，优先直行车在两者中都于 5.9 秒进入通行区，
且优先车最长停车均为 0；queue2 中先行车辆清空至后车进入间隔为 4.8 秒。
四辆转弯前车时，queue2 的清空间隔为 9.2 秒，优先车进入时刻仍为 10.3 秒。
这些结果提示原自由到达预测没有充分利用前方转弯车造成的实际约束。
这是该合成场景的结果，不能推广成任意固定 K 充分，也不能把清空间隔直接当作
配置 lead gap 的同义指标。后续应比较按 movement 的局部候选与队列阻挡关系。

定向场景另检查 30 秒内排空、完成后无 reservation、通行进入/清除配对，以及
两条垂直通行区没有拍级同时占用。该夹具不是连续二维车辆碰撞认证。

## 交通质量口径

逐个体记录累计停车、最长连续停车、观测时长与结束原因。速度 ≤0.1m/s 视作停车，
时长分辨率为一个仿真步长。初态已在途的行程标记左截断，窗口结束未完成标记
右截断；只有窗口内开始并完成的行程才报告完整行程时间。

城市冲突区记录进入/清除、资源持有、同区多 owner 累计及最长连续时长。
同区多 owner 可能包含兼容 movement，不能直接等同碰撞；没有观察到重叠也不能
推出连续几何无碰撞。初态在区车辆及窗口未释放资源的截断边界单列。

## 测量结果

城市计时均为 4 workers；前缀为 512 拍，统计 tick 65–512，较长窗口另列。
100k 表示个体总数；
此窗口 Active 为 65577–75000，不能称为稳定 100k Active。

### 首轮消融：100k、junction_long_tail

| frontier / 工作范围 | Core 均值 ms | p95 ms |
| --- | ---: | ---: |
| approx / all | 56.995 | 67.984 |
| approx / p3 | 49.036 | 56.120 |
| approx / p2 | 50.330 | 56.322 |
| approx / both | 44.151 | 50.948 |
| queue2 / both | 43.095 | 49.744 |

四臂 approx 使用同一全候选局部时窗与普通浮点 ETA，仅改变工作范围。
组合降幅约 22.5%，但这仍是单次顺序筛查；queue2 额外约 1ms 的差异不足以
单独认证收益。候选的均值与 p95 均仍高于 33ms，未达到 16ms。

10k movement_mixed 首轮的均值依次为：approx/all 4.968、p3 4.334、p2 4.899、
both 4.081、queue2/all 4.928、queue2/both 3.847ms。P2 单独在这档没有明显优势，
说明收益受工作负载影响，不能把 100k 的降幅固定外推。

100k 各臂完成 10269，距离 2151.185km，停车 Active 拍占比约 11.175%；
这些测得的聚合值相同，只是本窗口事实，不作为必须相同的通过条件。
观测到的 76046 条个体行程片段中，65577 条在窗口结束仍未完成，完整新起止
行程为 0。最长连续停车 15.345 秒，p95 9.933 秒；不能把前缀完成者的观测
时长当作总体旅行时间。完成 owner 持资源数、未配对 clear 事件及同区多 owner
拍级暴露均为 0；窗口仍有 1042 个未结束 reservation。

approx/both 的 Core 虽为 44.151ms，完整 iteration 均值仍为 134.511ms，
其中既有 Harness observation 83.673ms、命令 2.906ms；新增质量观察另约
2.19ms/拍，排除在 iteration 计时之外。这不是生产发布链路成本，也没有证明
异步接入后能以 33ms 步长持续实时。

### 平衡复测、阶段分解与较长窗口

同一 100k 输入、无阶段插桩 release，A=approx/all，B=approx/both：

| 次序 | Core 均值 ms | p95 ms |
| --- | ---: | ---: |
| A1 | 52.376 | 56.979 |
| B1 | 43.718 | 49.257 |
| B2 | 44.359 | 49.783 |
| A2 | 53.124 | 59.483 |

同块 A 均值 52.750，B 均值 44.038ms，约降 16.5%。本次 B 两次均低于 A
两次，支持存在实质净收益；首轮 22.5% 不作为固定收益承诺。电源为平衡，未
控制全部桌面后台负载、未记录实时频率和线程 CPU 时间，仍非产品认证。

诊断构建的阶段均值如下，子项不能再次加到父项上，也不将各阶段 p95 相加：

| 阶段 | approx/all ms | approx/both ms |
| --- | ---: | ---: |
| Core | 53.129 | 44.751 |
| 预检 | 4.053 | 4.146 |
| occupancy | 3.174 | 3.115 |
| Waiting 准备 | 9.361 | 2.438 |
| Conflict 准备 | 16.966 | 12.326 |
| └ frontier | 5.154 | 5.402 |
| └ P3 准备 | 2.038 | 3.070 |
| └ P3 分发/等待 | 3.642 | 1.719 |
| └ P3 消费 | 4.426 | 0.476 |
| └ P4 | 0.806 | 0.772 |
| Motion | 6.631 | 9.203 |
| Conflict 收尾 | 5.279 | 5.648 |
| Waiting 输出 | 4.839 | 4.919 |
| commit | 2.152 | 2.260 |

工作范围判断让 P3 准备增加约 1.03ms，但分发和消费显著减少。P2 少算预览后，
Motion 增加约 2.57ms，证实存在成本转移；只报 Waiting 的约 6.92ms 节省会
夸大收益。整拍实际约节省 8.38ms。剩余预检、Conflict 收尾、Waiting 输出合计
约 14.71ms；Motion 为 9.20ms。即使剩余 frontier 全部免费，诊断 Core 仍约
39.35ms。这仅是成本算术，提示下一轮不能继续只优化 frontier 或 P4。

10k movement_mixed 另从初态运行 8192 拍（131.072 秒仿真时间，大于 122.496
秒完整信号周期）。参照/组合 Core 均值为 5.110/4.223ms，p95 5.974/5.024ms；
单次 A/B 只作后续行为与收益筛查，不替代 100k 正式后段。两者均完成 2303，
成功替换 544，距离 566.221km，停车 Active 拍比例 55.384%。观察到 1367 次
资源释放、最长已释放资源持有 13.184 秒；完成 owner 持资源、未配对 clear、
纵向车体重叠及同区多 owner 拍级暴露均为 0。

新增个体指标揭示了聚合值掩盖的问题，两模型均有：

- 最长连续停车 **129.536 秒**；所有行程片段的最长连续停车 p95 为 110.288 秒。
- 窗口结束未完成片段中，**3107 条**连续停车至少 60 秒，**164 条**至少 120 秒。
  164 条均为普通初始车辆，没有设置专门阻挡角色。样例为 tile=0、slot=740、
  incarnation=0，初始路线 `t000.c01.n-e`、occurrence=0、progress=92000mm；
  其他 tile 有重复样例。编号与初态记录已进入 summary.json。
- 8044 条观察片段中仍没有窗口内开始且完成的新行程，不能认证完整旅行时间。
  这些停车时长也被窗口右截断，129.536 秒不是已知最终等待上限。

因此质量结论是“本轮未发现候选新增上述退化，但存在需定位的长等待”，而非
“吞吐相同所以质量通过”。目前记录只有决定批摘要，尚不能判定具体停因是信号、
前车队列、下游存储、让行规则还是夹具拥堵；不把它直接定性为死锁。

## 下一切片与验收范围

1. 保留本轮组合原型；下一轮优先削减**预检、Conflict 收尾和 Waiting 输出**的
   全量工作。源码中 `conflict_state_valid()` 逐车辆槽验证；收尾逐更新车辆计算
   资源和非资源 Gate 决定；Waiting 输出逐车发现非入口 Gate 观察。研究把检查
   移到状态变化/命令边界，并按改变的 owner、membership、Gate 生成结果。
   不要求保留旧版每拍观察行或首错顺序，仍检查真实资源释放和失败后的可用状态。
2. 针对上述长等待样例加**选定个体的停因轨迹**，记录入口信号、前车/下游阻挡、
   许可拒绝与资源状态。保留城市需求，同时用较小可控场景分离拥堵、规则和
   夹具因素；不再用一次总里程正常或聚合值相同结束质量分析。
3. queue2 暂保留研究候选；探索按 movement 维护局部来车及真实队列阻挡，
   继续量实际通行间隔和优先流延误。未将固定 K=2 定为产品规则。
4. 本轮没有实施多频率决策、稳定 100k Active、正式生命周期晚窗、连续二维
   碰撞检查、内存/分配峰值或宿主队列年龄测试。16ms/33ms 实时目标都未达成。
