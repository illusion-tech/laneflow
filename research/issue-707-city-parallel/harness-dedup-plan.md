## 原型边界

拍后调用顺序为 events → state → counts → parking_invariants。后三者读取同一个
已提交世界。H1 将 live/身份与生命周期计数、停车绑定聚合合并进 state 的车辆遍历，
共享局部 VehicleState 与 ParkingBinding 值，随后执行原有容量和设施总量核验。
保留所有生命周期状态、逐拍摘要字节、质量累计、空间排序和不变量检查。

拍前 step_before、red_waiters 和事件消费不参与合并。不新建整世界状态快照，
不按车辆增加跨拍缓存，不将旧代 handle 或失败候选的数据带到后续调用。

在新的研究 checkout 保留原始直接读取路径作为 H0 和短审计 oracle；这只是有限
实验的对照，不是对生产接口增加兼容层。审计在同一个提交状态上比较摘要、计数和
逐拍质量，同时分别执行原有检查。合法输入观察结果须一致；失败输入须被拒绝，
不要求多个同时存在的错误保持相同报错先后。

## 验证和测量

1. 保持 B1 源码/输入/既有证据只读，独立记录新源码、补丁和二进制身份。
2. 运行 Harness 相关测试、新增同状态审计与身份/停车聚合负向检查。
3. 单独启用逻辑工作量计数，记录真实车辆读取、停车绑定查询及遍历量；该构建
   不并入性能结果。计数必须位于实际调用或遍历点，不能用样本 hits 代替调用数。
4. 无 WPR、无工作量插桩的 release，100k 既有 fixture 做 H0/H1/H1/H0 短 ABBA；
   记录每臂暖机后 observation、iteration、Core mean/p95/p99 与完整进程墙钟。
   所有性能臂串行，期间不编译、不运行其他分析任务。
5. 用较小的多 gap / 混合生命周期输入验证两种路径，检查摘要、事件、命令和质量
   数据。测试记录内存组织及新增容量；不把理论结构大小包装为实测进程峰值。
6. 仅接受观测内容不减少且净成本下降的候选；不明显则收口，不扩大 Harness 重构。

性能与审计分开记账。Runtime 未改也需报告 Core 变化，因为缓存和执行节奏可能
改变其计时。任何收益仅归到实测成本范围，不视为 Core 算法提速或实时认证。
