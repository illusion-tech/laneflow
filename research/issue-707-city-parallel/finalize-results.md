## 长等待追踪方法

上一轮 164 条 ≥120 秒长等待片段覆盖 22 个局部槽位、多个重复路网片区。
本轮选定 tile=0 的 slot 740、744、676、604、532、465，以及 0、739 对照。
从原初态按原 10k movement_mixed 输入运行 8192 拍，不恢复伪造晚窗。

独立 `stop-trace` 二进制每 64 拍采集选定句柄的运动内核调用，包括预览调用：
前车间隙、最低间隙、信号/停车/Waiting/Conflict 约束、hard room、提议距离与
速度，以及最近 Gate 的灯色和策略决定；Harness 同时记录提交后车辆状态及其
决定。轨迹写入在 Core 之外，内核采样和共享日志本身有成本，所以诊断臂不用于
性能结论。此 feature 暴露研究用句柄槽位访问器，不作为正式 API 交付。

无轨迹的 release 用于性能；阶段诊断另用 `entry-audit,short-profile`。构建、
计时与 Python 离线分析串行，保留个体停车、截断行程、资源释放与纵向重叠观察。

## 测量与诊断结果

4 workers，release，工具链 1.98.0，平衡电源方案。计时、构建与离线分析串行；
未锁定 CPU 频率，也未隔离全部桌面后台负载。Core 为公共 `step()` 调用时间；
iteration 含 advance 与缓冲语义输出，扩展交通观察、诊断 CSV、最终 flush 和
checkpoint 在其外。Harness 不是宿主生产链路。

100k 输入为 junction_long_tail 多 gap 夹具，前 512 拍，统计 tick 65–512。
实际 Active 65577–75000，33ms 步长，共 16.896 秒仿真时间，不能称为稳定
100k Active 或正式后段认证。10k 使用 movement_mixed，16ms 步长。

### 长等待的直接停因

两种配置从同一初态各运行 8192 拍，即 131.072 秒仿真时间，覆盖一个
122.496 秒信号周期。每 64 拍取样一次，每个选定槽位 128 个样本。
下表为提交后速度为零的样本；约束采自同拍内核调用，包含预览，计数不可相加为时长。

| tile=0 槽位 | 零速样本数 | 实际拒绝或最近运动约束 |
| --- | ---: | --- |
| 740 | 126 | 69 次红灯零空间；57 次绿灯、无前车，但 Conflict 为零空间，其中 LeadGap 50、LagGap 4、ConflictOccupied 3 |
| 744 | 126 | 69 次红灯零空间；57 次绿灯、无前车，但 Conflict 为零空间，其中 LeadGap 53、LagGap 1、ConflictOccupied 3 |
| 676 | 124 | 全部无前车且 Conflict 为零空间；ConflictOccupied 118、LagGap 6 |
| 604 / 532 / 465 | 119 / 115 / 114 | 前车间隙等于最低跟车间隙，运动空间为零，队列向后传递 |
| 0 / 739 对照 | 71 / 52 | 取样零速时均是前车间隙限制；其余采样拍仍有移动 |

all 与 combined 的上述样本分布相同。本轮并非把旧结果当正确答案：事实是
收尾优化保留了这些长等待，**交通停滞问题没有解决**。740/744 不能只解释成
红灯等待；676 的主要直接原因是资源占用，后车则受真实队列约束。

源码中 `rebuild_entry_frontier` 的 ETA 输入为路线距离、当前速度与最大加速度，
没有把前方红灯、队列或其它冲突阻塞作为到达可行性的输入；`evaluate_yield_target`
先检查占用，再以 frontier 和 lead/lag 判定。因此“被阻塞的车辆仍持续产生很近
的最早到达预测”是后续应验证的机制假设。当前日志没有记录拒绝读到的具体
frontier owner/ETA，也没有记录全部 zone owner 的等待链，不能据此认定虚假占用、
永久死锁或误拒绝，更不能用这八个样本解释全部 164 条长等待。

两臂均行驶 566.221km，完成 2303 次，Active 为 5714–7500，零速 Active
车拍占比 55.384%。最长连续停车 129.536 秒；右截断片段中 ≥60 秒为 3107，
≥120 秒为 164。纵向重叠观测、同 zone 多 owner 暴露、无匹配释放和已完成
车辆仍持资源均为零。以上只说明本观察口径未发现相应异常，不是几何无碰撞证明，
也不代表交通效率已达标。样本包含初态既有行程，无完整新发起且完成的行程，
不能给出无截断旅行时间结论。

## 下一片的明确取舍

保留 combined 作为下一片的研究参照，outputs/changed 已显示削减重复工作的
价值；checks 仅作为明确弱化全量审计的研究策略，不视为已完成所有变更边界
校验。交通质量仍未通过：长等待原样存在，必须继续定位并验证改善。

接受并缩小用户提出的“固定路线区间 + 进度跨界”方案，具体见
[Motion 边界变化与阻塞依赖计划](motion-boundary-next-plan.md)。复用现有编译
路线和 passage transition，让 Motion 一次产出 enter/clear，驱动占用、释放
与必要事件；删除被替代的扫描。保留准入、下游认领、lag 历史和 lead 预测所需
权威，不能只留下当前占用，也不能新增缓存后保留全部旧工作。

本轮 changed 只跳过部分无资源收尾，不是上述边界增量模型；尚未测出稀疏更新
与批量重建的交叉点。下一片须统计真实边界变化、唤醒和维护成本，同时补具体
阻塞 owner/ETA 链，再判断是否优先调整 gap。Motion/frontier SIMD 是后续互补
方向，当前没有汇编与打包成本证据，不能承诺其收益。
