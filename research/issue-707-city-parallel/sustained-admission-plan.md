# 持续负载的有界候选准入

2026-10-07。Refs #707。承接维护者“开始下一步”，先验证调用方负载准入方案。
前置失败证据保持在 [合并后短窗结果](post-815-baseline-results.md)，不改写。

## 冻结候选

仅改 `SUSTAINED-ACTIVE` 的回收计划和调用方调度，Runtime、路网及七套正式场景不改。
采用目录中属于本 tile、首边为 95000 mm 外部进口车道的行驶路线，按入口车道 key 分组，
组内路线按 key 排序。每条入口有 11 个候选车头位置：`7000 + 8500 * layer` mm，
`layer=0..10`，初速为零。候选车身仍必须由 Runtime 验证，计划枚举不等于准入授权。

每个实际 Completed 槽位至多一个请求，身份和 incarnation 规则不变。用槽位和成功
incarnation 确定候选起点，按候选尝试编号轮转入口、位置及该入口的路线，避免按全局
路线数量给路线丰富的入口更多请求。候选顺序、每边界 64 次尝试上限、8 tick 后重试
和全部位置写入计划，生成后冻结摘要。64 次都拒绝时保留同一 pending 请求，直到成功
或观察窗口结束；不假定所有拒绝都能通过换入口解决。

同边界重试复用现有有序调度和 RequestLedger，attempt 严格递增。每次调用公共
`replace_completed_vehicle`，拒绝必须保持原车辆、游标、资源和请求身份；成功只
增加一次出生、移除和 incarnation。记录实际路线、位置、拒绝与尝试次数，不能只保留
成功调用。整步耗时与调用方准入成本分开；增加候选不能隐藏调用方开销。

## 验证与停止条件

第一版 `211c0c8f` 已冻结到 `sustained-admission-20261007-v1`：每 tile 的 94 个入口
多于每边界 64 次预算，先轮换入口使若干请求停留在同一拥挤位置。十万短窗仍有 7 拍
未达目标，保留全部失败证据。第二版仅调整候选位置顺序：每次尝试同时轮换入口和
位置，位置索引为 `(floor(base / E) + attempt - 1) mod P`；预算和安全检查不变。
第二版必须生成独立二进制、计划与结果，不能复用第一版的成功或失败结论。

1. 计划验证拒绝空入口、空路线、零预算、非法位置及污染；七套正式计划保持既有摘要。
2. 定向阻塞测试证明同边界有界、超过 64 次仍保留一个请求、窗口末 pending 及解除
   阻塞后只成功一次；跨 worker 实际回收、拒绝不变性和逐拍语义继续验证。
3. 新目录冻结源码、二进制和计划；先重跑一万/十万 1/16 workers 的 256 拍短窗。
4. 十万命令后、step 前 `N_intent` 每拍须达到 100000；step 后完成行程造成的下降
   单列。下一边界能安全补回才可认为该窗口维持了整步工作负载。不改目标为宽松比例。
5. 短窗通过后先做一轮 512 暖机 + 4096 观察拍，验证覆盖回收阶段的实际负载、
   拒绝/命令成本、交通计数和调用方墙钟；失败先归因，不扩大为四轮性能矩阵。
6. 负载与合理交通结果成立后才恢复 8→16→16→8 测量。该切片仍不关闭 #707，
   不把 probe 当正式性能认证，不把 Active 数量单独当交通质量证明。
