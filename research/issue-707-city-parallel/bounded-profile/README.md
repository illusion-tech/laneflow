# 持续负载有界性能剖析

Refs #826。源码基线 `9d61f8d2b0d2ccceb22580a346b1031fdc153022`。

`instrumentation.patch` 只给研究构建接入 `timers.rs`，不改变正式 Runtime API 或状态
语义。先用 `git apply --check` 核对补丁，再应用；完成构建后反向应用补丁。研究模块
只通过补丁引用，普通 workspace 构建不编译它。使用 Rust 1.98.0、默认 features、
release；记录补丁、模块和二进制 SHA256。原始证据保存在仓库外独立目录。

计划沿用持续十万车辆候选顺序，只将观察期缩为 1024 拍，保留 512 拍暖机、16 workers。
普通版、插桩版各一次；如首轮存在明确定位缺口，最多各追加一次同窗口。

每拍 stderr 输出一行 JSON，包含原有的外层 `step_ns`、`command_ns`、`observation_ns`；
`stages` 和 `outcomes` 的各项均为 `[调用次数, 纳秒]`。
`outcomes` 按成功、入口阻挡、后车安全拒绝和其他结果分类，只统计公共替换调用；
分类来自返回值，不解析错误文字。每次调用前后对计数器做差，保留早返回路径。

区间是调用线程或 step 协调线程上的包含式墙钟：`FreshAdmission` 包含安全检查和索引准备；
`DirectFollowers` 包含 `UpstreamFollowers`；`MotionLoop` 包含列准备、分发及消费；
`ObserveState` 包含车辆扫描和车身排序检查，`StateBodies` 还包含后续等待区、信号、
剩余权利摘要与哈希收尾。嵌套项不能相加。`ColumnDispatch`
包含等待 worker 完成，不能解释为各 worker CPU 累计。没有逐车计时，不给每车热循环
加锁或计时；本轮不测最长 worker 块与真实并发参与数。粗粒度区间结束时通过原子计数器
汇总跨线程结果，只在同步返回、全部 worker 完成后的边界读出及清零。每进程只运行
一个研究世界，不支持多个世界并发共用此计数器。

`reset` 在每拍命令前清除安装期统计，`flush` 在原观测计时结束后输出。输出与
计数器会扰动缓存、代码布局和墙钟，插桩延迟单列，不用于 16 ms 产品预算认证。
正常/插桩必须对拍状态摘要、命令、事件和展开计划，核对实际 Active 与拒绝计数。
还须检查每个 step 阶段每拍恰好出现一次；零次数不能解释成零成本。
源码中的安全检查、全量状态扫描、摘要、不变量及候选逻辑均保留。

结束条件是定位具名成本与慢拍阶段，给出一个后续优化方案；不在本切片实施优化，
也不替代 #707 的三轮完整观察协议、资源与交通质量验收。

独立测试入口为 `rustc +1.98.0 --edition 2024 --test timers.rs -o timers-tests.exe`，
然后运行生成的测试程序。覆盖结果分类差分、跨拍清零及八线程计数归并；测量程序的
全量状态对拍负责验证插桩未改变本次实际交通执行结果。
