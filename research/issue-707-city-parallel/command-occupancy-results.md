# 命令里借执行资源并行重建占用索引：结果

**日期**：2026-10-11；Refs #861，父任务 #707 继续开放。设计见
[`traffic-runtime-vehicle-placement.md`](../../docs/design/traffic-runtime-vehicle-placement.md)
第 8 节。

## 1. 结论与交付范围

执行资源支持协调器并行时，生成、替换与驶离停车走到占用索引重建点、索引已过期，就
让出：活动世界在执行作用域里借执行资源并行重建，再从头执行这条命令。并行重建失败时
退回原位置串行重建并照常报错。调度线程少于 4 时行为不变。不改规则、公共 API、错误
分类、格式或资源所有权。

普通 ABBA 观察窗公共命令合计下降 39.4%–39.9%，命令 p95 下降 43%–44%，p99 下降
26%–29%，最大值下降 14%–23%；step 分位无一致方向。四次运行的交通文件逐字节一致。
本交付不宣称 16 ms 达标或 #707 完成认证。

## 2. 依据

分阶段计时与计数探针（不合入，main `1e91b764`；交通文件与未插桩运行逐字节一致），
观察窗 132 批命令：

| 观察                                 | 结果                                   |
| ------------------------------------ | -------------------------------------- |
| 每批命令里的占用索引重建             | 正好 1 次（132/132），全部由准入触发   |
| 重建原因                             | 步进推进了观测序号（132/132）          |
| 新车记录因来源不符放弃插入           | 0                                      |
| 命令里串行重建                       | 平均 7.4 ms，合计约 0.98 s，约占 47%   |
| 步进开头并行重建同一份索引           | 平均约 1.0 ms                          |
| 命令补丁后的记录与步进重建逐项相同   | 132/132（存放顺序与排序后都相同）      |
| 命令补丁后前车表可用                 | 0/132                                  |

最后两行是不选「步进末尾建表、下一次步进复用」的依据之一：复用前要补建前车表。

同一探针把剩下的非准入时间拆开：观察窗命令全部是 `replace_completed_vehicle`；
17,491 次在准入之前因与已有车辆重叠被挡（`Blocked`），每次约 33 µs，合计约 0.58 s。
这是下一个候选。

## 3. 实现与正确性

见设计 8.2–8.4 节。要点：

- 让出点就是现行的重建点。让出前命令没有提交任何东西，重新执行时已提交世界相同，
  结果与不让出时相同；
- 并行与串行重建产出同一份索引（每条边的记录按完整键排序，前车表与每条边的最前
  记录同时写入）；
- 并行重建在执行作用域里运行，worker panic 使世界失效；失败时来源保持为空，留给
  原位置报告。

验证：

- 16 worker 与单 worker 世界逐次比较：生成 12 批 × 4 次，命令结果、占用索引全部内容
  （记录与存放顺序、后缀、前车表、每条边的最前记录）与最终状态摘要相同；每批最多
  让出一次，并行重建次数等于让出次数；
- 注入并行重建分配失败：退回串行，结果相同；注入 worker panic：世界失效，之后的命令
  被拒绝；驶离停车同样逐次比较；
- 变异检查：去掉让出后的重新执行，4 个新测试全部失败；
- Rust 1.98.0：Runtime 默认与 `placement-fixtures` 两种配置全量测试通过；Clippy 两种
  配置 `-D warnings` 通过；`fmt` 通过。`spawn_overlap_allocation` 打印的两行断言
  信息与 main 相同，测试通过。
