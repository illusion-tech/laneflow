## 首轮失败与串行中断

首轮 `e9dddc61a957875514cc5360e7f73d79a83b0d80` 在一万 W1/16 ms 第 21466 拍
失败：rank 187 在 entry 停止线前由 `13900 mm/s` 直接投影为零，触发核验器误加的
紧急减速度上限。整数几何合同 §1/§5 明确要求硬剩余空间耗尽时清速度与微米余数；
性能基线的硬不变量只要求加速度有限，未将 `emergency_decel` 定为已提交速度差的
绝对上限。该失败来自核验合同映射错误，Runtime 生产代码与输入均未改动。

修正后保留实际最大减速度和超 profile 紧急减速度的拍/车计数。这个计数为诊断值，
不能当作物理平顺性通过。停止线、重叠、身份、人口、事件和精确重放断言均保留。
正式矩阵中，16 ms 最大观察减速度为 `868750 mm/s²`，33 ms 为
`421213 mm/s²`；各行超 profile 次数见回执。这是现行硬投影的实际速度突降，
并非物理平顺性合格结论。

`65dfce5ee22d50b52a582f5c0239a1903c09bf06` 的串行矩阵完成一万四行双进程对照后，
因改用并发调度而主动停止；十万 W1/16 ms 首轮最后进度日志为 27648/43524，
回执仍为 `complete=false`。已完成的四行有效，但该矩阵整体未完成，不能称 8/8。
正式实现 `4c0338f9` 从头重跑全部八行，没有拼接或跳过已中断行。

仓库保留[首轮失败回执](failed-e9dddc61.json)、[串行部分矩阵](partial-65dfce5e.json)
和[主动中断说明](interruption-65dfce5e.json)，它们均不得作为完整通过结果。
