# 资格表提交成本结论

## 决策

保留最小优化：P7 清除上一拍已提交资格后，先检查本拍下一资格表是否全空。
全空时直接保留原有紧凑空表示，非空时仍逐槽复制。latest decisions 仍在同一
P7 提交段交换。完整资格谓词、首次资格时钟、正式 `conflict_state_valid`、
失败原子性、资源权威与公开格式均沿用现行合同。

本项不扩大到触及槽位列表、独立尝试代次或资格缓存。扫描/清空仍随配置容量增长，
预留内存没有减少。本项不关闭 #707/#537/#539 等产品级认证工作。

## 正常库整拍

冻结 A=`c0d8cc0b056c3daaf5a03d8e6acdc392517acdd7`、
B=`00df1af1031e25b8206ab1e40e2178fb6ffefc1d`。两者基于 main
`72102fabb2cda5ebadde52dc1260c8402762efda`，A→B 仅修改资格提交顺序。
编译使用相同 rustc 1.98.1、release、Cargo.lock、runtime manifest 和
placement-fixtures feature。正常库没有 cfg(test) 归因钩子。

每场景三组 ABBA / BAAB / ABBA，第二组反转场景顺序。每个进程观测 128 拍；
共 72 个正常库进程、9216 个逐拍样本。均值汇总没有删除告警轮次，也没有选择

普通容量和大容量空资格组的收益方向一致，是保留候选的主要证据。高活动率组
收益不明显；parked 三组均更快，但第三组差幅偏大且基线进程有 CPU 告警，不能
把总体 -12.40% 当作稳定保证。真实非空资格两组的方向均有反转：小容量总体多约
0.060 微秒，大容量多约 3.085 微秒。这不是非空路径的提速证据，也不足以断言
严格无退化；当前未观察到跨三组稳定回退，保留该限制及全部负面结果。

这些是当前 Windows 主机、固定输入上的串行观测，不是城市密集 Conflict、并行
加速或 100000 车辆 33 ms 认证。短窗口对调度、频率与缓存状态敏感；未采集 PMU，
不从时间变化声称 cache miss 减少。

## 成本归因与内存

36 个独立诊断进程与正常库使用相同输入及结束状态摘要。诊断包含完整 11 阶段、
资格提交及其子项，父子计时不能相加，诊断绝对耗时也不能与正常库时间相减。

大容量空资格组中，基线每拍复制约 125～133 微秒、复制后全空扫描约 160～193
微秒，资格提交约 289～326 微秒。候选复制 calls/items/ns 全为零，扫描仍访问
十万槽位长度上界，约 78～86 微秒；资格提交约 78～86 微秒。整拍收益应直接
取上面的正常库 A/B，不能把这些局部差额再叠加。

运动暂存清空和下一资格表清空仍在。`scan items` 是传入长度上界，遇到首个
Some 时短路，不能把它当成实际元素访问数。首位、末位、密集和全空另有三组
表级诊断；合成槽位只说明提交操作，不冒充合法交通世界。全空免复制，其他
模式仍完整复制；全部表级调用零分配/重分配。

所有 36 个诊断进程的 128 拍窗口均为零 allocation/reallocation/allocated bytes；
真实资源窗口每拍恰有一个已提交资格，保留 reservation 和 NoGrant。
各组两臂、三轮和全部窗口的 retained memory 完全相同。capacity 的 world-owned
为 111067169 bytes，约 105.92 MiB；shared 单列 29664 bytes。完整 owner 账本
见 JSON/数表。跳过复制不缩小 capacity，不能宣称节约约 95 MiB 的容量内存。
