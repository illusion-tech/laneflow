# 输出与权威提交热路径的有限研究结论

本报告汇总 #219 的三项有界候选，结论截至生产基线
`6d2b33bf5fd40d9a751e55be93edac910f1161ba`。范围是当前道路机动车特化的
输出收尾、转移事件与权威提交，不覆盖所有交通执行域或城市级性能。

## 结论与停止点

两条零输出快路径在部分既定输入上观察到平均整步耗时下降；未武装迁移日志清理
没有证明稳定提速。收益来自省略重复生成扫描，不来自取消首遍校验、减少应有
事件或放宽原子提交。三项修改均保留既有生产合同，不需要新 ADR 或设计改写。

| 候选与证据                                                        | 有界判断                                              | 生产改动边界                                                     |
| ----------------------------------------------------------------- | ----------------------------------------------------- | ---------------------------------------------------------------- |
| [#618：未武装日志](../issue-618-unarmed-journal/README.md)        | 四组区间均跨零，仅作私有实现清理，不计性能收益        | 前移日志存在性判断，省去无用比较、路线定位及 `VehicleDelta` 物化 |
| [#620：零转移事件](../issue-620-zero-event/README.md)             | 三组未武装输入有平均耗时下降；武装组未证明提速        | 首遍完整验证、计数和 reserve 后，仅省略零事件的第二遍生成        |
| [#622：零非入口 Gate](../issue-622-zero-non-entry-gate/README.md) | 三组输入有平均耗时下降；10000 / 16 未武装组未证明提速 | 首遍计数和 reserve 后，仅省略零非入口 Gate 的第二遍生成          |

有限研究在这三项候选后停止，不追加第四候选或扩大基准矩阵。这不是“输出路径
已经优化完毕”；未测输入若出现真实瓶颈，应以新画像和独立立项判断后续工作。

## 成本归因与相互包含

来源为 [#216 的真实 step CPU 画像](../issue-216-exact-path/cpu-profile.md)，
生产基线 `6fefd582364685c07ed83af79b2bec80f5223fc5`，不是上述三项修改后的画像。
以下统一为 10000 车辆 / 256 边输入的 `step` CPU 采样权重，不是精确墙钟分摊。

| 位置                                    | 权重     | 解释边界                                                                         |
| --------------------------------------- | -------- | -------------------------------------------------------------------------------- |
| `finalize_waiting_outputs` 含子调用     | 14.45%   | 包含 Waiting 决策、非入口 Gate 扫描和转移事件，不是 Waiting 车辆占比或可删除比例 |
| 同一非内联符号 self                     | 12.92%   | 仍含编译进该符号的内联体，已包含在上一行，不能相加                               |
| 内联 `visit_transition_events` self     | 约 5.05% | 属于输出收尾子树；不能再加到 14.45% 上                                           |
| `CommittedStateMut::commit` 非内联 self | 5.01%    | 包含内联日志物化及状态写回，不等于纯存储指令成本                                 |

输出、事件、校验、提交没有形成四个互斥的独立计时桶；校验与计数、生成遍历交织，
现有画像不能给出独立的“校验成本”。`VehicleDelta::from_state` 约 1.52% 的旧叶栈
权重嵌在提交路径中，也不是 #618 的加速比。修改后未重采 CPU，不能称上述数值为
当前剩余热点份额，或与旧探针墙钟占比相减。

运动 / controller、状态传递与下一状态物化属于 #217；occupancy、leader 和查询
horizon 属于 #216。推进的含子调用权重已经包含查询，不把它整体记为运动算法；
#219 仅处理派生输出和 P7 提交，不据此重构运动接口或状态布局。

## 生产 A/B 与资源证据

下表是各自基线下，12 对独立进程平均耗时比值的几何平均变化，负数表示更快。
完整描述性 95% 区间、源码指纹、复现命令见各候选报告；“未证明”不代表等效。

| 输入（车辆数 / 边数） | 日志   | #618             | #620             | #622             |
| --------------------- | ------ | ---------------- | ---------------- | ---------------- |

| 10000 / 256           | 未武装 | +0.73%（未证明） | -6.46%           | -4.11%           |

- 每项均为 12 对 AB/BA 平衡轮次、四种输入轮转，共 96 进程、270336 拍正式样本，
  另保留 12288 拍排除暖机样本。生产库无研究探针；64 拍窗口、100 ms 步长，
  Individual / Active / Intent 等于车辆数，Presented / Aggregate 为 0。
- 整对 bootstrap 10000 次、seed 618；区间为描述性区间，不把逐拍当独立实验或
  短窗口 p99 当稳定尾延迟证明。#622 一千车辆组进程 p95 中位数反而从
  408.55 增至 413.50 微秒，不能声称尾延迟改善。
- 同机 AMD Ryzen 9 9955HX、Windows MSVC、Rust 1.98.0 默认 release，平衡电源计划，
  未锁频 / 绑核；测量期间无本任务 Cargo 构建或 ETW 采样，不声称宿主始终空闲。
- 每项两版六组输入的暖态分配 / 重分配均为零，状态摘要与迁移日志字节数一致。

- 独立进程轮次及未排序逐拍样本全部保留于原运行工作树的 `target/issue-618/`、

  其他机器复算历史批次需要取得本地制品；复测沿用 #618 的既有入口和脚本。

三轮依次使用不同基线，没有同批最初版本与最终版本的整体验证；不能相加这些
百分比，或宣称 #219 的总加速比。未测十万车辆、非零事件 / Gate 密集输入的性能、
长尾稳定性、跨机器 / 跨平台性能，以及优化后的剩余 CPU 分布。

## 保持的合同与后继输入

既有 [阶段协议](../../docs/design/traffic-runtime-phase-protocol.md) 与
[修订切换设计](../../docs/design/traffic-runtime-revision-cutover.md) 仍是权威：

- P7 只消费完整受检的 `CommitPlan`，没有新增可恢复错误出口；tick、时间、迁移
  日志空记录、资源增量与溢出后推进保持。未改变公开 API、格式、Adapter 或依赖。
- 事件首遍仍访问并验证完整输入；零非入口 Gate 不意味着零 Waiting 决策或零事件，
  已有决策排序和后续 `stage_transition_events` 不受该快路径跳过。
- 逐拍快照与三类输出、事件内容和规范顺序保持；由有到无仍发布空批次。回归覆盖
  首遍 / 后续不变量错误、失败保留旧状态与已发布批次，以及 retry/fresh 一致。
  各切片历史 Runtime release 分别为 449、452、455 passed，均 0 failed、29 ignored；
  构建、格式、架构与生产库严格 Clippy 证据见各自报告，本汇总不冒充重新执行。

向 #220 提供的是串行输出 / 提交成本边界、两条有限快路径和上述不可削弱合同，
不是分区或线程方案。并行设计还须结合 #215 的工作负载口径、#216 的 exact / halo
边界及 #217 的运动局部性结果，证明错误顺序、规范输出及全步原子性；这些结果
不能自动构成 #220 的 G1 冻结依据。若后继需要改变提交阶段、状态布局或公开合同，
须独立设计并判断 G1 / ADR，不能借本次有限研究直接授权。
