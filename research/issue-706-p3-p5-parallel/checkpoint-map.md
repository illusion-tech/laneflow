### 1.4 交错警报

- **reserve 与更晚错误的先后**：conflict_tick.rs:549 rebuild 先于 550-557 预留。原顺序下 frontier 内部失败（含 ensure_cells 分配失败）先于候选预留失败成为首错；改成「先统一预留再 rebuild」会在两失败并发时改变首错身份。
- **早退分支 #5**：horizon 为 None 时 rebuild 整体跳过；但 534-547 的清障已发生。若把清障挪进 rebuild 条件内，静态 cell 的 frontier 携带上拍残留，P4/P5 读到脏 frontier。
- **reservation 跳过的读取基础**：conflict_tick.rs:570 经 conflict_read 合并层读 owner（conflict.rs:2901-2932）；正因 534 先 discard_staged，读到的才是纯拍初 committed reservation。被跳过车辆**不占用 candidates 但已占用 cache_index**（568-569 在前）——重排若把紧凑位分配挪到跳过之后，motion_cache 位置契约（evaluate 内 `get(active_index)`）被破坏。
- **缓存复用证明的前置**：candidates 预留上界 `active_order.len()`（#16）依赖「每车至多一次 push 即返回」（867-886 早退 / 957 / prepare_resource_candidate 单次 push）；worker 若改变该结构，预留证明失效，裸 push 可能静默扩容（违反 state.rs:94 「增长全走 checked reserve」不变量）。
- **排序与位置切片**：586 排序必须晚于全部追加；排序交换 candidate 记录而 cells_start/end 指向的侧车 Vec 不动。任何按 worker 分片局部排序都会破坏稳定键全局序（conflict.rs:343-379）。
- **break 的单调性前提**：663-667 依赖 conflicts 按 route position 排列且 directed 下界随距离单调（注释 664-665）；投机实现若逐 occurrence 独立计算而不保留 break，结果值相同但工作量/测试计数不等价。
- **failpoint/计数可观测性**：reserve 的 failpoint 触发以「实际越过容量」为条件（conflict_tick.rs:270-274、conflict.rs:4180-4181）；并行化若改变 reserve 次数或容量轨迹，既有 failpoint 测试注入点会漂移。

### 2.4 交错警报

- **A1（缓存写先于早退，742-749 vs 750-752）**：horizon 在门距早退**之前**落缓存。若重排为「先检查距离再写缓存」，超 horizon 车的 horizon 不被缓存，P5 复用失效、horizon 重算计数变化。复用证明依赖：写者在 727 已成功算出 horizon。
- **A2（早退跳过计算与错误，750-752）**：串行中，门距超 horizon 的车**不会**执行 765 的 `WaitingInvariantViolation` 与 777 的 `NonFiniteMotion`。若改成「全部算完再统一检查」，更晚错误提前暴露，首错顺序被破坏。
- **A3（预留原位，875）**：真实 `try_reserve` 紧贴 push，其与 857/门级 `ConflictInvariantViolation` 之间无其它错误点；把预留上提为批量会与同车更早领域错误竞争失败位置（OOM 遮蔽串行先到的领域错误），scratch failpoint 测试也按此位置注入。
- **A4（首 outcome 即返回，885/890）**：每车至多产出一个 staged 决定**或**一个候选，更远 Gate 不求值。跨车可见顺序依赖按 `update_sequence` 规范消费；`conflict_candidates` 虽在 586-588 重排序，失败前缀与 `conflict_motion_by_vehicle` 赋值仍以消费序为准。
- **A5（waiting 快照依赖，753-765）**：`waiting_stop_for` 与 plan 裁决读取本拍 Waiting 阶段暂存。P3 投机必须在该快照冻结后进行。
- **A6（preview 复用证明链，766-768 → tick.rs:56-73）**：复用要求 cache 身份匹配（721-726 vehicle 检查）且 waiting_stop 相等或「新增且不受影响」；移除/替换约束必须重算。证明输入若被并发改写，复用结论失效——投机只读快照即可保持。
- **A7（无资源 Deny 静默返回，867-874）**：无资源 Gate 的 `NotEvaluated` **不**落 staged_decisions（注释 868-869：避免前方资源拒绝后报告未到达的 Gate）；`NotRequired` 则 continue 扫描后续 Gate。若统一改成「无资源也暂存」，发布决定集与最终运动范围的关联被破坏。

**实现要点**：698-797（身份检查、horizon、距离、waiting_stop、preview）全是纯函数式受检读，可按车投机；798-866 的 Gate 循环为「首 outcome 胜出」车内串行但可随车并行投机；真实预留 875 与全部共享写（缓存两处、staged_decisions、§3 候选暂存）必须协调器按 `update_sequence` 保序规范消费，且 `NonFiniteMotion`/归属变体（`Conflict*` vs `Waiting*`）在消费侧按 P3 口径重映射。

### 3.4 交错警报

- **A1（Err 路径亦落盘）**：922-927 与 971 的写入发生在函数内任何可失败检查之前；任一后续 Err 后工作区仍保留该车的 motion plan / eligibility。今天无害是因为 Err 使整拍失败、下拍 540-547 清空；若并行方案改为「单车失败可继续」，语义即变。
- **A2（reserve 先于领域检查）**：1007 的分配失败排在 1011-1075 所有 `ConflictInvariantViolation` 之前。若改成「算完→统一检查→统一预留」，首错顺序从 [AllocFailed, Invariant…] 翻成 [Invariant…, AllocFailed]。
- **A3（共享 Vec 先追加后检查）**：1084-1086 把 cells 追加进共享 Vec 早于 1090 downstream 求值与 1122 候选 push；downstream 返回整车 Err 时共享 Vec 中留有**无候选引用的孤儿 cells**。仅因 Err 中止整拍（588 排序不执行）而无害。任何允许继续的方案必须回滚或改为协调器延迟追加。
- **A4（preflight NoGrant 整体跳过 downstream）**：1089 的跳过使 NoGrant 候选的 downstream_start==end、无 claim 并集（注释 1027-1028 明确 Protected 仍收集资源但 preflight 拒绝不收集下游）。无条件求值 downstream 会暴露 1239 的 `ScratchAllocFailed` 及 plan 内部 `InvalidBundle`——串行路径下这些错误被跳过掩盖。
- **A5（reason 优先级来自短路而非取秩）**：yield 阶段（1066-1074）已产出 reason 时 downstream 完全不执行，最终 reason = yield 最小秩；downstream 的 NoGrant 恒为 `DownstreamStorageBoundary`（rank 5，conflict_tick.rs:319-330）。并发合并若取全局最小秩表面等价，但前提是**丢弃**并发求出的 downstream 错误；若改为评估即报错则违反 A4。
- **A6（共享暂存容量复用改变失败时机）**：`conflict_cell_work`/`conflict_downstream_work` 跨候选复用容量，1007/1239 的热路径通常 no-op；改任务私有暂存后首候选即冷分配，failpoint（270-274 按 `capacity-len` 差值触发）与 AllocFailed 的出现位置随之改变。
- **A7（偏移即顺序，成功值前缀核心）**：cells_start/end（1079/1130）与 downstream_start/end（1104/1132）取自跨车累积 Vec 的当前 len；追加序 = live_order（560）× gate 序（787）。worker 私有计算可并行，但协调器**必须按原串行序追加（或等价重定偏移）**，且首 Err 即停（首错 = live_order×gate 序的第一个 Err）。cells_start/end 错位 → acquire 1294-1298 读到别人的 cells → 仲裁结果改变。
- **A8（跨车只读输入须冻结）**：`evaluate_yield_target` 读 committed cells + 本拍 frontier（conflict.rs:2690-2724，frontier 由 549→593-687 单写者构建）；`leader_gap`（1182-1189）读 derived occupancy。二者均含**他车**状态。worker 投机成立的前提：这些输入在本拍 prepare 阶段冻结、只由协调器先行构建。

### 4.3 交错警报（P5）

- **A1（reserve 与更晚错误的先后）**：parking_arrivals 的 try_reserve（1637）位于循环内第 N 车到达判定后；第 N+1 车仍可能 NonFiniteMotion（1629）使整拍回滚。若把预留重排为循环前统一预留，N 车 alloc 失败与 N+1 车领域错误的首错顺序互换——违反首错顺序与「成功值前缀」可证明性。**这正是 #706 核心反例之一：A 车到达 reserve 注入失败 + B 车 NonFiniteMotion → 必须返回 `ParkingObservationAllocFailed`。**
- **A2（缓存复用证明的前置）**：reuse 证明（tick.rs:75-108）有效前提是 P2 预览与 P5 消费之间拍初 committed 未被改动、且 entry.vehicle==handle 身份过滤通过（1607-1611）。任何把 committed 写入提前到运动循环之前的重排都会使 HardStopped/Travel 边界证明失真。
- **A4（拍初/拍末信号分工）**：运动与 Waiting 决定用拍初信号（conflict_tick.rs:1528、waiting.rs:2451 注释）；eligibility 校验（conflict_tick.rs:1536-1544）用 next_signal_aspects，故 fill_signal_aspects（1661）必须插在 finalize_waiting_step 之后、finalize_conflict_step 之前。前移污染拍初决定；后移使资格校验读到旧值。
- **A6（motion_cache 生命周期）**：1678 的 clear 必须在 finalize_waiting_outputs 之后——后者 2422-2441 用缓存把 update_index 映射回 live 序（缺失才线性回退）；提前清缓存改变 NON_ENTRY_* 计数路径（对拍测试钉死计数）。
- **A8（next_state_by_vehicle 跨阶段接力）**：由 finalize_waiting_step（2261）建立，finalize_conflict_step（1551）、visit_transition_events（transitions.rs:235）、commit_conflict_transitions（1676）消费；workspace 跨阶段单写者状态，投机 worker 不可见、不可写。
