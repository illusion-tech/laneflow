## 3. 七项未决：初步定案方向（待统筹确认后写入定案材料）

分类口径：**需 G1 决策** = 涉及核心规则 / 数据格式 / 快照 schema / 新错误路径 /

### 3.1 T01 承载形式

- **问题**：固定预制过渡以什么形态进入最终拓扑。
- **提案**：**带中心线真实 `LaneEdge` + 普通 successor**（`B0_up→T01→B1_down`），
  必要分段同切两 lane（lane 纵向共延伸不变量）；T01 为经授权规则派生的编制
  材料时**保存来源映射与构造依据、不得冒充原 SUMO connection**。
  不选 Junction/ManeuverPath-managed 形态（那是备选固定连接区，独立 G1）；
  不选无真实边的横向 overlay（需跨 lane 位置映射，属 #273）。
- **依据**：route-design §2.4；`road-junction-model.md` §3.2/§3.3（完整
  ManeuverPath 覆盖规则）；#806 裁决确认材料化方向。
- **分类**：承载形式与 ManeuverPath 兼容声明 → **需 G1 决策**；来源保真规则 →
  **可自决**（裁决已定）。
- **风险**：T01 若被纳入 Junction path 须完整 entry/internal/exit 声明
  （route-design §6.1 第 1 项）；merge/diverge §17.4 适用边界随 G1 记录。

### 3.2 占用投影公式与 overlap 求解顺序

- **问题**：换道期间源/目标占用投影的精确公式，及与 `vehicle-following.md`
  §6.4 overlap 判据的求解顺序（双占用不误判为非法重叠，也不合法化真重叠）。
- **提案**：
  1. **投影公式（v1 保守整边）**：车辆占用 T01 期间，在同区共横向边
     （样本中 `S00`/`S11`）各记一条**全长保守投影**占用记录（`lo_mm=0`、
     `hi_mm=length`）；本车自身记录按 `VehicleHandle` 自排除。选择整边投影
     是因为它**不需要跨 lane 位置映射**（不依赖 #273，整边界语义下保守可行）；
     部分区间投影（按车身扫掠精确展开）推迟到 #273/横向几何 G1。
  2. **实际车体判据不变**：两辆**不同**车的实际车体记录重叠仍按 §6.4 判
     非法（不因投影存在而合法化）；投影↔投影、投影↔他车实际记录的重叠不判
     「状态损坏」，而是**准入/仲裁必须使其不可达**——若提交后出现，按状态
     完整性违例处理（S4 验收断言）。
  3. **求解顺序**：P1 重建占用索引时实际记录与投影记录同表（投影带标记）；
     跟车/准入查询两者都视为占用（后杠间隙照常）；§6.4 物理重叠校验只对实际
     车体记录执行。
- **依据**：`vehicle-following.md` §6.4/§7（占用桶/记录形状）；route-design
  §2.3 子合同 4；sample `transition_material.t01.occupancy_projection`。
- **分类**：公式与求解顺序 → **需 G1 决策**；「保守优先、无 stationing」的
  选型原则 → 可自决。
- **风险**：整边投影降低过渡区并行度（保守代价）；不得把双投影计为两辆车或
  两份容量（route-design §6.2 第 3 项口径）。

### 3.3 仲裁顺序落点

- **问题**：过渡进入仲裁在固定步进安全求解顺序中的位置。
- **提案**（对齐 `traffic-runtime-phase-protocol.md` P0–P8）：
  - **P3 资源请求**：过渡进入请求作为**组合资源 bundle**（源边 + 目标边 +
    过渡区边 + 下游清空区间），与 Waiting 本地预选、Conflict 请求同阶段提交；
  - **P4 确定性联合裁决**：all-or-nothing，基线为 C(T) + 较早成功 staged
    claims；同拍竞争按稳定顺序（live 序）裁决；no-grant = 在 `sl-t01` 前
    **等待**，不是错误；
  - **P5**：正式运动从 C(T) 计算，不在预览位置上提交；**P7**：原子提交
    （状态/资源/事件同一提交），车尾清空复用 Conflict 的真实车长清空判据；
  - 普通 successor（直行流）不进入该仲裁，保持原车道连续流语义。
- **依据**：phase-protocol §3（P3/P4 读写集、"本地预选先于 Conflict 请求"、
  all-or-nothing）；route-design §2.3 子合同 6/7。
- **分类**：**需 G1 决策**（执行顺序与新资源 bundle 语义）；no-grant=等待、
  失败原子 → 可自决（沿现行合同）。
- **风险**：不得另建第二套安全权威；必须与 Following/Signal/Waiting/Conflict/
  Parking 同一求解顺序落点，不得提前在 P2 预览里裁决。

### 3.4 快照形状

- **问题**：过渡阶段/预约/清空事实的持久化形状与版本影响。
- **提案**（对齐 `traffic-runtime-snapshot.md` §3/§6）：
  - 车辆记录新增 **tagged 过渡状态**：`PreEntry | InTransition | Clearing` +
    reservation wire row（acquired tick、源/目标/过渡区边 `StableId128` + 整数
    毫米区间并集、route occurrence 证明）；完整 reservation 只装入运行时
    权威（仿 Conflict 行），车辆不持副本；
  - 机动/门/等待/冲突出现项照旧**不入档**，恢复经目标修订重编译（ADR 0029 §6）；
  - 确定性状态摘要前像扩展过渡记录段；`runtime_state_version` 5→6 与摘要
    版本递增按版本轴规则**由 G1 定号**（未知版本失败关闭照旧）；
  - 恢复对称原则照旧：稳定引用 + 快照局部标识 + 整数毫米，无进程句柄/槽位/
    generation；恢复不重复 grant/事件。
- **依据**：`traffic-runtime-snapshot.md` §2/§3/§6（版本轴、每世界可变状态表、
  摘要前像）；ADR 0029 §6；route-design §2.3 子合同 8。
- **分类**：schema 形状与版本号 → **需 G1 决策**；持久化原则对齐（稳定引用、
  失败关闭、零部分恢复）→ 可自决。
- **风险**：摘要想定必须使「只改过渡阶段标签」与「改资源预约」产生不同摘要；
  恢复后 eligibility/reservation 必须复核，不允许凭旧 ordinal/修订复活。

### 3.5 #273 排除条件

- **问题**：#237 首版在什么条件下明确不需要 #273（共享 stationing/横向几何）。
- **提案**（确认性，`cross-section-access.md` §3.2.1 + #273 非目标一致）：
  1. 过渡以真实边物化且**完全落在显式 section 边界内**（整边界锚点）；
  2. 位置表达只用 edge-local 整数毫米 + route occurrence（禁百分比/最近点
     投影）；
  3. 占用投影采用整边保守公式（§3.2），不做跨 lane 位置映射；
  4. 不要求段级边界 identity。
  **触发登记 #273 为真实依赖的条件**（任一即登记）：任意纵向位置过渡；
  部分区间投影需要共享 stationing；出现长度百分比/跨 lane 进度换算诉求；
  段级边界锚点成为必要输入。
- **分类**：**可自决**（范围确认，#273 非目标已明文不阻塞首版）。
- **风险**：实现中若发现整边界语义不够用，必须回到本项重开，不得私下扩展。

### 3.6 跨层合同落地条件

- **问题**：route-design §3.4 六项共同输入如何转为正式契约。
- **提案**：把六项（含统筹附条件与裁决补修）落成**合同文本 + 逐项权威引用**
  （`cross-section-access.md` §5/§6 AccessRule 权威、锚点现行绑定语义、
  ADR 0025/0033 修订/制品绑定、边链身份限逐修订身份 + 文档化映射）；类型化
  schema 随 S1/S3 实现切片落地；凡现行模型不提供的保证逐条记入「生产 G1
  缺口清单」交统筹汇总，不静默假设。
- **分类**：合同文本与缺口登记 → **可自决**；类型化 schema → 随实现切片
  （届时如涉数据格式变更再走 G1）。
- **风险**：不得发明跨修订稳定 ID 语义；许可依据不得自造。

### 3.7 执行能力检查位置与拒绝语义

- **问题**：静态材料可先验证，但生产执行必须有能力检查并在不支持时拒绝——
  检查在哪、怎么拒绝。
- **提案**：
  - **检查位置（双层）**：① `register_route` 出现项编译期——若编译出的
    出现项含过渡而当前运行时不支持过渡执行，返回结构化错误、注册失败、
    注册表不变（与 route-system D5 失败原子一致）；② spawn/绑定期准入
    复核（与 (class, Route) 绑定期校验同位），防止能力/配置不一致；
  - **拒绝语义**：结构化错误类别（如 `TransitionUnsupported`）、失败关闭、
    零部分状态、不 warn-and-continue；能力声明放执行配置（不入快照，随
    WorldConfig 容量语义进摘要与否由 G1 定）；
  - 静态材料验证（S3 发射/校验）不依赖运行时能力，可先行。
- **依据**：route-system D4/D5（注册校验/失败原子）；裁决 3(b) 口径；
  快照 §2「执行能力校验」恢复链既有先例。
- **分类**：检查位置与能力声明形状 → **需 G1 决策**；失败关闭/结构化拒绝 →
  可自决（沿现行）。
- **风险**：能力检查不得被绕过（direct/candidate/cutover/restore/replay 全部
  入口统一，参照 `route_edge_occurrence_capacity` 的统一预算先例）。

## 4. S1/S3 切片设计框架

### 4.1 S1：展开器过渡感知扩展（converter）

- **输入**：过渡声明（来源 lane 对 + 过渡边界 + 最终边链，§3.4 第 4 项契约）。
- **语义**：仅在声明边界处允许来源 lane 转移，其余保持 `from_lane == 到达
  lane` 严格语义；无材料处 `lane-continuity-gap` 失败关闭不变。
- **契约同步**：`real-road-workloads.md` §3.1 措辞随 G1 修订（「禁止边内
  换道」→「仅在声明过渡材料处允许来源 lane 转移」）；`routes.toml` schema
  不变。
- **A0/A1 测试等值要求**（硬性）：
  1. A0 五组测试 + 修订后诊断测试 + A1 十组测试**逐项语义等值通过**（反例、
     连续对照、来源分域、人口身份/顺序/绑定、重复构建确定性、六类诊断分类）；
  2. 等值证明采用「旧入口、旧输入、既有结论不变」口径（协调章程 §2 共享
     改动行为等值范围同款）；任何既有断言变化必须单列理由并经审阅；
  3. 新增用例只增不改：样本 `s1` 三拓扑（gap/continuous-control/transition）
     为新增验收输入。
- **验收/拒绝**：route-design slice-plan S1 矩阵不变；拒绝面新增「无声明
  即转移」负例（在非声明边界改 lane 必须失败关闭）。

### 4.2 S3：过渡材料化与静态发射（compiler / authoring）

- **来源保真**：派生编制材料保存来源映射与构造依据，不冒充 SUMO connection
  （裁决口径）；合成来源为原生声明。
- **分段与锚点**：`B-up/TZ/B-down` 共延伸切分、T01 整数毫米长度、`sl-t01`/
  J2 门停止线重绑；边界不足/重叠失败关闭。
- **单一最终权威拓扑**：一份归一化输出同时供展开与静态发射（route-design
  §3.1）；LFCA/`SharedNetworkRevision`/digest 随同一修订产出。
- **几何发射预算实测口径**（A1 教训内建）：
  1. 以样本 `network` 钉版几何（T01 9.5 m 缓斜、I2 6.7 m）在**冻结提交 +
     固定工具链（Rust 1.99.1）+ 全新输出目录**实测发射，记录逐边结果；
  2. **失败处置**：逐字保留发射器错误原文（如 A1 的 weld-budget 曲率错误），
     归类为**独立几何问题**；不得修绿几何代码、不得提高预算、不得改写为
     路线物化失败、不得静默改钉版几何；
  3. 若需改几何，走样本 `meta.version` 递增 + changelog 说明，另行审阅；
  4. 实测属于 S3 实现切片执行期——本 G1 材料只冻结上述口径。
- **验收/拒绝**：route-design slice-plan S3 矩阵不变 + 来源保真与发射预算
  两条新增拒绝面（伪造来源、放宽预算混过）。
