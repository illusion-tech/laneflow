## 当前路径与旧假设

每组 512 × 128 = 65536 个车辆拍：

- 当前 signal Gate 解释次数为 **0**，Motion Conflict/Waiting 屏障扫描均为 **0**。
  `MotionReach` 在第一扇够不着的门退出，与后缀受控门数量无关。
- 显式 `reach=None` 的单次回放，全绿解释 16 / 256 / 4096 扇门；第二门红灯均
  解释 2 扇门。该回放说明旧算法为何会受长信号链影响，不能当作当前整步基线。
- 插桩到的二分调用共 16 × 65536 = **1048576 次/组**。计的是方法调用，不是
  比较次数、CPU 时间或全仓所有二分。2 次/车辆拍查询空 `speed_limit_drop`；
  剩余 14 次操作随路线增长的表。

| 基线 site                                                      | 每车辆拍调用 | 查询对象与语义                                                            |
| -------------------------------------------------------------- | -----------: | ------------------------------------------------------------------------- |
| `tick:1788`、`conflict_tick:45`、`tick:4009`                   |            3 | Waiting preview、P3 reach、Motion 拒绝门起点；P3 的跨边零点回看键可能不同 |
| `waiting:1449`、`waiting:1457`、`waiting:2950`、`waiting:3019` |            4 | Waiting traversal 的机动、Waiting、Gate 与机动首门定位                    |

| `conflict_tick:2059`、`conflict_tick:2062`                     |            2 | Conflict finalize 的 Gate 下界/上界                                       |

完整 site 清单与独立小夹具计数见 [diagnostic.log](evidence/diagnostic.log)。Waiting

核验 resource authority。它们补充近门/持有路径，不是长 Conflict 出现项扩容矩阵。
本组墙钟增长与更长定位表一致，但没有以受控整步 A/B 隔离其贡献，不能把全部差值
归因到上述 14 次调用。

## 构建、内存与原型

| 圈数 | 路线登记墙钟范围（ms） | 世界 owned bytes | 稠密原型额外 bytes |
| ---- | ---------------------: | ---------------: | -----------------: |
| 8    |          0.0071–0.0209 |           717341 |                600 |
| 128  |          0.0473–0.0535 |           755741 |               9240 |
| 2048 |          4.3380–5.8606 |          1370141 |             147480 |

登记包括正式路线编译，输入边序列构造不计入；世界 owned bytes 来自独立诊断的
现有 ownership ledger，不含共享静态根。长路线登记增长也值得留意，但本切片
没有把它归因为某个具体构建循环。

研究原型每个 hop 存六个 `u32` 拓扑下标，含末端哨兵。2048 圈额外约 144 KiB；
三轮/两种灯态构建为 0.245–0.691 ms。每批 262144 次、每次取六项的离散查询：
2048 圈二分为 11.838–13.202 ms，稠密读取为 0.359–0.382 ms。8 圈相应为
2.814–3.189 ms 和 0.363–0.424 ms。逐 hop 校验和两种查询 checksum 一致。

这些是测试构建的孤立查询回放：访问分布、缓存局部性与实际阶段不同，且本长路线
夹具的 Conflict 列为空；**不是可采用的整步加速数字**。不直接合入这个六列索引。
优先研究空跨越区间的精确短路；若仍需要索引，再缩到实际受益列并做普通构建 A/B。

原型不持有任何策略/信号/资源决定。它若由 `CompiledRoute` 所有，注册、换路线
注册、恢复和切换重编译时随新表构建；销毁旧路线即销毁旧表，不存在跨世代有效的
缓存条目。上面的构建代价也是全量重建代价，未单独量化生命周期端到端耗时。
跨阶段车级游标复用还须绑定完整 vehicle/route handle、同拍与 old/next position，
不能把 grant/held-resource 路径或边界回看覆盖掉。

## 正确性与决定

- 新增测试覆盖循环路线所有 hop 的起点、近门和边界，以及绿/红/黄灯；把当前
  有界信号查询与无上界结果的可达投影比较。它核验查询结果，不替代全步行为测试。
- 两个 class 与两个 policy 在相同近门位置、全绿下分别产生允许/拒绝结果，每次
  解释 1 扇门；不存在可跨 class/policy 共用的限制门结论。
- 完整 Runtime 单元测试和既有回归覆盖近门/跨边、资源持有、句柄代次、路线替换、
  snapshot restore、cutover、class 漂移拒绝、失败原子性和重试。本 PR 未改变
  `MotionReach` 截断规则，也没有把新索引接入交通执行。
- 原始证据以字节 SHA-256 绑定，Rust verifier 校验 18 组 × 128 拍、组身份、
  每组末状态核验值、诊断计数与索引行数，并拒绝缺行、重复样本和异常矩阵输入。
