# Frontier 单遍分类与 P5 资源标记整拍验证

本轮分别交付两个切片。P0-A 消除 Frontier 的全量 Active 计数，改为精确稀疏计数和
一遍窄字段分类。P0-B 在 P5 已有数据流内生成资源标记，Waiting 暂存后稀疏补充，
消除独立全量资源筛选。P0-B 普通整拍两个平衡顺序分别改善 3.02%、4.14%；P0-A
分别改善 0.06%、1.26%，尚不能认定有稳定收益。16 ms 和持续十万 Active 仍未达标。

P5 每拍分别产生 73292.832 行冻结义务标记和最终几何标记，规范消费形成
2827.684 个候选。Waiting 后只考虑 16.387 个实际控制覆盖，本窗口新增候选为零：
真实成员取得已经被冻结的 Waiting 计划标记覆盖。稀疏补充仍保留，专门测试覆盖
P5 未标记而收尾新增成员的情况，不能据本窗口的零观测删除它。

筛选时间已经包含在 ConflictFinalize，Frontier 已包含在 WaitingOutputs，不能再次
相加。P5 标记的抽样线程耗时之和为 0.149–0.162 ms/拍，仅抽样部分物理块且包含
probe 成本，不能外推为整拍墙钟或净节省。不同字段接口执行的身份/计数 probe
次数不同，诊断也有成本。P5Dispatch 的上升见证了成本转移；普通净收益只取上述
独立 ABBA/BAAB，不把原 1.30 ms 全额减到普通 mean/p95。

## 正确性与交付

Frontier 容量仍按精确 Active 数预留，同一行控制覆盖唯一且重复写回替换原项。
完整车辆/路线 generation、游标、进度、速度和状态直接读 Next 与稳定上下文。
所有 Next 都参与分类，资源名单不限制近门或缓存失效发现；不宣称旧逻辑值接口
必然发生完整结构复制。

P5 只生成保守标记，完整预览复用与计算路径都覆盖；完整 join 后仍在原位置消费
首错、实际到达 reserve 和控制分配。Waiting 暂存后的补充只扫描实际控制变化，
去重并保持规范顺序和既有容量。静态 Waiting maneuver 位按路线出现项登记，循环
物理边不折叠；缺失材料保守保留，不提前返回领域错误。资源 owner/generation、
全部 grant 消费、passage 配对、事件剩余项与失败重试检查保留。

测试 oracle 在 Waiting 暂存后逐行核对旧完整筛选谓词，独立于新标记和静态位。
不分配临时列表，覆盖边尾、零进度回看、成员、Clearing、grant、资格及完整生命周期。
完整 release + placement 回归的 544 个单元测试及相关集成测试、数值内核十个测试、
研究工具 121 个测试、check、Clippy、格式、架构与新头导出锚点通过。
三个隔离负向变体分别漏掉普通 Frontier、仅按 cursor 筛选、漏掉 Waiting 补充；
原测试和冻结执行文件复跑都返回预期 101。原源码、变体、执行文件和日志全部保留。

开发中发现的 oracle 临时分配、边界夹具错误和静态容器预算回归均修复，失败日志
保留；预算测试保持原门槛，位图登记后使用固定切片。一次不存在的 Cargo alias
未执行架构检查，随后用真实 xtask 命令通过，原日志和更正收据保留。
