# 资源收尾工作集：整拍对照与完整性验证

本切片将 Conflict 收尾、Waiting 非入口决定发现和事件访问连接到同一份规范有序
工作集。对上一版列式实现，两组普通整拍均值分别降低 **9.88%、9.40%**，约
23.6–23.7 ms → 21.4 ms。同期旧 AoS 对照均值也改善，但两臂有明显慢进程，
只能作为完整方案出现收益的候选证据；#814 / #815 保持研究与草稿状态。

- 本切片源码：`22da2c7cc75fde6c1434f9b0a53c8133bff1213c`；上一版：
  `902ac9bfeacd9158861808408039a4d695c74a90`；旧 AoS：
  `cbfbb14a714d819cd5e608a1b759575d378f3d53`。

  同提交。每组对照的环境、Rust/Cargo、原生工具链与收集器五项构建身份一致。
- Rust 1.98.0、release / locked / offline、默认全局目标特性，列式臂 AVX2。
  MIXED-PEAK seed 544；100000 总车辆，初始 75000 Active、25000 Parked；
  workers=4、dt=33 ms；每进程 256 拍、无预热。

- 16 个普通进程和 6 个独立诊断进程全部匹配独立 AoS 的 commands、events、ticks、
  resolved plan、checkpoint、初末计数和原子拒绝；所有载荷摘要与字节数核验通过。

## 4. 完整性与失败语义

筛选保留跨 occurrence、边尾 Gate 决定、零进度旧 Gate 回看、旧新 Waiting/traversal、
Waiting/Conflict 计划、资格与完整句柄 reservation；旧 traversal 为空但位于 Waiting
maneuver 内也保留。缺失路线或边长交回原阶段验证。全部 grant 消费、passage 转移
及剩余事件校验保留；完整 join、规范首错、真实停车 reserve 与提交边界不变。

行号容量在 P5 求值前按实际 Active 数 fallible 准备，attempt 结束清空复用。
它属于 scratch，不复制资源权威；零/非零容量计量及丢弃后容量复用测试通过。
没有公开 API、静态格式、快照或 Adapter 合同变更。

- Runtime release / placement 单元测试 539 项通过，20 项手动探针保持 ignored；
  相关集成与文档测试通过。motion-kernel 10 项、研究工具 121 项通过。
- Waiting、Conflict、信号三种完整生命周期及失败重试轨迹与强制完整遍历一致；
  既有固定轨迹、Gate 边界投影、资源账本、参与/并发、首错与分配回归通过。
- fmt、相关 all-targets release Clippy（`-D warnings`）及冻结新头的诊断导出锚点通过。
- 隔离源码将生产筛选弱化为 cursor-only，专门回归返回 101；冻结测试程序重复返回
  101。原生产源码未改动，原件、变异源码、程序与日志均保留。
- 诊断启动脚本一次拼接错误发生在原生进程启动前；修复前原生记录为零，原脚本与
  错误保留，六个既定诊断序号均只执行一次。
