## 3. A4 正式设计骨架（核心义务）

### 3.1 现状基线（设计义务起点，非缺陷认定）

`tick.rs:4528` `hop_gate_permitted`：`compiled.hop_gate[hop]` 为 `None` 时
**直接返回 `true`**（无门 hop 无条件放行）；有门时仅查 Gate 策略。该现状是
A4 设计义务的起点——新增 successor/过渡本身不产生换道安全能力。

### 3.2 预约模型：约束所有潜在进入者（裁定语义）

- **过渡预约**（P3 组合资源 bundle）：源边区间 + 目标边区间 + 过渡区边
  （含共横向投影边）+ 下游清空区间；以 all-or-nothing 申请（A3）。
- **P4 裁决义务（裁定核心）**：不得只检查拍初过渡区为空。对每个被预约区间，
  P4 必须纳入**全部潜在进入者**：
  1. 过渡区内及其上游/下游当前车辆（现状占用）；
  2. **源/目标车道上尚未进入共享区的接近车辆**——按其路线前视与运动可达
     范围（`MotionReach`/前视窗）判定预约有效期内能否到达被预约区间；
  3. 对可达者追加**制动约束证明**：在其当前速度/profile 制动能力下能否在
     区间外安全停住或按让行规则避让；
  4. **任一潜在进入者无法证明安全 → 该预约申请 no-grant**，换道车在
     `sl-t01` 前等待（等待非错误、非非法路线）；证明责任在换道申请侧。
- **P5 遵守义务**：普通直行运动（含**无门 hop**）必须遵守当拍已取得的预约；
  hop/运动许可在既有 Gate 检查之外增加「与当拍 committed/staged 预约不冲突」
  约束（`hop_gate_permitted` 的 `None => true` 分支须补预约判据）。直行车不得
  以无门为由穿越被预约区间。
- **双保险结构**：P4 证明（申请侧义务）+ P5 遵守（所有进入者义务）；二者缺一
  不得放行。

## 4. A5/A6 回写要点

- **A5（snapshot 增补）**：车辆记录 tagged 过渡状态 + reservation wire 行；
  **三轴版本分别说明**——LFRS 7→8（容器：车辆记录新增过渡状态/预约行槽位）、
  runtime state 5→6（状态形状扩展）、digest 8→9（规范前像扩展过渡记录段）；
  核对编号与版本轴分离规则（snapshot §2：容器版本与事实版本不混用单号）。
  **首版限制**：活动过渡或持预约世界**拒绝跨修订切换**（保留旧世界、零部分
  提交）；迁移后续设计，能力限制记入 G-E 处置（更新登记）。
- **A6（选项 3）**：不新增配置字段；换道支持能力属**实现能力**；不支持时在
  路线注册 / 车辆准入 / 恢复入口结构化拒绝（`TransitionUnsupported` 类、
  失败关闭、零部分状态）；不加 WorldConfig、不扩义 ExecutionConfig；逐世界
  行为需求出现时独立设计。D5 验收归属注记照旧（S3 静态验证 + 拒绝断言；
  注册成功在 S4）。
