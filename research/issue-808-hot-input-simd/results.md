# 直接热输入与稀疏 SIMD：未获可重复整拍收益

对应 #808。全部 36 个进程完成且重验证通过，三臂交通记录和逐拍状态摘要一致。
十万筛选窗 SIMD 的整步均值比基线高 **6.821%**，只有 **1/3 组**改善；
一万平均进程 p95 回退 **5.462%**。十万最大组内同臂均值跨度达 **19.408%**，
本批次存在明显波动。`continue_candidate=false`：停止这版候选接入，不追加正式长窗。
这证明本轮没有建立可重复收益，不能据此断言所有 SIMD 或热布局都会变慢。

## 冻结来源与实际改造

- 正式基线：`fcd803f2cb28ba7a94f3f0ff589e7e9b7bdbd7d3`。
- 实际采集器、导出补丁和采集提交：`70bfbffbdbb35aafede89fdc63f738b62d918da8`。
  #807 已通过 Merge Queue 的 Rebase 方式合并；本 PR 只将 #808 提交移到主线，
  没有替换已采集的源码、二进制或基线。原采集提交由
  `codex/808-hot-input-source-freeze` 保留；报告在采集之后提交。
- A=`base` 原 P5；B=`layout` 直接热输入标量；C=`candidate` 同布局稀疏 SIMD。
  三臂均使用普通 release、Rust 1.98.0、locked/offline、workers=4，默认目标特性；
  没有全局 AVX2、FMA、fast-math 或近似倒数。研究 SIMD 依赖为 `wide = 1.5.0`。
- 当前主机观察为 AMD Ryzen 9 9955HX，16 核 / 32 逻辑处理器，Windows x64 MSVC。
  [host.json](evidence/host.json) 记录采集后的主机观察；没有连续测量功耗或温度。
- 直接按 Compute 通道写七个热字段数组，移除 `[IidmInput; 4]` 中间数组和冷准备值内的
  IIDM 副本。内核借用数组；全复用批次不初始化/调用 IIDM，不足两个可向量化通道时
  用标量。复用结果与计算冷字段分开，尾批和异常输入保留原语义。
- 布局臂包含公共运动原语的 prepare/finish 拆分以及 P5 批量组织；融合路径和 Waiting
  预览仍走标量包装，但也经过该拆分。不能把 B/A 差异单独归因于 P5 输入收集。
  原型只存在于独立导出树，正式 Runtime、API、格式和 Accepted 并行合同未变。

## 方案与完整矩阵

使用冻结 MIXED-PEAK 输入，seed 544。一万总车辆初始 7500 Active / 2500 Parked、
固定步长 16 ms；十万初始 75000 Active / 25000 Parked、33 ms。每进程 256 拍，
无预热；全窗 1–256、进入窗 1–64、筛选窗 65–256 分列。每规模三组六进程，
`ABC CBA / BCA ACB / CAB BAC`，每臂每规模六进程。构建与回归完成后串行采集，
没有选择性重跑、删除轮次或改变继续条件。

## 内核与暂存诊断

独立诊断在完整采集后执行一次：一个进程内三组轮转，每条计时 409600 辆，
计时前已收集输入，四个通道均使用。**不包含收集、准备、join、结果消费或提交**，
也没有测量实际交通中的向量通道利用率。九条记录全部保留，摘要均为 `787082915329000`。

| 实现             | 三条计时平均 ns / 辆 |
| ---------------- | -------------------- |
| 原逐车标量       | 5.133626             |
| 预收集热输入标量 | 4.000163             |
| 预收集借用 SIMD  | 3.723226             |

同布局 SIMD 在这个诊断中比标量快 **6.923%**；这是一次稠密、预收集内核诊断，
不是稳定整拍吞吐结论。原标量与批量实现还包含检查位置差异，不能把全部差值归于 SIMD。
实际汇编确认候选有 `divps` / `mulps` packed 算术；标量臂对应内核没有 packed 算术。
候选同时保留标量回退，未见 FMA。完整汇编和函数片段均在归档中。

实际 `size_of`：单车 IIDM 输入 40 字节，热批次 280，计算冷准备值 288，
复用/到达元数据 128。四个冷槽为 1152 字节，四个结果准备槽为 512，
可选热批次为 280，三个静态组件合计 **1944 字节**；此外还有内核结果、局部量与调用帧。
分离后返回的准备元数据较小，但不能仅比较 128 与旧 368 就声称栈占用降低。
本轮没有新增逐批堆分配；没有测量实际栈峰值或证明保留内存下降。
plain 输出的 `peak_storage` 零值是关闭诊断后的占位，不作为内存测量。

只把 IIDM 参数改成连续数组，仍保留公共原语拆分、冷准备/返回、路线投影、掩码和
结果消费。内核改善不足以证明这些整拍成本已被消除；本轮也没有独立拆分它们的贡献。
下一份实验应先增加“仅公共原语拆分”的对照来定位成本，随后再冻结 P2–P5 共享热输入
或更大的批量流水线。跨拍权威、槽位代次/修订/恢复/失败失效规则，以及 P4 资源依赖
仍需另行设计和验证；[整拍数据流](data-flow.md) 保留了各阶段可研究方向。
