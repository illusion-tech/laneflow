## 1. 目标与边界

首版只覆盖**固定预制过渡**：出发前确定完整实际边链，横向转移经由以真实
`LaneEdge` 物化的过渡段（§3）执行，其安全由本合同 §5 的预约约束证明。

明确排除（首版）：潮汐/可逆车道、动态 lane-use 全集、自由在线选道、活动车
改 Route、任意位置横向转移、全量 `ResolvedLanePlan`、部分区间投影与共享
stationing（依赖 #273）。备选固定受控连接区不属本合同（独立 G1，见
`road-junction-model.md` §17.4）。

执行序（维护者裁定）：**本合同（含 §5 A4）完成并冻结 #237 后，方可 S1/S3
实现立项**。本合同不改生产代码；`tick.rs` 引用只定义设计义务，不作缺陷认定。

## 2. 术语

- **固定预制过渡**：带中心线真实 `LaneEdge` 物化的横向转移段（如 `T01`）。
- **过渡预约**：对源区间、目标区间、过渡区边（含共横向投影边）与下游清空
  区间的一组组合资源请求（§5.1）。
- **潜在进入者**：预约有效期内可能进入任一被预约区间的车辆——含过渡区内及
  其上/下游车辆、**源/目标车道上尚未进入共享区的接近车辆**。
- **实际车体记录**：按车辆实际路线位置与车长产生的占用记录
  （`vehicle-following.md` §7）。
- **投影记录**：过渡期间对共横向边附加的保守占用记录（§4），带投影标记。

## 3. 承载形式（裁定 A1 回写）

1. 固定预制过渡以**带中心线真实 `LaneEdge` + 普通 successor** 物化
   （如 `B0_up→T01→B1_down`）；必要分段同切全部同向 lane（`lane 纵向共延伸`
   不变量，`cross-section-access.md` §3.2）。
2. **来源保真**：过渡边为经授权规则派生的编制材料时，必须保存来源映射与
   构造依据，**不得冒充原 SUMO connection**；合成来源为原生声明。
3. 身份按**逐修订身份 + 文档化映射**登记（不发明跨修订稳定 ID，G-A）。
4. 路线物化为显式边链（如 `[A0, I1, B0_up, T01, B1_down, I2, C0]`）；
   `register_route` 静态序列合同不变（普通 successor 即满足相邻校验，无新增
   注册校验类别）。注册成功只证明静态合同，不证明换道安全（`route-system.md`
   D4 分层）。

## 4. 占用分类与投影（裁定 A2 回写）

**整边保守投影（v1 基线）**：车辆占用过渡边期间，在同区共横向边各记一条
**全长保守投影**记录（`lo_mm=0`、`hi_mm=length`，带投影标记）；不做跨 lane
位置映射（免共享 stationing，G-B 规避）。投影不计为第二辆车或第二份容量。

分类处置表（按 `vehicle-following.md` §6.4 同则分档，**非一律完整性违例**）：

| 记录对                      | 处置                                                                                                                  |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 本车 ↔ 本车（含自身投影）   | 自排除（`VehicleHandle`）                                                                                             |
| 实际车体 ↔ 实际车体（异车） | §6.4 分档：负 gap 超物理阈值 = 非法重叠；阈值内归零接触；仅违反 `min_gap` 的输入仍合法                                |
| 投影 ↔ 实际车体（异车）     | 同 §6.4 分档：超阈值 = 须由 §5 预约约束阻止（committed 后出现按状态完整性违例）；阈值内归零接触；`min_gap` 档不判非法 |
| 投影 ↔ 投影（异车）         | 保守重叠合法（整边投影固有）；只影响准入与跟随间隙判定，不判非法重叠                                                  |

投影记录参与跟车/准入占用查询（视为占用，后杠间隙照常）；物理重叠校验只对
实际车体记录执行。

## 5. 同拍联合求解与预约约束（裁定 A3/A4 回写，核心）

### 5.1 预约对象与生命周期（四态）

过渡预约 bundle = **源区间 + 目标区间 + 过渡区边（含共横向投影边）+ 下游
清空区间**，all-or-nothing 申请。

| 态                  | 进入时机                         | 权威位置           | 退出条件              |
| ------------------- | -------------------------------- | ------------------ | --------------------- |
| 申请（requested）   | P3 提交组合 bundle               | 请求结构（W 准备） | P4 裁决               |
| 暂存授予（staged）  | P4 all-or-nothing grant          | staged claims（W） | P7 提交或本拍失败丢弃 |
| 已提交（committed） | P7 原子提交（含 acquired tick）  | C(T+Δ) 预约权威    | 车尾清空              |
| 释放（released）    | `rear >= clearance` 真实车尾清空 | —（无残留）        | —                     |

no-grant 不留痕；失败拍丢弃 staged、保留 committed。

### 5.2 P4 潜在进入者约束（A4 核心：新预约约束所有潜在进入者）

裁决过渡预约申请时**不得只检查拍初过渡区为空**。对每个被预约区间，P4 必须：

1. 枚举**全部潜在进入者**：过渡区内及其上/下游当前车辆（实际车体记录），
   以及**源/目标车道上尚未进入共享区的接近车辆**；
2. 对接近车辆按其路线前视与运动**可达范围**（`MotionReach`/跟车前视窗）判定
   预约有效期内能否到达被预约区间；
3. 对可达者追加**制动约束证明**：以其当前速度与 profile 制动能力证明可在
   区间外安全停住或按让行规则避让；
4. **任一潜在进入者无法证明安全 → 该申请 no-grant**，换道车在 `sl-t01` 前
   等待（等待非错误、非非法路线）；**证明责任在换道申请侧**。

### 5.3 P5 遵守义务（无门不豁免）

普通直行运动（含**无门 hop**）必须遵守当拍已取得的预约（committed +
本拍 granted）：hop/运动许可在既有 Gate 检查之外增加「与当拍预约不冲突」
判据。现行 `tick.rs:4528` `hop_gate_permitted` 的 `None => true`（无门 hop
直接放行）是**设计义务起点，非缺陷认定**；义务履行后无门 hop 不得以无门为
由穿越被预约区间。

**双保险结构**：§5.2（P4，申请侧证明）+ §5.3（P5，全体进入者遵守），缺一
不得放行。P5 运动从 C(T) 计算（预览无提交权）；P7 状态/预约/事件单次原子
提交，车尾清空用真实车长判据（`rear >= clearance`，不随车头离开释放）。

### 5.4 读写关系

| 阶段 | 读                                                                   | 写                                                         |
| ---- | -------------------------------------------------------------------- | ---------------------------------------------------------- |
| P3   | C(T)（占用索引含投影、committed 预约、profile/路线）、D(T)、局部意图 | 过渡预约请求 bundle（含潜在进入者清单与可达/制动证明输入） |
| P4   | C(T) 资源基线、D(T)、请求、较早成功 staged claims                    | `ResolutionBatch`：grant/no-grant、资源 stop（只写 W）     |
| P5   | C(T)、裁决、拍初信号、**当拍预约集（committed + granted）**          | 最终 next states、实际 crossing、转移、事件（W）           |
| P7   | 绑定同一基线的计划                                                   | C(T+Δ) 原子提交（状态/预约/事件同一提交）                  |

预约与 Waiting/Conflict 的组合资源仲裁同一求解顺序、同一安全权威（
`traffic-runtime-phase-protocol.md` §3；复用 Conflict 的 committed +
earlier-staged claim 与车尾清空原语，不另建第二套安全权威）。

## 6. 能力检查（裁定 A6 = 选项 3 回写）

1. 换道支持能力属**实现能力**，**不新增配置字段**：不加 `WorldConfig`、
   **不扩义 `ExecutionConfig`**（#302/#303 冻结边界：执行配置仅 worker 数，
   不进交通身份；扩义方案已排除）。
2. 运行时不支持过渡执行时，**结构化拒绝**（`TransitionUnsupported` 类、
   失败关闭、零部分状态）于三类入口：路线注册（`register_route` 出现项
   编译期，注册表不变）、车辆准入（绑定期复核）、恢复（零部分丢弃 staging）；
   全部入口统一（direct / candidate / cutover / restore / replay）。
3. **验收归属**：静态侧只做独立静态序列验证 +「执行不支持时注册被拒」断言
   （S3）；含过渡路线的注册成功与注册表原子性验收在能力落地后（S4）。
4. 逐世界行为需求（如按世界选择交通行为）出现时独立设计；届时方可考虑
   WorldConfig 方案（选项 1），不静默启用。

## 9. 持久化与版本轴（裁定 A5，权威定义见 snapshot 衔接注记）

- 车辆记录 tagged 过渡状态（`PreEntry | InTransition | Clearing`）+ 预约
  wire 行（acquired tick、源/目标/过渡区边 `StableId128` + 整数毫米区间并集、
  route occurrence 证明）；完整预约只装运行时权威，出现项不入档（恢复重编译）。
- **三轴版本分别升级并核对编号**：LFRS **7→8**（容器：过渡状态/预约行槽位）、
  runtime state **5→6**（状态形状扩展）、digest **8→9**（规范前像扩展过渡
  记录段）；容器与事实版本不混用单号（snapshot §2）。
- **首版限制**：活动过渡或持预约世界**拒绝跨修订切换**（保留旧世界、零部分
  提交）；迁移为后续设计并登记能力限制（G-E 更新）。

## 10. 排除、能力限制与缺口

- 首版排除清单见 §1；能力限制见 §9（跨修订迁移）与 §6（选项 2 扩义
  `ExecutionConfig` 永久排除，除非 #302/#303 边界另行修订）。
- 缺口登记沿 G-A…G-F（G1 决策包 §四）：G-A 逐修订身份（§3.3 落地）；G-B
  整边投影规避（§4）；G-C merge/diverge profile 缺（备选启用前必须补齐）；
  G-D 不适用（A6 裁定选项 3，无 WorldConfig 扩项）；G-E **更新**：活动过渡/
  持预约世界跨修订迁移或拒绝，首版取拒绝，迁移后续设计；G-F 诊断升格另评。
