# 编译器资源账本

> **状态**：Proposed（[#1296][issue-1296]，随 [ADR 0035][adr-0035] 修订一并评审）<br>
> **日期**：2026-11-16<br>
> **决策依据**：[ADR 0035][adr-0035]；[编译器基础 §5.3][compiler-limits]

## 1. 目标与非目标

**编译器资源账本**（compiler resource ledger）是 `laneflow-compiler` 内全部受控分配的唯一
记账入口。它对照所选配置档的宿主预算，在分配前拒绝超出预算的计划，并把计划与实际
分配在结构上绑定。

本设计提供：

1. 编译、发射与公开检查共用的账本模型：顶层操作划界、计划准入与预留守恒、授予与
   存储绑定、释放、报告封存与预算耗尽后的错误出口；
2. 现有各阶段计量结构到账本的迁移映射；
3. 发射与差异发射的计划口径，使发射阶段首次纳入宿主预算；
4. 账本一致性检查、报告量与分步合入条件。

本设计不提供：

- 新的限额维度。限额只有容量维度、制品容量与宿主预算维度，见 ADR 0035 第 1 节。
- 分配器级证据。进程堆峰值、分配次数与驻留集继续由 `stats_alloc`、`dhat` 与
  [操作系统计数器读取][os-probe] 在测量入口承担；账本报告的是受控请求字节（第 3.5 节）。
- 计算量约束。按容量维度累计遍历工作量的预算（如 MIR 策略校验的 `WorkBudget`）不变。
- 磁盘预算。单次发射写入暂存目录的磁盘总字节不是编译器资源预算，见第 6.3 节。
- 公开接口。账本是包内私有结构，公开面只新增报告量（第 7 节）。

## 2. 现状

调研基于 `051f515a`。

| --------------------------- | ----------------------- | ------------ | ---------------- | ------------------------------------------------------- |
| `AdmissionTotals`           | 共同模块准入            | 每模块准入前 | 容量维度、存续   | 存续累计与其余阶段各自独立                              |
| `DomainBudget`              | HIR 构建计划            | 开工前计划   | 暂存、存续       | 计划 148 处按类型折算，分配写在各领域文件，只靠约定对应 |
| MIR、LIR 计划               | `mir.rs`、`lir/plan.rs` | 开工前计划   | 暂存、输出、存续 | 各自手工累加上游阶段存续                                |
| `SourceMapSizing`           | 源映射冻结              | 开工前计划   | 暂存、输出、存续 | 同上                                                    |
| `PreflightScratch`          | 道路编辑借用预检        | 逐次分配前   | 暂存、存续       | 最接近目标形态，但只服务一个前端                        |
| `GeometryScratch*` 三个结构 | 道路编辑几何编译        | 逐次分配前   | 暂存、存续余量   | 与预检各写一套                                          |
| `Scratch`                   | 发射器、公开检查        | 边分配边记账 | 仅暂存           | 不计存续；对象树、编码缓冲、内存对象字节与差异映射未计  |

HIR 计划、MIR、LIR 与源映射冻结各定义一份同名的 `requested_bytes` 字节折算函数，非测试代码
共 316 处调用。HIR、MIR、LIR 与源映射冻结各自把编译单元、上游阶段存续、本阶段拥有存储
与暂存手工相加后核对 `CompilerControlledLiveBytes`；发射器在生成候选后直接调用公开的
`check_portable_policy_sources` 与 `check_portable_policy_diff`，两者各自新建暂存计量器，
且发射与检查都不核对存续。

## 3. 账本模型

### 3.1 账本按顶层操作划界

账本的边界是**宿主发起的顶层操作**：一次 `CompilationUnitBuilder` 准入过程、一次
`Compiler::compile`、一次发射，或宿主直接调用的一次公开检查入口。顶层操作内部调用的
任何逻辑不新建账本，只在父账本上取得子编译遍预算；本次操作已生成且仍存活的对象在
内部调用期间持续计入父账本。

公开检查入口是“新建检查账本 + 调用内部检查实现”的薄包装；发射以自身账本直接调用
同一内部实现。检查器仍从最终字节独立建立语义检查视图，ADR 0024 的检查独立性只约束
语义视图，不受资源归属方式影响。

| 账本     | 顶层操作                                                                                  | 初始存续                                                   |
| -------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 准入账本 | `CompilationUnitBuilder` 从创建到冻结编译单元；每次 `add_*` 或 `build` 是其中一次准入调用 | 零                                                         |
| 编译账本 | 一次 `Compiler::compile`                                                                  | 编译单元的受控存续：编译单元按值移入，其存储由本次编译拥有 |
| 发射账本 | 一次 `emit_portable_candidate` 或 `emit_portable_candidate_to_staging`                    | 零：`CompilationOutput` 与差异 base 字节由调用方借出       |
| 检查账本 | 宿主直接调用的一次 `check_portable_policy_sources` 或 `check_portable_policy_diff`        | 零：调用方字节借出；发射内部的检查不建检查账本             |

每个账本绑定一份 `CompileLimits`，只读取其中的宿主预算维度。外部输入的归属：

- **按值移入**的存储由本次操作拥有，计入初始存续。冻结编译单元时，准入账本的存续随
  编译单元转为编译账本的初始存续。
- **借出或共享引用延续**的存储（`&CompilationOutput`、调用方字节、对既有 `Arc` backing
  的浅克隆）不计入；本次新建的容器计入，容器内借用的载荷不重复计入。
- **复制或驻留**进本次操作的载荷按新存储计入。

**准入调用。**准入账本跨越 builder 的整个生命周期，持有已准入模块的存续；每次
`add_*(&mut self)` 或 `build` 在其上开启一次准入调用，按本次 candidate 求计划。某次
`add_*` 失败只结束本次准入调用：本次 candidate 与临时工作存储释放或随诊断转交宿主
（第 3.6 节），已准入模块及其账本状态保持不变，与[编译器基础][compiler-foundation-context]
中“失败不改变已提交的索引和计数、caller 保留旧 bundle 时同一 builder 可重试”的合同一致。

**口径。**编译账本的初始存续包含编译单元，与 `051f515a` 各阶段存续总量中的
`unit.controlled_live_bytes` 口径一致。发射与检查账本是新增口径：`051f515a` 的发射路径
不核对存续。报告与证据比较新旧峰值时须注明口径；继承相同的宿主预算数值不意味着继承
相同的工作集约束。

### 3.2 计划

每个编译遍在任何与计数成正比的分配前，由一个纯函数按实际计数求出本遍**计划**：

- **计划峰值** `P`：本遍名下同一时刻存续的授予字节之和的上界，即本遍输出与工作集之和；
  工作集内互斥的子阶段取峰值。计划表达峰值，不表达历次申请的总量。
- 计划只依赖已经过容量准入的计数，不读取配置档，不分配内存。

计划字节按授予请求的受检 `Layout` 累加（第 3.5 节）；哈希表按现有保守桶倍率计入。全部
乘加使用受检算术，无法表示时按宿主预算超限处理，观测值记为 `u64::MAX`。同一份计划函数
既用于运行时准入，也用于自洽检查求峰值；不存在第二份等价算术。

### 3.3 准入与预留守恒

账本维护两个量：存续 `L`（已授予且尚未释放的受控请求字节）与预留 `R`（已准入、尚未
转为存续的额度）。任何时刻满足

```text
L + R ≤ B
```

其中 `B` 是 `CompilerControlledLiveBytes`。一个编译遍预算持有自己的计划峰值 `P` 与在用量
`U`（本遍名下同时存续的授予字节），满足 `U ≤ P`；本遍尚未消费的额度 `P − U` 计入 `R`。

| 操作                   | 效果                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------- |
| 准入编译遍计划         | 检查 `L + R + P ≤ B`；成立则 `R += P`，否则按宿主预算拒绝，此时尚未分配               |
| 准入子编译遍计划       | 从父编译遍未消费额度中划出 `P_sub`；超出父额度属记账缺陷                              |
| 授予 `n` 字节          | 要求 `U + n ≤ P`；成立则 `R −= n`、`L += n`、`U += n`；不成立属记账缺陷，不分配       |
| 分配器拒绝已授予的请求 | 回滚该授予：`L −= n`、`R += n`、`U −= n`，返回分配失败                                |
| 释放本遍存续的存储     | 存储实际释放后 `L −= n`、`U −= n`、`R += n`：额度回到本遍，可再次授予                 |
| 输出转移               | 编译遍结束时本遍输出转为账本的输出存续，留在 `L` 中、不重复记账，后继持有者释放时归还 |
| 编译遍结束             | 未转为输出的授予必须已全部释放；退还 `R` 中本遍剩余额度                               |
| 取消或错误返回         | 预算随作用域结束退还未消费预留；已授予的存储随所有者析构释放并归还                    |

同一账本同一时刻只有一个活动的顶层编译遍预算，子预算按栈嵌套，因此不会出现两个
已准入、尚未消费的同级计划各自通过准入的情形。512 B 暂存申请、释放、再申请一次，
本遍 `U` 的峰值是 512 B；与计划峰值比较的是 `U`，不是历次申请总量。

### 3.4 授予与存储绑定

授予直接驱动分配并随存储持有：

- 受控存储只能由账本存储入口创建（定长序列、定长切片、字节缓冲、按上界预留的哈希表
  等），入口以授予的元素类型、数量与受检 `Layout` 发起分配请求；不存在“先扣字节、
  调用方再另写 `with_capacity`”的两步流程。具体 Rust 类型由实现决定。
- 存储的可用逻辑容量受授予约束，不得自行扩容；扩容、深复制与新增嵌套存储各需新的
  授予。`Vec<String>` 一类结构的外层授予不覆盖内层载荷，内层载荷逐项授予或集中到一个
  有授予的字节区。
- 共享 backing 的浅克隆共用一份授予；任一句柄释放不归还额度，最后一个句柄释放时归还。
- 移动存储所有权不改变计费：授予随存储移动，不重复记账，也不提前归还。
- 存储形态转换先取得新存储的授予，旧存储释放后归还，计划覆盖转换期间新旧存储的共存。
  例如 `ImmutableObjectSource::from_boxed_bytes` 的 `Box<[u8]>` 转 `Arc<[u8]>` 会建立新的引用
  计数分配并复制载荷。

### 3.5 计量口径

账本计量**受控请求字节**：授予请求的受检 `Layout` 大小。分配器内部开销与分配器可能
多给的容量不计入，由分配器层证据衡量。账本不对容器实际 `capacity()` 作硬上界承诺：
`try_reserve_exact` 只保证不为未来增长多预留，分配器仍可能提供更多空间。一致性检查
核对的是：分配请求的类型、数量与 `Layout` 来自已准入授予，容器的可用逻辑容量不超出
授予。

### 3.6 返回点转交与报告封存

顶层操作或准入调用终止时，`Ok` 与 `Err` 返回值接管的存储都在返回点**显式转交宿主**：

- `Ok`：编译输出、发射候选等返回值的存储。
- `Err`：失败不返回部分 LIR 或制品候选，但返回拥有存储的诊断集合，包括诊断数组的外层
  存储，以及移入诊断集合、此后只由它持有的 candidate context 等存储。

转交按授予逐项执行：该授予的额度从 `L` 中移出，记为**转交宿主**；宿主持有期间不计入后续
调用，再次按值移入编译器时（如 builder 返回的 `CompilationUnit` 传入 `Compiler::compile`），
按第 3.1 节计入接收账本。转交与释放是两种结果：转交的存储仍然存活，不得记为“已释放”，也
不得为满足结束检查而提前归还。诊断集合对账本仍持有的共享 backing（如 builder 已准入
模块的 context）只复制句柄，按第 3.4 节共用一份授予，该授予留在原账本，不转交。

结束检查：

| 账本或调用               | 终止时须满足                                                                      |
| ------------------------ | --------------------------------------------------------------------------------- |
| 编译、发射、检查账本     | 转交之后 `L = R = 0`；其余授予均已释放                                            |
| 准入调用（`add_*`）      | 本次调用的预留全部退还；`L` 只剩已准入模块的存续，未转交的 candidate 存储均已释放 |
| 准入账本（`build` 成功） | 已准入存续随编译单元移入编译账本（第 3.1 节），转交之后 `L = R = 0`               |

返回点同时封存资源报告，分别记录**已释放**与**转交宿主**的字节；报告中的存续峰值不因
转交而改写。

### 3.7 外部字节准入

差异 base 与公开检查入口接收的调用方字节，在格式预检之后、计划准入之前按 ADR 0035
第 4 节的制品容量准入；计划所用的行数、字节数只取自已通过制品容量准入的受检视图。

## 4. 错误与诊断

| 情形                     | 编译路径                                     | 发射与检查路径                                               |
| ------------------------ | -------------------------------------------- | ------------------------------------------------------------ |
| 容量维度超限             | 现有容量维度诊断                             | 制品容量超限，标明输入一侧与容量维度                         |
| 计划准入超出宿主预算     | `CompilerControlledLiveBytes` 诊断，形状不变 | `CompileLimitExceeded`，维度为 `CompilerControlledLiveBytes` |
| 授予超出编译遍预算       | 编译器内部错误诊断                           | 发射内部缺陷错误                                             |
| 分配器拒绝已授予的请求   | 授予回滚，按现有分配失败处理                 | 授予回滚，`AllocationFailure`                                |
| 编译遍结束仍有未归还授予 | 测试构建中失败；发布构建按内部错误报告       | 同左                                                         |

记账缺陷不是资源限额，调用方不能通过换用配置档绕过；错误携带阶段与记账点标识，便于
定位。具体诊断代码与错误变体名在实现时登记。

**预算耗尽后的错误出口。**拒绝计划之后，构造错误不得再依赖一笔可能同样被拒绝的
普通授予：

- 每次编译与每次准入调用在开始时预留固定的失败诊断额度：容量为 `max_diagnostic_count`
  的诊断收集器与诊断集合的外层存储，计入 `L + R ≤ B`。全部失败诊断只使用这份额度；诊断
  记录中的来源位置与稳定键借用或共享已计费的存储，不复制载荷。配置档自洽检查核对
  宿主预算不小于该额度。
- 成功返回时，这份预留退还。失败返回时，由它授予的诊断存储随诊断集合转交宿主（第 3.6 节），
  不再属于该账本；同一 builder 的下一次准入调用重新从准入账本预留一份额度，不把已转出
  的存储当作 builder 所有。
- 发射与检查路径的资源失败、记账缺陷与分配失败错误不分配堆内存，只携带维度、请求值、
  预算值与阶段标识，文本在展示时格式化；这些错误没有需要转交的存储。
- 失败返回时，除转交宿主的诊断存储外，本次操作或调用持有的存储随所有者析构释放，未
  消费预留全部退还；同一 `Compiler` 可以立即用于下一次操作，同一 builder 可以继续准入。

既有 16 条、17 条截断与较小规范键替换的诊断保留测试保留，另增两项验收：

- 宿主预算耗尽时仍能返回错误、释放未转交的资源，并允许下一次操作；
- 保留第一次 `add_*` 失败返回的 `DiagnosticBundle`，继续对同一 builder 添加合法模块并完成
  `build`：旧诊断仍可读取，已准入模块不丢失，存储不重复计费，授予不提前归还，报告分别
  记录转交宿主与已释放的字节。

## 5. 各阶段迁移

| 现结构                       | 迁移后                                                       |
| ---------------------------- | ------------------------------------------------------------ |
| `AdmissionTotals` 的存续累计 | 准入账本；容量维度计数保留在 `AdmissionTotals`               |
| `DomainBudget`               | HIR 各领域的编译遍计划；持久表转为输出，查找表与暂存为工作集 |
| MIR、LIR、源映射计划         | 各自的编译遍计划；手工累加上游存续改为读取账本当前存续       |
| `PreflightScratch`           | 道路编辑预检编译遍预算；计划取预检计数推出的上界，逐索引授予 |
| `GeometryScratch*`           | 道路编辑几何编译遍预算                                       |
| 发射器 `Scratch`             | 发射账本与检查账本（第 6 节）                                |
| 四份 `requested_bytes`       | 删除，由计划函数的统一折算取代                               |
| `WorkBudget`                 | 不变                                                         |

道路编辑预检“预算充足时保留原字段首错顺序、索引无法容纳时优先返回预算诊断”的规则
不变，预算诊断的维度由暂存维度改为 `CompilerControlledLiveBytes`。

## 6. 发射阶段计划

### 6.1 单制品发射

| 编译遍                | 计划内容                                                                        | 释放时机                 |
| --------------------- | ------------------------------------------------------------------------------- | ------------------------ |
| LFCA 构建与编码       | LFCA 内存对象树、编码缓冲；预备 LFCA 取得修订标识后释放，再发射正式 LFCA        | 对象编码完成后释放对象树 |
| 目标实体索引          | 按 ADR 0035 第 5 节只建立一次，授予给发射上下文                                 | LFSD 构建结束            |
| 关系投影自校验        | 策略引用校验与关系元组比较的工作集                                              | 自校验结束               |
| LFSM 构建、编码与检查 | LFSM 对象树、编码缓冲、`check_portable_policy_sources` 的借用索引与临时序号集合 | 各自结束时               |
| 内存发射对象字节      | 编码缓冲与转为 `Arc<[u8]>` 时新建的存储共存，转换后释放编码缓冲                 | 候选返回调用方时离开账本 |

### 6.2 差异发射

计划覆盖最大变化量：

- base 实体索引（制品容量准入之后）与共用的目标实体索引；
- 策略成员投影与配对排序；
- 关系分组、几何比较与静态规则比较的工作集；
- 实体、关系、几何、静态规则、空间配置与策略各变化表在 LFSD 对象组装前同时存续的
  变化行，before/after 载荷按两侧行数之和取上界；
- LFSD 对象树、编码缓冲与 `check_portable_policy_diff` 的检查视图。

现有按 `(EntityKind, StableId128)` 建立的有序映射改为按实体索引顺序排列的连续表，几何
比较改为借用受检视图，只为变化行复制载荷，使计划取闭式上界。Genesis 只有目标一侧，
按同一计划函数以空 base 求值。

### 6.3 可移植字节与磁盘

| 资源                             | 约束责任                             |
| -------------------------------- | ------------------------------------ |
| 单个 LFCA/LFSM/LFSD 的字节       | 调用方 `FormatLimits` 与线格式硬上限 |
| 本次发射新增且同时存续的受控内存 | 发射账本的宿主预算                   |
| 暂存目录的存储额度与并发任务治理 | 宿主                                 |
| 暂存、输出与各阶段峰值           | 账本报告与证据                       |

成功候选固定包含三个对象，每个对象受接收预算 `M` 约束，因此最终候选字节不超过 `3M`；
该上界描述最终候选，不描述累计 I/O（预备 LFCA 另写一次并在取得修订标识后释放）。本设计
不把单次发射的磁盘总字节定义为编译器资源预算：暂存存储额度和并发任务治理由宿主负责，
编译器执行单对象格式预算、受控内存预算与临时对象生命周期保证，沿用现有暂存对象在创建、
编码、`finish` 失败与释放路径上的清理机制。暂存目录中的对象字节与只读映射不计入受控存续。

## 7. 报告量

账本在返回点封存**资源报告**：

| 字段             | 含义                                                 |
| ---------------- | ---------------------------------------------------- |
| 存续峰值         | 账本生命周期内 `L` 的最大值，口径见第 3.1 节         |
| 各阶段工作集峰值 | 编译管线、单制品发射、差异发射与检查各自的工作集峰值 |
| 转交宿主字节     | 返回点随 `Ok` 或 `Err` 返回值转交宿主的受控请求字节  |
| 已释放字节       | 账本生命周期内实际释放并归还的受控请求字节           |
| 输出逻辑字节     | 现有 `CompilationMetrics` 的输出逻辑字节，口径不变   |
| 保留容量         | 编译结束后编译器保留的容量；当前实现恒为零           |

编译报告并入 `CompilationMetrics`；发射报告随 `PortablePublicationCandidate` 返回。报告量是
受控请求字节，不等于进程堆峰值或驻留集，不作为限额，用于证据记录与回归比较。

## 8. 一致性检查与测试

- **账本一致性**：测试构建中，账本记录每个编译遍的计划峰值 `P`、在用量 `U` 的峰值与每次
  授予的 `Layout`；常规测试核对任何时刻 `U ≤ P`、`L + R ≤ B`，分配请求全部来自授予，
  编译遍结束时无未归还授予，账本结束时满足第 3.6 节。该检查在全部现有编译器测试与
  fixture（固定测试环境）上运行。
- **账本单元测试**：准入边界值与边界加一；两层嵌套预算；释放后同一额度再次授予；分配器
  拒绝时授予回滚；错误返回与提前退出路径的归还；共享 backing 浅克隆与最后句柄释放；
  存储形态转换的共存；输出转移；`Ok` 与 `Err` 返回点的转交与报告封存；准入调用失败只
  回滚本次 candidate。
- **预算耗尽的错误出口**：第 4 节的验收。
- **配置档自洽检查**：格式可表示性、可成功规模维度、诊断保留维度与差异场景矩阵按
  [编译器基础 §5.3][compiler-limits] 执行。
- **发射纳入宿主预算的回归**：官方 fixture 与百万档端到端证据入口记录发射账本报告。若
  峰值超出宿主预算，先排除重复计费、未归还预留与不必要的存续延长，再记录真实峰值并
  显式调整宿主预算，说明依据。

## 9. 实现顺序

分三步合入。每一步的基本账本一致性与拒绝测试随该步合入常规 CI；第三步负责完整资格
验证。

| 步骤                  | 内容                                                                                                                                                                           | 合入时须成立的条件                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 1. 账本核心与发射端   | 删除四个字节维度；新增 `p100()` 与 `single_network_1m()`，删除旧的三档并迁移调用方；账本核心；发射、差异发射与两个公开检查入口迁入账本；制品容量准入；发射端目标索引只建立一次 | 发射及其内部检查共用发射账本；编译管线保留现有暂存与输出成本计算及存续总量比较，只去掉与已删维度的比较；授予、释放、拒绝与失败回滚已有测试 |
| 2. 编译管线逐阶段迁入 | 准入、道路编辑、HIR、MIR、LIR 与源映射冻结逐阶段迁入；删除旧计量结构与重复的折算函数                                                                                           | 每迁入一个阶段即以账本替换其旧存续总量比较，并验证存续、预留与所有权转移                                                                   |
| 3. 配置档自洽检查     | P100 边界矩阵、真实差异场景、官方 fixture 与百万档证据入口                                                                                                                     | 第 8 节检查按[编译器基础 §5.3][compiler-limits] 的配置档分级规则执行：P100 在常规 CI 中运行，百万档在常规 CI 中只执行格式可表示性检查      |

第一步完成后 #1288 的直接原因消除，且不存在手写暂存常量；编译管线在第二步完成前仍由
各阶段现有的存续总量比较执行宿主预算。
