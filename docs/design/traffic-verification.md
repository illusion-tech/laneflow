# 交通验证的显式组合与共享判据

<a id="applicability"></a>
## 1. 适用边界

本文是待接受的设计，不授予实现开工或产品通过结论。正文中的“须”“不得”是建议
冻结的目标合同；现行行为继续由各执行核验合同约束。设计接受也不表示共享包、
迁移、恢复协议或性能验收已经交付。

本设计服务道路机动车验证。生产交通运行时负责执行交通规则，验证执行器
（harness）负责驱动受检工作负载、观察结果并证明指定性质。两者的职责不因共享
检查代码而合并。公开组件与宿主边界沿用 [ADR 0021][adr-0021]，不需要另设生产
架构 ADR；若实现要求改变该边界，应回到设计评审。

现状对照的代码基线为 [200c27aa][baseline]，已合入
[信号参考修订][signal-reference-change]。独立信号许可的受检域和正式合同沿用
[LF-SYNTH 执行核验][lf-synth-execution]；共享化须保持已合入的独立判据及证据
准入。冻结输入字节、D1 规则及生产 Runtime API 不由本文改写。

<a id="composition"></a>
## 3. 规约、计划与会话

### 3.1 三个对象

- **验证规约（verification specification）**：规定本次要证明的性质、适用域、
  必需事实、完整窗口和场景见证。一个正式配置档（profile）是规约的具名组合，
  不是任意布尔开关的集合。
- **受检验证计划（checked verification plan）**：将规约与实际输入、事实提供者
  及规则实现绑定后得到的不可变计划；只包含当前输入确实可执行的组合。
- **验证会话（verification session）**：拥有阶段、实际检查覆盖、历史、见证和
  未完成义务，消费事实并产生结果。它不执行交通命令，不持有可变世界。

正式规约的构造入口放在各 harness 私有模块中，由其受检输入身份和执行目的选择。
共享包不建立包含 W1–W4、Urban 所有 case 的全局枚举，也不依赖两类生成器。
组合所声明的必需项与本次提供的模块分别保存；绑定须检查前者被后者完整覆盖。
正式入口不能接受调用方通过 CLI 删除必需规则；诊断组合具有不同身份，不能产出
正式规约的通过回执。

计划绑定至少检查：输入/路网身份、字段单位、事实能力、规则适用域、所需阶段、
必需规则及见证提供者。缺事实、域不支持、未安装模块分别报错，不以“不适用”代替。
每条规则有稳定的执行顺序，依赖在绑定时检查；逐拍没有动态依赖图求解。

### 3.2 组合方式与 Rust 形状

| 变化点             | 采用方式                         | 约束                                           |
| ------------------ | -------------------------------- | ---------------------------------------------- |
| 同一角色的参考实现 | 少量具体策略或枚举，必要时用泛型 | 例如不同信号参考域；策略不能读取生产许可结果   |
| 必须同时成立的性质 | 显式 AllOf 组合                  | 任一必需项违反即失败，成功不能抵消另一项失败   |
| 跨拍历史和见证     | 具名有状态监视器                 | 明确状态所有权、重建条件与保存格式             |
| 生命周期           | 固定阶段协议                     | 初始、命令、步进结果、恢复、终结各有入口       |
| 场景专项           | harness 本地构造与监视器         | 不把整个 `Burst` 或 Urban `Harness` 搬进共享包 |

建议共享包命名为 `tools/laneflow-traffic-verification`，`publish = false`。
按事实、计划/会话及独立规则分模块；Rust 类型名称可在接口评审中细化，但上述
责任不能重新混合。不引入动态插件发现、脚本规则、`Any` 事实袋或每行
`Vec<Box<dyn Checker>>` 访问世界。块级、绑定或报告边界若需要动态分派，可按实际
收益选用；不为每种规则子集生成一套嵌套泛型类型。

共享包优先只依赖公开静态值类型及自身事实结构。`SignalAspect` 等公开枚举可以
共享，不复制同名定义。Runtime 的公开状态与事件由 harness 事实适配器读取；
共享规则不得依赖 `TrafficWorld`、生产求解器、有效许可结果、安全速度上界或
困境区豁免结果。生产 Runtime、Bevy 和两类生成器不得反向依赖验证包。
现有 audit-test-support 与 host-observe 保持其审计测试辅助和环境观测职责。

### 3.3 通过由执行产生

会话须自身记录必需阶段确实执行、应检行/事件被覆盖、成功步数、失败标志和见证。
仅证明 `required ⊆ installed` 不足以通过；安装后未运行、只检查初态、漏遍历或
缩短窗口均不能通过。正式 `finish` 消费会话或使其进入终态，满足以下所有条件
才产生由私有构造入口创建的通过回执：

1. 预期完整窗口执行完毕，最后边界身份及时间一致。
2. 每个必需检查按其规定阶段和工作集执行，没有违反。
3. 必需场景见证满足，规约要求清空的未完成义务均已清空。
4. 会话未失败、未重复终结，没有尚未消费的步进结果。

执行完整性、性质结果、触发覆盖及必需见证分开表达。没有黄灯过门可以记录为
该触发计数为零；不能据此宣称黄灯边界已覆盖，也不能追加既有工作负载未要求的
黄灯见证。相反，场景明确要求的过门、预约或到达一次都未发生时不能通过。

证据消费者从自己的预期输入与执行目的选择规约，不能采用报告自报的规则集合
作为预期。该机制防止实现误接线，不是抵抗恶意 harness 伪造事实的密码学认证；
独立参考、适配器正反例和规定的证据比较仍不可省略。

<a id="facts"></a>
## 4. 事实与独立参考

### 4.1 最小事实边界

验证事实（verification facts）是带身份、单位及时间边界的只读输入，不是复制
一个完整世界的可选字段对象。

| 事实     | 必需绑定                               | 来源与限制                                            |
| -------- | -------------------------------------- | ----------------------------------------------------- |
| 静态域   | 输入、路网修订、路线及门出现位置       | 从受检输入/公开静态表建立一次；不逐车重复解析目录     |
| 车辆身份 | 逻辑身份及 incarnation、当前句柄映射   | 不以可回收槽位或 Runtime 私有 generation 冒充宿主身份 |
| 拍前运动 | 本边界全部命令后的速度、进度、状态     | 只保留启用规则所需列一次                              |
| 拍后运动 | 成功步进后的已提交状态                 | 借用只读视图，与拍前身份精确关联                      |
| 事件     | 所属成功步进、有序跨度、载荷           | 不借用上一成功拍残留事件判断失败拍                    |
| 命令结果 | 尝试序号、成功游标、前后身份、实际结果 | 与驱动器实际调用一一对应；Blocked 也有结果            |
| 参考输入 | 原始信号计划、政策、profile 数值及几何 | 参考函数不消费 Runtime 的有效许可或安全求解结果       |

逻辑身份的载荷可由 harness 紧凑映射，但须无碰撞、可核对且包含代次。恢复时
重新绑定运行时句柄；不持久化工作线程或旧进程句柄作为身份正本。

### 4.2 信号许可的首批域

首批信号参考复用 [LF-SYNTH 执行核验][lf-synth-execution] 的独立判据：W 域中使用拍初
已提交速度、拍初整数毫米进度到停止线的距离，以及精确受检的紧急减速度，
以严格不等式判定 D1。等号属于可停侧。不得用拍末速度、拍末灯态、含 carry 的
替代距离或 epsilon 改变判定边界。

纯许可判据适合共享；W 的六阶段周期、`CellOffset` / `Synchronized`、固定 entry
长度、指定 profile 和 W4 探针属于 harness 的域适配与规约。W4 指定过门仍要求
许可原因为 Green。一般 `f32` profile 不得经四舍五入后冒充 W 的精确整数参考域；
扩展域须另行定义数值归约和证明。

首批 W 域还要求 `ProtectedGroup`、独立 `prohibition: None`，且没有
Waiting/Conflict。安装和恢复均执行域绑定；原始紧急减速度及其派生值都要核对，
不能仅因派生整数相等就接受不同原始 profile。

Urban 的静态政策包含无控、许可型、受保护及红灯右转等解释，见
[路口政策来源][urban-policy]。首批 Urban 组合不启用 W 信号参考，也不宣称完整
合法通行证明。未来启用许可验证时须具备该政策域的独立时序、禁止条件及参考
能力；缺少其中之一即拒绝该配置。角色的“红灯等待后过门”见证不能替代它。

### 4.3 状态变化与事件配对

W 域保留当前“先识别 0→1 转换，再逐字段核对一对事件”的实现方向，包括 tick、
车辆、更新序号、Gate、route、occurrence、hop、锚点及 live 顺序，最后拒绝余项。
在 fromEdge 停止线端但未转换不算过门；显式命令造成的摆放变化也不算运动过门。

该能力首批只绑定已证明的 W 二边单门域。多门、多次经过同一物理门、跨路线运动
的扩展须按路线门出现位置枚举实际跨越并核对全事件序列，不能将任意
`route_edge_index` 变化都解释成 W 的一对事件。扩展域未实现时在绑定阶段拒绝，
不让 Urban 首次接入顺带承诺通用跨门验证。

<a id="body-separation"></a>
## 5. 首个跨 harness 共同性质：车身区间分离

### 5.1 单位与证明范围

首批共享的是两个 observer 已采用的**含微米余数的提交车身区间严格分离**，
不是对所有合法 Runtime 输入的毫米准入判定。每个 Active 车辆的前保险杠为
`progress_mm * 1000 + carry_um`，车长为 `length_mm * 1000`，运算使用足够宽的
受检整数。以 `(逻辑身份, incarnation)` 的完整值作为 owner，只排除 owner 完全
相同的片段；任一身份分量不同即视为不同 owner。同空间的不同 owner 非空半开
区间不得相交，恰好相接合法，`min_gap` 不属于该性质。

[整数几何 §5][integer-geometry] 的 Runtime 物理重叠比较采用截断后的非空整数
毫米区间。当前 harness 的微米性质更强，规约须声明这一点；若将来切换毫米语义，
应明确登记验证语义变化。D1 的毫米停止距离与本节事实使用不同单位明确的类型。

Parked、Completed 的正确性由停车/生命周期规则承担。路线起点外的车尾截断，
非空车身片段检查不覆盖新鲜摆放的 `[0,0]` 退化入口点准入，也不覆盖一切二维
几何相交或 Conflict 路权。

### 5.2 两个事实适配器

Urban 从当前 route occurrence 开始，沿**该车实际路线**向后展开车长，逐个输出
带物理边身份的非空 `[back, front)`：当前段 `back = max(front - remain, 0)`；
消费该段后，若尚有车身且存在前一 occurrence，则在其边长处继续。车长可跨多条
短边；相同物理边的不同 occurrence 最终进入同一物理边比较。边界、单位溢出、
非法 carry 和超出当前边长的前端应作为事实错误拒绝。

Synth W 的受检两边路线及静态隔离关系允许继续使用已有有序车辆遍历。其适配器
须证明用于比较的区间属于同一受检一维空间，且已覆盖需比较的车辆；不能把同路线
分组直接当成任意路网的物理边分组。共同区间判据由两个适配器调用，W 的顺序不
反转/不超车规则单独保留。不要为接口统一将 W 的线性检查升级成全车排序。

W 快路径绑定还须核对：路线内 occurrence 的物理边及长度符合无别名一维走廊；
不同分组不共享需互检的物理车身空间；Active 行完整且不重复；既有 lane order
顺序约束独立验证。任一前提不成立即拒绝快路径，不仅凭 `rank / 25` 推断空间隔离。

当前换道合同没有 source/target 双份投影车身；真实车身沿实际路线展开，T 资源格
预约另行核验，见 [跟车与占用合同][vehicle-following]。不得在事实适配器中把预约
空间或虚构的横向投影当成第二份车身。未来占用模型改变须扩展受检域。

### 5.3 公共判据与集合算法

共同规则至少包含“同空间、不同 owner 的两个非空半开区间是否相交”的纯判据，
以及需要任意片段集合时的有序扫描。owner 包含 incarnation；同 owner 的重复
片段可自排除，但不能遮蔽它与别的 owner 的重叠。

任意集合按 `(space, lo, hi, owner)` 的稳定顺序扫描。每个空间保留终点最远的
两个**不同 owner**及其确定性并列键；检查当前片段时，选出 owner 不同的最远
终点，与当前起点作严格比较，再更新这两个候选。同空间内不因一个较短的同 owner
片段而遗忘更长片段。排序后扫描为线性，候选状态为常数；集合的收集与排序成本
另算，不能隐藏在“纯判据 O(1)”后面。

候选保存 owner、实际区间及确定性并列键，空间改变时重置。有序扫描对选出的
候选调用同一半开区间相交判据；Synth 有序相邻检查也调用该判据。两条执行路径
只在候选枚举和域证明上不同，不分别内联另一套重叠判断。

必须拒绝以下嵌套反例：A 的 `[0,100)`、A 的 `[50,70)`、B 的 `[80,90)`。
只比较排序后的相邻片段并跳过同 owner 会漏检。这是通用集合算法的证明要求，
不表示已证明当前 Urban 冻结输入存在该可达缺陷。

实现测试须用简单的独立两两枚举作为小规模集合参考，覆盖嵌套、同 owner、重复边、
相接、不同 incarnation 和输入排列；不以生产 occupancy 查询作为预期答案。
两个 harness 的事实适配器分别有合法事实与注入重叠事实的接线测试。Runtime 拒绝
不合法摆放不能替代 checker 的负例。

<a id="lifecycle"></a>
## 6. 固定阶段与状态所有权

以已完成 `k` 个成功步进的边界为基准；下一次成功步进产生 `k+1`。命令的原有
boundary/tick 编号在驱动器适配，不通过共享化改变计划解释。

| 阶段入口        | 前置与动作                                            | 不得发生                                     |
| --------------- | ----------------------------------------------------- | -------------------------------------------- |
| 绑定            | 验证规约、输入、域及所需事实，建立不可变计划          | 从待验报告推导降低后的预期                   |
| 初始边界        | 核验身份、时钟、状态、信号及初始零事件                | 增加成功步进数或伪造过门                     |
| 命令结果        | 按实际顺序消费成功、Blocked、失败回执                 | 跳过失败尝试或把尝试数当成功游标             |
| 命令结束 / 拍前 | 校验本边界命令已处理，采集一次拍前所需列              | 使用命令前旧位置作为位移或 D1 起点           |
| 成功步进后      | 消费本次结果一次，核对拍号/时间、状态、事件并更新历史 | 重复消费、遗漏必需检查或接受陈旧事件         |
| 预期失败步进后  | 仅启用原子性/重试规约时核对未提交及规定的外部结果     | 递增成功拍、自动执行成功拍观察或忽略意外失败 |
| 终结            | 检查完整窗口、覆盖、义务及见证，进入终态              | caller 自行填写通过或失败后重新 finish 成功  |

成功 spawn/replace 建立新 live 绑定，按宿主合同推进 incarnation；despawn 移除
当前活跃身份及其可消费拍前行，但按义务保留已结束代次的历史和见证。leave/park
保留逻辑身份及代次，更新状态和运动基线；reserve/cancel 核对运动不变及绑定变化。
Blocked 可增加尝试及拒绝统计，
不得推进成功 command cursor、incarnation 或位置。连续多个边界命令全部处理
之后才形成拍前事实。

验证会话只保存跨拍判定所需历史；需求生成、pending 队列、宿主随机流及实际命令
调度仍由驱动器拥有。事实适配器拥有必要拍前列与可复用 scratch，拍后尽量借用
已提交视图。事件编码与文件写入不进入判据。

规则发现违反使会话进入不可通过的失败终态；不要求所有 monitor 实现通用
prepare/commit/rollback。预期 Runtime 失败是规约中的受检输入，与 checker
发现违反不同。原子性规约的检查若失败，同样终止验证；未完成的一轮尝试不得
生成可恢复的正式验证检查点。

预期失败通过原子性检查后仍停留在同一“命令已结束”的边界，以相同受检
`TickInput` 重试该步进；不退回命令前阶段重复执行已提交的命令。若规约允许修改
重试输入，须由该规约显式定义，不能由共享会话默许。

<a id="restore"></a>
## 7. 保存恢复

验证检查点只允许在已验证的边界、且不处于等待步进结果的状态创建。材料须明确
是本边界命令执行前还是全部执行后；不允许含义不明的“当前 tick”。

| 状态                              | 所有者与保存要求                                             |
| --------------------------------- | ------------------------------------------------------------ |
| 输入、路网、规约及执行目的绑定    | 宿主恢复材料保存并核对；恢复时从同一正式构造入口重新绑定计划 |
| 成功步数、命令阶段与实际游标      | 精确保存；保留现有 `after_commands` 等价语义                 |
| 逻辑身份、incarnation、历史及见证 | 保存必要值及未完成义务，恢复后重新绑定句柄                   |
| pending、需求、随机流、计划进度   | 驱动器继续拥有；与验证材料及 Runtime 快照原子绑定            |
| 拍前缓冲、排序/分块 scratch、池   | 不持久化；从已核验状态重建，不要求原 worker 布局             |

恢复边界只作状态与材料一致性核对，不重放已经计数的成功步进，不重复累计 crossing
或见证。若检查点在命令后，已执行命令不能再执行；如果在命令前，则按原计划执行
一次。既有 Synth 后缀比较和 Urban 保存恢复证明仍须保持。

新增必需检查状态缺失时拒绝，不使用 `serde(default)` 清零后继续宣布原规约通过。
确可由现存状态完整重建的字段必须在合同中给出重建依据及等值测试。验证状态只进入
harness 宿主材料，不扩展 Runtime LFRS。

<a id="evidence"></a>
## 8. 证据身份与准入

| 身份轴       | 责任                         | 本设计的处理                                       |
| ------------ | ---------------------------- | -------------------------------------------------- |
| 输入身份     | 冻结输入字节及来源           | 保留，不能靠改输入避开规则失败                     |
| 规则语义身份 | 所证明性质、适用域及完成条件 | Synth 沿用 `semantic_contract`，不另设同义版本正本 |
| 观察编码身份 | 轨迹、摘要原像及事件字节编码 | 独立维护，不拿共享 crate 版本替代                  |
| 宿主恢复格式 | 如何解释阶段、映射及验证历史 | 必要字段/阶段变化按格式规则显式升级                |

正式配置档由受信的执行目的与输入/case 身份选择，绑定实际规则语义身份。需要持久化
该绑定时，应纳入既有回执或宿主材料，而非为框架再造一套平行证据清单。Urban 须在
其正式回执中具有明确的规则语义准入；其 `urban-observation-v4` 编码号不能兼任
“证明什么”的规则身份。具体字段及版本值由相应迁移切片登记，不能接受缺字段
的旧证据并推断其拥有新语义。

纯等价搬迁不自动产生新的规则语义版本。增加必需性质、改变受检域或完成条件、
修正使旧执行错误通过的判据时，须判断可接受执行集合是否改变并登记相应升级。
观察编码和恢复载荷的结构变化分别处理；不能为了“一个版本正本”把三种职责混成
一号。旧证据不得编辑字段转标，不维护并行旧检查器供开关选择。

普通、burst、worker、matrix、restore、retry 的正常参考、oracle 准备及正式测量
消费者须共用对应准入函数。`complete=false`、缺失/未知/错误语义身份、错输入、
错执行目的或窗口不完整在使用内容前拒绝。

缩短的恢复探针即使在自身回执中 `complete=true`、`attestation=Pass`，也只证明
探针范围。消费者须从其预期目的绑定 `probe` 与 `end_tick`，不能从待验报告自选
窗口；普通完整窗口或正式性能入口不得接受缩短探针代替完整语义参考。

绑定 oracle 一致性规约只证明本次测量与已经完整核验的参考符合其对拍合同；它不
重新独立证明全部交通性质。retry 证明失败原子性及重试等值；L1 保留预约生命周期
专项。不同执行目的必须显式区分，不把所有入口都改为逐帧全量审计。

<a id="execution-cost"></a>
## 9. 执行成本与确定性

### 9.1 结构预算

- 每个实际步进尝试只采集一次所需拍前列；成功步进后的共同检查复用现有逐车/分块
  遍历。已有可证明等价的历史列允许直接复用，不要求额外完整复制。
- 每个规则不得各自复制世界、创建线程池或建立逐车堆容器。按实际工作集配置缓冲，
  安装/域变化后的增长与逐车分配分别统计；不能将所有分配都称作初始化。
- 车身投影成本按实际片段数 `K` 计算，不能假定 `K = N`。Urban 复用块内排序及
  归并后的片段，集合检查为 `O(K)`；Synth W 保留已有受检顺序的 `O(N)` 路径。
  新收集/排序确有必要时须单列成本与域依据。
- Urban 复用 `StateView`、`ObservationScratch`、常驻观察池及稳定块序。现行
  `run_blocks` 和块结果仍有容器分配，本设计不声称现有 observer 已全面零分配。
- 规则计算有必要成本；融合遍历只能减少重复读取、投影、复制和调度，不能把新增
  判据写成零成本。

### 9.2 确定性边界

Urban 的规范摘要块大小 `4096` 是观察编码的一部分，保持该块界及根摘要组合。
改变 worker 数或任务分配不得改变规定的状态、事件、计数、摘要或首错选择。
任意改变规范编码块大小不属于无语义变化的执行配置调整；若改变须升级编码。

规则在固定阶段和规则顺序执行，块内采用稳定行键，块间按规范块序归并；跨块集合
错误再按固定集合顺序选择。不得依赖线程完成先后或 `HashMap` 遍历顺序选首错。
不同执行切分可验证性质与错误的等值性，但最终字节仍按规范编码块形成。

### 9.3 计量计划与待裁预算

性能验收至少分三组：相同检查集合的结构迁移、新增/增强性质的必要成本、完整配置
的整轮成本。结构迁移组的基线与候选须具有相同受检性质和规则语义；不能把
green-only 与独立许可差异记为组合框架开销。增强组允许用明确标注的旧检查集合
或关闭新增模块的诊断运行测增量，但该对照不能产出完整新规约的正式通过。
完整配置组必须启用全部必需项。

代表性负载包括 Synth W1（稳定人口）、W3（命令及停车）、W4（边界专项），以及
Urban 的稳定运行与人口变更场景；规模、窗口、worker 配置、运行顺序与实现提交须
在测量任务开始前登记，消费对应完整受检计划。逻辑测试可用小样本，不能以缩短
正式窗口的结果作为正式性能结论。

记录观察耗时分位数、整轮墙钟、实际片段数、扫描次数、分配次数/字节及缓冲高水位。
分配/扫描计数与墙钟实验隔离；后者按 [开发阶段评审 §5.1][development-gates]
使用获准的安静窗口。Runtime step 计时外的观察工作仍会影响缓存和整轮成本；
不得通过移动真实服务工作或只报告 Runtime 时间掩盖它。

**G1 接受前须裁定的项目**：等价迁移允许的观察耗时与整轮回退预算，以及新增性质
允许的增量预算，分别给出统计口径与拒绝条件。现有代码不能推出合适百分比；不套用
signal-system 的 20%/30%，也不在看过结果后选择刚好通过的阈值。以上结构预算与
计量分组是本设计的明确建议，时间预算尚待维护者选择。

## 10. 首批组合与迁移验收

| 执行目的                      | 共同能力                                              | 保持专项与证明范围                                         |
| ----------------------------- | ----------------------------------------------------- | ---------------------------------------------------------- |
| Synth W1/W2                   | 共同运动/身份事实、车身分离、独立许可、跨门与事件核对 | 固定人口、冻结停车、信号周期、每个 Active 完整窗口恰过一次 |
| Synth W3                      | 同上，含有序命令结果与身份代次                        | 到达屏障、停车/离位、Blocked 重试与最终人口见证            |
| Synth W4                      | 同上                                                  | B0 不过门、B1 指定探针且 Green，不放宽为任意合法黄灯       |
| Urban 语义运行                | 首批复用车身区间判据与适配器负例                      | 原有角色/人口/预约/停车见证；不额外声称通用信号合法性      |
| Synth L1                      | 明确独立组合身份和完成条件                            | 首批不要求重写全部预约生命周期监视器                       |
| retry / restore / measurement | 按各自目的选择计划、阶段及准入                        | 分别证明原子性/继续运行等值/oracle 一致性，不扩大证明范围  |

迁移必须给 `previous`、`crossed`、`transitions`、减速度累计、incarnation、
预约历史、arrival/completion 及 pending 等现有字段指定唯一所有者。规则抽出后
删除已迁移的重复实现；未迁移专项保留明确调用位置，不使用空实现假装已接入。

| 必测主题 | 具体拒绝或等值要求                                                                                                    |
| -------- | --------------------------------------------------------------------------------------------------------------------- |
| 组合缺项 | 必需规则未安装、事实不足、域不支持、启用后漏调用均不能通过                                                            |
| 完成范围 | 缩短窗口、缺必需见证、遗留义务、重复 finish 被拒；零黄灯触发不凭空失败                                                |
| 信号     | 严格等号两侧、拍初/拍末混用、红灯、独立禁止条件/域错配、W4 Green 专项                                                 |
| 事件     | 跨门漏事件、多事件、乱序、错身份、错 occurrence、命令摆放不算过门                                                     |
| 车身     | 相接、嵌套、重复物理边、同 owner 多段、跨多条短边、起点截断与单位差异                                                 |
| 命令     | spawn/replace 后新基线；despawn→spawn 清除旧 live 绑定且不串用历史；leave/park 代次不变；Blocked 不推进成功游标及位置 |
| 失败步进 | 原子性规约受检失败、不消费陈旧事件、重试不重复命令；checker 失败后不可正式通过                                        |
| 恢复     | 命令前/后边界、错身份/版本、缺历史拒绝、后缀及累计等值、不重复计数；缩短探针不能充当完整参考                          |
| 并行     | worker 与分配顺序变化时规范摘要、计数及首错一致，保留固定编码块                                                       |
| 成本     | 同检查集合比较；适配器/片段/缓冲单列；验证层与整轮均有受控证据                                                        |

详细实施顺序、开工状态和本次检查结果由 [任务][verification-issue] 与交付 PR
维护。仅建立共享 crate、trait 或报告 DTO 不构成本设计的实施完成。
