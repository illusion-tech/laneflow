## 1. 问题与设计立场

路网修订不可变（ADR 0025），而城市游戏的改路与制品重发布要求运行中世界换绑
新修订。本文冻结该换绑的事务设计，立场有三：

- **一切经过事务**：不存在绕过事务的修订替换；候选在提交前对外不可见，放弃
  是正常路径而非错误。
- **失败关闭**：任何不一致、超限或无法证明等价，旧世界原样继续，零切换事件。
- **权威分离**：迁移权限与"哪些实体可牺牲"的裁决在宿主/上层（ADR 0021）；
  Runtime 只验证、不授予、不提供迁移回调——回调会把游戏规则复制进迁移路径，
  破坏封闭契约与失败关闭审计。

## 2. 切换描述符（`NetworkRevisionCutoverDescriptor`）

描述符是宿主在对象外可信提供的封闭契约输入（随存档清单或发布信任链交付），
冻结字段如下：

| 字段                  | 契约                                                                                                                                                      |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `formatVersion`       | 描述符封闭契约版本；未知值拒绝                                                                                                                            |
| `baseLfcaOrigin`      | base 侧 LFCA origin 四联：digest / byte length / `NetworkRevisionId` / `networkRevisionDerivationVersion`；与 LFSD base/target binding 同构，逐项交叉验证 |
| `targetLfcaOrigin`    | target 侧 LFCA origin：同上四联                                                                                                                           |
| `semanticDiffOrigin`  | LFSD origin：format version / digest / byte length；同修订恢复可缺失                                                                                      |
| `migrationPolicyKind` | 封闭种类选择器（术语表：封闭种类选择器；§3）；不是协议版本，兼容拒绝由 `formatVersion` 承担                                                               |
| `worldBinding`        | 目标世界身份、活动世界世代与**基线**命令/事件游标；事务启动时逐项比对，双游标作为迁移增量日志应用起点，静默期由等价证明复核最终值                         |

Runtime 的一致性验证只回答「这份输入与两侧已认证制品、活动聚合当前值是否精确
一致」，不回答「这次迁移是否该发生」。仅凭 `StableId128`、LFSD 或调用方自报
revision 不构成迁移权限；#299 历史 receipt 与静态镜像 descriptor 不复活；描述符
不可扩展，未知字段、未知版本、附加载荷一律拒绝。验证先于解析：
`semanticDiffOrigin` 的 byte length 在任何解析、分配或哈希之前与宿主声明的上限
做 O(1) 比较，超限即拒绝——认证只证明对象真实，不证明对象可承受
（`network-compiler.md` §9.6 同一原则）。

两侧 `SharedIdentityIndex` 各随所属修订提供：base 侧来自活动聚合，target 侧随
候选；等价证明中共同复核稳定引用映射，不进入任何制品。

## 3. 迁移策略（封闭种类选择器）

| kind                    | 语义                                                                                                                                                                                                                    |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `same_revision_restore` | 同修订换根：两侧 `NetworkRevisionId`、`networkRevisionDerivationVersion` 与 identity / constraint / execution-contract versions 精确相等；动态状态原样重绑。origin 字节差异仅承担来源审计（ADR 0020 §12 / ADR 0025 §8） |
| `cross_revision_direct` | 跨修订直移：经 LFSD 把每个动态实体的稳定引用直移到 target                                                                                                                                                               |

三条闭合原则：

1. **逻辑恒等**：迁移是稳定引用键控逻辑状态上的恒等变换——直移只改序号绑定，
   不产生、不消灭、不改写逻辑内容。由此导出两条必然结论：当期
   `RouteHandle` / `VehicleHandle` 跨切换保持有效（ADR 0029 §6 原地更新语义，
   Adapter 持有的引用继续寻址同一逻辑实体）；等价证明的摘要期望值 = 旧世界
   在静默点由自身摘要机制独立计算的确定性状态摘要，不取自候选路径（§5）。
2. **重绑即重验证**：每个动态实体重绑后必须在 target 修订上重新满足其全部
   注册/准入不变量（等价于重执行 `register_route` / `spawn` 检查）。引用不存在，
   或实体仍在但原样重绑会违反 target 不变量，都视为不可映射。
3. **不可映射即整体失败**：任一实体不可映射，整个事务失败关闭，旧修订、旧
   动态状态、旧 source、旧 diff base 原样生效，零事件。「删路前清场/劝阻」的
   游戏体验由宿主在发起前用 LFSD 预检与生命周期命令编排；声明式逐类丢弃或
   自动改道是未来独立 G1 的设计空间，不在本契约。

## 4. 状态机

```text
Prepare → Delta Catch-up → Quiescent Commit → Retire
```

- **Prepare**：在固定步进安全边界**原子完成基准捕获与迁移增量日志武装**，随后
  旧世界恢复步进、从该不可变基准构造候选。基线与日志记录之间不存在窗口——
  边界之后旧世界的每次提交都必然落入日志，否则该提交既不属于基线也不属于
  日志，追赶永远无法到达。构造失败即丢弃候选，旧世界无感知。跨修订目标
  修订在构造前按本世界执行合同复验——信号相位不短于固定步长且为步长整数倍
  （与 `install` 路径对等；候选不经 install 构造，此校验必须显式发生），
  不兼容即整体失败关闭。
- **Delta Catch-up**：候选在后台按规范顺序应用迁移增量，逐步追近旧世界提交
  点；不模拟未来、不重执行输入命令。追不上、日志溢出、迁移失败或预算超限
  即放弃候选，旧世界继续。日志消费按字节偏移续读，泵送摊还线性于记录数。
- **Quiescent Commit**：在固定步进安全边界暂停旧世界步进（含输入），排空
  日志尾，完成等价证明与摘要复核，原子换绑。证明失败即放弃候选，旧世界从
  暂停点恢复步进。
- **Retire**：新聚合与切换事件批次同界只发布一次；旧修订在最后一个借用
  视图/令牌退出后回收，不为提前回收撤销有效借用。事务形态下提交消耗事务
  对象：换出的旧世界动态状态随事务析构同步释放，不依赖宿主后续丢弃。

三条提交前置约束：

- **在途唯一**：每世界同时至多一个在途切换；静默期原子复核活动聚合
  origin / 世界世代，base 已前移则候选过期失败关闭。事务丢失（宿主静默
  丢弃、或消耗形 `commit`/`abandon` 以错世界结算后丢弃事务对象）时来源
  世界保持在途锁定（`InFlightTransaction`）；宿主以世界级恢复入口
  `abandon_in_flight_cutover` 显式放弃在途候选——旧世界从当前状态继续、
  零事件，无在途时该入口失败关闭。
- **target 来源绑定**：候选携带目标 `CommittedNetworkSource`，晋升前与
  `targetLfcaOrigin` 完成对应验证（editable：重编译产物一致；published：引用
  一致）；未经绑定验证的 source 不晋升。
- **目标绑定执行计划**：执行计划是每世界可重建对象；提交边界前按 target
  重建/失效旧计划，激活与晋升同界——首个新修订 tick 不经旧计划执行。

维护暂停模式仅宿主显式声明、整个准备期停表、单独预算；不作为在线改路的
隐式语义。

### 4.1 观测与 Routing 交互（#303 G1 已接受）

准备期对外只导出活动旧聚合的观测，候选世界不可见。在旧世界成功执行的 Routing
候选注册已经成为普通路线生命周期变更，必须进入迁移增量日志并在 target 根上按
§3 重绑/重验证，并消费 #303 已接受的统一 `route_edge_occurrence_capacity`；target
路线总 occurrence 超限时整个切换失败关闭。候选聚合重复持有的路线热表属于 #302
峰值 retained memory，不把同一逻辑路线重复计入活动聚合的语义容量。成功提交与聚合
换绑同界递增世界世代，使旧观测导出/admission session、未注册候选和旧修订成本绑定
全部 stale；调用方在新修订先取 full，已经注册的路线句柄仍按逻辑恒等保持。切换放弃
不递增世代、不改变旧观测 stream 身份。精确合同见
`traffic-observation-and-routing-integration.md` §5。

## 5. 迁移增量日志与等价证明

- 日志是已提交变更流（术语表）的有界物化：规范排序的动态状态/生命周期变化
  与命令/事件游标。不记录未提交中间态，不重复旧世界事件。
- **覆盖区间为半开区间** [基线游标, 静默点提交游标)：区间内的提交变更进入
  候选；静默边界上已接受未提交的命令，其归属由最终游标在同一原子边界的取样
  唯一决定。不存在既不在基线也不在日志、也不由最终游标定归属的提交。
- **有界性**：字节上界（默认值由容量合同登记）；溢出即放弃候选，不截断、
  不丢弃尾记录、不降级为全量重放。放弃后宿主可显式改用维护暂停模式重试，
  除此之外不存在第二种在线降级路径。
- **等价证明**：候选状态 + 事件批次 ≡ 迁移函数作用于旧世界暂停点已提交状态。
  采用结构性增量论证（迁移增量重放与迁移函数作用等价），不在窗口内对全量
  状态重算迁移函数；叠加确定性状态摘要比对（期望值来源见 §3 逻辑恒等）作为
  独立于候选路径的损坏检测。

## 6. 切换事件批次

迁移函数生成、准备期不可见、只与新修订/状态绑定**原子提交恰一次**的规范排序
事件集合；放弃零发布，无部分可见中间态。v1 事件枚举在 §3 整体失败关闭下不含
实体消失类生命周期事件，允许空集起步；不得扩展为通用事件通道。

事件游标是世界状态的实轴（捕获/恢复如实落盘，与命令游标同构）。快照恢复把
事件游标一并回滚到快照点：恢复点之后已交付的批次按回滚语义视为未发生，宿主
消费端必须随恢复回卷自身副作用（与命令重放同界）。事件轴不提供独立于快照轴
的去重通道；批次身份由世界身份与事件游标复合构成，恢复即新流边界。游标推进
量在换绑前预检，耗尽以 `EventCursorExhausted` 先于任何突变失败关闭。

## 7. 原子晋升与共存

同一安全边界原子替换（全或全不）：

1. 活动聚合指向的新 `Arc<SharedNetworkRevision>`；
2. 迁移后的每世界动态状态；
3. 新 `CommittedNetworkSource`；
4. editable 聚合的 `EditableDiffBase`——「target LFCA 成为下一次 LFSD 的
   diff base」仅适用 editable 聚合；runtime-only 发布聚合没有 diff base、
   不发射 LFSD；
5. 修订绑定的 Spatial facade / 只读快照（若存在绑定）；
6. 规范排序切换事件批次。

#303 G1 已接受合同要求同一原子边界还包括：

7. 活动世界世代递增；
8. 由新 `(world_id, WorldGeneration)` 自然形成新的 `ObservationStreamBinding`，并把
   `ObservationStateSequence` 同界重置为初值 `0`；不维护第三套 stream 计数器。

以上两项不能在聚合晋升前后另行修改；成功提交后调用方不可能观察到“新 root +
旧世代/stream”或“旧 root + 新世代/stream”。放弃保持两项原值。

Spatial / Adapter 绑定沿 ADR 0029 §6 的 `(世界令牌, NetworkRevisionId)` 失效
模式：提交后旧修订绑定失效，调用方按新修订重新 bind，首个切换后位姿提取不落
在旧根上；旧会话在途借用可完成。

迁移期共存内存：current root、retained base LFCA、target LFCA/LFSM/LFSD、
candidate root、scratch、旧/候选动态双份、迁移增量日志与未提交事件批次；峰值
按 §9 预算。

## 8. 失败关闭故障映射

| 故障                        | 行为                                                                                                     |
| --------------------------- | -------------------------------------------------------------------------------------------------------- |
| 描述符不一致 / 不可信       | 事务拒绝启动；旧聚合原样生效                                                                             |
| 候选构造失败（Prepare）     | 丢弃候选，旧世界无感知；零事件                                                                           |
| 世界世代耗尽                | 在任何候选暂存前失败关闭；旧聚合/世代原样生效；零事件                                                    |
| 日志溢出                    | 放弃候选；旧世界继续；零事件                                                                             |
| 追赶失败 / 预算超限         | 放弃候选；旧世界继续；零事件                                                                             |
| 语义证据缺失                | 等价证明或摘要比对失败 → 放弃候选；零事件                                                                |
| 不可映射实体（§3）          | 整体失败关闭；旧修订/状态/source/diff base 全保留；零事件                                                |
| 保存发生在候选准备期        | 只捕获旧 `CommittedNetworkSource` 与对应 Runtime Snapshot；事务不受影响（快照文档 §5）                   |
| 事务丢失（丢弃/错世界结算） | 来源世界保持 `InFlightTransaction` 锁定；宿主以 `abandon_in_flight_cutover` 显式放弃，旧世界继续；零事件 |

「候选准备期」= 自 Prepare 起至 Quiescent Commit 原子提交或放弃之前的候选存活
全程。

## 9. G1 预算

度量协议：同机描述性基线（沿 `LF-P100-REF-01` 先例），量化切片登记初值。1.0 前
预算可依据可复现的实现、工作负载和产品证据收紧、放宽或重构；每次变化必须说明
原判据为何不再成立、更新同一事实源，并在影响实现合同或验收结论时返回 G1，不能
在 G2 静默改口径。

| 维度               | 上限/口径                                                                                                                                                                                                                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 静默提交窗口       | v1 ≤ 2 个固定步进边界（调度约束），且窗口内全部工作受墙钟/主线程停顿上限约束（ADR 0021 §5 在线静默提交停顿预算）。库内可确定性判定的超限轴为追赶滞后与日志字节溢出，两者即时放弃候选；墙钟上限不在提交路径内读时钟，由本节证据与规模投影验收（跨修订二次项优化归 #531），排空量受日志字节上界约束 |
| 在线准备干扰       | 不改变旧世界已提交状态与事件语义；稳态 tick 不因准备新增分配；资源干扰描述性报告                                                                                                                                                                                                                  |
| 追赶滞后与后台资源 | 最大追赶滞后（tick 距离）与后台 CPU / 内存上限，超限即放弃候选——日志字节上限不限制滞后，候选不得无限存活、后台不得无限占用                                                                                                                                                                        |
| 迁移增量日志       | 字节上界 + 文档化默认值；溢出失败关闭                                                                                                                                                                                                                                                             |
| 候选共存峰值       | §7 共存清单全部对象的峰值按基线登记                                                                                                                                                                                                                                                               |
| 候选规范制品字节   | LFCA/LFSM/LFSD 候选 exact bytes 分别量化                                                                                                                                                                                                                                                          |
| save/load 停顿     | 见快照文档 §8                                                                                                                                                                                                                                                                                     |
| 维护暂停完整停顿   | 单独预算；只在宿主显式停表时发生                                                                                                                                                                                                                                                                  |
| 旧修订回收延迟     | 最后借用退出后的回收延迟描述性量化                                                                                                                                                                                                                                                                |

## 10. G2 边界与必测义务

G2 回写（切片 A 落定，#511）：

- `worldBinding` 精确形式（v1）：`world_id: u64` 由宿主指定、同一宿主进程内
  不得复用（术语表「世界身份」）；活动世代为字段私有的
  `WorldGeneration(u64)`，`install` 从 `0` 开始，成功切换 checked `+1`，耗尽在
  暂存前以 `WorldGenerationExhausted` 失败关闭。Runtime 通过
  `TrafficWorld::world_binding()` 签发当前身份/世代；事务启动时两者逐项比对，
  因而同 origin 的旧描述符也不能发生 ABA 复用。命令基线游标已随切片 B（#512）
  落地为真实已应用输入命令计数，事务启动逐项比对（失配即
  `BaselineCommandCursorMismatch`）；事件基线游标已随切片 C（#513）成为
  真实轴：`world_binding()` 签发已提交切换事件计数，事务启动逐项比对
  （失配即 `BaselineEventCursorMismatch`），快照 wire 同轴贯通。
- 同修订等价证明精确形式（v1）：结构不变量（边/车位计数相等 + 逐路线对
  target 根重编译成功）加逻辑恒等 oracle（切换与未切换世界在切换边界与
  每一步之后比对完整规范化已提交状态：tick/时间、全部车辆整值状态、
  位姿来源、信号灯色组、停车占用）。等修订号 ⇒ 语义载荷相等 ⇒ 重编译
  确定性同构，因此 Prepare 段路线内容/计数失败在合法输入下结构性不可达，
  作为防御性闭合保留。#303 将 compiled-route 热表改为可失败预留后，v1
  可注入 Prepare 失败包括候选表或路线编译缓冲预留失败
  （`StagingAllocFailed`）与占用重建容量预留失败
  （`OccupancyRebuild(OccupancyAllocFailed)`）；两者都在提交前返回并保持旧聚合不变。
- 同步形态边界：Prepare 与 Quiescent Commit 在同一次 `&mut self` 调用内
  完成，无 tick 交错、无并发候选；「稳态 tick 不因准备新增分配」的 v1
  可测形式 = 切换前后稳态 tick 分配账本相等（实测均为零，§9 初值表）。
- 切片 C（#513）回写：迁移增量日志字节默认值 `8 MiB`（Prepare 一次预留
  arena、溢出粘性失败关闭）、追赶滞后上限默认 `600` tick 与每泵 `4,096`
  条（`CutoverTransactionLimits::default`）、切换事件批次枚举 v1 仅
  `RevisionCutoverCommitted`（恰一次交付；事件游标成为真实轴，在
  `world_binding()` 签发入口按 `BaselineEventCursorMismatch` 收紧）、
  维护暂停 v1 形态 = 宿主停表使用模式（Prepare 与静默提交之间零步进，
  停顿单独计量，无独立运行时入口）。save/load 停顿已随切片 B（#512）按
  快照文档 §8 登记 published 初值（editable load 空缺不视为已满足）；
  Spatial 重绑义务随 editable/Spatial 绑定切片回写。空缺不视为已满足。
- Prepare 的 v1 形态（切片 C 登记）：候选构造（结构克隆 + 直移 + 全量
  重验证）在 `prepare_cross_revision_cutover` 调用内同步完成——宿主泵式
  单线程下其阻塞量与「首个泵内构造」等价，仅支付时点不同；失败关闭
  语义与合同 §4 一致（构造失败即解除武装、旧世界无感知）。分段构造与
  线程化后台属未来形态，引入时回写本节。
- 跨修订直移精确形式（v1，切片 C 落定）：候选 = Prepare 边界的结构克隆
  （槽位布局与旧世界一致，当期句柄恒等保持）+ LFSD 认证（O(1) 长度、
  SHA-256、注册表校验、绑定行与两侧 origin 逐项交叉验证）+ 两侧
  `SharedIdentityIndex` 序数重绑（`None` 即引用不存在）；追赶只应用迁移
  增量，生命周期增量写入即重验证；静默期摘要复核期望值 = 旧世界捕获 +
  target origin 头部替换；最终命令游标由静默边界原子取样写入候选后参与
  摘要与晋升。
- 正式审阅轮回写（切片 C）：Prepare 对目标修订执行信号程序 × 本世界步长的
  install 对等校验（不兼容即 `TargetSignalProgramInvalid`，先于 LFSD 认证与
  武装）；泵送按记录边界字节偏移续读（`records_from`），消费摊还线性；事件
  游标推进量在两入口换绑前 checked 预检（`EventCursorExhausted`）；
  `commit` 消耗事务对象，换出的旧世界随事务析构同步释放（§4 Retire）；
  重绑表四张稠密映射走同一可失败预留（首个切片 C 审阅补轮），事务丢失的
  世界级恢复入口 `abandon_in_flight_cutover` 登记 §4/§8，事件批次与提交
  记录 `#[must_use]` 防语句位静默丢弃交付。恢复配对以日志武装轮次闭合：
  世界每次成功武装递增 `migration_epoch`（进程内守卫，不落盘），事务绑定
  武装轮次并纳入配对校验——恢复后重新武装的新日志对旧事务按
  `TransactionWorldMismatch` 失败关闭，旧事务不得认领后继日志。失败结算
  显式释放候选动态表与重绑表；候选信号灯色切片同走可失败预留。

必测义务：§8 每类故障的注入测试（保全旧值 + 零事件）；静默提交窗口两类超限
放弃；维护暂停重试端到端；不可映射整体失败与宿主清场重试（引用不存在与重绑
非法各至少一类）；事件批次恰一次（含空批次零重复）；晋升无中间态；句柄跨
切换有效；在途唯一（过期候选失败）；摘要比对捕获候选侧损坏；策略种类与派生
版本不匹配拒绝；target 来源绑定验证；旧修订借用回收与 Spatial 重绑；在线准备
干扰不变量（准备期稳态 tick 零新增分配、旧世界事件语义不变的确定性断言）；
追赶滞后超限放弃；信号程序不兼容拒绝与放行对照（对齐程序推进到 LFSD 认证）；
事件游标耗尽两入口失败关闭；事务消耗后旧世界释放的弱引用断言；日志偏移
续读的预算断点不丢记录（泵分段等价）；重绑预留失败解除武装；错世界消耗
结算后的世界级恢复路径与无在途失败关闭；恢复后旧事务对新日志失败关闭；
失败结算释放候选（动态表与重绑表清空的 test-only 断言）；信号灯色预留
失败注入。#303 接缝还必须覆盖世界世代/观测 stream/
`observationStateSequence` 与 root 同界原子变化、target 路线 occurrence 容量
max/max+1 与超限零提交，以及 abort 三者完全不变。
