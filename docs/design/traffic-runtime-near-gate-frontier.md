## 1. 结论

入口 frontier 是产品 Runtime 的唯一维护路径。它不再每拍为全部 Active 车辆打开路线。

1. 运动已经算出下一提交状态时，用这一状态的一拍可达上界和换边时记下的门距，写下一批的近门集合和失效名单。这一状态就是下一拍 frontier 要读的拍初状态。
2. 下一拍 frontier 只为近门车辆打开路线，收集本拍让行要读的 cell；只对失效车辆整段重走；其余车辆按反向索引复用已经记住的冲突距离。
3. 本拍新进入 Active、本拍替换路线、本拍句柄 generation 发生变化的车，必须在本拍就成为别人的接近来源。同一槽位只保留最新 generation。
4. 冲突入口不近于当前拒绝停车的信号门、该车没有冲突 reservation，并且按紧急减速度能在该门前停住时，到达下界不早于本信号周期内的下一档放行。速度为 0 视为已经停住。停不住则保持运动下界。路线游标把上一边终点规范成下一条边的零进度、零余量时，车辆仍停在上一 hop 的准入门上，该门距离按 0 计。

到达下界仍然允许偏早，不允许偏晚。已有 reservation 的车不因红灯被推迟。红灯、零速或没有 reservation 本身不删除这辆车。自己的门候选仍按活动车辆求值；本文只减少别的车本拍能看见的接近记录从哪来。

## 2. 状态放在哪

维护数据放在 `TickWorkspace`，不进入已提交权威，不写入快照，也不提供查询 API。世界身份（`world_id` 与 `WorldGeneration`）对不上、或名单尚未在成功提交时发布时，这一拍退回全量重走。

逻辑上分成四份，不能互相覆盖：

| 数据 | 谁写入 | 谁读取 | 失败时 |
| --- | --- | --- | --- |
| 已发布的近门集合和失效名单 | 成功提交（P7） | 下一拍 frontier | 失败不替换已发布名单 |
| 本拍待发布名单 | 运动结果写出之后、提交之前 | 只由 P7 发布 | 下一次分类先清空再重写。没有证明时窗时不分类、不预留。需要名单时，待发布侧和已发布侧在同一次分类里备好容量 |
| 槽位缓存和 cell 反向索引 | 整段重走 | 复用与分类 | 先按地址备好一个新槽位再拆旧链接。同一地址只记录一次车辆槽位，重复出现项仍留在该车缓存里。唯一地址从可复用 scratch 排序去重一次，不扫描该车缓存前缀，也不为去重扫描其他车辆的成员列表；这份投影与按路线距离保存的出现项序列分开。容量失败时索引保持原样。提交链接中途失败则标记为未发布，下一拍全量重走；生命周期增量保留到成功提交 |
| 生命周期增量 | 两次 `step` 之间的命令 | 下一拍 frontier | 成功提交后才清空。按槽位记下最新 generation，消费时一次整理 |

命令不能插进一次 `step`。增量在 `spawn_vehicle`、`replace_completed_vehicle`、`leave_parking` 和已提交的 `rebind_parking_route` 上记录。`despawn_vehicle` 和进入 `Parked` 时拆掉该槽位的反向索引。快照恢复和修订切换构造新的工作区，不把恢复出来的车记成增量；下一拍走全量重走。

## 3. 近门与失效

分类读取本拍运动结果，也就是下一拍 frontier 的拍初状态。沿用这份已经写好的状态，不再按 Active 顺序重新读取或复制车辆状态。没有证明时窗时不写名单。

记固定步长为 `dt` 秒，缓存里的最大加速度为 `a`（m/s²），下一状态的速度为 `v`（mm/s）。一拍可达上界是：

```text
v * dt + 0.5 * (a * 1000) * dt^2 + 2 mm
```

门距是整段重走时、从当时进度到下一道 Gate 的距离，换边之前不改写。同一条边上用下一状态的进度差扣减。`2 mm` 只吸收边界上的浮点误差，不扩大证明时窗。没有下一道 Gate 时，这辆车不因为门距进入近门集合。

缓存对不上时，这辆车同时进入近门集合和失效名单。对不上是指：没有有效槽位、句柄 generation 不同、路线序号或路线 generation 不同、所在边不同，或进度回退。更远的冲突原先在证明时窗外，按下一状态的剩余距离已经进入该车下一速度和缓存加速度的时窗上界时，也进入失效名单。时窗上界用同一套运动式，时间换成证明时长，并额外加 `1 mm`。比较用的是下一状态的位置和速度，因此本拍已经发生的位移和速度变化都算进失效。

## 4. 本拍 frontier

已发布名单存在时：

1. 为近门车辆和本拍增量打开路线。只收集一拍可达上界内、非受保护 Candidate 门上的让行目标。受保护门、拒绝停车的门，以及已经持有冲突 reservation 的车，不参加这轮目标收集。
2. 整段重走失效车辆、本拍增量和缓存已经对不上的近门车辆。重走使用现行 `PreparedApproachEta`，距离仍是路线上的精确剩余距离。证明时窗外的第一处冲突记下距离后停止，和全量重走的提前退出相同。槽位缓存只保留时窗内的出现项，容量随这些项增长；第一项就在时窗外时，空缓存不预留路线后缀。
3. 其余车辆不打开路线。反向索引只复用本拍目标里出现的 cell：剩余距离等于记下的距离减去同一条边上的进度差，再套当前速度、余量和最大加速度的下界。

目标或复用名单都按确定的地址顺序和 `live_order` 序号处理。cell 里仍然只保留两个不同 owner，排序规则不变。

全量重走只发生在名单尚未发布，或世界身份变化的时候。它仍扫描活动车辆并写入槽位缓存，不读取研究开关，也不是一条可以选回去的旧路径。

## 5. 红灯到达下界

运动下界先按第 4 节算完。然后只在下面的条件同时成立时，再和信号放行下界取较大值：

- 该车没有冲突 reservation；
- 从当前位置沿受控门链能找到当前拒绝其停车的信号门；
- 冲突入口距离不小于该门的距离；
- 按该车紧急减速度能在该门前把速度降到 0。速度为 0 时视为已经停住。紧急减速度不是有限正数时，无法证明能停住，保持运动下界。

放行下界是本周期内、从当前已提交时刻算起、下一档不再把该门解释为拒绝停车的等待时间，最多看一个周期。当前相位本身若仍拒绝，等待从它的结束偏移起算。一个周期内找不到放行档，或周期为 0，就保持运动下界。放行下界晚于该 cell 的证明时窗时，本时窗不插入这条记录；下一拍重新计算。

找当前拒绝停车的门时，从路线游标起算。进度和余量都为 0、且不是路线第一条边时，游标先回到上一 hop：该处仍是上一边的准入门，门距用上一边的长度作为已经走完的基准，停在门上时剩余为 0。

入口比红灯门更近的冲突，包括资源占用那种更近的入口，保持运动下界。这不把占用改写成放行。

## 6. 明确不做

不关闭性能认证父任务，不改 10k / 2 ms 与 100k / 16 ms 的预算，也不把研究测量里的绝对毫秒数写成新产品记录。

不实现稠密 binding、屏障跳过、观测去重、拒绝有效期、轻量候选、车道块、硬间隙投影、同边前车表或延迟物化。不扫描全部 Active 车辆来发现让行目标。不把这套维护放进研究记录分支。

不新增公开 API、数据格式、Adapter 协议或运行时开关。1.0 前只有这一套路径。

## 7. 测试

同一输入、同一计划、同一工人数，结果必须可重复。对照的是同一二进制里的全量重走与本路径，不是历史交通文件哈希。

定向测试至少覆盖：

- 本拍新进入 Active，并且位于近门；下一拍让行能看见它的接近记录。
- 本拍把路线换到近门；这一拍整段重走，不沿用旧路线的缓存。
- 同一车辆下标、generation 已经变化，并且新车位于近门。
- 车停在红灯停止线上、入口距离为 0、没有 reservation 时，到达下界不为 0。进度和余量都为 0 的翻边游标也算停在上一 hop 的准入门上。入口比红灯门更近时不抬高。已有 reservation 的车不套用放行下界。按紧急减速度在红灯门前停不住的车保持运动下界。
- 本周期内的放行档会抬高下界；放行晚于证明时窗则不插入；一个周期内没有放行档时保持运动下界。跨周期后仍按当前周期内的下一档计算。
- 证明时窗外的冲突经过本拍运动进入时窗后，下一拍让行查询能看见这个来源。
- 已发布失效名单里的旧句柄，在槽位被新 generation 复用后，不能压掉新车的接近记录。
- 反向索引提交中途失败后，同一已提交状态上的重试与全量重走给出相同的接近记录。

短窗同边车身重叠必须为 0。一次短窗重叠为 0 不证明所有让行场景都与全量重走等价。
