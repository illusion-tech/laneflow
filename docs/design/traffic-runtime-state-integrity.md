本文是 #955 G1 设计，冻结运行时状态完整性校验的**检测范围**与失真处置的**权威
边界**。背景约束来自 #794 归因收口：普通机器（无系统级 ECC）在内存压力下存在
**页级内存失真**（首个分歧偏移落在 4 KiB 页边界、整页替换、页整数倍位移、伴随
零页；见 `../reference/validation-matrix.md` 环境失真指纹）。确定性（ADR 0003/0030）
是重演的必要条件，但不自动提供正确性判据。

## 1. 问题、设计立场与范围

**问题**：页级内存失真可能把静默损坏写进运行时依赖的数据。宿主检查点对拍
（`(command_cursor, tick, deterministic_state_digest)`，snapshot §6）能在事后定位分歧
区间，但它把「失真」与「确定性缺陷」混在同一信号里；共享静态根被打中时，它还会被
所有世界同时消费，且无法靠回滚或重演修复。

**设计立场**：

- **检测与处置分权**：Runtime 侧提供检测能力并交付结论；停用与恢复处置归宿主（§3、
  ADR 0032）。
- **证据先于机制**：#794 已归因的失真全部来自文件写出 / 读回路径，已由 #954 收口；
  运行中 Runtime 匿名堆的同类失真尚无观测证据。本期只在**根投入使用之前**与**宿主
  显式审计时**认证共享根，不在运行中轮转校验；运行中检测以 #963 的浸泡证据为准入
  条件，进入二期（§9）。
- **无可信基准不作宣称**：期望值无法独立建立或核验时，不得宣称检测或恢复成功；判因
  允许「无法判因」（§2.4、§7）。
- **不改变提交语义与 tick 成本**：完整性不进入 committed-state barrier，不改变 P0–P8 的
  首错、事件与提交语义，不增加每拍工作（§4.4）。
- **1.0 前只留一套权威**：恢复权威落点冻结为一条政策的两个阶段（§3）。

**范围外**（显式不做）：

- 运行中轮转校验（共享根或热状态）——二期入口见 §9；
- 每 tick 全量校验；热状态的 Runtime 内逐写保护（写集增量期望值、逐记录保留期望值、
  工作区与输出批次保护）；
- Runtime 内的根级失效状态与自动失败关闭（停用由宿主执行，§3）；
- 恶意篡改防御（本设计只处理非恶意的环境失真，不构成安全边界）；
- 分布式重放；实现与实测（归 §10 实现切片）；
- 权威落点冻结前的任何自动纠偏（自动回滚、自动重演、自动重写状态）；
- 代码页、栈、宿主自有内存、GPU / 设备内存的完整性（§5 漏检面）。

## 2. 可信期望值与前像（必答第 0 项定案）

### 2.1 前像总表

| 前像           | 定义                                                                                                                                                                                                                            | 管什么                                              | 谁持有期望值                                                                 |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------- |
| 逻辑摘要前像   | #302 确定性状态摘要的规范化前像（`laneflow:runtime-state-digest:v1\0`、digest 7、runtime state 5），布局无关、只覆盖 C(T)；SHA-256，**不替换**                                                                                  | C(T) 逻辑内容；用于宿主检查点对拍与审计重放（§4.3） | 宿主（检查点三元组，ADR 0021）                                               |
| 耐久根内容前像 | **复用** `NetworkRevisionIdV1` 的前像：规范路网语义载荷 `canonicalNetworkSemanticPayloadV1`（语义节 `0x0001..=0x0006` 按 sectionKind 序组帧），摘要 = `SHA-256("laneflow.network-revision.v1\0" ‖ payload)`；不另设编码与域分隔 | 共享根权威语义内容；根认证的依据（§4.2）            | 构建方建立（即 `NetworkRevisionId`），宿主随来源引用持久（受 #954 读回保护） |

**编码复用（不新增规范编码）**：耐久根内容前像的字段清单、整数 / 序列 / 可选值编码、
分段组帧与版本轴全部以 [`portable-canonical-artifact.md` §3.8](portable-canonical-artifact.md#38-路网修订标识)
及其引用的 LFCA 语义节格式为准；任一编码变化必须体现为 `sectionFormatVersion` 或
`networkRevisionDerivationVersion` 变化，不得静默得到不同摘要。构建方与认证方因此
对同一健康根得到逐字节相同的前像。

**派生表**：根的派生表不入耐久前像，由权威内容确定性重建；根认证从已认证的语义内容
重算派生表并与当前根比对（§4.2）。共享静态根不在 C(T) 内（ADR 0030），逻辑层不为
它另设第二份摘要。

### 2.2 期望值来源、时点与绑定

| 对象           | 建立时点（可信时点）                                                                                                                                                                             | 绑定                |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------- |
| 耐久根内容基线 | 构建完成点，由构建方建立：`NetworkRevisionId`（发布来源另含 LFCA digest / exact length）；宿主随来源引用（`PublishedLfcaReference` / `CommittedNetworkSource`）跨进程 / 重启持久，不新增旁车文件 | `NetworkRevisionId` |
| C(T) 逻辑内容  | 宿主检查点：宿主按自己的策略保存检查点并持久三元组                                                                                                                                               | 检查点三元组        |

**根来源期望值（穷尽；任何期望值都不得取自被认证根自身的 `origin`）**：

| `origin` 字段                                                                                   | 期望值的独立来源                                                                          |
| ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `NetworkRevisionId`；LFCA digest / exact length（仅发布来源）                                   | 宿主持久的来源引用，经 #954 读回认证后作为根认证输入                                      |
| `networkRevisionDerivationVersion`、六轴静态契约版本、`partitionPlanningHintsDerivationVersion` | 运行中二进制的编译期常量：reader / builder 本就只接受一组精确版本，这些值不需要也不应持久 |

根来源期望值只在单次根认证调用内存在，不在 Runtime 内常驻；认证按**字段值**（不按
布局取字节）把它与根对象 `origin` 逐字段比对。

**登记时点即期望值冻结点**：共享根构建后不可变，构建完成点之后的任何内容变化都是
失真（与 #954 读回合同的「登记后失真」口径一致）。

**独立核验**：认证从被认证的根**重新读取并计算**，读取必须真实触达被认证字节（不
缓存折叠），使零页与整页替换可被观察；期望值来自宿主持久来源与二进制常量，不来自
被认证对象。

**失配复算确认**：根认证判出失配时，重读来源引用并以新的缓冲 / 候选再跑一次。两次
结论不一致 = `Untrusted`（判因 无法判因，认证过程自身被打中），两次都失配才判
`Mismatch`。复算只在失配路径发生。

### 2.3 认证不变量

1. **基线建立不变量**：耐久根内容基线由构建方从已认证构建输出建立；未核对即建立的
   「自发基准」在任何路径都不合法。根认证不得从被认证根自身取期望值（§2.2）。
2. **checked reserve**：根认证所需缓冲（流式缓冲或重建候选，§11）在认证开始时按计数
   可失败预留（#532 原语）；预留失败 = 可重试的认证失败，不判 `Untrusted`。
3. **只读**：根认证只读共享根，不给根本体引入可变性、原子或内部状态
   （`shared-static-network.md` §8 不变）。

### 2.4 可信基准、失败分类与「无法判因」

**预留失败 ≠ 不可信**：认证期的容量预留失败是可重试的认证失败，不进入失配结论。

**`Untrusted`（认证过程不可信）的生产者（穷尽）**：失配复算两次结论不一致；语义载荷
重算与派生表重算结论冲突（一方通过、一方失配）。不可信时不得宣称检测或恢复成功，
遥测输出「无法判因」。

**检查点、输入命令日志、摘要自身被打中**：三者都由宿主拥有（ADR 0021、snapshot §6），
本设计**不在 Runtime 内登记检查点锚或命令摘要**——Runtime 登记的锚与宿主持久副本
分歧时，无法区分哪一侧被打中，只能判「无法判因」，并不比宿主自己核对持久副本多出
判据。持久侧完整性由 #954 第一层写后回读覆盖；宿主审计重放（§4.3）在独立世界里
重算摘要，摘要值在原世界内存中被打中的情形表现为对拍分歧，交宿主判因。

### 2.5 Rust 有效性约束（保证收窄）

页级失真可以改写枚举判别值、`bool`、引用或 `Vec` / `Box` 的指针、长度与容量。这类
字段一旦被打中，下一次类型化读取就可能触发未定义行为或非法访问，而这可能发生在
根认证之前。因此：

- 根 backing 中任意位模式皆有效的普通数据（序号、范围、整数距离等），以及根对象
  头部的标量语义元数据（`origin` 各字段），失真表现为错误值或越界 panic，前者在下一次
  根认证时可检，后者是可观察的失败停止；
- 含枚举（含 `Option`）、`bool`、`char`、引用或指针的元素类型，以及根对象头部的
  `Arc` / `Box` 元数据，**不承诺**认证时可检；其失真可能直接表现为进程崩溃或未定义
  行为，列入 §5 漏检面。G2 盘点根 backing 中这类类型并给出清单（§11）；
- 进程崩溃对宿主而言是失败停止，宿主按 §3 阶段二处置，但 Runtime 不对其给出判因。

## 3. 恢复权威落点（必答第 1 项定案）

**定案：一条权威政策的两个阶段，不并行第二套**（ADR 0032）。

- **阶段一（检测，停用）**：根认证或宿主审计重放给出非 `Pass` 结论后，失真对象**停止
  使用**——不自动纠偏、回滚、重演或重启。根认证失败的根不得安装、恢复或作为切换
  目标；在用根审计失配时，宿主停止该根的全部消费者（所有世界与 Spatial 会话）。
  停用由宿主执行：Runtime 不持有根级失效状态，也不自行失败关闭。
- **阶段二（处置，归宿主）**：宿主按现行设施恢复，即从检查点恢复并依序重放输入命令
  序列，用检查点三元组对拍定位首个分歧区间（snapshot §6）。Runtime 只交付检测结论、
  判因与失真指纹。

这是现行合同（失同步只诊断、处置归宿主）在完整性维度的延伸：失同步的状态仍是合法
确定性状态，只诊断不停用；完整性失配的对象可信度已被破坏，先停用再处置。两者处置权
相同，区别只在是否停用。

**已发布结果**：停用不撤销已发布事件 / 观测 / 宿主副作用。宿主在自己的边界决定丢弃、
重放或对拍；事件去重与副作用回退属于宿主回放链。

**共享静态根被打中的独立失败语义**：共享根（`SharedNetworkRevision`）不在 C(T) 内，
**不属回滚 / 重演可修复面**。根认证 `Mismatch` / `Untrusted` 时：

- 认证前（安装、恢复、切换之前）：该根不投入使用；宿主按来源重新加载或重编译后再认证；
- 在用根审计：处置只能是**根重建**——宿主停止该根的全部消费者，重编译 / 重新加载并
  认证共享根后，用持久制品 restore 新 world 并绑定新根；不得期望通过检查点回滚或命令
  重演「修好」共享根；
- 遥测把共享根单列判因类别。

**为什么停用由宿主执行**：坏根唯一的处置是宿主重建；Runtime 自行失败关闭不改变处置
路径，却要求每个消费者携带可核对的失效状态（绑定聚合、核对点、发布线性化、快照
门控），这一机制本身又落在同一故障模型之下（§12 第二次收窄）。

**备选取舍记录**：

| 落点                 | 裁决     | 理由                                                                                   |
| -------------------- | -------- | -------------------------------------------------------------------------------------- |
| (a) 检测后交宿主处置 | **采用** | 与 ADR 0021 宿主边界、snapshot §6 处置归属一致；宿主已有检查点 + 命令重放设施          |
| (b) 仅检测后停用     | **采用** | 作为 (a) 的阶段一；单独采用会留下「检出了但没人处置」的悬空态                          |
| (c) 磁盘检查点回滚   | 不采用   | 自动改变状态，承担全套合同修订义务；把宿主存档清单的权威搬进 Runtime，与 ADR 0021 冲突 |
| (d) Runtime 内重演   | 不采用   | 需自持命令权威，等于复制宿主回放链，违背「Runtime 不新增隐藏输入权威」（snapshot §6）  |

(c)(d) 及任何自动改变状态的方案若未来采用，必须先单开 G1 与 ADR，并承担同一合同
修订义务：已发布事件 / 观测 / 宿主副作用处置、句柄映射、修订切换交互、事件去重、
执行主体与宿主协调；不能安全处理已发布结果时停止或交宿主。

## 4. 校验机制合同（必答第 2 项定案）

### 4.1 校验对象分列与本期取舍

| 类别 | 对象                                                      | 本期机制                                                       | 理由                                                                  |
| ---- | --------------------------------------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------- |
| 逻辑 | C(T) 不可变已提交视图                                     | **宿主检查点对拍与审计重放**（#302 摘要，§4.3）                | 见下文「热状态」                                                      |
| 物理 | 热表（车辆、占用、冲突、等待）、工作区                    | **不在 Runtime 内保护**，列入 §5 漏检面                        | 见下文「热状态」                                                      |
| 物理 | 输出批次（events / observations / StepOutcome、位姿批次） | **不保护**，列入 §5 漏检面                                     | 生成到交付在同一次调用内完成；保护需要全部查询入口进入放行状态机      |
| 物理 | 共享静态根                                                | **根认证**：投入使用前与宿主审计时（§4.2）；运行中不轮转（§9） | 不可变、被全部世界共享、不可由回滚 / 重演修复；运行中失真尚无观测证据 |

**热状态为什么不在 Runtime 内保护**：

1. **检测界不成立**。Active 车辆等热记录每拍被读取并重写，下一拍的合法写入**由
   已失真的值推导而来**，失真并未消失，而是进入合法状态并取得新的「正确」期望值。
   轮转校验只有在失真发生后、下一次读取之前恰好轮到该记录时才能检出，单次事件的
   检出概率约为轮转周期的倒数。
2. **成本不可兑现**。逐记录保留期望值与写集增量物理期望值是**每拍**成本：按现行
   #302 规范化的实测量级（release，规范化 + SHA-256：一万条约 2.6–2.7 ms，十万条约
   31–35 ms，不含 capture），十万档每拍仍在毫秒级。
3. **与现行提交实现不匹配**。现行 P7 是对 `committed.vehicles` 等表的原地写，不是指针
   切换。
4. **Rust 有效性**。热表元素（如 `Option<VehicleState>`）含枚举与 padding（§2.5）。
5. **威胁面尚无 Runtime 堆证据**。#794 已归因条目全部来自文件写出 / 读回路径
   （`validation-matrix.md` file-backed emission、`Artifacts::load`、write-readback），
   该路径已由 #954 收口。

### 4.2 共享根认证

- **输入**：被认证的共享根；宿主持久的来源引用（§2.2）。期望值的版本字段取自运行中
  二进制常量。
- **步骤**（全部通过才判 `Pass`）：
  1. 根 `origin` 与根来源期望值逐字段比对；
  2. 按 §2.1 复用的前像取得语义载荷，重算 `NetworkRevisionIdV1` 与来源引用比对（取得
     路径 G2 二选一，§11）；
  3. 从已认证的语义内容确定性重算派生表，与当前根比对；
  4. 任一步失配按 §2.2 复算确认。
- **调用时机**：宿主在**安装、恢复与切换之前**认证将要投入使用的根（构建 / 加载之后、
  首次绑定之前）；宿主可在任意时刻对**在用根**发起审计认证，频率由宿主策略决定。
  认证是宿主调用的只读入口，不改变 `TrafficWorld::install`、`restore_lfrs`、
  `SpatialSession::bind` 与切换入口的签名与语义；宿主未调用时无检测（§5 第 11 条）。
- **并发**：认证只读不可变根，可与在用世界的 `step` 并发进行，不加锁、不阻塞消费者。
- **结论交付**：返回 `Pass` / `Mismatch` / `Untrusted`、判因与失真指纹（§7）；结论
  不写入根、世界或快照。

### 4.3 C(T) 的宿主审计重放

C(T) 的失真检测沿用现行宿主设施，不新增 Runtime 合同：

- 宿主按自己的策略保存检查点并持久三元组（snapshot §6）；
- **审计重放**：宿主可在独立世界（同进程、独立进程或另一台机器）从较早检查点重放
  输入命令至较晚检查点，比对三元组；分歧即首个分歧区间。原世界内进入 C(T) 的失真
  （含被消费后传播的热状态失真）与摘要值本身的失真表现为对拍分歧。只比对三元组
  **不覆盖输出批次**——生成之后才失真、未进入 C(T) 的事件、观测、`StepOutcome` 与
  位姿批次不产生分歧（§5 第 2 条）；宿主若要覆盖输出，可自行记录输出批次并在重放时
  逐批比对，这是宿主策略，不形成 Runtime 合同；
- **换机器重放是判因证据，不是判因结论**：时序或平台相关的缺陷可能在另一台机器上
  不复现，宿主自有的检查点或命令日志被打中也可能独立地复现或不复现；区分环境失真
  与确定性缺陷需要独立认证的输入与重复重放共同支持，宿主据此判因；
- 检测滞后 = 宿主检查点间隔 + 重放耗时，由宿主策略决定，Runtime 不承诺界；
- Runtime 侧的义务只有一条（实现切片 C）：提供**有界成本的 #302 摘要路径**——直接
  从 C(T) 流式计算、不按记录分配，使宿主能在检查点 cadence 上负担摘要；摘要字节与
  #302 冻结前像逐字节一致，不新增摘要版本。

### 4.4 时序与操作边界

- **不进入 tick 路径**：根认证不在 P0–P8 内，不改变首错、事件与提交语义，不增加
  `StepError`；`step`、生命周期命令、观测导出、位姿提取与快照保存的签名与成本不变。
- **不进入 committed-state barrier**：认证只读不可变根，与提交阶段无交集；worker 数
  不进入任何前像（ADR 0030）。
- **快照保存**：不加完整性门控——C(T) 不在 Runtime 内受检，门控不提供额外判据。检测
  滞后内被保存的检查点可能包含坏状态（§5 第 7 条）。

### 4.5 选型原则与碰撞声明

- **逻辑层**：SHA-256（#302 冻结，不替换、不新增第二逻辑摘要算法）。
- **耐久根内容前像**：复用 `NetworkRevisionIdV1`（SHA-256，域分隔
  `laneflow.network-revision.v1\0`），不新增算法与域分隔。
- **失败口径**：失配或认证过程不可信即判非 `Pass`；不设容差，不取多数。
- **残余风险**：认证按 SHA-256 第二原像假设定性声明，不作数值保证级声明。任何
  「通过」结论只覆盖声明对象与认证时刻。

## 5. 检测时机与漏检面（必答第 3 项定案）

**检测时机（本期）**：共享根在每次投入使用之前认证一次，运行中由宿主按需审计；
Runtime 内**无轮转、无抽样、无增量**。共享根的检测滞后 = 失真发生到下一次宿主审计
或下一次重新认证的间隔，由宿主策略决定，Runtime 不承诺上界。C(T) 的检测滞后由宿主
检查点与审计重放策略决定（§4.3）。

**显式漏检面（总表）**：

1. **热状态全部**（车辆、占用、冲突、等待、工作区）：Runtime 内不检；失真被消费后会
   传播为合法状态（§4.1）。只由宿主审计重放在检查点粒度兜底；
2. **输出批次**（事件、观测、`StepOutcome`、位姿批次）：生成到交付之间的失真不可检，
   宿主审计重放只比对三元组也不覆盖（§4.3）；
3. **每世界已编译路线表**：注册后不可变，但本期不保护（候选二期对象，§9）；
4. **Rust 有效性破坏**（§2.5）：枚举判别值、指针、长度等被打中时可能在认证之前崩溃或
   触发未定义行为；
5. **两次认证之间的根失真**：根投入使用之后、下一次宿主审计之前发生的失真，在此期间
   被所有消费者读取，产生的状态与输出由宿主据检测时间点处置；宿主不审计时没有检测
   上界；
6. **认证期间的并发消费**：在用根审计与 `step` 并发时，认证给出结论之前的消费同样
   基于该根，归入第 5 条；
7. **检出前固化**：检测滞后内被保存的检查点可能包含坏状态；兜底为宿主审计重放与处置
   丢弃；
8. **认证结论之后的失真**：`Pass` 只覆盖认证时刻；结论交付之后的失真归第 5 条；
9. **未覆盖面**：代码页、栈（含认证中间状态）、宿主自有内存、GPU / 设备内存、宿主
   持久层（后者由 #954 与宿主合同覆盖）；
10. **登记即错**：构建方从已失真的输入建立耐久内容基线——由构建侧认证（LFCA 摘要、
    #954 读回）兜底，Runtime 不可检；
11. **宿主未调用认证或审计**：认证是宿主调用的入口（§4.2），未调用时对应时点无检测。

## 6. retained-memory 裁决与分类方案（必答第 4 项定案）

**裁决**：服从第 1 项落点——Runtime 内不常驻任何完整性状态；每世界、每根的**稳态保留
新增为零**。根认证只有认证期峰值，结束即释放；验证点不承载回滚 / 重演 / 纠偏能力。

**#380 账本穷尽分类**：

| 所有权类目                            | 性质     | 规模说明                                                                       |
| ------------------------------------- | -------- | ------------------------------------------------------------------------------ |
| 根认证缓冲（流式缓冲或重建候选，§11） | 认证峰值 | 认证期间短持有：反向编码约为流式缓冲，重建比对约为一份根；与根构建峰值同期报告 |
| 诊断 / 遥测缓冲                       | 认证峰值 | 有界，仅在失配时持有                                                           |

**分列口径**：实现报告把「稳态保留 / 认证峰值 / 宿主恢复峰值」三列分开，不得相加冒充
单一数字；稳态保留一列须实测为零。宿主恢复峰值（restore + 重放）按 snapshot §8 度量，
不属 Runtime 侧。

## 7. 结论与遥测级别（必答第 5 项定案）

**认证结论三值**：

| 结论        | 含义                               | 语义                             |
| ----------- | ---------------------------------- | -------------------------------- |
| `Pass`      | 本次认证覆盖的内容全部一致         | 只覆盖声明对象与认证时刻，不外推 |
| `Mismatch`  | 期望值与重算值不等，复算确认仍不等 | 宿主停用该根（§3）               |
| `Untrusted` | 认证过程不可信（§2.4）             | 宿主停用该根；判因「无法判因」   |

**失败分类不变量**：认证期的预留失败是可重试的认证失败；`Mismatch` / `Untrusted` 才
要求停用。二者不得混同。

**判因轴**：`物理-共享静态根` / `无法判因`。C(T) 的判因归宿主审计重放，不在 Runtime
判因轴内。可定位时（派生表比对能给出首个分歧位置）附失真指纹分类（与 #794 /
`validation-matrix.md` 对齐）：页边界偏移、整页替换、页整数倍位移、零页、非页对齐
（后者提示非环境失真，转代码嫌疑）；语义载荷摘要失配只能判对象级，不附位置。

**遥测级别**（递进包含）：

| 级别             | 内容                                                                                                     | 默认 |
| ---------------- | -------------------------------------------------------------------------------------------------------- | ---- |
| `L0 Trace`       | 认证步骤进度                                                                                             | 关   |
| `L1 Verdict`     | 认证结论、认证时刻，以及距上次 `Pass` 的时间（检测滞后的**上界**；无注入时间戳时不报告「实际检测滞后」） | 开   |
| `L2 Mismatch`    | 失配现场：失配步骤、可定位时的位置与期望 vs 实际、指纹分类                                               | 开   |
| `L3 Disposition` | 判因 + 处置提示（根重建入口）                                                                            | 开   |

实际检测滞后只在故障注入中以注入时间戳计算。遥测不进入 C(T)、摘要与快照；遥测失败
不改变认证结论。

## 9. 二期入口：运行中检测

运行中检测（共享根的运行中轮转校验，以及热状态的 Runtime 内保护）不属本设计；若要
进入，必须另开 G1，并至少满足：

1. **证据**：故障机上的 Runtime 长时浸泡 + 宿主审计（§4.2、§4.3）观测到运行中失真，
   给出频率、对象与指纹（#963）；
2. **检测概率**：对每拍重写的对象如实给出单事件检出概率，不得用轮转周期冒充检测界；
3. **成本**：以同二进制开 / 关差值实测给出每拍成本，不得以「摊销」掩盖每拍固定成本；
4. **提交实现**：说明与原地写 P7 的关系及对现行性能工作的约束；
5. **Rust 有效性**：说明受保护对象的布局如何满足任意位模式有效，或如实收窄保证；
6. **封闭写法**：以通则而非逐项列举声明可信面（哪些内存按可信或未覆盖处理）、校验器
   自身控制状态的保护规则（新增状态自动适用）与消费面（只有列明的操作推进校验，其余
   读根路径统一归漏检面），并说明失效状态如何随根跨任务传递而不留只持根的旁路
   （§12 第二次收窄记录了逐项列举不收敛的原因）。

候选对象按价值排序：共享根运行中轮转 → 每世界已编译路线表（注册后不可变，成本只
发生在注册时）→ Parked / Completed 记录 → 其余热表。
