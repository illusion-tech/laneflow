本文是 #955 G1 设计，冻结运行时状态完整性校验的**检测范围**与失真处置的**权威
边界**。背景约束来自 #794 归因收口：普通机器（无系统级 ECC）在内存压力下存在
**页级内存失真**（首个分歧偏移落在 4 KiB 页边界、整页替换、页整数倍位移、伴随
零页；见 `../reference/validation-matrix.md` 环境失真指纹）。确定性（ADR 0003/0030）
是重演的必要条件，但不自动提供正确性判据。

**本版范围是审阅后收窄的结果**（取舍见 §12 修订记录）：Runtime 内检测只覆盖**不可变
的共享静态根**；每拍读后重写的热状态（车辆、占用、冲突、等待、工作区、输出批次）
不在 Runtime 内逐写保护，由宿主审计重放覆盖，并在 §5 如实声明漏检面。热状态的
Runtime 内保护若要进入，须先有 Runtime 堆失真的观测证据，并另开 G1（§9）。

## 1. 问题、设计立场与范围

**问题**：页级内存失真可能把静默损坏写进运行时依赖的数据。宿主检查点对拍
（`(command_cursor, tick, deterministic_state_digest)`，snapshot §6）能在事后定位分歧
区间，但它把「失真」与「确定性缺陷」混在同一信号里；共享静态根被打中时，它还会被
所有世界同时消费，且无法靠回滚或重演修复。

**设计立场**：

- **检测与处置分权**：Runtime 负责检测并失败关闭；恢复处置归宿主（§3、ADR 0032）。
- **检测放在检测有效、成本可控的地方**：只有在失真被消费并传播之前、对象不会被
  合法写入覆盖时，轮转校验才有可兑现的检测界。满足这一点的是不可变的共享静态根，
  而不是每拍重写的热状态（论证见 §4.1）。
- **无可信基准不作宣称**：期望值无法建立或独立核验时，不得宣称检测或恢复成功；
  判因允许「无法判因」（§2.4、§7）。
- **不改变提交语义**：校验不进入 committed-state barrier，不改变 P0–P8 的首错、
  事件与提交语义，不因执行块切分额外延迟一拍（§4.4）。
- **1.0 前只留一套权威**：恢复权威落点冻结为一条政策的两个阶段（§3）。

**范围外**（显式不做）：

- 每 tick 全量校验；热状态的 Runtime 内逐写保护（写集增量期望值、逐记录保留期望值、
  工作区与输出批次保护）——本期不做，二期入口见 §9；
- 恶意篡改防御（本设计只处理非恶意的环境失真，不构成安全边界）；
- 分布式重放；
- 实现与实测（归 §10 实现切片）；
- 权威落点冻结前的任何自动纠偏（自动回滚、自动重演、自动重写状态）；
- 代码页、栈、宿主自有内存、GPU / 设备内存的完整性（§5 漏检面）。

## 2. 可信期望值与前像（必答第 0 项定案）

### 2.1 前像总表

| 前像             | 定义                                                                                                                                                                       | 管什么                                                        | 谁持有期望值                                 |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- | -------------------------------------------- |
| 逻辑摘要前像     | #302 确定性状态摘要的规范化前像（`laneflow:runtime-state-digest:v1\0`、digest 7、runtime state 5），布局无关、只覆盖 C(T)；SHA-256，**不替换**                             | C(T) 逻辑内容；用于宿主检查点对拍与审计重放（§4.3）           | 宿主（检查点三元组，ADR 0021）               |
| 耐久根内容前像   | 共享根**权威语义内容**的规范序列化（公开语义字段规范序；不含布局 / 地址 / capacity / 派生表）：`laneflow:shared-root-content:v1\0` + `NetworkRevisionId` + 版本轴；SHA-256 | 跨进程 / 重启可用的共享根内容基线；安装认证与全量重认证的依据 | 构建方建立，宿主旁车持久（受 #954 读回保护） |
| 根物理完整性前像 | 共享根 backing 按实际字节布局逐页计算：`laneflow:physical-integrity:v1\0` + 区域种类 + 页序 + 长度 + 内容字节（**仅已初始化字节**）                                        | 共享根物理字节是否被页替换、零页、页整数倍位移改写；布局绑定  | Runtime 侧共享根绑定聚合（每根一份，§4.2）   |

两层边界：逻辑摘要前像不因布局变化而变；根物理前像逐页绑定物理布局。根的派生表
不入耐久前像，由权威内容确定性重建，其物理正确性由根物理前像承接。共享静态根不在
C(T) 内（ADR 0030），逻辑层不为它另设第二份摘要。

**初始化字节约束**：根物理前像只覆盖已初始化字节。保护区页（共享根 backing）的全部
已初始化字节必须属于权威语义内容或派生表；padding 等未初始化字节所在部分不入前像，
记入 §5 漏检面。

### 2.2 期望值来源、时点与绑定

| 对象           | 建立时点（可信时点）                                                                                                                                                                                                                                | 绑定                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |
| 耐久根内容基线 | 构建完成点，由构建方建立；宿主持久旁车携带，跨进程 / 重启持久                                                                                                                                                                                       | `(NetworkRevisionId, 分段)` |
| 根物理布局基线 | 安装 / 认证点：以耐久根内容基线核对当前 backing，**并从已认证权威内容确定性重算派生表与当前 backing 比对**；两者都通过才建立物理布局基线，比对与建基线取**同一遍读**。不持久；重启 / 重载必须重建，不得沿用旧基线，也不得在核对内容基线之前自行建立 | `(区域种类, 页序)`          |
| C(T) 逻辑内容  | 宿主检查点：宿主按自己的策略保存检查点并持久三元组                                                                                                                                                                                                  | 检查点三元组                |

**登记时点即期望值冻结点**：共享根安装后不可变，物理布局基线建立后的任何字节变化
都是失真（与 #954 读回合同的「登记后失真」口径一致）。

**独立核验**：校验路径与写入路径分离——根校验从被校验页**重新读取并计算**前像与
基线比对；读取必须真实触达被校验字节（不缓存折叠），使零页与整页替换可被观察。
物理布局基线本身的构造缺陷由**全量重认证**（以耐久根内容前像重算，不同构造谱系）
兜底（§4.2）。

### 2.3 保护不变量

1. **页隔离**：根基线表（物理布局基线的期望值数组）与共享根 backing **不得同页**；
   建立基线时断言两组页号不相交，断言失败 = `Untrusted`。
2. **双副本**：根基线表保存主副本与复核副本，两者不同分配、不同布局；主 / 复核
   分歧 = `Untrusted`。
3. **校验器控制状态**：根校验游标为单调计数，双写并互证；回退或副本分歧 =
   `Untrusted`。
4. **租约状态**：共享根完整性租约的失效标记双副本分歧**视为已置位**（fail-safe，
   不得把毒性洗掉）；失效世代单调，单副本跨两次读下降 = `Untrusted`。
5. **基线建立不变量**：一切基线的建立必须以既有可信参照核对为前置（物理布局基线以
   耐久内容基线为参照；耐久内容基线由构建方从已认证构建输出建立）。未核对即建立的
   「自发基准」在任何路径都不合法。
6. **checked reserve**：根基线表、复核副本与 scrub 读缓冲在安装 / 认证时按计数可失败
   预留（#532 原语）；预留失败 = 安装失败、零部分安装，不置 `Untrusted`。

### 2.4 可信基准、失败分类与「无法判因」

**预留失败 ≠ 不可信**：安装 / 认证期的容量预留失败是可重试的安装失败，不进入完整性
失败关闭态。

**`Untrusted`（校验过程不可信）的生产者（穷尽）**：页隔离断言失败；根基线表主 / 复核
分歧；校验器控制状态失配或回退；租约内部失配（§2.3 第 4 条）；全量重认证与物理
布局基线结论冲突（物理基线判通过、内容重认证判失配，或反之）。不可信时不得宣称检测
或恢复成功：失败关闭，遥测输出「无法判因」。

**检查点、输入命令日志、摘要自身被打中**：三者都由宿主拥有（ADR 0021、snapshot §6），
本设计**不在 Runtime 内登记检查点锚或命令摘要**——Runtime 登记的锚与宿主持久副本
分歧时，无法区分哪一侧被打中，只能判「无法判因」，并不比宿主自己核对持久副本多出
判据。持久侧完整性由 #954 第一层写后回读覆盖；宿主审计重放（§4.3）在独立世界里
重算摘要，摘要值在原世界内存中被打中的情形表现为对拍分歧，交宿主判因。

### 2.5 Rust 有效性约束（保证收窄）

页级失真可以改写枚举判别值、`bool`、引用或 `Vec` / `Box` 的指针、长度与容量。这类
字段一旦被打中，下一次类型化读取就可能触发未定义行为或非法访问，而这发生在 scrub
发现之前。因此本设计的保证**收窄为**：

- 保护区 backing 的元素类型应为**任意位模式皆有效**的普通数据（序号、范围、整数
  距离等）；通过 checked 索引消费时，失真表现为越界 panic 或错误值，前者是可观察的
  失败停止，后者所在页在被预检轮到时可检；
- 含枚举（含 `Option`）、`bool`、`char`、引用或指针的元素类型，以及根对象头部的
  `Arc` / `Box` 元数据，**不承诺**检出后失败关闭；其失真可能直接表现为进程崩溃或
  未定义行为，列入 §5 漏检面。G2 必须盘点根 backing 中这类类型并给出清单；
- 进程崩溃对宿主而言是失败停止，宿主按 §3 阶段二处置，但 Runtime 不对其给出判因。

## 3. 恢复权威落点（必答第 1 项定案）

**定案：一条权威政策的两个阶段，不并行第二套**（ADR 0032）。

- **阶段一（检测，失败关闭）**：校验发现失配或校验过程不可信，立即失败关闭——世界
  停止推进，不自动纠偏、回滚、重演或重启。
- **阶段二（处置，归宿主）**：宿主按现行设施恢复，即从检查点恢复并依序重放输入命令
  序列，用检查点三元组对拍定位首个分歧区间（snapshot §6）。Runtime 只交付检测结论、
  判因与失真指纹。

这是现行合同（失同步只诊断、处置归宿主）在完整性维度的延伸：失同步的状态仍是合法
确定性状态，只诊断不停机；完整性失配的状态可信度已被破坏，先失败关闭再交宿主。
两者处置权相同，区别只在是否停机。

**已发布结果**：失败关闭不撤销已发布事件 / 观测 / 宿主副作用；失败关闭确立后不再接受
任何提交。宿主在自己的边界决定丢弃、重放或对拍；事件去重与副作用回退属于宿主回放链。

**共享静态根被打中的独立失败语义**：共享根（`SharedNetworkRevision`）不在 C(T) 内，
**不属回滚 / 重演可修复面**。触发条件 = 根校验的任何 `Mismatch` 或 `Untrusted`。触发时：

- 检测方所在操作以完整性终止性错误结束，不进入提交；
- **根级失效（poison）传播**：失效状态**不写入共享根本体**（共享根保持不可变、无原子、
  无内部可变，[`shared-static-network.md`](shared-static-network.md) §8），而由**共享根
  完整性租约**承载。租约随**共享根绑定聚合**（根 `Arc` + 租约 + 构建方旁车基线 + 根
  校验器 + 完整性模式）跨边界传递；安装、绑定、恢复与切换输入一律携带聚合，**不存在
  只传根、拿不到租约的绑定路径**；同根只能有一份租约（同根不同租约 = 绑定失败）；
- **核对点**：全部消费者（世界与 Spatial）在每次消费操作入口核对租约，并在不可回退的
  发布点之前复核（P7 开始前、生命周期命令提交前、位姿批次交付前、切换原子更替前、
  恢复 world 发布前）；复核 = 毒标已置 ∨ 世代 ≠ 入口快照，不一致即不提交 / 不交付并
  失败关闭。poison 置位是非阻塞的单调写；复核之后已在途、即将落地的那一次发布允许
  完成，此后不再接受提交；
- 处置只能是**根重建**：重编译 / 重安装 / 重新认证共享根后，宿主用持久制品 restore 新
  world 并绑新聚合；宿主不得期望通过检查点回滚或命令重演「修好」共享根；
- 遥测把共享根单列判因类别；根级失效是共享事件，单列遥测；
- **「事务放弃」与「完整性失败关闭」分词**：切换 / 恢复失败回旧世界继续是事务放弃
  （不置粘滞）；但其中检出的聚合侧 `Mismatch` / `Untrusted` 仍并行触发根级失效，
  两者独立结算（[`traffic-runtime-revision-cutover.md`](traffic-runtime-revision-cutover.md) §8）。

**备选取舍记录**：

| 落点                 | 裁决     | 理由                                                                                   |
| -------------------- | -------- | -------------------------------------------------------------------------------------- |
| (a) 检测后交宿主处置 | **采用** | 与 ADR 0021 宿主边界、snapshot §6 处置归属一致；宿主已有检查点 + 命令重放设施          |
| (b) 仅校验失败关闭   | **采用** | 作为 (a) 的阶段一；单独采用会留下「检出了但没人处置」的悬空态                          |
| (c) 磁盘检查点回滚   | 不采用   | 自动改变状态，承担全套合同修订义务；把宿主存档清单的权威搬进 Runtime，与 ADR 0021 冲突 |
| (d) Runtime 内重演   | 不采用   | 需自持命令权威，等于复制宿主回放链，违背「Runtime 不新增隐藏输入权威」（snapshot §6）  |

(c)(d) 及任何自动改变状态的方案若未来采用，必须先单开 G1 与 ADR，并承担同一合同
修订义务：已发布事件 / 观测 / 宿主副作用处置、句柄映射、修订切换交互、事件去重、
执行主体与宿主协调；不能安全处理已发布结果时停止或交宿主。

## 4. 校验机制合同（必答第 2 项定案）

### 4.1 校验对象分列与本期取舍

| 类别 | 对象                                                      | 本期机制                                                                  | 理由                                                                  |
| ---- | --------------------------------------------------------- | ------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 逻辑 | C(T) 不可变已提交视图                                     | **宿主检查点对拍与审计重放**（#302 摘要，§4.3）；Runtime 不新增逻辑层轮转 | 见下文「热状态」                                                      |
| 物理 | 热表（车辆、占用、冲突、等待）、工作区                    | **不在 Runtime 内保护**，列入 §5 漏检面                                   | 见下文「热状态」                                                      |
| 物理 | 输出批次（events / observations / StepOutcome、位姿批次） | **不保护**，列入 §5 漏检面                                                | 生成到交付在同一次调用内完成；保护需要全部查询入口进入放行状态机      |
| 物理 | 共享静态根 backing                                        | **根校验器**：入口预检轮转 scrub + 全量重认证（§4.2）                     | 不可变、被全部世界共享、不可由回滚 / 重演修复，轮转校验的检测界可兑现 |

**热状态为什么不在 Runtime 内保护**（审阅结论，§12）：

1. **检测界不成立**。Active 车辆等热记录每拍被读取并重写，下一拍的合法写入**由
   已失真的值推导而来**（下一个位置从被打坏的 `progress_mm` 推进），失真并未消失，
   而是进入合法状态并取得新的「正确」期望值。轮转校验只有在失真发生后、下一次读取
   之前恰好轮到该记录时才能检出：每窗覆盖 1/`M` 的轮转，单次事件的检出概率约为
   1/`M`（`M` = 128 时约 0.8%）。对热状态而言，秒级检测界只是名义值。
2. **成本不可兑现**。逐记录保留期望值与写集增量物理期望值是**每拍**成本，而不是摊销
   成本：十万档 Active 车辆每拍都变；按现行 #302 规范化的实测量级（release，规范化 +
   SHA-256：一万条约 2.6–2.7 ms，十万条约 31–35 ms，不含 capture），即使换成不分配
   的序列化与非密码哈希，十万档每拍仍在毫秒级，超出 5% 预算数倍；工作区与占用索引
   每拍几乎整体重写，写集增量约等于每拍对热数据全量哈希。
3. **与现行提交实现不匹配**。现行 P7 是对 `committed.vehicles` 等表的原地写（逐槽写回、
   `retain`、转移提交），不是指针切换；「期望值与状态同一原子发布」需要新增双缓冲
   登记表，「保护区一切物理写经写集路径」需要改造 `laneflow-runtime` 中所有写热表的
   路径。
4. **Rust 有效性**。热表元素（如 `Option<VehicleState>`）含枚举与 padding，失真后可能
   在 scrub 之前就触发未定义行为（§2.5），检出后失败关闭无法承诺。
5. **威胁面尚无 Runtime 堆证据**。#794 已归因条目全部来自文件写出 / 读回路径
   （`validation-matrix.md` file-backed emission、`Artifacts::load`、write-readback），
   该路径已由 #954 收口；运行中 Runtime 匿名堆的同类失真尚未观测到。

### 4.2 根校验器

- **持有方**：根校验器挂在共享根绑定聚合上（每根一份、非每世界），持有根基线表（主 /
  复核）、轮转游标与 scrub 读缓冲；全部消费者共享。
- **推进方式（入口预检）**：每次消费操作（世界 `step`、Spatial 位姿提取）在入口、
  任何提交工作开始之前，以原子方式从共享游标领取**不相交的 K 页区间**并完成校验，
  校验通过后操作才继续。这一推进方式**不可绕过**——它就在消费操作内部，没有可以
  不调用的单独校验入口；失败的 `step` 尝试同样在入口完成预检。多消费者并发领取
  不丢页、不回退游标。
- **结论处理**：`Mismatch` / `Untrusted` → 置位根级失效（§3），当前操作以完整性终止性
  错误结束（P0 不开始 / 提取不交付），全部绑定消费者在下一个核对点失败关闭。
- **全量重认证**：安装、绑定新聚合、恢复、切换以及宿主显式审计时，以耐久根内容前像
  全量重认证并重算派生表比对（与 §2.2 建基线同一路径）。这是独立于物理布局基线的
  第二构造谱系，覆盖物理基线构造缺陷与基线表共因失真；结论冲突 = `Untrusted`。
- **无消费不推进**：没有消费者时游标不推进；此期间根未被消费，失真也没有暴露面。

### 4.3 C(T) 的宿主审计重放

C(T) 的失真检测沿用现行宿主设施，不新增 Runtime 合同：

- 宿主按自己的策略保存检查点并持久三元组（snapshot §6）；
- **审计重放**：宿主可在独立世界（同进程、独立进程或另一台机器）从较早检查点重放
  输入命令至较晚检查点，比对三元组；分歧即首个分歧区间。原世界内的失真（含热状态、
  输出、摘要值本身）表现为对拍分歧；换机器重放可区分环境失真与确定性缺陷；
- 检测滞后 = 宿主检查点间隔 + 重放耗时，由宿主策略决定，Runtime 不承诺界；
- Runtime 侧的义务只有一条（实现切片 C）：提供**有界成本的 #302 摘要路径**——直接
  从 C(T) 流式计算、不按记录分配，使宿主能在检查点 cadence 上负担摘要；摘要字节与
  #302 冻结前像逐字节一致，不新增摘要版本。

### 4.4 时序与操作边界

- **入口预检位于 P0 之前**：它只读不可变的共享根与根校验器自有状态，不读写 C(T)；
  预检失败时 P0 不开始，不改变 P0–P8 的首错、事件与提交语义，不增加可恢复
  `StepError`；`step` 仍同步返回，成功路径的返回类型不变（错误轴扩展见 §7）。
- **跨块不额外延迟一拍**：预检在分发之前串行完成，执行块与 worker 切分不改变预检
  位置、检测滞后与期望值；worker 数不进入根基线表或任何前像（ADR 0030）。
- **不进入 committed-state barrier**：预检不在 P0–P8 之内；租约复核是对单一原子世代的
  读取，不引入新的提交阶段。
- **快照保存**：失败关闭的世界拒绝保存（§7）；本期不对正常世界的保存路径加门控——
  C(T) 不在 Runtime 内受检，门控不提供额外判据（§5 第 7 条）。

### 4.5 选型原则与碰撞声明

- **逻辑层**：SHA-256（#302 冻结，不替换、不新增第二逻辑摘要算法）。
- **耐久根内容前像**：SHA-256，独立域分隔。
- **根物理前像**：128 位非密码哈希（G2 选型，见 §11）；主 / 复核副本可同算法，因为
  构造缺陷与共因由全量重认证（不同谱系）承接。
- **失败关闭口径**：失配或校验过程不可信即失败关闭；不设容差，不取多数。
- **残余风险**：根物理层按所选构造声明单页单事件的未检出概率（固定非密码算法为
  随机失真内容模型下的启发式值，不作保证级声明）；全量重认证按 SHA-256 第二原像假设
  定性声明；`N_evt` 次事件累计 ≤ `N_evt` × p，不做独立性承诺。任何「通过」结论只
  覆盖声明对象与范围。

## 5. 间隔、抽样与漏检面（必答第 3 项定案）

**根校验间隔（导出值）**：

```text
M_root = min(标称次数, floor(60 s / fixed_delta_time_ms))     （按消费次数计）
K      = ceil(根保护页数 / M_root)                             （每次入口预检页数）
共享根检测滞后 = M_root 次消费；按标称 cadence 每拍消费时 ≤ 60 s
```

- **60 s 为合同值**（按世界时间计）；`M_root` 与 `K` 是导出值。长步长配置（ADR 0028
  允许到 1000 ms）下 `M_root` 按上式收敛，不得沿用标称次数突破秒上限。
- 稀疏消费者（如纯 Spatial 按宿主调度提取）的检测滞后**以消费次数计**；未消费期间
  根没有暴露面，不需要额外的墙钟推进。
- `K` 由根保护页数与 §8 预算共同约束；若 `K` 使预检超出预算，按 §8 回 G1，不得放宽
  60 s。
- 热状态与 C(T) 不在 Runtime 内抽样；其检测滞后由宿主检查点策略决定（§4.3）。

**显式漏检面（总表）**：

1. **热状态全部**（车辆、占用、冲突、等待、工作区）：Runtime 内不检；失真被消费后会
   传播为合法状态（§4.1）。只由宿主审计重放在检查点粒度兜底；
2. **输出批次**（事件、观测、`StepOutcome`、位姿批次）：生成到交付之间的失真不可检；
3. **每世界已编译路线表**：注册后不可变，但本期不保护（候选二期对象，§9）；
4. **Rust 有效性破坏**（§2.5）：枚举判别值、指针、长度等被打中时可能在检出前崩溃或
   触发未定义行为，不承诺检出后失败关闭；
5. **检出前消费**：根失真发生后、被预检轮到之前，消费者读取坏值产生的状态与输出——
   根级失效确立后宿主据检测时间点处置；
6. **根基线表主 / 复核同击中且保持一致**：由全量重认证兜底，重认证之前不可检；
7. **检出前固化**：检测滞后内被保存的检查点可能包含坏状态；兜底为宿主审计重放与处置
   丢弃；
8. **未初始化字节**（padding 等）不在根物理前像内；
9. **未覆盖面**：代码页、栈、宿主自有内存、GPU / 设备内存、宿主持久层（后者由 #954
   与宿主合同覆盖）；
10. **登记即错**：构建方从已失真的输入建立耐久内容基线——由构建侧认证（LFCA 摘要、
    #954 读回）兜底，Runtime 不可检。

## 6. retained-memory 裁决与分类方案（必答第 4 项定案）

**裁决**：服从第 1 项落点——验证点只有**共享根绑定聚合**一处（每根一份，2/8/32 worlds
共享、不随世界数放大）；每世界只增加 O(1) 的失败关闭状态。验证点只有检测面，不承载
回滚 / 重演 / 纠偏能力。

**#380 账本穷尽分类**：

| 所有权类目                         | 性质     | 规模说明                                                        |
| ---------------------------------- | -------- | --------------------------------------------------------------- |
| 根基线表主副本                     | 稳态保留 | O(根保护页数)，每页一个物理前像值                               |
| 根基线表复核副本                   | 稳态保留 | 同上（不同分配 / 布局）                                         |
| 耐久根内容基线（旁车载入副本）     | 稳态保留 | O(根分段数)                                                     |
| 共享根完整性租约与根校验器控制状态 | 稳态保留 | 每根 O(1)（失效标记双副本 + 失效世代 + 游标双写）               |
| 根 scrub 读缓冲                    | 稳态保留 | 固定 K 页；安装时预留、每次预检复用，按稳态计（不按窗口峰值计） |
| 每世界失败关闭状态                 | 稳态保留 | 每世界 O(1)                                                     |
| 全量重认证缓冲                     | 认证峰值 | 安装 / 恢复 / 切换 / 审计时短持有；与根构建峰值同期报告         |
| 诊断 / 遥测缓冲                    | 认证峰值 | 有界，仅在失配时持有                                            |

**分列口径**：实现报告把「稳态保留 / 认证峰值 / 宿主恢复峰值」三列分开，不得相加冒充
单一数字。宿主恢复峰值（restore + 重放）按 snapshot §8 度量，不属 Runtime 侧。
完整性关闭配置下，根基线表、复核副本、scrub 缓冲为零，租约为空操作。

## 7. 失败语义与遥测级别（必答第 5 项定案）

**校验结论三值**：

| 结论        | 含义                              | 语义                                  |
| ----------- | --------------------------------- | ------------------------------------- |
| `Pass`      | 本次预检 / 重认证覆盖的页全部一致 | 只覆盖声明对象与范围，不外推          |
| `Mismatch`  | 期望值与重算值不等                | 失败关闭 + 根级失效                   |
| `Untrusted` | 校验过程不可信（§2.4）            | 失败关闭 + 根级失效；判因「无法判因」 |

**失败分类不变量**：安装 / 认证期的预留失败是可重试的安装失败；`Mismatch` /
`Untrusted` 才触发粘滞失败关闭。二者不得混同。

**失败关闭语义**：世界进入完整性失败关闭态后不再推进、不再提交。`step` 与全部变更
入口（生命周期命令、管理面写入口、快照保存、切换）返回同一终止性错误（世界状态轴，
不归可重试 `StepError` 语义；标识符 G2 落定）。只读**取证入口**保留（导出冻结视图、
根校验器状态与遥测；不承诺可信、不进入正常观测流），句柄与世代保持不变供宿主取证。
取证实例是 snapshot §5「同一 `world_id` 不得与旧 world / session 并存」禁令的显式例外
（终态、只读、不参与 restore）；恢复的新 world 不得复用取证实例的 `world_id`。
`abandon_in_flight_cutover` 等纯锁释放调用是清算例外（只释放锁、不产生提交边界）。
Spatial 会话在租约置位后拒绝位姿提取，同一终止性错误经 Adapter 传播为 session 级终止。

**判因轴**：`物理-共享静态根` / `根基线` / `无法判因`。C(T) 的判因归宿主审计重放，
不在 Runtime 判因轴内。判因附失真指纹分类（与 #794 / `validation-matrix.md` 对齐）：
页边界偏移、整页替换、页整数倍位移、零页、非页对齐（后者提示非环境失真，转代码
嫌疑）。

**遥测级别**（递进包含）：

| 级别            | 内容                                                | 默认 |
| --------------- | --------------------------------------------------- | ---- |
| `L0 Trace`      | 预检进度、游标位置                                  | 关   |
| `L1 Verdict`    | Pass / Mismatch / Untrusted 计数与实际检测滞后      | 开   |
| `L2 Mismatch`   | 失配现场：页序、区域种类、期望 vs 实际、指纹分类    | 开   |
| `L3 FailClosed` | 失败关闭 + 根级失效 + 判因 + 处置提示（根重建入口） | 开   |

遥测不进入 C(T)、摘要与快照；遥测失败不影响失败关闭语义。

## 8. 性能测量协议与待验证预算

**计入口径（定案）**：入口预检在 `step` / 位姿提取内部执行，本来就在 Core 与
Spatial+Adapter 的墙钟里，**不单列**。唯一口径是**同一二进制、完整性开 / 关两臂交替
（ABBA）**的差值：

- Core 差值 ≤ [`core-runtime-performance-baseline.md`](core-runtime-performance-baseline.md)
  §6 对应规模 Core p95 主行的 5%（一万 ≤ 0.10 ms/tick，十万 ≤ 0.80 ms/tick）；
- Spatial+Adapter 差值 ≤ 该行 p95 预算的 5%（≤ 0.20 ms/frame）；
- 差值必须大于同二进制运行间极差才算有效测量；小于极差时报告「不可分辨」并附极差，
  不报为零；
- 入口预检每次处理固定 K 页，没有周期性突发；全量重认证只在安装 / 恢复 / 切换 / 审计时
  发生，计入这些操作自身的停顿报告，不进 tick 分布；
- integrated frame 与 catch-up frame 按性能基线 §6/§8 原口径统计，不因完整性另开例外。

**待验证预算**（实测归实现切片 D）：

| 维度                        | 一万（16 ms 拍）            | 十万（33 ms 拍）  | 一百万          |
| --------------------------- | --------------------------- | ----------------- | --------------- |
| Core 开 / 关差值            | ≤ 0.10 ms/tick              | ≤ 0.80 ms/tick    | 只报绝对值      |
| Spatial+Adapter 开 / 关差值 | ≤ 0.20 ms/frame             | ≤ 0.20 ms/frame   | 只报绝对值      |
| `M_root`（每拍消费时）      | ≤ 3750 次（60 s）           | ≤ 1818 次（60 s） | 按 cadence 导出 |
| K（每次预检页数）           | ceil(根保护页数 / `M_root`) | 同左              | 同左            |
| 全量重认证停顿              | 随安装 / 恢复报告           | 同左              | 同左            |
| 稳态保留                    | 待实测（§6）                | 待实测            | 待实测          |

**测量协议**：普通拍分布与 catch-up 帧分列；稳态零分配沿性能基线 §8.3（预检复用安装期
预留的 K 页缓冲）；恢复停顿口径 = 宿主处置链停顿，按 snapshot §8 度量，不进产品 Gate。
任一数字被实测推翻且影响合同或验收结论时返回 G1。

## 9. 二期入口：热状态的 Runtime 内保护

热状态的 Runtime 内保护不属本设计；若要进入，必须另开 G1，并至少满足：

1. **证据**：故障机上的 Runtime 长时浸泡 + 宿主审计重放（§4.3）观测到 Runtime 堆失真，
   给出频率与指纹；
2. **检测概率**：对每拍重写的对象如实给出单事件检出概率，不得用轮转周期冒充检测界；
3. **成本**：以同二进制开 / 关差值实测给出每拍成本，不得以「摊销」掩盖每拍固定成本；
4. **提交实现**：说明与原地写 P7 的关系（双缓冲登记表或提交结构改造）及对现行性能
   工作的约束；
5. **Rust 有效性**：说明受保护热表的布局如何满足任意位模式有效，或如实收窄保证。

候选对象按价值排序：每世界已编译路线表（注册后不可变，成本只发生在注册时）→
Parked / Completed 记录 → 其余热表。

## 11. G2 落定清单（实现内容，不属 G1 冻结）

- **根物理前像哈希**：128 位非密码哈希候选（如 XXH3-128），按单页计算吞吐与预检成本
  实测落定；新 crate 须过
  [`../governance/dependency-security.md`](../governance/dependency-security.md) 与
  cargo-deny。
- **参数**：`M_root` 标称次数、K 的取值与页数估算（按部署路网 backing 字节数，4 KiB / 页）。
- **类型盘点**：根 backing 中不满足任意位模式有效的元素类型清单（§2.5）。
- **API 标识符**：共享根绑定聚合、租约、根校验器入口、完整性模式字段、完整性终止性
  错误类型、取证入口、遥测句柄。
- **流式摘要路径**：#302 摘要的不分配实现形态，以逐字节一致的回归测试守住前像。

## 12. 修订记录：审阅后收窄

本版相对第一轮审阅版本（PR #958 前 17 个提交）删除的机制与理由：

| 删除的机制                                   | 理由                                                                                                                                     |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 逻辑记录与结构保留期望值（逐提交登记、双族） | 热记录每拍重写，检出概率约 1/`M_rec`；每拍成本数倍于预算（§4.1）                                                                         |
| 全量共因核对 `N_L`                           | 非检测判据；按现行实现，核对拍一万档约 2.7 ms、十万档约 33 ms，无法满足突发预算且禁止分片                                                |
| 热表 / 工作区物理期望值与写集增量登记        | 工作区每拍整体重写、消费前失真不可检；写集路径改造覆盖全部热表写入；P7 为原地写                                                          |
| 输出批次前像、不透明待决结果、校验窗放行     | 查询入口（`latest_transition_events`、`committed_pose_sources`、`vehicle` 等）与独立观测导出可绕过放行；返回值不透明也不能强制调用校验窗 |
| 待决快照与保存门控                           | C(T) 不在 Runtime 内受检，门控不提供额外判据                                                                                             |
| Runtime 侧检查点锚与命令摘要登记             | 与宿主持久副本分歧时只能判「无法判因」；锚在持久化之前登记还会产生幽灵锚                                                                 |
| 双族异族配对、三层互证、滚动摘要             | 对象收窄到不可变共享根后，构造缺陷与共因由全量重认证（不同谱系）承接                                                                     |
| 校验摊销「单列」口径                         | 预检就在 `step` 内，单列无法与 Core 分开测量；改为同二进制开 / 关差值                                                                    |

保留：ADR 0032 的恢复权威落点与 (c)(d) 取舍、失败分类、共享根绑定聚合与根级失效、
耐久内容基线 + 派生表重算认证、L0–L3 遥测与失真指纹判因。
