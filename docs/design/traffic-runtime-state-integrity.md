本文是 #955 G1 设计，冻结运行时状态完整性校验与失真处置的权威边界。背景约束来自
#794 归因收口：普通机器（无系统级 ECC）在内存压力下存在**页级内存失真**（首个分歧
偏移落在 4 KiB 页边界、整页替换、页整数倍位移、伴随零页；见
`../reference/validation-matrix.md` 环境失真指纹），失真不绑定特定测试或固定
entry，`fs::read` 与映射读回均可观察。确定性（ADR 0003/0030）是重演的必要条件，
但不自动提供正确性判据：确定性只保证「相同输入得到相同输出」，不保证「内存里的
状态仍是曾经提交过的那个状态」。本设计补的是后一个判据及其处置边界。

现行合同不因本设计改变权威归属：失同步只诊断、处置归宿主
（[`traffic-runtime-snapshot.md`](traffic-runtime-snapshot.md) §6）；输入命令序列与
检查点由宿主记录（ADR 0021）；确定性状态摘要前像为 #302 冻结的 SHA-256
（digest 7 / runtime state 5）；共享静态根不在 C(T) 内（ADR 0030）。本设计只在其上
增加检测面、失败关闭语义与遥测，不新增隐藏输入权威，不改变交通状态、摘要前像与
容器版本轴。

## 1. 问题、设计立场与范围

**问题**：页级内存失真把静默损坏写进运行时状态。确定性回放能定位分歧区间（宿主对拍
检查点三元组 `(command_cursor, tick, deterministic_state_digest)`），但它把「失真」
与「确定性缺陷」混在同一信号里，且只有在状态已经错了之后才显形。需要在运行时内部
提供正确性判据：检出失真、给出可信判因、并把处置权放在唯一权威处。

**设计立场**：

- **检测与处置分权**：Runtime 负责检测并失败关闭；恢复处置归宿主（§3）。
- **两类前像分立**：逻辑摘要前像管「状态内容是否仍是已提交的那个逻辑状态」；物理
  完整性前像管「物理字节是否发生失真」。两者对象、前像、算法与期望值来源各自独立，
  不互相替代（§2、§4）。
- **无可信基准不作宣称**：期望值无法建立或独立核验时，不得宣称检测或恢复成功；
  判因允许「无法判因」（§2、§7）。
- **不进入提交关键路径**：完整性校验不得进入 committed-state barrier，不得因执行
  块切分额外延迟一拍（§4）。
- **1.0 前只留一套权威**：恢复权威落点冻结为一条政策的两个阶段，不并行第二套
  （§3、ADR 0031）。

**范围外**（显式不做）：

- 每 tick 全量校验；
- 恶意篡改防御（本设计只处理非恶意的环境失真与随机损坏，不构成安全边界）；
- 分布式重放；
- 实现与实测（性能实测、retained-memory 账本合入、恢复率测量归实现 Issue）；
- 权威落点冻结前的任何自动纠偏（自动回滚、自动重演、自动重写状态一律不属本设计）；
- 代码页、栈、宿主自有内存、GPU/设备内存的完整性（漏检面显式声明，§5）。

## 2. 可信期望值与前像（必答第 0 项定案）

### 2.1 两类前像分立

| 前像                       | 定义                                                                                                                                       | 管什么                                                                                     | 算法                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------ |
| 逻辑摘要前像               | #302 确定性状态摘要的规范化前像（域分隔 `laneflow:runtime-state-digest:v1\0`、digest 7、runtime state 5、规范记录序列），布局无关、只覆盖 C(T) | 逻辑状态内容正确性：当前状态是否仍是曾经提交过的那个逻辑状态（多重度、绑定、live 序保留）   | SHA-256（#302 冻结，**不替换**）           |
| 物理完整性前像             | 对物理内存区域（热表、工作区、共享静态根 backing）按实际字节布局逐区域计算的完整性前像：域分隔字节 + 区域种类 + 页序 + 长度 + 内容字节      | 物理字节正确性：内存区域是否被页替换、零页、页整数倍位移等失真改写，与逻辑值无关、布局绑定 | SHA-256 截断 128 位（独立机制，见 §4.3）   |

两层前像的边界：逻辑摘要前像不因布局、地址、capacity 变化而变；物理完整性前像
逐页绑定物理布局，句柄表重排、容量调整都会改变物理前像，这正是它要检测的面。物理层
检出「页被打中」，逻辑层检出「失真已经进入逻辑状态的后果」；两层都失败时以 §7 判因
轴归类，允许「无法判因」。

物理完整性前像按**区域种类**（热表 / 工作区 / 共享静态根 / 期望值登记表）分域分隔，
避免不同对象之间重放同一前像。共享静态根不在 C(T) 内（ADR 0030），只有物理层覆盖
它；逻辑层不为共享根另设第二份摘要。

### 2.2 期望值来源与保护方案

**由谁建立、在什么可信时点**：期望值由**写者**（写入该状态的路径）在**写冻结点**
建立，登记进完整性期望值登记表（下称登记表）：

| 对象         | 登记时点（可信时点）                                                                                     | 绑定                                  |
| ------------ | -------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| 逻辑状态     | committed-state barrier 的提交完成点（P7 发布完成后、下一拍开始前），由提交路径从刚提交的不可变视图计算   | `(tick, command_cursor)` + 摘要版本轴 |
| 热表 / 工作区 | 该页最后一次写入完成后的写冻结点（拍末或工作区复用前），由写者从即将冻结的字节计算                        | `(tick, 页序, 区域种类)`              |
| 共享静态根   | 共享根构建 / 安装 / 恢复认证完成点（`SharedNetworkRevision` 发布前）                                     | `(NetworkRevisionId, 区域种类, 页序)` |
| 恢复后状态   | fresh restore / 同修订恢复成功、world 发布前的 staging 完成点                                             | 恢复后的 `(tick, command_cursor)`     |

登记时点即期望值冻结点：此后该页 / 该状态视为不可变，直到下一次合法写入触发重新登记。
「源缓冲损坏」式的注入定义为**登记后发生**的失真（与 #954 读回合同的登记时点语义
一致）。恢复路径沿 [`traffic-runtime-snapshot.md`](traffic-runtime-snapshot.md) §5
「任一失败零部分恢复」：登记表在 staging 期建立失败即恢复失败关闭，不发布 world，
不得在无登记表的世界上宣称检测能力。

**存放位置与隔离**：登记表是进程内诊断状态，**不进入快照、摘要前像与容器版本轴**
（digest 7 / runtime state 5 不变）。登记表使用独立分配域：

- 登记表页与被校验页**不得同页**。分配器按页对齐分别取域，安装 / 恢复时断言登记表
  页号集合与被校验页号集合不相交；断言失败即「校验过程不可信」失败关闭。
- 登记表不与任何被校验对象共享 backing 页、缓存缓冲或中间数组；写者向登记表写入
  使用登记表自有缓冲。
- 页号不相交断言只保证不同页；同页失真的共因风险由双副本与三层互证承接（下条）。

**双副本与三层互证**：登记表自身也受失真威胁，每个登记项保存两份独立副本：

1. **主副本**：紧凑二进制记录（对象标识、tick / 游标绑定、期望值）；
2. **复核副本**：不同布局、不同分配域、**不同哈希族**（CRC32C，防共因实现缺陷）；
3. **登记表滚动摘要**：每次校验窗结束时对登记表整体更新的滚动摘要，与主 / 复核
   副本互证。

三层中任意两层不一致即「校验过程不可信」失败关闭；三层同击中的残余风险显式声明
（§4.4）。登记表的建立、增长与重算全部走 checked reserve（#532 原语）：预留失败
返回完整性登记错误、无副作用、可重试，不进 fixed-step 热状态。

**独立核验**：校验路径与写入路径分离——校验在拍后校验窗内从被校验对象**重新计算**
前像并与登记表比较；重算使用校验自有缓冲，不复用写者缓存缓冲，使「缓存与内存
不一致」类失真可分歧（与 #954 两路读回同一口径）。校验读取必须真实触达被校验字节
（不缓存折叠），使零页与整页替换可被观察。

**无法建立可信基准**：以下任一情形即「校验过程不可信」：

- 登记表建立失败（预留失败、页隔离断言失败、双副本初始化分歧）；
- 登记表三层互证分歧；
- 期望值绑定不闭合（tick / 游标单调性破坏、跨修订绑定错位）；
- 检查点锚、输入命令游标登记与宿主持久副本分歧（见下表）。

不可信时**不得宣称检测或恢复成功**：世界进入失败关闭，遥测输出「校验过程不可信 /
无法判因」，不输出「通过」结论，不进入恢复语义。

**检查点、输入命令日志、摘要自身被打中**：

| 被打中对象           | 保护与处置                                                                                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 检查点锚             | 检查点三元组 `(command_cursor, tick, deterministic_state_digest)` 由宿主持久（宿主存档清单，对象外绑定，ADR 0021）；Runtime 在校验窗登记同值锚并与之核对。分歧 = 不可信基准，无法判因，交宿主；宿主持久层自身的写后回读由第一层（#954）覆盖 |
| 输入命令日志         | 宿主拥有（ADR 0021），其持久完整性不在本设计覆盖内；Runtime 在每条命令应用时把 `(command_cursor, 命令摘要)` 登记进登记表，命令日志与登记表分歧 = 不可信基准 |
| 确定性状态摘要自身   | 摘要值经双副本 + 三层互证保护；登记值与重算值一致但都经同一失真内存时的残余风险显式声明（§4.4），此时允许「无法判因」，不得把「重算得同一错误值」当作通过 |
| 登记表本体           | 双副本 + 滚动摘要三层互证；任意两层分歧 = 失败关闭、无法判因                                                                                             |

## 3. 恢复权威落点（必答第 1 项定案）

**定案：一条权威政策的两个阶段，不并行第二套。**

- **阶段一（检测，失败关闭）**：校验发现失配或校验过程不可信，立即失败关闭——世界
  停止推进，不自动纠偏、不自动回滚、不自动重演、不重启世界。
- **阶段二（处置，归宿主）**：检测后交宿主处置。宿主按现行设施恢复：从检查点
  （Runtime Snapshot + 命令游标）恢复并依序重放输入命令序列，用检查点三元组对拍
  定位首个分歧区间（[`traffic-runtime-snapshot.md`](traffic-runtime-snapshot.md) §6）。
  Runtime 只交付检测结论、判因与失真指纹，不执行处置。

这是现行合同（失同步只诊断、处置归宿主）在完整性维度的延伸：失同步的状态仍是合法
确定性状态，因此只诊断不停机；完整性失配的状态可信度已被破坏，因此先失败关闭再交
宿主。两者处置权相同（宿主），区别只在是否停机，权威不双轨。

**已发布结果的处置**：失败关闭不撤销已发布事件 / 观测 / 宿主副作用（不自动纠偏）。
从检测时刻起 Runtime 不再产生新提交；宿主在自己的边界决定丢弃、重放或对拍。Runtime
不隐藏、不重发、不去重事件——事件去重与副作用回退属于宿主回放链，不是 Runtime 职责。

**共享静态根被打中的独立失败语义**：共享静态根（`SharedNetworkRevision`）不在 C(T)
内（ADR 0030），**不属回滚 / 重演可修复面**。共享根失配时：

- 世界失败关闭（与其它失配同一阶段一语义）；
- 处置只能是根重建：重编译 / 重安装 / 重新认证共享根后重新恢复世界；宿主不得期望
  通过检查点回滚或命令重演「修好」共享根；
- 遥测把共享根单列判因类别，不与热表失配合并。

**备选取舍记录**（四个落点冻结其一；(c)(d) 不采用）：

| 落点                             | 裁决     | 理由                                                                                                                                                              |
| -------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| (a) 检测后交宿主处置             | **采用** | 与 ADR 0021 宿主边界、snapshot §6 处置归属一致；合同修订义务最小；宿主已有检查点 + 命令重放设施                                                                    |
| (b) 仅校验失败关闭               | **采用** | 作为 (a) 的阶段一；单独采用 (b) 会留下「检出了但没人处置」的悬空态，故与 (a) 合为一条政策的两个阶段                                                                 |
| (c) 磁盘检查点回滚               | 不采用   | 自动改变状态，承担全套合同修订义务（见下）；把宿主存档清单的权威搬进 Runtime，与 ADR 0021 冲突                                                                     |
| (d) Runtime 内重演               | 不采用   | 需自持命令权威，等于复制宿主回放链，违背「输入命令序列由宿主记录、Runtime 不新增隐藏输入权威」（snapshot §6）；合同修订义务与 (c) 同级                             |

(c)(d) 及任何自动改变状态的方案若未来采用，必须先单开 G1 与 ADR 改写并承担同一合同
修订义务：已发布事件 / 观测 / 宿主副作用处置、句柄映射（局部标识 → 新句柄）、修订
切换交互、事件去重、执行主体与宿主协调方式；不能安全处理已发布结果时停止或交宿主。
1.0 前不为 (c)(d) 保留双轨、开关或兼容层。

## 4. 校验机制（必答第 2 项定案）

### 4.1 校验对象分列

| 类别   | 对象                                                   | 前像             | 说明                                                                        |
| ------ | ------------------------------------------------------ | ---------------- | --------------------------------------------------------------------------- |
| 逻辑   | C(T) 不可变已提交视图                                  | 逻辑摘要前像     | 提交完成后到下一拍开始前不可变；校验窗内只读                                |
| 物理   | 热表（占用索引、leader 图、车辆热列、车辆目录等）      | 物理完整性前像   | 逐页登记与轮转 scrub                                                       |
| 物理   | 工作区（每 tick 派生 scratch）                         | 物理完整性前像   | 派生即不存；登记在消费完成后的写冻结点，见 §4.5                            |
| 物理   | 共享静态根（`SharedNetworkRevision` backing，不在 C(T)） | 物理完整性前像 | 安装 / 认证时登记；轮转 scrub + 换根 / 恢复 / 审计时全量重验                |
| 保护面 | 完整性期望值登记表                                     | 自身三层互证     | §2.2；不是被校验对象的期望值来源，是保护面本身                              |

### 4.2 逻辑层校验：双路径全量对拍 + 增量记录轮转

- **全量对拍（间隔 N_L）**：在被抽样 tick 的拍后校验窗内，从同一不可变 C(T) 视图以
  #302 规范前像**独立重算** SHA-256 摘要，与提交路径在同一 `(tick, command_cursor)`
  登记的摘要比对。两条路径不共享缓冲与排序临时表；任一不等 = 失配失败关闭。
  逻辑期望值来源 = 提交路径登记值；重算 = 校验路径。两者分歧即有一侧被打中，判因
  归 §7。
- **增量记录轮转（高频）**：记录级期望值在记录写入 / 提交时增量登记（只更新变化
  记录）；校验窗按逻辑记录轮转重算子集并逐项比对。单条记录的检测滞后 ≤ 轮转周期
  （§5）。
- 分段 / 抽样子校验是**独立机制**，只作检测线索与滞后压缩，不冒充 #302 摘要、不作
  正确性判据；正确性判据只有全量 #302 对拍与记录级期望值比对两类。

### 4.3 哈希选型（前像冻结后选型）

- **逻辑层**：SHA-256（#302 冻结，不替换、不新增第二逻辑摘要算法；digest 7 不变）。
- **物理层**：**独立机制**明示——SHA-256 截断 128 位，域分隔字节
  `laneflow:physical-integrity:v1\0`，前像含区域种类 + 页序 + 长度 + 内容字节。它不
  替换 #302，不进入摘要版本轴。若实测该选型不达 §8 摊销预算，允许实现切片降级为
  硬件 CRC32C（同前像形状），但必须同步抬高 §4.4 残余风险声明并回写本节。
- **登记表复核副本**：CRC32C（不同哈希族，防共因实现缺陷）。

### 4.4 碰撞口径与残余风险声明

- **失败关闭口径**：失配或校验过程不可信即失败关闭；不设容差、不取「多数副本正确」。
- **未检出碰撞残余风险（显式声明）**：
  - 逻辑层单点比较（失真值 vs 期望值，各 256 位）：未检出概率 ≤ 2⁻²⁵⁶ / 事件；
  - 物理层（128 位截断）：≤ 2⁻¹²⁸ / 页·事件；
  - 登记表共因失真（主 / 复核副本同击中且保持互相一致）：≤ CRC32C 的 2⁻³² / 事件，
    这是本设计声明的**最大残余风险**，列为独立复核项——实现切片可把复核副本升为
    第二完整哈希独立实现（上界降到 ≤ 2⁻⁶⁴ 量级）或引入周期独立复核，升档结论回写
    本节；
  - 三层互证同击中的联合残余风险不作数值承诺，命中即「无法判因」。
- 未检出碰撞不构成恢复成功依据：任何「通过」结论都只覆盖声明的对象与窗口。

### 4.5 检测滞后、提交边界与并行约束

- **检测滞后上限**：见 §5 公式与规模数值；校验不得以「永远排不上」形态存在，轮转
  周期与 N_L 都是合同值。
- **不得进入 committed-state barrier**：校验的读、算、写（登记）全部位于 barrier
  之外的拍后校验窗与写冻结登记点；不进入 P0–P8 任何阶段，不改变首错、事件、提交
  语义，不增加可恢复错误。校验窗内的失败只产生遥测与失败关闭信号，不回灌当拍结果。
- **跨块不额外延迟一拍（写入冻结约束）**：登记写入只发生在既有写冻结边界（拍初
  读取之前 / 拍后校验窗）；执行块与 worker 切分不改变校验调度、登记时点与检测滞后，
  不得因分块新增一拍延迟或第二份期望值权威。校验任务只读 C(T) 与登记表，与执行块
  无耦合；worker 数不进入登记表、不进入任何前像（与 ADR 0030 一致）。
- **工作区的取舍**：不为工作区做消费前校验（那会进入 tick 热路径与提交关键路径）。
  工作区前像在消费完成后的写冻结点登记，校验窗轮转重算比对；tick 内已消费的失真
  后果由逻辑层对拍兜底。该取舍把工作区的检测从「事前」降为「事后 + 逻辑兜底」，
  漏检面显式记入 §5。

## 5. 间隔 N、抽样 / 增量与漏检面（必答第 3 项定案）

**检测滞后公式**（`W_sched` = 校验窗调度余量，合同值 ≤ 1 个校验窗）：

```text
逻辑全量对拍滞后   = N_L × fixed_delta_time_ms + W_sched
逻辑增量轮转滞后   = M_rec × fixed_delta_time_ms + W_sched
物理页 scrub 滞后  = M_phys × fixed_delta_time_ms + W_sched
总检测滞后上限     = max(以上三项)
```

**机制与间隔**（初值为待验证预算，实测归实现 Issue；§8 表格同此口径）：

| 机制             | 覆盖             | 间隔 / 周期（待验证预算）                          | 漏检面                                                                                             |
| ---------------- | ---------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 逻辑全量对拍     | 全部 C(T)        | 一万 N_L = 64 拍；十万 N_L = 256 拍；一百万 N_L = 1024 拍 | 抽样拍之间进入又离开逻辑状态的失真（自愈覆盖）不可检；后果残留则由下一次对拍或记录轮转检出          |
| 逻辑增量轮转     | 逐记录           | 轮转周期 M_rec ≤ 128 拍                            | 记录被合法写入覆盖（自愈）后不可检；被打中的期望值本身由 §2.2 三层互证承接                          |
| 物理页轮转 scrub | 热表 / 工作区 / 共享根全部页 | 全覆盖周期 M_phys ≤ 256 拍（K 页 / 校验窗，按 §8 摊销预算求解） | 失真发生在某页 scrub 之后且在其下次 scrub 之前被合法写入覆盖（自愈）；被消费后清空的工作区残留不可检 |

**显式漏检面（总表）**：

1. 自愈性覆盖：失真落在两次检查之间且被合法写入改回 / 覆盖——两层都不可检，显式声明；
2. tick 内工作区失真：消费前不校验（§4.5 取舍），后果由逻辑层兜底，兜不住的残留进
   下一轮物理 scrub；
3. 未覆盖面：代码页、栈、宿主自有内存、GPU / 设备内存、宿主持久层（检查点制品与
   命令日志的持久完整性由 #954 第一层与宿主合同覆盖）；
4. 三层同击中（登记表主 / 复核 / 滚动摘要一致地坏）：不可检，「无法判因」；
5. 登记即错（写者写入时读到的字节已坏）：期望值忠实记录坏值，逻辑层不可检，物理层
   若该页仍在轮转窗口内可检；残余由宿主检查点回放对拍兜底（语义层兜底）。

最大检测延迟按规模写明：一万 ≤ 256 × 16 ms ≈ **4.1 s**；十万 ≤ 256 × 33 ms ≈
**8.4 s**；一百万 ≤ 1024 拍 × 固定步长，合同值**上限 60 s**（无实时 SLA，只定检测
延迟上限）。以上为待验证预算，实测归实现 Issue，可依据可复现证据收紧。

## 6. retained-memory 裁决与分类方案（必答第 4 项定案）

**裁决**：服从第 1 项落点——落点为「失败关闭 + 宿主处置」，因此**验证点持有方 =
Runtime 完整性校验组件**（登记表与校验器由 Runtime 持有、随世界生命周期建立与
销毁）；它只有检测面，**不另给恢复语义**——登记表、校验器与校验 scratch 都不是
恢复设施，不承载回滚 / 重演 / 纠偏能力。

**#380 账本穷尽分类**：本设计新增的保留内存按 `retained memory ledger` 词条合同
（按所有权穷尽枚举，新增字段必须触发编译失败以强制分类）登记为下列所有权类目；
实现不得以「诊断内存」笼统归类：

| 所有权类目                       | 性质     | 规模                                             |
| -------------------------------- | -------- | ------------------------------------------------ |
| 期望值登记表主副本               | 稳态保留 | O(热表页数 + 逻辑记录数)                         |
| 期望值登记表复核副本             | 稳态保留 | 同上（不同布局 / 哈希族 / 分配域）               |
| 登记表滚动摘要与页映射表         | 稳态保留 | O(热表页数)                                      |
| 校验重算缓冲（逻辑全量 + 记录级） | 校验峰值 | 与全量摘要缓冲同量级，校验窗内短持有             |
| 页 scrub 读缓冲                  | 校验峰值 | 固定 K 页缓冲，校验窗内短持有                    |
| 诊断 / 遥测缓冲（失真指纹输出）  | 校验峰值 | 有界，仅在失配时持有                             |

**稳态保留与恢复峰值分列**：稳态保留 = 上表前三行（校验关闭配置下为零）；校验峰值 =
后三行，在校验窗内出现、窗后释放。**「恢复峰值」不属 Runtime 侧**：落点下恢复是宿主
处置（restore + 重放），其峰值按 [`traffic-runtime-snapshot.md`](traffic-runtime-snapshot.md)
§8 度量（恢复峰值内存已有登记口径）分列在宿主恢复链，不与校验峰值混记。实现报告
必须把「稳态保留 / 校验峰值 / 宿主恢复峰值」三列分开，不得相加冒充单一数字。

## 7. 失败语义与遥测级别（必答第 5 项定案）

**校验结论三值**：

| 结论          | 含义                                       | 语义                                                                     |
| ------------- | ------------------------------------------ | ------------------------------------------------------------------------ |
| `Pass`        | 本窗口声明对象全部一致                     | 只覆盖声明对象与窗口，不外推                                             |
| `Mismatch`    | 期望值与重算值不等                         | 失败关闭；判因按对象类别                                                 |
| `Untrusted`   | 校验过程不可信 / 无法建立可信基准          | 失败关闭；判因「无法判因」，不输出通过                                   |

**失败关闭语义**：`Mismatch` 或 `Untrusted` 使世界进入完整性失败关闭态——不再推进、
不再提交、不自动纠偏 / 回滚 / 重演 / 重启；`step` 返回终止性失败（完整性错误轴，
非 `StepError` 可重试语义，具体 API 标识符由 G2 落定）。已发布事件 / 观测 / 宿主
副作用不撤销；句柄、世代与冻结视图保持不变供宿主取证；处置权在宿主（§3）。

**判因轴**：`逻辑对象` / `物理-热表` / `物理-工作区` / `物理-共享静态根` / `登记表` /
`无法判因`。判因不承诺唯一根因；多层同时显形时按「最靠近写者的证据」归类，证据
冲突一律「无法判因」。判因输出附失真指纹分类（与 #794 / `validation-matrix.md`
环境失真指纹对齐）：页边界偏移、整页替换、页整数倍位移、零页、非页对齐（后者提示
非环境失真，转代码嫌疑，走环境对照再谈代码）。

**遥测级别**（级别是递进包含，不是并行通道）：

| 级别            | 内容                                                                  | 默认 |
| --------------- | --------------------------------------------------------------------- | ---- |
| `L0 Trace`      | 校验窗进度、scrub 轮转位置、登记量                                    | 关   |
| `L1 Verdict`    | 每校验窗 Pass / Mismatch / Untrusted 计数与滞后实际值                | 开   |
| `L2 Mismatch`   | 失配现场：对象、页序、tick / 游标、期望 vs 实际、指纹分类             | 开   |
| `L3 FailClosed` | 进入失败关闭 + 判因轴结论 + 处置提示（宿主恢复入口）                 | 开   |

遥测是诊断面，不进入 C(T)、不进入摘要、不进入快照；遥测失败不影响失败关闭语义。

## 8. 性能测量协议与待验证预算

**计入口径（定案）**：校验摊销**单列**，不计入
[`core-runtime-performance-baseline.md`](core-runtime-performance-baseline.md) §6
W1 presentation 主行 p95（一万 Core ≤ 2 ms/tick、十万 Core ≤ 16 ms/tick）。理由：
校验是可配置韧性面（N_L / K 可调、可整体关闭），混入 Core p95 会把韧性成本误记为
交通求解成本，并使关闭校验的基线失去可比性。同时给摊销上限预算防止无界增长：
**校验摊销 ≤ 对应规模 Core p95 主行的 5%**（待验证预算）。

**测量协议**：

- 校验摊销按「普通拍 / 校验拍」分列统计（对齐 catch-up frame 单独统计口径）：
  校验拍（计入校验窗摊销的整拍）tick 墙钟与校验窗耗时分别报告 p50/p95/p99/max；
  摊销成本 = 校验窗总耗时 / 窗间拍数，报告 p95/p99。校验拍预算 = 对应规模 Core p95
  主行 + 5% 摊销，p99 ≤ 1.5×（下表），只作单列报告行，不与 W1 presentation 主行
  合并判 Product Pass/Fail。
- 恢复停顿口径 = 宿主处置链停顿（`restore_lfrs` + 命令重放至失配区间前），按
  [`traffic-runtime-snapshot.md`](traffic-runtime-snapshot.md) §8 度量维度报告
  （load 停顿、恢复峰值内存、重放停顿），**不进产品 Gate**（对齐性能基线 §8.2
  「不套用 W1 绝对预算、只报告」的处置方式）。校验失败关闭本身不产生恢复停顿——
  停顿发生在宿主处置时。
- 稳态零分配纪律沿性能基线 §8.3：W1/W2 稳态热路径保持 `0 allocation / 0
  reallocation`；登记表增长在安装 / 恢复 / 首个容量边界一次性 checked reserve，
  校验窗重算缓冲复用预留容量，不在每拍热路径分配。
- 百万档无实时 SLA，只定检测延迟上限（§5）；只运行明确声明的有限 observation。

**待验证预算**（分规模；全部为待验证预算，实测归实现 Issue；1.0 前可依据可复现
证据收紧、放宽或重构，影响合同或验收结论时返回 G1）：

| 维度                         | 一万（16 ms 拍）                    | 十万（33 ms 拍）                    | 一百万（不冻结 cadence）      |
| ---------------------------- | ----------------------------------- | ----------------------------------- | ----------------------------- |
| 校验摊销（每拍摊销 p95）     | ≤ 0.10 ms（5% × 2 ms）              | ≤ 0.80 ms（5% × 16 ms）             | 无实时 SLA；只报绝对值        |
| 校验拍 p95 / p99             | ≤ 2.10 ms / ≤ 3.15 ms（Core p95 主行 + 5% 摊销；p99 ≤ 1.5×；单列报告） | ≤ 16.80 ms / ≤ 25.20 ms（同口径；单列报告） | 只报 p50/p95/p99/max          |
| 逻辑全量对拍间隔 N_L         | 64 拍（≈ 1.0 s）                    | 256 拍（≈ 8.4 s）                   | 1024 拍                       |
| 逻辑增量轮转 M_rec           | ≤ 128 拍（≈ 2.1 s）                 | ≤ 128 拍（≈ 4.2 s）                 | ≤ 512 拍                      |
| 物理全覆盖周期 M_phys        | ≤ 256 拍（≈ 4.1 s）                 | ≤ 256 拍（≈ 8.4 s）                 | ≤ 1024 拍                     |
| 总检测延迟上限               | ≈ 4.1 s                             | ≈ 8.4 s                             | ≤ 60 s                        |
| 稳态保留（登记表 + 页映射）  | 待实测（O(页数 + 记录数)）          | 待实测                              | 待实测                        |
| 校验峰值 / 宿主恢复峰值      | 分列报告                            | 分列报告                            | 分列报告                      |
| 恢复停顿                     | 报告不 Gate                         | 报告不 Gate                         | 报告不 Gate                   |

页数假设（用于求解 K 页 / 校验窗）：热表 + 工作区按待验证上界约 2 KiB / 活跃车
（含页对齐与页映射），一万档约 5,120 页；按摊销预算求得 K ≈ 32 页 / 校验窗即可使
M_phys ≤ 256 拍。该假设与 K 由实现切片按实测修正。
