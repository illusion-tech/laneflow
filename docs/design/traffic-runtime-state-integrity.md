本文是 #955 G1 设计，冻结运行时状态完整性校验的**检测范围**与失真处置的**权威
边界**。背景约束来自 #794 归因收口：普通机器（无系统级 ECC）在内存压力下存在
**页级内存失真**（首个分歧偏移落在 4 KiB 页边界、整页替换、页整数倍位移、伴随
零页；见 `../reference/validation-matrix.md` 环境失真指纹）。确定性（ADR 0003/0030）
是重演的必要条件，但不自动提供正确性判据。

## 1. 问题、设计立场与范围

**问题**：页级内存失真可能把静默损坏写进运行时依赖的数据。宿主检查点对拍
（`(command_cursor, tick, deterministic_state_digest)`，snapshot §6）能在事后定位分歧
区间，但它把「失真」与「确定性缺陷」混在同一信号里；共享静态根被打中时，它还会被
所有世界同时消费，且无法靠回滚或重演修复。

**设计立场**：

- **检测与处置分权**：Runtime 侧提供检测能力并交付结论；停用与恢复处置归宿主（§3、
  ADR 0032）。
- **证据先于机制**：#794 已归因的失真全部来自文件写出 / 读回路径，已由 #954 收口；
  运行中 Runtime 匿名堆的同类失真尚无观测证据。本期只在**根投入使用之前**与**宿主
  显式审计时**认证共享根，不在运行中轮转校验；运行中检测以 #963 的浸泡证据为准入
  条件，进入二期（§9）。
- **无可信基准不作宣称**：期望值无法独立建立或核验时，不得宣称检测或恢复成功；判因
  允许「无法判因」（§2.4、§7）。
- **不改变提交语义与 tick 成本**：完整性不进入 committed-state barrier，不改变 P0–P8 的
  首错、事件与提交语义，不增加每拍工作（§4.4）。
- **1.0 前只留一套权威**：恢复权威落点冻结为一条政策的两个阶段（§3）。

**范围外**（显式不做）：

- 运行中轮转校验（共享根或热状态）——二期入口见 §9；
- 每 tick 全量校验；热状态的 Runtime 内逐写保护（写集增量期望值、逐记录保留期望值、
  工作区与输出批次保护）；
- Runtime 内的根级失效状态与自动失败关闭（停用由宿主执行，§3）；
- 恶意篡改防御（本设计只处理非恶意的环境失真，不构成安全边界）；
- 分布式重放；实现与实测（归 §10 实现切片）；
- 权威落点冻结前的任何自动纠偏（自动回滚、自动重演、自动重写状态）；
- 代码页、栈、宿主自有内存、GPU / 设备内存的完整性（§5 漏检面）。

## 2. 可信期望值与前像（必答第 0 项定案）

### 2.1 前像总表

| 前像           | 定义                                                                                                                                                                                                                            | 管什么                                              | 谁持有期望值                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 逻辑摘要前像   | #302 确定性状态摘要的规范化前像（`laneflow:runtime-state-digest:v1\0`、digest 7、runtime state 5），布局无关、只覆盖 C(T)；SHA-256，**不替换**                                                                                  | C(T) 逻辑内容；用于宿主检查点对拍与审计重放（§4.3） | 宿主（检查点三元组，ADR 0021）                                                                                     |
| 耐久根内容前像 | **复用** `NetworkRevisionIdV1` 的前像：规范路网语义载荷 `canonicalNetworkSemanticPayloadV1`（语义节 `0x0001..=0x0006` 按 sectionKind 序组帧），摘要 = `SHA-256("laneflow.network-revision.v1\0" ‖ payload)`；不另设编码与域分隔 | 共享根权威语义内容；根认证的依据（§4.2）            | 构建方建立（即 `NetworkRevisionId`）；发布来源由宿主随 `PublishedLfcaReference` 持久，编辑来源不持久、由重编译重算 |

**编码复用（不新增规范编码）**：耐久根内容前像的字段清单、整数 / 序列 / 可选值编码、
分段组帧与版本轴全部以 [`portable-canonical-artifact.md` §3.8](portable-canonical-artifact.md#38-路网修订标识)
及其引用的 LFCA 语义节格式为准；任一编码变化必须体现为 `sectionFormatVersion` 或
`networkRevisionDerivationVersion` 变化，不得静默得到不同摘要。构建方与认证方因此
对同一健康根得到逐字节相同的前像。

**派生表**：根的派生表不入耐久前像，由权威内容确定性重建；根认证按来源确定性重建
候选根（含派生表），与当前根逐表比对（§4.2）。当前根不保留规范身份 field-tag / value
前像（`shared-static-network.md` §5.1），无法从根反向编码出语义载荷，因此耐久前像只
在来源一侧重算。共享静态根不在 C(T) 内（ADR 0030），逻辑层不为
它另设第二份摘要。

### 2.2 期望值来源、时点与绑定

| 对象           | 建立时点（可信时点）                                                                                                                                                                                                                                                             | 绑定                |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- |
| 耐久根内容基线 | 构建完成点，由构建方建立：发布来源为 `NetworkRevisionId` 与 LFCA digest / exact length，宿主随 `PublishedLfcaReference` 持久；编辑来源为已提交 `RoadEditingState` 本身，宿主随 `CommittedNetworkSource` 持久（不持久 revision，`shared-static-network.md` §9）；均不新增旁车文件 | `NetworkRevisionId` |
| C(T) 逻辑内容  | 宿主检查点：宿主按自己的策略保存检查点并持久三元组                                                                                                                                                                                                                               | 检查点三元组        |

**根来源期望值（穷尽；任何期望值都不得取自被认证根自身的 `origin`）**：

| `origin` 字段                                                                                   | 期望值的独立来源                                                                                   |
| ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `NetworkRevisionId`（发布来源）                                                                 | `PublishedLfcaReference` 中的 revision，经第 1 步按同修订判据与宿主字节互证（§4.2）                |
| LFCA digest / exact length（发布来源）                                                          | 投入使用前取宿主本次提供的字节；在用根审计无独立期望值，不进入结论（见下文「发布来源的字节身份」） |
| `NetworkRevisionId`、LFCA digest / exact length（编辑来源）                                     | 从已提交 `RoadEditingState` 重编译得到的候选根 `origin`（§4.2 第 1 步）                            |
| `networkRevisionDerivationVersion`、六轴静态契约版本、`partitionPlanningHintsDerivationVersion` | 运行中二进制的编译期常量：reader / builder 本就只接受一组精确版本，这些值不需要也不应持久          |

**发布来源的字节身份**：根 `origin` 的 LFCA digest / exact length 记录的是**根构建时
所用字节**，按宿主声明的调用时机处理：

- **投入使用之前**（安装、恢复与切换之前）：根由宿主本次提供的字节构建，期望值是
  这份字节的 digest / exact length；
- **在用根审计**：没有独立期望值，字节身份字段**不进入结论**。现行生产合同允许健康根
  与任一同修订引用配对——`TrafficWorld::install` 只核对 revision，snapshot §5 与切换
  `same_revision_restore` 允许目标来源与目标根的 digest / length 不同——活动聚合绑定的
  引用因此不一定指名根构建所用字节，宿主本次提供的字节也不一定是。语义内容仍由
  revision 与第 3 步逐表比对完整覆盖。字节身份字段的失真列入漏检面（§5 第 15 条）。

期望值都不取自被认证根；调用时机由宿主声明，不从根推断。

编辑来源的 `CommittedNetworkSource` 只有 `RoadEditingState`，不持久 revision；以重编译
结果作为期望值不违反「不取自被认证根」：期望值来自宿主持有的 `RoadEditingState` 与
二进制常量，与被认证根相互独立。

**构建选项与限额**：宿主同时提供 builder 资源限额 `SharedNetworkBuildLimits`（retained /
scratch / policy-work 上限，即宿主构建这类根时使用的同一组限额；根不保留构建时的
限额）与可选的取消标志，认证原样传给 builder（`SharedNetworkBuildOptions`）。限额不
进入期望值：超限是操作失败（§2.4），不是失配（首次根侧失配之后的复算超限除外，§2.2）。

**构建选项期望值**：空间保留构建选项 `SpatialBuildOption`（`Omit` / `RetainAvailable`）
不进入 LFCA、存档与发布对象，却决定根的 Spatial component 是 `None` 还是
`Some(SharedSpatialNetwork)`（`shared-static-network.md` §6.3）。认证由宿主提供该选项
——即宿主构建或加载此根时使用的同一选项，取自宿主配置——作为重建输入，不从被认证
根的 Spatial 是否存在推断。

根来源期望值只在单次根认证调用内存在，不在 Runtime 内常驻；认证按**字段值**（不按
布局取字节）把它与根对象 `origin` 逐字段比对。

**登记时点即期望值冻结点**：共享根构建后不可变，构建完成点之后的任何内容变化都是
失真（与 #954 读回合同的「登记后失真」口径一致）。

**独立核验**：认证从被认证的根**重新读取并计算**，读取必须真实触达被认证字节（不
缓存折叠），使零页与整页替换可被观察；期望值来自宿主持有的来源与二进制常量，不来自
被认证对象。

**失配复算确认**：根认证判出失配时，重新读取来源（发布来源为宿主提供的字节，编辑来源为
`RoadEditingState`）并重建新的候选再跑一次。两次的**完整
失配证据**——失配步骤、首个不等的逻辑位置、期望值与实际值（来源摘要失配时为 digest /
length 值对）——全部相同 = `Mismatch`；任一项不同（含一次失配、一次通过）=
`Untrusted`（判因 无法判因：证据不可复现，认证过程自身可能被打中，不得据此判因到
根或来源）。复算只在失配路径发生。

**复算未完成**：首次失配之后，复算因取消、预留 / 分配失败或 builder 超限而未能完成
时，按首次失配的位置归类，不以操作失败抹去已取得的证据：

- 首次失配在第 2 / 3 步（根侧）：判 `Untrusted`（判因 `无法判因`），保留首次失配证据
  （步骤、位置、期望值与实际值）进入 L2，按 §3 处置——投入使用之前不投入使用，在用根
  审计停用该根；取消只能放弃复算，不能撤销根侧证据；
- 首次失配在第 1 步（来源侧）：属操作失败（与宿主未能提供来源同类），不停用根，首次
  证据记为来源审计诊断，宿主隔离来源后重试。

### 2.3 认证不变量

1. **基线建立不变量**：耐久根内容基线由构建方从已认证构建输出建立；未核对即建立的
   「自发基准」在任何路径都不合法。根认证不得从被认证根自身取期望值（§2.2）。
2. **checked reserve**：根认证自身分配的缓冲（候选根，§4.2）在认证开始时按计数可失败
   预留（#532 原语），builder scratch 沿用 builder 现有的调用方限额约束
   （`shared-static-network.md` §10.1）；来源字节由宿主持有、认证期借用。预留失败属
   操作失败（§2.4），不判 `Untrusted`。
3. **只读**：根认证只读共享根，不给根本体引入可变性、原子或内部状态
   （`shared-static-network.md` §8 不变）。

### 2.4 可信基准、失败分类与「无法判因」

**操作失败（不进入三值结论）**：认证入口的结果在 `Pass` / `Mismatch` / `Untrusted` 之外
另有操作失败一类，穷尽为：

- 候选根缓冲预留失败；
- builder 的调用方预算超限、取消与分配失败，以及调用方要求的 lane-pose capability
  不可用（`shared-static-network.md` §7.3）；编辑来源重编译的同类资源失败与取消；
- 宿主未能提供来源：asset 缺失、宿主资产认证失败（属宿主资产准入，Runtime 不判因）。

例外：首次根侧失配（§4.2 第 2 / 3 步）之后，复算阶段发生的上述失败不属操作失败，按
§2.2「复算未完成」判 `Untrusted`。

操作失败不判因、不触发停用，也不宣称 `Pass`。投入使用之前遇到操作失败时，该根不
投入使用（与 snapshot §5「资产缺失、重编译失败……失败关闭」一致），宿主可按原因
重试；在用根审计遇到操作失败时，该次审计无结论，根照常使用，宿主可重试。取消只由
调用方发起：只有宿主提供了取消标志，结果才可能是已取消。builder 的输入内容类错误（input kind / binding / contract 失配、Spatial
presence 与表矛盾、计数 / 范围溢出、引用 / 身份 / 次序 / 闭合失配）说明来源字节与其
已认证绑定不一致，按 §4.2 第 1 步失配处理（判因 `来源`，经复算确认），不属操作失败。

**`Untrusted`（认证过程不可信）的生产者（穷尽）**：

- 失配复算两次的完整失配证据不一致（§2.2）；
- 认证过程 panic：认证入口在边界以 `catch_unwind` 包住整个认证过程（与
  `kernel/execution.rs` 现行做法一致），捕获的 unwind 转为 `Untrusted`，判因
  `无法判因`，不向宿主传播；`panic=abort` 构建下按进程终止语义处理；
- 首次根侧失配之后复算未完成（§2.2「复算未完成」）。

认证的
各步骤分别有独立锚定的期望值，一个步骤通过、另一个步骤复算后仍失配是局部失真的正常
表现，判 `Mismatch` 并按失配步骤判因（§7），不判 `Untrusted`。不可信时不得宣称检测或
恢复成功，遥测输出「无法判因」。

**检查点、输入命令日志、摘要自身被打中**：三者都由宿主拥有（ADR 0021、snapshot §6），
本设计**不在 Runtime 内登记检查点锚或命令摘要**——Runtime 登记的锚与宿主持久副本
分歧时，无法区分哪一侧被打中，只能判「无法判因」，并不比宿主自己核对持久副本多出
判据。持久侧完整性归宿主持久层（工具与 harness 写路径的写后回读由 #954 覆盖）；宿主审计重放（§4.3）在独立世界里
重算摘要，摘要值在原世界内存中被打中的情形表现为对拍分歧，交宿主判因。

### 2.5 Rust 有效性约束（保证收窄）

页级失真可以改写枚举判别值、`bool`、引用或 `Vec` / `Box` 的指针、长度与容量。这类
字段一旦被打中，下一次类型化读取就可能触发未定义行为或非法访问，而这可能发生在
根认证之前。因此：

- 根 backing 中任意位模式皆有效的普通数据（序号、范围、整数距离等），以及根对象
  头部的标量语义元数据（`origin` 各字段），失真表现为错误值或越界 panic。错误值在下一次
  根认证时可检（在用审计中的 `origin` 字节身份字段除外，§2.2）；认证过程中的 panic 由
  认证入口转为 `Untrusted`（§2.4），在 `panic=unwind` 构建下也不会让宿主捕获后继续使用
  该根；消费者调用（`step` 等）中的 panic 按 `traffic-runtime-parallel-execution.md` §4
  处理：该世界退出可用状态，宿主销毁并重建；
- 含枚举（含 `Option`）、`bool`、`char`、引用或指针的元素类型，以及根对象头部的
  `Arc` / `Box` 元数据，**不承诺**认证时可检；其失真可能直接表现为进程崩溃或未定义
  行为，列入 §5 漏检面。G2 盘点根 backing 中这类类型并给出清单（§11）；
- 进程崩溃对宿主而言是失败停止，宿主按 §3 阶段二处置，但 Runtime 不对其给出判因。

## 3. 恢复权威落点（必答第 1 项定案）

**定案：一条权威政策的两个阶段，不并行第二套**（ADR 0032）。

- **阶段一（检测，停用）**：触发条件是根认证判定根失配（投入使用之前任何非 `Pass`；在用
  根审计中判因为 `共享静态根` 或 `无法判因` 的非 `Pass`），或宿主对审计重放的
  分歧做出判因、认定为完整性失配；失真对象随即**停止使用**——不自动纠偏、回滚、重演
  或重启。审计重放的原始分歧在判因之前按失同步处理，只作诊断；判因为「无法判因」
  时是否停用由宿主决定（§4.3）。根认证失败的根不得安装、恢复或作为切换
  目标；在用根审计判因为 `共享静态根` 或 `无法判因` 时，宿主停止该根的全部消费者
  （所有世界与 Spatial 会话）。在用根审计判因为 `来源` 时，坏的是审计输入而非根：
  已安装的根与其绑定引用未被证伪，宿主**不停用根**，隔离或重新加载来源后重试，该次
  审计对根无结论（§5 第 14 条）。
  停用由宿主执行：Runtime 不持有根级失效状态，也不自行失败关闭。
- **宿主侧停止边界**（在用根停用时）：停止 = 宿主不再对该根的消费者发起新调用。已开始
  的 Runtime 调用（`step`、生命周期命令、观测导出、位姿提取等）都是同步调用，不被中途
  打断，正常返回；宿主自有、持有根 `Arc` 的异步任务（`shared-static-network.md` §8）由
  宿主等待或取消。根重建在全部在途调用返回、宿主任务结束之后才开始。结论交付之后才
  返回的结果（已提交状态、事件、观测、位姿批次）与结论之前的结果同属基于该根的产出，
  按下文「已发布结果」由宿主处置。Runtime 不提供排空、取消或结果标记协议。
- **阶段二（处置，归宿主）**：宿主按现行设施恢复，即从检查点恢复并依序重放输入命令
  序列，用检查点三元组对拍定位首个分歧区间（snapshot §6）。Runtime 只交付检测结论、
  判因与失配位置。

这是现行合同（失同步只诊断、处置归宿主）在完整性维度的延伸：失同步的状态仍是合法
确定性状态，只诊断不停用；完整性失配的对象可信度已被破坏，先停用再处置。两者处置权
相同，区别只在是否停用。

**已发布结果**：停用不撤销已发布事件 / 观测 / 宿主副作用。宿主在自己的边界决定丢弃、
重放或对拍；事件去重与副作用回退属于宿主回放链。

**共享静态根被打中的独立失败语义**：共享根（`SharedNetworkRevision`）不在 C(T) 内，
**不属回滚 / 重演可修复面**。根认证 `Mismatch` / `Untrusted` 时：

- 认证前（安装、恢复、切换之前）：该根不投入使用；宿主按来源重新加载或重编译后再认证；
- 在用根审计（判因 `共享静态根` / `无法判因`）：处置只能是**根重建**——宿主停止该根的全部消费者，重编译 / 重新加载并
  认证共享根后，用持久制品 restore 新 world 并绑定新根；不得期望通过检查点回滚或命令
  重演「修好」共享根；
- 遥测把共享根单列判因类别。

**为什么停用由宿主执行**：坏根唯一的处置是宿主重建；Runtime 自行失败关闭不改变处置
路径，却要求每个消费者携带可核对的失效状态（绑定聚合、核对点、发布线性化、快照
门控），这一机制本身又落在同一故障模型之下（ADR 0032 取舍）。

**备选取舍记录**：

| 落点                 | 裁决     | 理由                                                                                   |
| -------------------- | -------- | -------------------------------------------------------------------------------------- |
| (a) 检测后交宿主处置 | **采用** | 与 ADR 0021 宿主边界、snapshot §6 处置归属一致；宿主已有检查点 + 命令重放设施          |
| (b) 仅检测后停用     | **采用** | 作为 (a) 的阶段一；单独采用会留下「检出了但没人处置」的悬空态                          |
| (c) 磁盘检查点回滚   | 不采用   | 自动改变状态，承担全套合同修订义务；把宿主存档清单的权威搬进 Runtime，与 ADR 0021 冲突 |
| (d) Runtime 内重演   | 不采用   | 需自持命令权威，等于复制宿主回放链，违背「Runtime 不新增隐藏输入权威」（snapshot §6）  |

(c)(d) 及任何自动改变状态的方案若未来采用，必须先单开 G1 与 ADR，并承担同一合同
修订义务：已发布事件 / 观测 / 宿主副作用处置、句柄映射、修订切换交互、事件去重、
执行主体与宿主协调；不能安全处理已发布结果时停止或交宿主。

## 4. 校验机制合同（必答第 2 项定案）

### 4.1 校验对象分列与本期取舍

| 类别 | 对象                                                      | 本期机制                                                       | 理由                                                                  |
| ---- | --------------------------------------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------- |
| 逻辑 | C(T) 不可变已提交视图                                     | **宿主检查点对拍与审计重放**（#302 摘要，§4.3）                | 见下文「热状态」                                                      |
| 物理 | 热表（车辆、占用、冲突、等待）、工作区                    | **不在 Runtime 内保护**，列入 §5 漏检面                        | 见下文「热状态」                                                      |
| 物理 | 输出批次（events / observations / StepOutcome、位姿批次） | **不保护**，列入 §5 漏检面                                     | 生成到交付在同一次调用内完成；保护需要全部查询入口进入放行状态机      |
| 物理 | 共享静态根                                                | **根认证**：投入使用前与宿主审计时（§4.2）；运行中不轮转（§9） | 不可变、被全部世界共享、不可由回滚 / 重演修复；运行中失真尚无观测证据 |

**热状态为什么不在 Runtime 内保护**：

1. **检测界不成立**。Active 车辆等热记录每拍被读取并重写，下一拍的合法写入**由
   已失真的值推导而来**，失真并未消失，而是进入合法状态并取得新的「正确」期望值。
   轮转校验只有在失真发生后、下一次读取之前恰好轮到该记录时才能检出，单次事件的
   检出概率约为轮转周期的倒数。
2. **成本不可兑现**。逐记录保留期望值与写集增量物理期望值是**每拍**成本：按现行
   #302 规范化的实测量级（release，规范化 + SHA-256：一万条约 2.6–2.7 ms，十万条约
   31–35 ms，不含 capture），十万档每拍仍在毫秒级。
3. **与现行提交实现不匹配**。现行 P7 是对 `committed.vehicles` 等表的原地写，不是指针
   切换。
4. **Rust 有效性**。热表元素（如 `Option<VehicleState>`）含枚举与 padding（§2.5）。
5. **威胁面尚无 Runtime 堆证据**。#794 已归因条目全部来自文件写出 / 读回路径
   （`validation-matrix.md` file-backed emission、`Artifacts::load`、write-readback），
   该路径已由 #954 收口。

### 4.2 共享根认证

- **输入**：被认证的共享根；宿主声明的调用时机（投入使用前 / 在用根审计）；宿主提供
  的来源；宿主提供的 `SpatialBuildOption`、`SharedNetworkBuildLimits` 与可选取消标志
  （§2.2）。发布来源为 `PublishedLfcaReference`
  （恢复时取存档中的引用，安装与切换前取宿主本次资产认证形成的引用，在用根审计时
  取活动聚合 `CommittedNetworkSource` 中的引用）与宿主经资产认证取得的 LFCA 字节：宿主解析不透明 asset key、
  完成发布加载认证（ADR 0025：LFCP v2 / manifest 绑定）后把字节借给认证入口，Runtime
  与 `laneflow-static-network` 不解析 asset key、不做文件 I/O。编辑来源为已提交
  `RoadEditingState`（实现随 #529，§10）。期望值的版本字段取自运行中二进制常量。
- **步骤**（先验证来源、推出全部期望值，再比对根；全部通过才判 `Pass`）：
  1. **来源验证**：发布来源对宿主提供的 LFCA 字节计算 digest / exact length，经 reader
     受检后按 §2.1 复用的前像从语义节重算 `NetworkRevisionIdV1`，与
     `PublishedLfcaReference` 按**同修订判据**比对——`NetworkRevisionId` 精确相等、
     版本轴与二进制常量精确相等（snapshot §5「恢复对称原则」、切换
     `same_revision_restore`）。字节 digest / length 与引用不同（同语义重发布）只记来源
     审计诊断；引用的刷新归恢复 / 切换路径，认证不写任何对象。编辑来源从已提交
     `RoadEditingState` 重编译（snapshot §5「恢复对称原则」），产出的完整 `origin` 即为
     期望值。本步结束时全部根来源期望值已确定（§2.2），且都不取自被认证根；
  2. **根 `origin` 比对**：根 `origin` 与第 1 步推出的期望值逐字段比对；发布来源的字节
     身份只在投入使用之前比对，在用根审计不比对（§2.2「发布来源的字节身份」）；
  3. **候选根比对**：以同一 builder 按宿主提供的 `SpatialBuildOption`、限额与取消标志
     确定性构建候选根，与当前根逐 component / 表**按值**比对（含派生表与 Spatial
     component 是否存在；不按布局或地址取字节）。`origin` 的字节身份字段（LFCA digest /
     exact length）不在本步比对——同语义重发布时候选根与当前根的字节身份合法地不同——
     只按第 2 步的口径核对。比较算子冻结为：整数、句柄、ID 与范围按值相等；
     `f32` / `f64` 字段按 `to_bits()` **位相等**，不得用 `PartialEq` 比较浮点——否则
     `+0.0` 被打成 `-0.0` 时判相等，NaN 位模式时判不等。健康根的浮点值来自已拒绝
     负零与非有限值的 LFCA（`portable-canonical-artifact.md` §2.1），由同一二进制的
     builder 确定性产出，与候选根逐位相等；
  4. 任一步失配按 §2.2 复算确认。
- **调用时机**：宿主在**安装、恢复与切换之前**认证将要投入使用的根（构建 / 加载之后、
  首次绑定之前）；宿主可在任意时刻对**在用根**发起审计认证，频率由宿主策略决定。
  认证是宿主调用的只读入口，不改变 `TrafficWorld::install`、`restore_lfrs`、
  `SpatialSession::bind` 与切换入口的签名与语义；宿主未调用时无检测（§5 第 11 条）。
- **并发**：认证只读不可变根，可与在用世界的 `step` 并发进行，不加锁、不阻塞消费者。
- **结论交付**：返回 `Pass` / `Mismatch` / `Untrusted`、判因与失配位置（§7）；结论
  不写入根、世界或快照。
- **观测时刻**：认证是对根的逐段扫描，没有原子的观测时刻；`Pass` 只表示每个字节在
  **被读取的那一刻**与期望值一致，不声称整个根在结论交付时刻无损（§5 第 8 条）。

### 4.3 C(T) 的宿主审计重放

C(T) 的失真检测沿用现行宿主设施，不新增 Runtime 合同：

- 宿主按自己的策略保存检查点并持久三元组（snapshot §6）；
- **审计重放**：宿主可在独立世界从较早检查点重放输入命令至较晚检查点，比对三元组。
  重放世界由 `restore_lfrs` 建立，恢复之前按 snapshot §5 认证其根（§4.2）。被审计的
  世界仍在运行时，重放只在**独立进程或另一台机器**上进行：snapshot §2 / §5 禁止恢复
  出的世界与仍存活的同 `world_id` 世界或会话在同一进程并存，而 `world_id` 进入摘要、
  不能为比对而改写；同进程重放只适用于原世界已停止，或只比对离线检查点的情形。
  不另设审计命名空间或特殊恢复模式；分歧即首个分歧区间。以**不含该失真的检查点**为
  起点时，原世界内进入 C(T) 且改变摘要等价类的失真（含被消费后传播的热状态失真）与
  摘要值本身的失真表现为对拍分歧；落在同一摘要等价类内的失真——同内容路线实例间的
  归属置换（snapshot §6「等价类边界」）——不改变三元组，检查点比对检测不到，其可观测
  面要到首个路线目标命令之后才显形，且只有宿主把耐久身份映射与命令结果纳入比对时
  才产生分歧，这是宿主策略（§5 第 12 条）；起点检查点本身已含失真时，快照与摘要围绕坏状态自洽，重放确定性地
  复现同一轨迹，不产生分歧（§5 第 7 条）。宿主若要覆盖这一情形，可自行长期保留更早的
  检查点或初始状态作为基线，这是宿主策略。只比对三元组
  **不覆盖输出批次**——生成之后才失真、未进入 C(T) 的事件、观测、`StepOutcome` 与
  位姿批次不产生分歧（§5 第 2 条）。同理，两个检查点之间短暂分歧、又在下一个检查点
  之前收敛的失真（例如车辆运动状态被打中数拍后，该车辆被后续命令移除）不留下三元组
  差异，检测不到（§5 第 13 条）；宿主可加密检查点或比对输出批次缩小这一窗口。宿主若要覆盖输出，可自行记录输出批次并在重放时
  逐批比对，这是宿主策略，不形成 Runtime 合同；
- **换机器重放是判因证据，不是判因结论**：时序或平台相关的缺陷可能在另一台机器上
  不复现，宿主自有的检查点或命令日志被打中也可能独立地复现或不复现；区分环境失真
  与确定性缺陷需要独立认证的输入与重复重放共同支持，宿主据此判因；判因为完整性失配
  后才按 §3 停用，原始分歧本身只作失同步诊断；
- 检测滞后 = 失真发生到下一个检查点的间隔 + 该检查点到审计重放启动的调度间隔 + 重放
  耗时，三项都由宿主策略决定，Runtime 不承诺界；检查点保存频繁而审计稀疏时，滞后由
  审计调度间隔主导；
- Runtime 侧的义务只有一条（实现切片 C）：提供**有界成本的 #302 摘要路径**——直接
  从 C(T) 计算、不经 `capture_snapshot` 的整份快照拷贝，使宿主能在检查点 cadence 上
  负担摘要。冻结前像与局部 ID、可交换的路线实例次序无关，需要先建立并排序车辆记录、
  路线记录、成员与路线分组（现行 `snapshot_digest.rs`），因此本路径允许 O(n) 归一化
  scratch：由调用方限额约束，按计数 checked reserve（#532 原语）预留，预留或限额失败
  沿用现行 `SnapshotDigestError`（无副作用、可重试，snapshot §6）；不以多次全量扫描
  换取零分配。摘要字节与 #302 冻结前像逐字节一致，不新增摘要版本。

### 4.4 时序与操作边界

- **不进入 tick 路径**：根认证不在 P0–P8 内，不改变首错、事件与提交语义，不增加
  `StepError`；`step`、生命周期命令、观测导出、位姿提取与快照保存的签名与成本不变。
- **不进入 committed-state barrier**：认证只读不可变根，与提交阶段无交集；worker 数
  不进入任何前像（ADR 0030）。
- **快照保存**：不加完整性门控——C(T) 不在 Runtime 内受检，门控不提供额外判据。检测
  滞后内被保存的检查点可能包含坏状态（§5 第 7 条）。

### 4.5 选型原则与碰撞声明

- **逻辑层**：SHA-256（#302 冻结，不替换、不新增第二逻辑摘要算法）。
- **耐久根内容前像**：复用 `NetworkRevisionIdV1`（SHA-256，域分隔
  `laneflow.network-revision.v1\0`），不新增算法与域分隔。
- **失败口径**：失配或认证过程不可信即判非 `Pass`；不设容差，不取多数。
- **残余风险**：来源侧按 SHA-256 第二原像假设定性声明，不作数值保证级声明。任何
  「通过」结论只覆盖声明对象，且只覆盖每个字节被读取的时刻（§4.2）。

## 5. 检测时机与漏检面（必答第 3 项定案）

**检测时机（本期）**：共享根在每次投入使用之前认证一次，运行中由宿主按需审计；
Runtime 内**无轮转、无抽样、无增量**。共享根的检测滞后 = 失真发生到下一次宿主审计
或下一次重新认证的间隔，由宿主策略决定，Runtime 不承诺上界。C(T) 的检测滞后由宿主
检查点间隔、审计调度间隔与重放耗时共同决定（§4.3）。

**显式漏检面（总表）**：

1. **热状态全部**（车辆、占用、冲突、等待、工作区）：Runtime 内不检；失真被消费后会
   传播为合法状态（§4.1）。只由宿主审计重放在检查点粒度兜底；
2. **输出批次**（事件、观测、`StepOutcome`、位姿批次）：生成到交付之间的失真不可检，
   宿主审计重放只比对三元组也不覆盖（§4.3）；
3. **每世界已编译路线表**：注册后不可变，但本期不保护（候选二期对象，§9）；
4. **Rust 有效性破坏**（§2.5）：枚举判别值、指针、长度等被打中时可能在认证之前崩溃或
   触发未定义行为；
5. **两次认证之间的根失真**：根投入使用之后、下一次宿主审计之前发生的失真，在此期间
   被所有消费者读取，产生的状态与输出由宿主据检测时间点处置；宿主不审计时没有检测
   上界；
6. **认证期间与结论之后的在途消费**：在用根审计与 `step` 并发时，认证给出结论之前的
   消费同样基于该根；结论交付时尚在进行、之后才返回的调用及其输出也是如此。二者都归入
   第 5 条，由宿主按 §3 停止边界与「已发布结果」处置；
7. **检出前固化**：检测滞后内被保存的检查点可能包含坏状态；兜底为宿主审计重放与处置
   丢弃。宿主保留的最早检查点本身已含失真时，从它重放自洽，审计重放检测不到（§4.3）；
8. **认证扫描期间与结论之后的失真**：认证读过的字节在扫描后续部分时被打中，以及结论
   交付之后的失真，`Pass` 都不覆盖（§4.2 观测时刻），归第 5 条；
9. **未覆盖面**：代码页、栈（含认证中间状态）、宿主自有内存、GPU / 设备内存、宿主
   持久层（后者归宿主合同；工具与 harness 写路径由 #954 覆盖）；
10. **登记即错**：构建方从已失真的输入建立耐久内容基线——由构建侧认证（LFCA 摘要、
    #954 读回）兜底，Runtime 不可检；
11. **宿主未调用认证或审计**：认证是宿主调用的入口（§4.2），未调用时对应时点无检测；
12. **摘要等价类内的 C(T) 失真**：同内容路线实例间的归属置换等不改变摘要的失真，
    三元组比对检测不到；宿主不比对耐久身份映射时无检测，比对时也可能延迟到首个路线
    目标命令之后，首个分歧区间未必包含失真时刻（§4.3）；
13. **检查点之间短暂分歧后收敛的 C(T) 失真**：失真在两个检查点之间造成分歧、又在
    下一个检查点前收敛到相同三元组时，三元组比对检测不到；期间产生的输出批次差异
    只在宿主比对输出批次时可见（§4.3）；
14. **来源不可用或损坏期间的在用根**：在用根审计判因 `来源` 或来源不可得时不停用根，
    该次审计对根无结论；宿主恢复可用来源之前，在用根得不到审计（§3）；
15. **在用根 `origin` 字节身份字段**：LFCA digest / exact length 在在用审计中没有独立期望
    值（§2.2），失真检测不到。其消费者是切换描述符的 origin 校验（`cutover.rs` 按 digest
    精确比对 LFSD 绑定），失配时拒绝切换（失败关闭），不产生静默的错误状态；来源审计
    诊断中的字节身份对比同样不可信。

## 6. retained-memory 裁决与分类方案（必答第 4 项定案）

**裁决**：服从第 1 项落点——Runtime 内不常驻任何完整性状态；每世界、每根的**稳态保留
新增为零**。根认证只有认证期峰值，结束即释放；验证点不承载回滚 / 重演 / 纠偏能力。

**#380 账本穷尽分类**：

| 所有权类目                               | 性质     | 规模说明                                                                                                                                                 |
| ---------------------------------------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 根认证缓冲（宿主借出的来源字节与候选根） | 认证峰值 | 认证期间短持有：约为来源字节加一份根（来源字节由宿主持有，计入同一峰值报告）；与根构建峰值同期报告；被认证根在认证期间始终存活，共存总量另含一份被认证根 |
| builder scratch                          | 认证峰值 | 两类来源都有：候选根构建时由调用方限额约束（`shared-static-network.md` §10.1）；编辑来源另含重编译 scratch                                               |
| 诊断 / 遥测缓冲                          | 认证峰值 | 有界，仅在失配时持有                                                                                                                                     |

**分列口径**：实现报告把「稳态保留 / 认证峰值 / 宿主恢复峰值」三列分开，不得相加冒充
单一数字。认证峰值同时报告两个值：**增量**（来源字节 + 候选根 + builder scratch，编辑
来源另含重编译 scratch）与**共存总量**（增量再加被认证根；在用根审计时被认证根同时由
世界持有，不重复计入世界侧预算）；稳态保留一列须实测为零。宿主恢复峰值（restore + 重放）按 snapshot §8 度量，
不属 Runtime 侧。

## 7. 结论与遥测级别（必答第 5 项定案）

**认证结论三值**：

| 结论        | 含义                                 | 语义                                                                                                        |
| ----------- | ------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| `Pass`      | 本次认证覆盖的内容在各自被读取时一致 | 只覆盖声明对象与读取时刻，不外推（§4.2）                                                                    |
| `Mismatch`  | 期望值与重算值不等，复算确认仍不等   | 按 §3 处置：投入使用前不投入使用；在用根审计判因 `共享静态根` / `无法判因` 时停用该根，判因 `来源` 时不停用 |
| `Untrusted` | 认证过程不可信（§2.4）               | 判因「无法判因」；投入使用前不投入使用，在用根审计时停用该根（§3）                                          |

**失败分类不变量**：操作失败（§2.4）不是结论，不判因、不停用；只有 `Mismatch` /
`Untrusted` 才可能要求停用，且按调用时机与判因处置（§3）：投入使用前任何非 `Pass`
都不投入使用；在用根审计判因 `来源` 时不停用根。二者不得混同。

**判因轴**：`来源`（§4.2 第 1 步失配：宿主提供的字节、引用或重编译输入）/ `共享静态根`
（第 2、3 步失配）/ `无法判因`。两种情形例外，判 `无法判因`：编辑来源的
`NetworkRevisionId` 失配——期望值由 `RoadEditingState` 重编译产出，`RoadEditingState`
失真与根失真无法区分（`NetworkRevisionId` 一致而派生表失配仍判 `共享静态根`）；
Spatial component 是否存在失配——宿主提供的 `SpatialBuildOption` 有误与根失真无法
区分。C(T) 的判因归宿主审计重放，不在 Runtime 判因轴内。

**失配位置**：第 3 步按值比对时报告首个不等的逻辑位置（component、表、元素序号与
字段）与期望 vs 实际值；来源摘要失配只能判对象级。按值比对不能证明失真起于页边界、
整页替换或按页整数倍位移（堆分配不一定按页对齐），认证遥测**不输出页级失真指纹**；
页级指纹只来自故障注入与浸泡取证中的环境对照（#963）。

**遥测级别**（递进包含）：

| 级别             | 内容                                                                                                             | 默认 |
| ---------------- | ---------------------------------------------------------------------------------------------------------------- | ---- |
| `L0 Trace`       | 认证步骤进度                                                                                                     | 关   |
| `L1 Verdict`     | 认证结论与认证时刻（距上次认证的间隔由宿主计算，Runtime 不跨调用保留状态；无注入时间戳时不报告「实际检测滞后」） | 开   |
| `L2 Mismatch`    | 失配现场：失配步骤、首个不等的逻辑位置、期望 vs 实际值                                                           | 开   |
| `L3 Disposition` | 判因 + 处置提示（根重建入口）                                                                                    | 开   |

实际检测滞后只在故障注入中以注入时间戳计算。遥测不进入 C(T)、摘要与快照；遥测失败
不改变认证结论。

## 9. 二期入口：运行中检测

运行中检测（共享根的运行中轮转校验，以及热状态的 Runtime 内保护）不属本设计；若要
进入，必须另开 G1，并至少满足：

1. **证据**：故障机上的 Runtime 长时浸泡 + 宿主审计（§4.2、§4.3）观测到运行中失真，
   给出频率、对象与指纹（#963）；
2. **检测概率**：对每拍重写的对象如实给出单事件检出概率，不得用轮转周期冒充检测界；
3. **成本**：以同二进制开 / 关差值实测给出每拍成本，不得以「摊销」掩盖每拍固定成本；
4. **提交实现**：说明与原地写 P7 的关系及对现行性能工作的约束；
5. **Rust 有效性**：说明受保护对象的布局如何满足任意位模式有效，或如实收窄保证；
6. **封闭写法**：以通则而非逐项列举声明可信面（哪些内存按可信或未覆盖处理）、校验器
   自身控制状态的保护规则（新增状态自动适用）与消费面（只有列明的操作推进校验，其余
   读根路径统一归漏检面），并说明失效状态如何随根跨任务传递而不留只持根的旁路
   （逐项列举没有封闭边界，见 ADR 0032 取舍）。

候选对象按价值排序：共享根运行中轮转 → 每世界已编译路线表（注册后不可变，成本只
发生在注册时）→ Parked / Completed 记录 → 其余热表。
