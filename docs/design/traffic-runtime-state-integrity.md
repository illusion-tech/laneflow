本文是 #955 G1 设计，冻结运行时状态完整性校验与失真处置的权威边界。背景约束来自
#794 归因收口：普通机器（无系统级 ECC）在内存压力下存在**页级内存失真**（首个分歧
偏移落在 4 KiB 页边界、整页替换、页整数倍位移、伴随零页；见
`../reference/validation-matrix.md` 环境失真指纹），失真不绑定特定测试或固定
entry，`fs::read` 与映射读回均可观察。确定性（ADR 0003/0030）是重演的必要条件，
但不自动提供正确性判据：确定性只保证「相同输入得到相同输出」，不保证「内存里的
状态仍是曾经提交过的那个状态」。本设计补的是后一个判据及其处置边界。

现行合同不因本设计改变权威归属：失同步只诊断、处置归宿主
（[`traffic-runtime-snapshot.md`](traffic-runtime-snapshot.md) §6）；输入命令序列与
检查点由宿主记录（ADR 0021）；确定性状态摘要前像为 #302 冻结的 SHA-256
（digest 7 / runtime state 5）；共享静态根不在 C(T) 内（ADR 0030）。本设计只在其上
增加检测面、失败关闭语义与遥测，不新增隐藏输入权威，不改变交通状态、摘要前像与
容器版本轴。

## 1. 问题、设计立场与范围

**问题**：页级内存失真把静默损坏写进运行时状态。确定性回放能定位分歧区间（宿主对拍
检查点三元组 `(command_cursor, tick, deterministic_state_digest)`），但它把「失真」
与「确定性缺陷」混在同一信号里，且只有在状态已经错了之后才显形。需要在运行时内部
提供正确性判据：检出失真、给出可信判因、并把处置权放在唯一权威处。

**设计立场**：

- **检测与处置分权**：Runtime 负责检测并失败关闭；恢复处置归宿主（§3）。
- **两类前像分立**：逻辑摘要前像管「状态内容是否仍是已提交的那个逻辑状态」；物理
  完整性前像管「物理字节是否发生失真」。两者对象、前像、算法与期望值来源各自独立，
  不互相替代（§2、§4）。
- **无可信基准不作宣称**：期望值无法建立或独立核验时，不得宣称检测或恢复成功；
  判因允许「无法判因」（§2、§7）。
- **不进入提交关键路径**：完整性校验不得进入 committed-state barrier，不得因执行
  块切分额外延迟一拍（§4）。
- **1.0 前只留一套权威**：恢复权威落点冻结为一条政策的两个阶段，不并行第二套
  （§3、ADR 0032）。

**范围外**（显式不做）：

- 每 tick 全量校验；
- 恶意篡改防御（本设计只处理非恶意的环境失真与随机损坏，不构成安全边界）；
- 分布式重放；
- 实现与实测（性能实测、retained-memory 账本合入、恢复率测量归实现 Issue）；
- 权威落点冻结前的任何自动纠偏（自动回滚、自动重演、自动重写状态一律不属本设计）；
- 代码页、栈、宿主自有内存、GPU/设备内存的完整性（漏检面显式声明，§5）。

## 2. 可信期望值与前像（必答第 0 项定案）

### 2.1 两类前像分立

| 前像                       | 定义                                                                                                                                       | 管什么                                                                                     | 算法                                       |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------ |
| 逻辑摘要前像               | #302 确定性状态摘要的规范化前像（域分隔 `laneflow:runtime-state-digest:v1\0`、digest 7、runtime state 5、规范记录序列），布局无关、只覆盖 C(T) | 逻辑状态内容正确性：当前状态是否仍是曾经提交过的那个逻辑状态（多重度、绑定、live 序保留）   | SHA-256（#302 冻结，**不替换**）           |
| 物理完整性前像             | 对物理内存区域（热表、工作区、共享静态根 backing）按实际字节布局逐区域计算的完整性前像：域分隔字节 + 区域种类 + 页序 + 长度 + 内容字节（**仅已初始化字节**，§4.1 初始化约束） | 物理字节正确性：内存区域是否被页替换、零页、页整数倍位移等失真改写，与逻辑值无关、布局绑定 | 可增量维护构造（写集增量更新）+ 周期独立复核（§4.3）   |

两层前像的边界：逻辑摘要前像不因布局、地址、capacity 变化而变；物理完整性前像
逐页绑定物理布局，句柄表重排、容量调整都会改变物理前像，这正是它要检测的面。物理层
检出「页被打中」，逻辑层检出「失真已经进入逻辑状态的后果」；两层都失败时以 §7 判因
轴归类，允许「无法判因」。

物理完整性前像按**区域种类**（热表 / 工作区 / 共享静态根 / 期望值登记表）分域分隔，
避免不同对象之间重放同一前像。共享静态根不在 C(T) 内（ADR 0030），只有物理层覆盖
它；逻辑层不为共享根另设第二份摘要。

### 2.2 期望值来源与保护方案

**由谁建立、在什么可信时点**：期望值由**写者**（写入该状态的路径）在**写冻结点**
建立，登记进完整性期望值登记表（下称登记表）：

| 对象         | 登记时点（可信时点）                                                                                     | 绑定                                  |
| ------------ | -------------------------------------------------------------------------------------------------------- | ------------------------------------- |
| 逻辑状态（记录与结构级） | 每个**已提交变更边界**的提交完成点：生命周期命令（路线注册、spawn、停车、replace 等）的共同提交点，以及 tick 的 P7 发布完成后；覆盖记录内容与结构面（计数 / 绑定多重度 / live 序） | `(tick, command_cursor)` 每次提交推进 |
| 逻辑状态（全量共因核对） | 抽样拍（间隔 `N_L`）的提交完成点由登记路径计算，与同一校验窗内校验路径的独立重算比对；**不跨提交持有、非检测判据**（§4.2）——只作共因核对转 `Untrusted` 的线索 | 抽样拍 `(tick, command_cursor)` + 摘要版本轴 |
| 热表 / 工作区 | 该页最后一次写入完成后的写冻结点（拍末或工作区复用前）；页期望值按**写集增量更新**（§4.3），写冻结点只冻结写集与增量 | `(tick, 页序, 区域种类)`              |
| 共享静态根   | **构建完成点由构建方建立**，作为受保护旁车元数据（逐段摘要 + `NetworkRevisionId` 绑定，独立于 backing 存放）随共享根携带；安装 / 认证是**核对**（当前 backing 重算 vs 旁车基线），不是重新建立——发布到安装之间的失真因此可检。跨进程 / 重启由宿主持久旁车携带并受第一层（#954）读回保护 | `(NetworkRevisionId, 区域种类, 页序)` |
| 输出批次     | 输出批次（events / observations / StepResult 载荷）生成完成点（P8 交付之前）；校验窗在交付前独立重算比对，失配则该批次不交付并失败关闭（§4.5） | `(tick, 批次种类)`                    |
| 恢复后状态   | fresh restore / 同修订恢复成功、world 发布前的 staging 完成点                                             | 恢复后的 `(tick, command_cursor)`     |
| 校验器控制状态 | 校验窗调度点（冗余导出更新，见 §4.1）                                                                   | 单调序号双写                          |

登记时点即期望值冻结点：此后该页 / 该状态视为不可变，直到下一次合法写入触发重新登记。
「源缓冲损坏」式的注入定义为**登记后发生**的失真（与 #954 读回合同的登记时点语义
一致）。恢复路径沿 [`traffic-runtime-snapshot.md`](traffic-runtime-snapshot.md) §5
「任一失败零部分恢复」：登记表在 staging 期建立失败即恢复失败关闭，不发布 world，
不得在无登记表的世界上宣称检测能力。

**存放位置与隔离**：登记表是进程内诊断状态，**不进入快照、摘要前像与容器版本轴**
（digest 7 / runtime state 5 不变）。登记表使用独立分配域：

- 登记表页与被校验页**不得同页**。分配器按页对齐分别取域，安装 / 恢复时断言登记表
  页号集合与被校验页号集合不相交；断言失败即「校验过程不可信」失败关闭。
- 登记表不与任何被校验对象共享 backing 页、缓存缓冲或中间数组；写者向登记表写入
  使用登记表自有缓冲。
- 页号不相交断言只保证不同页；同页失真的共因风险由双副本与三层互证承接（下条）。

**双副本与三层互证**：登记表自身也受失真威胁，每个登记项保存两份独立副本：

1. **主副本**：紧凑二进制记录（对象标识、tick / 游标绑定、期望值）；
2. **复核副本**：不同布局、不同分配域、**与所选主构造异族**的哈希（禁止同族配对，
   防共因实现缺陷；族配对由 §4.3 成对落定）；
3. **登记表滚动摘要**：每次校验窗结束时对登记表整体更新的滚动摘要，与主 / 复核
   副本互证。

三层中任意两层不一致即「校验过程不可信」失败关闭；三层同击中的残余风险显式声明
（§4.4）。登记表的建立、增长与重算全部走 checked reserve（#532 原语）：预留失败
返回完整性登记错误、无副作用、可重试，不进 fixed-step 热状态。

**独立核验**：校验路径与写入路径分离——校验在拍后校验窗内从被校验对象**重新计算**
前像并与登记表比较；重算使用校验自有缓冲，不复用写者缓存缓冲，使「缓存与内存
不一致」类失真可分歧（与 #954 两路读回同一口径）。校验读取必须真实触达被校验字节
（不缓存折叠），使零页与整页替换可被观察。

**无法建立可信基准**：以下任一情形即「校验过程不可信」：

- 登记表建立失败（预留失败、页隔离断言失败、双副本初始化分歧）；
- 登记表三层互证分歧；
- 期望值绑定不闭合（tick / 游标单调性破坏、跨修订绑定错位）；
- 检查点锚与宿主持久副本分歧；命令登记条目自身三层互证分歧（两侧前像口径差异不属
  不可信基准，见下表）。

不可信时**不得宣称检测或恢复成功**：世界进入失败关闭，遥测输出「校验过程不可信 /
无法判因」，不输出「通过」结论，不进入恢复语义。

**检查点、输入命令日志、摘要自身被打中**：

| 被打中对象           | 保护与处置                                                                                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 检查点锚             | 检查点三元组 `(command_cursor, tick, deterministic_state_digest)` 由宿主持久（宿主存档清单，对象外绑定，ADR 0021）；Runtime 在校验窗登记同值锚并与之核对。分歧 = 不可信基准，无法判因，交宿主；宿主持久层自身的写后回读由第一层（#954）覆盖 |
| 输入命令日志         | 宿主拥有（ADR 0021），持久完整性不在本设计覆盖内。命令期望值为**宿主自报**：宿主按耐久身份前像计算命令摘要并随命令传入，Runtime 登记 `(command_cursor, 宿主摘要)`，**不独立重算宿主前像**（Runtime 不保存或解释宿主 ID，snapshot §6）；跨权威比对归宿主检查点对拍。Runtime 侧只检登记条目自身失真（三层互证）；两侧前像口径差异不判因、不判 `Untrusted`，有效重放不得因句柄映射差异被误判 |
| 确定性状态摘要自身   | 摘要值经双副本 + 三层互证保护；登记值与重算值一致但都经同一失真内存时的残余风险显式声明（§4.4），此时允许「无法判因」，不得把「重算得同一错误值」当作通过 |
| 登记表本体           | 双副本 + 滚动摘要三层互证；任意两层分歧 = 失败关闭、无法判因                                                                                             |

## 3. 恢复权威落点（必答第 1 项定案）

**定案：一条权威政策的两个阶段，不并行第二套。**

- **阶段一（检测，失败关闭）**：校验发现失配或校验过程不可信，立即失败关闭——世界
  停止推进，不自动纠偏、不自动回滚、不自动重演、不重启世界。
- **阶段二（处置，归宿主）**：检测后交宿主处置。宿主按现行设施恢复：从检查点
  （Runtime Snapshot + 命令游标）恢复并依序重放输入命令序列，用检查点三元组对拍
  定位首个分歧区间（[`traffic-runtime-snapshot.md`](traffic-runtime-snapshot.md) §6）。
  Runtime 只交付检测结论、判因与失真指纹，不执行处置。

这是现行合同（失同步只诊断、处置归宿主）在完整性维度的延伸：失同步的状态仍是合法
确定性状态，因此只诊断不停机；完整性失配的状态可信度已被破坏，因此先失败关闭再交
宿主。两者处置权相同（宿主），区别只在是否停机，权威不双轨。

**已发布结果的处置**：失败关闭不撤销已发布事件 / 观测 / 宿主副作用（不自动纠偏）。
从检测时刻起 Runtime 不再产生新提交；宿主在自己的边界决定丢弃、重放或对拍。Runtime
不隐藏、不重发、不去重事件——事件去重与副作用回退属于宿主回放链，不是 Runtime 职责。

**共享静态根被打中的独立失败语义**：共享静态根（`SharedNetworkRevision`）不在 C(T)
内（ADR 0030），**不属回滚 / 重演可修复面**。共享根失配时：

- 世界失败关闭（与其它失配同一阶段一语义）；
- **根级失效（poison）同步传播**：失效标记**不写入共享根本体**——`SharedNetworkRevision`
  保持不可变、无原子、无内部可变（[`shared-static-network.md`](shared-static-network.md)
  §8/§11），失效状态由**共享根完整性租约**承载，且租约必须**绑进共享根 API**：
  完整性开启时跨边界的唯一句柄是**共享根绑定聚合**（`Arc<SharedNetworkRevision>` +
  共享根完整性租约 + 构建方旁车基线），`install` / `SpatialSession::bind` 以聚合为准
  （[`shared-static-network.md`](shared-static-network.md) §4/§8、
  [`traffic-runtime-shared-consumption.md`](traffic-runtime-shared-consumption.md) 与
  [`adapter-api.md`](adapter-api.md) 已同步回写，签名调整归实现切片），**不得存在只传
  根、拿不到租约的第二条绑定路径**。租约失效标记为受保护双副本。任一消费者检出共享根
  失配即置位租约标记；所有绑定消费者——全部世界与 Spatial——在下一次读取 / 步进 /
  位姿提取前核对租约并失败关闭（终止性错误），不等
  各自 scrub 到该页；任何消费者不得继续从已失效根读取、提交或发布位姿；
- 处置只能是根重建：重编译 / 重安装 / 重新认证共享根后，所有消费者重新恢复 / 重绑；
  宿主不得期望通过检查点回滚或命令重演「修好」共享根；
- 遥测把共享根单列判因类别，不与热表失配合并；根级失效是共享事件，单列遥测。

**备选取舍记录**（四个落点冻结其一；(c)(d) 不采用）：

| 落点                             | 裁决     | 理由                                                                                                                                                              |
| -------------------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| (a) 检测后交宿主处置             | **采用** | 与 ADR 0021 宿主边界、snapshot §6 处置归属一致；合同修订义务最小；宿主已有检查点 + 命令重放设施                                                                    |
| (b) 仅校验失败关闭               | **采用** | 作为 (a) 的阶段一；单独采用 (b) 会留下「检出了但没人处置」的悬空态，故与 (a) 合为一条政策的两个阶段                                                                 |
| (c) 磁盘检查点回滚               | 不采用   | 自动改变状态，承担全套合同修订义务（见下）；把宿主存档清单的权威搬进 Runtime，与 ADR 0021 冲突                                                                     |
| (d) Runtime 内重演               | 不采用   | 需自持命令权威，等于复制宿主回放链，违背「输入命令序列由宿主记录、Runtime 不新增隐藏输入权威」（snapshot §6）；合同修订义务与 (c) 同级                             |

(c)(d) 及任何自动改变状态的方案若未来采用，必须先单开 G1 与 ADR 改写并承担同一合同
修订义务：已发布事件 / 观测 / 宿主副作用处置、句柄映射（局部标识 → 新句柄）、修订
切换交互、事件去重、执行主体与宿主协调方式；不能安全处理已发布结果时停止或交宿主。
1.0 前不为 (c)(d) 保留双轨、开关或兼容层。

## 4. 校验机制（必答第 2 项定案）

### 4.1 校验对象分列

| 类别   | 对象                                                   | 前像             | 说明                                                                        |
| ------ | ------------------------------------------------------ | ---------------- | --------------------------------------------------------------------------- |
| 逻辑   | C(T) 不可变已提交视图                                  | 逻辑摘要前像     | 提交完成后到下一拍开始前不可变；校验窗内只读                                |
| 逻辑   | 已发布输出批次（events / observations / StepResult 载荷） | 输出批次期望值（第三类） | 生成时登记、交付前（校验窗内）独立重算比对；失配则该批次不交付并失败关闭（§4.5） |
| 物理   | 热表（占用索引、leader 图、车辆热列、车辆目录等）      | 物理完整性前像   | 写集增量登记 + 轮转 scrub                                                   |
| 物理   | 工作区（每 tick 派生 scratch）                         | 物理完整性前像   | 派生即不存；登记在消费完成后的写冻结点，见 §4.5                            |
| 物理   | 共享静态根（`SharedNetworkRevision` backing，不在 C(T)） | 物理完整性前像 | 构建方旁车基线（§2.2），安装 / 认证时核对；轮转 scrub + 换根 / 恢复 / 审计时全量重验 |
| 保护面 | 完整性期望值登记表                                     | 自身三层互证     | §2.2；不是被校验对象的期望值来源，是保护面本身                              |
| 保护面 | 校验器控制状态（轮转游标、调度位置、失败关闭粘滞位）   | 双副本 + 冗余导出 | 游标 / 调度位置由登记表滚动摘要冗余导出、单调双写；粘滞位正 / 反相双副本；控制状态页纳入保护页集合。控制状态失配 = `Untrusted`；粘滞位按「先置位后写余」顺序写，置位自身失败即失败关闭 |

**初始化字节约束（Rust soundness）**：物理前像只覆盖**已初始化字节**。保护页进入
scrub 集合前必须满足二者之一（G2 落定）：

- 整页初始化的专用页分配：页对齐分配、显式写满后才入保护区；`Vec` spare capacity、
  结构 padding 等未初始化字节所在页**不入**保护区；
- 页内初始化掩码：掩码按页登记进登记表并自身受保护，前像只哈希掩码覆盖字节。

未初始化字节不在前像内（读取它们在 Rust 中非法，且会让期望值依赖无关的分配器
内容）；该面显式记入 §5 漏检面。工作区「按容量登记」只在整页初始化或掩码登记成立
时有效。

### 4.2 逻辑层校验：双路径全量对拍 + 增量记录轮转

- **记录与结构保留期望值轮转（逻辑检测判据）**：期望值在**每个已提交变更边界**
  （生命周期命令的共同提交点、tick 的 P7 后）增量登记、**跨时间保留**，覆盖 #302
  前像的全部成分——
  - **记录内容**：逐记录期望值，只更新变化记录；
  - **结构面**：集合计数、路线分组绑定多重度、live 序序结构（如相邻对组合哈希），
    每次提交推进。只登记记录内容会漏掉「丢条目 / 重复条目 / 换序 / 车辆改挂路线
    分组」这类每条记录摘要纹丝不动的结构失真，而同窗全量共因核对只会把已坏结构
    再哈希一遍。

  校验窗按记录与结构轮转独立重算子集并逐项比对。期望值保留自提交点，因此能检出
  **窗口之前已持久化**的 C(T) 失真；命令变更提交的记录与结构在提交当时即被期望值
  覆盖，不会逃逸。逻辑层检测滞后 = 轮转周期 M_rec（§5），这是覆盖 C(T) 全部前像
  成分的逻辑检测界。
- **全量共因核对（间隔 N_L，非检测判据）**：在被抽样 tick 的校验窗内，登记路径与
  校验路径从同一不可变 C(T) 视图**各自**按 #302 规范前像计算 SHA-256 摘要并比对；
  两条路径不共享缓冲与排序临时表，任一不等 = 失配失败关闭。**同窗建立、同窗比对、
  不跨提交持有**的全量摘要只能检出路径缺陷、窗口内失真与账目分歧——它检不出窗口
  之前已持久化的 C(T) 失真（两条路径读到同一份坏视图会产出同一摘要），因此**不作
  正确性判据、不承担检测界**，只作共因核对转 `Untrusted` 的线索。
- 分段 / 抽样子校验是**独立机制**，只作检测线索与滞后压缩，不冒充 #302 摘要、不作
  正确性判据；逻辑正确性判据只有记录级保留期望值比对一类。**可选强化**（实现切片）：
  跨提交增量维护的全态累积摘要（可交换组合构造，独立机制，不替换 #302）作为保留
  期望值，落地后可提供全态 `N_L` 检测界，届时回写本节。

### 4.3 哈希选型（前像冻结后选型）

- **逻辑层**：SHA-256（#302 冻结，不替换、不新增第二逻辑摘要算法；digest 7 不变）。
- **物理层**：**独立机制**明示——域分隔字节 `laneflow:physical-integrity:v1\0` +
  区域种类 + 页序 + 长度 + 内容字节，不替换 #302、不进入摘要版本轴。构造硬要求：
  **写集增量维护**——写者写入时按写字节增量更新页期望值（成本 O(写字节)），**禁止
  每脏页整页重哈希**（正常拍脏页远多于 scrub 预算 K，逐页重哈希等于每拍近全量热态
  哈希，§8 摊销预算不成立）。候选构造由 G2 按测量落定：
  - CRC32C 按写集 delta（可增量移除旧字节 / 加入新字节，单页 32 位）；
  - 页内子块 Merkle（子块哈希 + 页值组合，子块哈希 = SHA-256 截断）。
- **独立复核（共因隔离）**：轮转 scrub 之外，周期性以**第二哈希族**整页重算并与主
  构造交叉核对（核对的是校验构造本身：主构造被打中 / 实现缺陷 / 增量账目分歧 →
  `Untrusted`）。复核周期 `M_rev` 为合同值，**进入检测滞后界**（§5）：待验证预算
  ≤ 1024 拍并按 §5 秒上限导出收敛，任何配置不得使 `M_rev` 突破该类别秒上限。
- **登记表复核副本**：与所选主构造**异族**的哈希，**禁止同族配对**——主选 CRC32C
  写集 delta 则复核取 SHA-256 族，主选子块 Merkle（SHA-256 族）则复核取 CRC32C 族。
  同族共因碰撞 / 实现缺陷会同时骗过主值与复核副本，使 §2.2 独立性与 §4.4 残余风险
  声明失效；G2 选型成对落定并回写 §2.2 / §4.3 / §4.4。

本节选型若在实测中调整，必须同步改写 §4.4 残余风险声明与 §8 预算分解并回写本节。

### 4.4 碰撞口径与残余风险声明

- **失败关闭口径**：失配或校验过程不可信即失败关闭；不设容差、不取「多数副本正确」。
- **未检出碰撞残余风险（显式声明）**：
  - 逻辑层单点比较（失真值 vs 期望值，各 256 位）：未检出概率 ≤ 2⁻²⁵⁶ / 事件；
  - 物理层按所选构造声明（G2 落定后回写为唯一值）：CRC32C 写集 delta ≤ 2⁻³² /
    页·事件；页内子块 Merkle + SHA-256 截断 ≤ 2⁻¹²⁸ / 页·事件。构造未落定前按弱构造
    （2⁻³²）保守声明；
  - 登记表共因失真（主 / 复核副本同击中且保持互相一致）：≤ 主构造弱族上界（当前
    保守值 2⁻³² / 事件），这是本设计声明的**最大残余风险**；§4.3 独立复核把「构造
    失效 / 共因 / 增量账目分歧」收窄为 `Untrusted` 判因，残余碰撞面仍按本值声明，
    列为独立复核项（可选升档：第二完整哈希独立实现把上界降到 ≤ 2⁻⁶⁴ 量级，升档
    结论回写本节）；
  - 三层互证同击中的联合残余风险不作数值承诺，命中即「无法判因」。
- 未检出碰撞不构成恢复成功依据：任何「通过」结论都只覆盖声明的对象与窗口。

### 4.5 检测滞后、提交边界与并行约束

- **校验窗的位置（同步合同）**：完整性校验窗是宿主每 tick 链上的**显式同步操作**，
  位于 `step` 返回之后、输出交付之前：

  ```text
  apply_pending → step → 完整性校验窗 → consume_world / 输出交付
  ```

  `step` 的 P0–P8 语义不变（P8 仍只交付结果，无新计算、无新错误），校验窗不是任何
  P 阶段的组成部分；它读取已提交 C(T)、登记表与待交付输出批次，返回 `Pass` /
  `Mismatch` / `Untrusted`。失败关闭是**世界状态**：此后 `step` 返回「世界已失败
  关闭」终止性错误（该错误属其调用自身的世界状态轴，不是校验窗那次调用的归属），
  未交付的输出批次不交付，已发布结果不撤销。检测滞后含窗调度余量 `W_sched` ≤
  1 tick；宿主不调用校验窗即无检测，检测滞后合同按调用频率满足。
- **检测滞后上限**：见 §5 公式与规模数值；校验不得以「永远排不上」形态存在，轮转
  周期与 N_L 都是合同值。
- **不得进入 committed-state barrier**：校验的读、算、写（登记）全部位于 barrier
  之外的校验窗与写冻结登记点；不进入 P0–P8 任何阶段，不改变首错、事件、提交
  语义，不增加可恢复错误。校验窗内的失败只产生遥测与失败关闭信号，不回灌当拍结果。
- **跨块不额外延迟一拍（写入冻结约束）**：登记写入只发生在既有写冻结边界（拍初
  读取之前 / 拍后校验窗）；执行块与 worker 切分不改变校验调度、登记时点与检测滞后，
  不得因分块新增一拍延迟或第二份期望值权威。校验任务只读 C(T) 与登记表，与执行块
  无耦合；worker 数不进入登记表、不进入任何前像（与 ADR 0030 一致）。
- **工作区与输出的取舍**：不为工作区做消费前逐页校验（那会进入 tick 热路径与提交
  关键路径）。工作区前像在消费完成后的写冻结点按写集增量登记，校验窗轮转重算比对；
  tick 内已消费的失真后果中，**已提交交通状态**由逻辑层对拍兜底，**已发布输出**
  （events / observations / StepResult 载荷）由输出批次期望值在交付前独立重算比对
  兜底（§4.1）——输出承载面被改而交通状态不变的路径因此可检，失配批次不交付。
  该取舍仍留下「输出批次重算之后、交付之前」的极小窗口与被消费清空的工作区残留，
  漏检面显式记入 §5。

## 5. 间隔 N、抽样 / 增量与漏检面（必答第 3 项定案）

**检测滞后公式**（`W_sched` = 校验窗调度余量，合同值 ≤ 1 个校验窗）：

```text
逻辑记录轮转滞后       = M_rec × fixed_delta_time_ms + W_sched        （逻辑检测判据）
物理页 scrub 滞后      = M_phys × fixed_delta_time_ms + W_sched        （快变集合：热表、工作区）
共享静态根 scrub 滞后  = M_phys_root × fixed_delta_time_ms + W_sched    （不可变集合）
独立复核滞后           = M_rev × fixed_delta_time_ms + W_sched          （构造失效 / 共因）
总检测滞后上限         = max(以上各项)，按类别列明
（全量共因核对周期 N_L 非检测判据，不进上式，不承担检测界）
```

**机制与间隔**（初值为待验证预算，实测归实现 Issue；§8 表格同此口径）：

| 机制             | 覆盖             | 间隔 / 周期（待验证预算）                          | 漏检面                                                                                             |
| ---------------- | ---------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 逻辑记录与结构轮转（检测判据） | 逐记录 + 结构面（计数 / 绑定多重度 / live 序） | 轮转周期 M_rec ≤ 128 拍（一百万 ≤ 512 拍） | 记录被合法写入覆盖（自愈）后不可检；登记即错不可检（见下）；被打中的期望值本身由 §2.2 三层互证承接 |
| 逻辑全量共因核对（**非检测判据**） | 全部 C(T) | 周期 N_L：一万 64 拍；十万 256 拍；一百万 1024 拍 | 同窗双路径检不出窗口前已持久化的 C(T) 失真（两路径读到同一坏视图产出同一摘要）——这正是它不承担检测界的原因；只检路径缺陷 / 窗口内失真 / 账目分歧 |
| 物理页轮转 scrub（快变集合） | 热表、工作区全部页 | 全覆盖周期 M_phys ≤ 256 拍（一百万 ≤ 1024 拍；K 页 / 校验窗，按 §8 摊销与突发双预算求解） | 失真发生在某页 scrub 之后且在其下次 scrub 之前被合法写入覆盖（自愈）；被消费后清空的工作区残留不可检 |
| 物理页轮转 scrub（不可变集合） | 共享静态根全部页 | 全覆盖周期 M_phys_root ≤ 1024 拍（分类轮转；期望值安装后不变，页集合随换根 / 恢复重建） | 无合法写入覆盖，故不新增自愈类漏检；代价只是该类检测滞后更大（见下）                                |
| 独立复核（第二哈希族） | 物理主构造、登记表 | 复核周期 M_rev ≤ 1024 拍（按秒上限导出收敛，进入检测滞后界） | 构造失效 / 共因 / 增量账目分歧的检出滞后；不承担页失真检测（那由 scrub 承担）                        |

**间隔拍数的权威口径**：§8 待验证预算表是分规模数值的唯一权威；本表拍数为一万 /
十万标称值（含一百万例外标注）。cadence 未冻结的规模（一百万）以及任何
`fixed_delta_time_ms` 大于标称值的配置，拍数按下式导出收敛：

```text
N = min(标称拍数, floor((该类检测延迟上限 − W_sched) / fixed_delta_time_ms))
```

**检测延迟上限（秒）是合同，拍数是导出值**；实现不得在长步长配置下沿用标称拍数
而突破秒上限。

分类轮转的理由：共享静态根不可变，其期望值一次登记后不变，不存在「合法写入覆盖失真」
的自愈面，因此允许比快变集合更长的轮转周期——放大检测滞后但不新增漏检面；快变集合
（热表 / 工作区）逐拍改写，必须保持 ≤ 256 拍的全覆盖周期。

**显式漏检面（总表）**：

1. 自愈性覆盖：失真落在两次检查之间且被合法写入改回 / 覆盖——两层都不可检，显式声明；
2. tick 内工作区失真：消费前不校验（§4.5 取舍）；已提交状态的后果由逻辑层对拍兜底，
   已发布输出的后果由输出批次期望值交付前核验兜底，兜不住的残留进下一轮物理 scrub；
3. 未覆盖面：代码页、栈、宿主自有内存、GPU / 设备内存、宿主持久层（检查点制品与
   命令日志的持久完整性由 #954 第一层与宿主合同覆盖）；
4. 三层同击中（登记表主 / 复核 / 滚动摘要一致地坏）：不可检，「无法判因」；
5. **登记即错**（写者写入时读到的字节已坏）：期望值忠实记录坏值，之后的 scrub 复现
   同一坏值，**不可检**（部分写重登记还会把写集外的坏值洗白）；只由宿主检查点回放
   对拍兜底（语义层兜底）。可选收窄：实现若提供精确写集，重登记只更新写集覆盖部分、
   对其余字节与旧期望值差分比对，可把该面收窄为「写集内登记即错」；收窄未落地前按
   不可检声明；
6. 输出批次「重算之后、交付之前」的极小窗口失真，以及被消费清空的工作区残留
   （§4.5 取舍的余量）；
7. 校验器控制状态被击中且双副本 + 冗余导出一致地坏（与第 4 条同口径，「无法判因」）；
8. 未初始化字节（`Vec` spare capacity、结构 padding）不在物理前像内（§4.1 初始化
   约束）：其被失真改写不可检，除非随后被初始化并重新登记。

最大检测延迟按类别与规模写明（待验证预算）：

- 逻辑检测判据（记录轮转 `M_rec`）：一万 ≤ 128 × 16 ms ≈ **2.1 s**；十万 ≤ 128 × 33 ms ≈ **4.2 s**；
- 热表 / 工作区快变集合（`M_phys`）：一万 ≤ 256 × 16 ms ≈ **4.1 s**；十万 ≤ 256 × 33 ms ≈ **8.4 s**；
- 共享静态根不可变集合（`M_phys_root`）与独立复核（`M_rev`）：≤ 1024 拍，一万 ≈
  **16.4 s**、十万 ≈ **33.8 s**；
- 全量共因核对（`N_L`）**非检测判据**，不计检测延迟（§4.2）；
- 一百万：全部检测类别合同值**上限 60 s**（无实时 SLA，只定检测延迟上限）。

上述拍数在各规模标称 cadence 下成立；对 cadence 未冻结的规模或长步长配置（ADR 0028
允许 `fixed_delta_time_ms` 到 1000 ms），间隔拍数按上文导出规则收敛，秒上限保持成立
——例：一百万档 `fixed_delta_time_ms = 1000 ms` 时各间隔导出为 ≤ 59 拍，总检测延迟
仍 ≤ 60 s + `W_sched`。以上为待验证预算，实测归实现 Issue，可依据可复现证据收紧。

## 6. retained-memory 裁决与分类方案（必答第 4 项定案）

**裁决**：服从第 1 项落点——落点为「失败关闭 + 宿主处置」，因此**验证点持有方 =
Runtime 完整性校验组件**（登记表与校验器由 Runtime 持有、随世界生命周期建立与
销毁）；它只有检测面，**不另给恢复语义**——登记表、校验器与校验 scratch 都不是
恢复设施，不承载回滚 / 重演 / 纠偏能力。

**#380 账本穷尽分类**：本设计新增的保留内存按 `retained memory ledger` 词条合同
（按所有权穷尽枚举，新增字段必须触发编译失败以强制分类）登记为下列所有权类目；
实现不得以「诊断内存」笼统归类：

| 所有权类目                       | 性质     | 规模                                             |
| -------------------------------- | -------- | ------------------------------------------------ |
| 期望值登记表主副本               | 稳态保留 | O(保护区总页数 + 逻辑记录数 + 结构面)            |
| 期望值登记表复核副本             | 稳态保留 | 同上（不同布局 / 哈希族 / 分配域）               |
| 登记表滚动摘要与页映射表         | 稳态保留 | O(保护区总页数)                                  |
| 校验器控制状态（游标 / 调度 / 粘滞位，双副本 + 反相 + 冗余导出） | 稳态保留 | O(1)                                   |
| 共享根旁车基线                   | 稳态保留 | O(共享根段数)；构建方 / 宿主持有，**N 世界共享一份**（2/8/32 worlds 不随世界数线性放大） |
| 共享根完整性租约                 | 稳态保留 | 每根 O(1)（失效标记双副本）；经共享根绑定聚合为全部消费者共享一份 |
| 校验重算缓冲（逻辑全量 + 记录与结构级） | 校验峰值 | 与全量摘要缓冲同量级，校验窗内短持有       |
| 页 scrub 读缓冲                  | 校验峰值 | 固定 K 页缓冲，校验窗内短持有                    |
| 诊断 / 遥测缓冲（失真指纹输出）  | 校验峰值 | 有界，仅在失配时持有                             |

**保护区总页数的口径**：保护区 = §2.2 登记对象全体的页集合——热表 + 工作区 +
共享静态根，**一个不漏**；登记表为每个保护区页持有主副本、复核副本与页映射条目，
即使该页内容不可变（共享根页在安装 / 认证时一次登记、稳态不重登记，但持续占
登记表），工作区页集合按容量登记、内容逐 tick 重登记。账面上界按每页「主 +
复核 + 页映射」约 ≤ 80 B/页（待验证上界）；共享根在十万 / 百万档按 10⁵ 页级
估算，登记表稳态为个位数 MiB 量级，主导保护区页数与 §8 稳态保留实测。任一类
保护页不入账都会使本账本与实测少算。

**稳态保留与恢复峰值分列**：稳态保留 = 上表前六行（校验关闭配置下，登记表与校验器
部分为零；旁车基线与租约随共享根存在）；校验峰值 = 后三行，在校验窗内出现、窗后
释放。共享基数口径：旁车基线与租约**每根一份**，2/8/32 worlds 共享测量下不随世界
数线性放大；随世界数增长的只有各世界的登记表与校验器部分。**「恢复峰值」不属 Runtime 侧**：落点下恢复是宿主
处置（restore + 重放），其峰值按 [`traffic-runtime-snapshot.md`](traffic-runtime-snapshot.md)
§8 度量（恢复峰值内存已有登记口径）分列在宿主恢复链，不与校验峰值混记。实现报告
必须把「稳态保留 / 校验峰值 / 宿主恢复峰值」三列分开，不得相加冒充单一数字。

## 7. 失败语义与遥测级别（必答第 5 项定案）

**校验结论三值**：

| 结论          | 含义                                       | 语义                                                                     |
| ------------- | ------------------------------------------ | ------------------------------------------------------------------------ |
| `Pass`        | 本窗口声明对象全部一致                     | 只覆盖声明对象与窗口，不外推                                             |
| `Mismatch`    | 期望值与重算值不等                         | 失败关闭；判因按对象类别                                                 |
| `Untrusted`   | 校验过程不可信 / 无法建立可信基准          | 失败关闭；判因「无法判因」，不输出通过                                   |

**失败关闭语义**：`Mismatch` 或 `Untrusted` 使世界进入完整性失败关闭态——不再推进、
不再提交、不自动纠偏 / 回滚 / 重演 / 重启。校验窗自身返回三值结论；失败关闭后
`step` 返回「世界已失败关闭」终止性失败（世界状态轴，非 `StepError` 可重试语义，
具体 API 标识符由 G2 落定）。失败关闭粘滞态拒绝**一切变更入口**——生命周期命令
（路线注册、spawn、replace、停车、despawn）、管理面写入口、快照保存与切换一律
返回同一终止性错误（各 API 暴露同一错误轴，不得留下任何能改写冻结视图的提交
边界）；只读**取证入口**显式保留（导出冻结视图、登记表与遥测，不承诺可信、不进入
正常观测流）。未交付的输出批次不交付；已发布事件 / 观测 / 宿主
副作用不撤销；句柄、世代与冻结视图保持不变供宿主取证。共享根失配触发根级失效
传播（§3）：所有绑定世界与 Spatial 消费者失败关闭，不止检测方。处置权在宿主（§3）。

**判因轴**：`逻辑对象` / `物理-热表` / `物理-工作区` / `物理-共享静态根` / `登记表` /
`无法判因`。判因不承诺唯一根因；多层同时显形时按「最靠近写者的证据」归类，证据
冲突一律「无法判因」。判因输出附失真指纹分类（与 #794 / `validation-matrix.md`
环境失真指纹对齐）：页边界偏移、整页替换、页整数倍位移、零页、非页对齐（后者提示
非环境失真，转代码嫌疑，走环境对照再谈代码）。

**遥测级别**（级别是递进包含，不是并行通道）：

| 级别            | 内容                                                                  | 默认 |
| --------------- | --------------------------------------------------------------------- | ---- |
| `L0 Trace`      | 校验窗进度、scrub 轮转位置、登记量                                    | 关   |
| `L1 Verdict`    | 每校验窗 Pass / Mismatch / Untrusted 计数与滞后实际值                | 开   |
| `L2 Mismatch`   | 失配现场：对象、页序、tick / 游标、期望 vs 实际、指纹分类             | 开   |
| `L3 FailClosed` | 进入失败关闭 + 判因轴结论 + 处置提示（宿主恢复入口）                 | 开   |

遥测是诊断面，不进入 C(T)、不进入摘要、不进入快照；遥测失败不影响失败关闭语义。

## 8. 性能测量协议与待验证预算

**计入口径（定案）**：校验摊销**单列**，不计入
[`core-runtime-performance-baseline.md`](core-runtime-performance-baseline.md) §6
W1 presentation 主行 p95（一万 Core ≤ 2 ms/tick、十万 Core ≤ 16 ms/tick）。理由：
校验是可配置韧性面（N_L / K 可调、可整体关闭），混入 Core p95 会把韧性成本误记为
交通求解成本，并使关闭校验的基线失去可比性。同时给两个独立预算防止无界增长或
互相冒充：**摊销预算**（跨轮转周期平均的每拍校验成本 ≤ 对应规模 Core p95 主行的
5%）与**突发预算**（单个校验窗在一拍内完成时的校验拍整拍上限，见测量协议）；
两者独立定义、同时满足，同一个 5% 不得作两种解释（待验证预算）。

**测量协议**：

- **突发预算与摊销预算分立**（同一 5% 不得两种解释）：
  - **摊销预算** = 校验窗总耗时 / 窗间拍数，报告 p95/p99，上限 = 对应规模 Core p95
    主行的 5%（跨轮转周期平均，见下表）；
  - **突发预算** = 校验拍（单个校验窗在一拍内完成时的整拍）tick 墙钟上限，报告
    p50/p95/p99/max 与 `burst_max = max(单窗最大值)`（对齐 §8.2 W4 burst 口径），
    预算见下表；摊销达标但单窗超突发上限仍不合格，反之亦然；
  - `(N_L, K, M_rec, M_phys, M_phys_root, M_rev)` 必须同时满足两预算；全量共因核对
    放不下突发预算时只允许调大 `N_L`（降核对频率）或缩小核对范围，**不得跨拍分片
    重算**——分片跨越提交会把多份已提交状态拼进同一摘要，产生不了可比对的期望值
    （§4.2）；间隔 / 周期是合同值，变更回写本节与 §5。
- 两预算覆盖的校验成本 = 写集增量登记 + K 页 scrub + 周期独立复核 + 输出批次核验 +
  记录级轮转重算，全部实测计入摊销 / 突发行；期望值重登记不得以逐脏页整页重哈希
  形态出现（§4.3 构造硬要求），出现即视为预算外。
- 校验摊销按「普通拍 / 校验拍」分列统计（对齐 catch-up frame 单独统计口径）；
  两套预算均只作单列报告行，不与 W1 presentation 主行合并判 Product Pass/Fail。
- 恢复停顿口径 = 宿主处置链停顿（`restore_lfrs` + 命令重放至失配区间前），按
  [`traffic-runtime-snapshot.md`](traffic-runtime-snapshot.md) §8 度量维度报告
  （load 停顿、恢复峰值内存、重放停顿），**不进产品 Gate**（对齐性能基线 §8.2
  「不套用 W1 绝对预算、只报告」的处置方式）。校验失败关闭本身不产生恢复停顿——
  停顿发生在宿主处置时。
- 稳态零分配纪律沿性能基线 §8.3：W1/W2 稳态热路径保持 `0 allocation / 0
  reallocation`；登记表增长在安装 / 恢复 / 首个容量边界一次性 checked reserve，
  校验窗重算缓冲复用预留容量，不在每拍热路径分配。
- 百万档无实时 SLA，只定检测延迟上限（§5）；只运行明确声明的有限 observation。

**待验证预算**（分规模；全部为待验证预算，实测归实现 Issue；1.0 前可依据可复现
证据收紧、放宽或重构，影响合同或验收结论时返回 G1）：

| 维度                         | 一万（16 ms 拍）                    | 十万（33 ms 拍）                    | 一百万（不冻结 cadence）      |
| ---------------------------- | ----------------------------------- | ----------------------------------- | ----------------------------- |
| 校验摊销（跨窗平均 p95）     | ≤ 0.10 ms/拍（5% × 2 ms）           | ≤ 0.80 ms/拍（5% × 16 ms）          | 无实时 SLA；只报绝对值        |
| 校验突发（校验拍整拍 p95 / p99 / max） | ≤ 3.0 / 4.0 / 16 ms（1.5× / 2× Core p95 主行，max 不超 fixed quantum；单列并报 burst_max） | ≤ 24 / 32 / 33 ms（同口径；单列并报 burst_max） | 只报 p50/p95/p99/max 与 burst_max |
| 全量共因核对周期 N_L（非检测判据） | 64 拍（≈ 1.0 s）              | 256 拍（≈ 8.4 s）                   | ≤ 1024 拍（按 60 s 上限导出收敛） |
| 逻辑检测判据：记录轮转 M_rec | ≤ 128 拍（≈ 2.1 s）                 | ≤ 128 拍（≈ 4.2 s）                 | ≤ 512 拍（按 60 s 上限导出收敛）  |
| 物理全覆盖周期 M_phys（热表 / 工作区） | ≤ 256 拍（≈ 4.1 s）          | ≤ 256 拍（≈ 8.4 s）                 | ≤ 1024 拍（按 60 s 上限导出收敛） |
| 物理全覆盖周期 M_phys_root（共享根） | ≤ 1024 拍（≈ 16.4 s）         | ≤ 1024 拍（≈ 33.8 s）               | ≤ 1024 拍（按 60 s 上限导出收敛） |
| 独立复核周期 M_rev（入检测滞后界） | ≤ 1024 拍（≈ 16.4 s）         | ≤ 1024 拍（≈ 33.8 s）               | ≤ 1024 拍（按 60 s 上限导出收敛） |
| 总检测延迟上限               | 逻辑 ≈ 2.1 s；快变 ≈ 4.1 s；共享根 / 复核 ≈ 16.4 s | 逻辑 ≈ 4.2 s；快变 ≈ 8.4 s；共享根 / 复核 ≈ 33.8 s | ≤ 60 s（全部检测类别）            |
| 稳态保留（登记表 + 页映射）  | 待实测（O(保护区总页数 + 逻辑记录数)，§6） | 待实测                       | 待实测                        |
| 校验峰值 / 宿主恢复峰值      | 分列报告                            | 分列报告                            | 分列报告                      |
| 恢复停顿                     | 报告不 Gate                         | 报告不 Gate                         | 报告不 Gate                   |

页数假设（用于求解 K 页 / 校验窗）：热表 + 工作区按待验证上界约 2 KiB / 活跃车
（含页对齐与页映射），一万档约 5,120 页；共享静态根按部署路网的 backing 字节数
另计（4 KiB / 页），在十万 / 百万档主导保护区页数与登记表稳态（§6）。按摊销与
突发双预算求得 K ≈ 32 页 / 校验窗可使快变集合 M_phys ≤ 256 拍；共享根 sweep 按
其字节数与摊销预算导出 M_phys_root，合同上限 1024 拍 / 60 s。该假设与 K 由实现
切片按实测修正。
