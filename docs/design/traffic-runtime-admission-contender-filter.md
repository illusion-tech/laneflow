# 准入缓存完整重建前的保守筛选

**文档状态**: Accepted（#828 / PR #829；#830 的 G1 输入）<br>
**最后更新**: 2026-10-08<br>
**适用范围**: 道路机动车 `spawn_vehicle` / `replace_completed_vehicle` 的派生候选缓存完整重建

关联：[新鲜摆放准入](traffic-runtime-vehicle-placement.md)、
[入口 frontier](traffic-runtime-near-gate-frontier.md)、
[整数几何](traffic-runtime-integer-geometry.md)、
[共享路网消费](traffic-runtime-shared-consumption.md)。
本提案不新增 ADR、公开 API、格式、依赖或运行时开关。当前准入合同继续有效；
本文尚不表示筛选已经实现或测得收益。

## 1. 决策与范围

只在 `placement.rs::rebuild_spawn_contenders` 的规范 `live_order` 遍历中，
对当前状态能证明没有任何候选贡献的已有车辆，省去完整运动预览。
首版保留线性遍历、原有顺序、外层表预留、空 owner 记录和增量维护。
不把筛选塞进共享的 `add_spawn_contender`：该函数也被成功命令后的增量刷新调用，
首版不扩展那条路径。

筛选只减少构造已有车辆候选缓存的计算。新车自身、重叠、前后车、停车约束、
速度下降、冲突/等待/下游权威的全部安全检查仍执行。不能用新车所处车道筛掉
其他可能影响让行或名额的路线，也不复用上一拍 frontier 名单。

## 2. 当前路径与必须保留的结果

完整重建对每辆符合原有 Active 与 `route_needs_contender` 判断的车辆，依次执行：

1. 取得 profile，调用 `preview_active_vehicle_with_waiting_stop`。
2. `contender_notes` 构造 `cells`（证明时窗内到达）、`ranks`（本拍会申请的第一处冲突）
   和 `waiting`（本拍会进入的等待区）。
3. `apply_contender_notes` 写入归约表、名单和 `OwnerContribution`。

`cells` 的计算使用当前提交态、`PreparedApproachEta` 和信号下界，独立于运动预览。
`ranks` / `waiting` 使用预览后的路线位置。三者为空仍会执行 `store_owner`；
`owner_sequence` 与增量刷新会读取这个记录，不能直接 `continue` 丢掉它。
首版保留空贡献的现行字段值，包括原代码推导的 `update_sequence`，
不借优化修正或重排其他元数据；发现既有问题应另行处理。

`ensure_spawn_contenders` 仍只在完整重建成功后写入 `ContenderBuilt`。
身份仍绑定当前世界世代和观测状态序号；恢复、换根、停车预约变化、路线改绑、
成功生成/替换等失效与增量规则继续由现行合同决定。

## 3. 首版充分条件

判定必须只读、无分配、不产生新领域错误。结果只有“已证明无贡献”与“完整求值”。
以下条件必须同时成立；不成立或材料不齐时调用原有完整路径，不提前返回成功或拒绝。

### 3.1 身份、权利与运动定义域

仍先执行原有 live 配对、Active、路线适用性和 profile 检查。
筛选读取完整车辆句柄、完整路线句柄、当前 occurrence、毫米进度与微米余数，
不按裸槽位、物理边或旧观测状态序号匹配。当前路网、路线与 profile 必须来自同一绑定。

首版排除有 `maneuver_traversal`、`waiting_membership`、停车绑定、冲突 reservation、
下游声明或其他待维护权利的车辆；读取权利时必须使用现有所有者查询，不能只看
`VehicleState` 上没有某个字段。资料无法确认也走完整路径。

`carry_um < 1000`；当前 occurrence 有受检边长、限速和剩余路线资料；
`0 < progress_mm < edge_length_mm`。零进度一律走完整路径，因而上一 hop 的零距门、
零余量翻边、重复边及零长度连接不会被首版排除。

### 3.2 一拍不能到达本边末端

复用 `tick::MotionReach::from_tick` 与 `excludes`，不复制浮点公式。
当前原语的证明域为速度不超过 `100000 mm/s`、最大加速度 `0.5..=50 m/s²`、
转换后的 `f32` 步长属于 `0.004..=1 s`；上界包含 `50 mm` 余量。
超域、非有限或不能构造上界时完整求值。取：

```text
distance = edge_length_mm - progress_mm
unreachable = MotionReach::from_tick(...).excludes(distance)
```

比较必须严格大于：恰好可达和边界舍入附近均不筛除。
首版要求本边末端不可达，比仅证明下一道门不可达更保守；因此不需要为筛选跨边行走，
也不改变 `gate_hops` 或等待区出现项的解释。
不要改用 `entry_frontier` 的 2 mm 分类余量；该分类的用途与这里的运动证明域不同。

由原语的位移上界和 `progress_mm > 0`，原完整预览若成功，下一位置仍在当前边内部。
`contender_notes` 不会到达本 occurrence 或后续 occurrence 的门，也不会越过等待入口；
其 `ranks` 必为空，`waiting` 必为 `None`。前车、信号、限速和硬房间只能把这一上界
进一步收紧；筛选不能用它们推导更小的上界以扩大命中。

### 3.3 证明时窗内没有冲突接近贡献

这个条件与一拍不可达分开：本拍过不了门的车仍可能在让行证明时窗内到达冲突入口。
使用当前 `policy_binding.horizon()`，从与 `contender_notes` 相同的当前位置二分
定位冲突出现项后缀，不能只找下一道 Gate 或按物理边去重。

- 没有证明时窗时，原路径不构造 `cells`；仍须满足本节其他条件。
- 后缀确实为空时，没有 `cells`。
- 否则只在首个后缀出现项能取得有限精确入口距离，并由同一
  `PreparedApproachEta::new(carry_um, speed_mm_s, max_accel, horizon)` 的
  `lower_bound` 返回 `OutsideHorizon` 时证明为空。
- 距离缺失、`BeyondFinite`、`Unprovable`、构造失败或首项仍在时窗内，全部完整求值。
  不为提高命中而扫过不明首项寻找更远的项。

这复现原路径在首个 `OutsideHorizon` 处停止的条件；路线出现项有序，后续距离不更近。
初始项为零距离、相同位置的多个 passage、环路再次出现同一边都保留原有排序语义。
不以红灯或当前零速单独证明为空，也不为筛选另外计算信号周期；这样不依赖放行推迟，
已有权利与无法停车的例外仍走完整路径。

### 3.4 完整预览成功性是独立义务

第 3.2、3.3 节只证明“完整预览成功时贡献为空”，**不证明可以吞掉预览错误**。
命令路径没有 P5 补做该车预览，不能套用 P2 将运动错误后移 P5 的规则。

实现必须把 `calculate_active_vehicle_motion` 的失败来源逐类闭合到受检不变量或
保留下来的校验。至少涵盖下面四组；任何一组无法闭合，就令这辆车走完整路径。

| 失败来源                                                   | 首版要求                                                                                                  |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 路线/profile/当前 hop/边长/限速/remaining 缺失             | 保留原检查顺序；查询缺失不得成为筛选命中                                                                  |
| `leader_query_horizon`、运动内核 proposal 的数值域         | 绑定受检 profile 范围与 `MotionReach` 域，证明任意合法占用 gap 下运算有定义；不能只以几何不可达代替此证明 |
| 停车绑定、后续限速、信号/门和路径包络                      | 无停车绑定；保留静态路线完整性，证明被省略的查询不能失败；不能用没有本拍候选来推定整个后缀有效            |
| `round_um`、`round_mm`、余数、`apply_travel_mm` 与结果位置 | 用同边内部的严格上界、受检速度/车型与整数范围闭合；边界及不能证明的量程完整求值                           |

后续实现 PR 必须给出这些来源到具体 guard、受检构造不变量及测试的对应表。
不允许引入“假设所有合法状态都不会失败”的未验证快捷返回，也不允许为了通过
对拍删除参考路径的错误检查。需要保留某个便宜校验时复用原语，不维护第二套校验规则。
本设计接受只批准上述有条件的筛选，不预先认证某个尚未提交的实现已满足成功性证明。

### 3.5 首版实现的成功性对应（#830）

`add_proven_empty_spawn_contender` 只由完整重建调用。命中前使用现有
`ConflictRead::has_authority` 查询完整 owner；合法已提交下游声明附属于 reservation，
暂存权利也由该查询排除。停车绑定、机动穿越和等待 membership 单独排除。
当前 profile 从绑定共享路网读取，缺失时回退，原路径仍决定错误。

`admission_preview_stays_inside` 把成功性证明再收窄：当前 hop 对应的限速下降后缀
必须为空；有任何后续下降或索引越界都完整求值。这不是删除降速规则，也不把这一
充分条件扩大到增量维护。对应如下：

| 失败来源                             | guard 或受检不变量                                                                                                                                                                                                                                                                                        | 验证                                                                                 |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 路线/profile/hop/边长/限速/remaining | 完整句柄查询；复用 `route_hop`，并核对结果位置将读取的 edge、limit、remaining 项                                                                                                                                                                                                                          | 内部预览证明测试覆盖缺失 cursor、零进度、边末和正常内部位置                          |
| 前车查询窗                           | 保留 `leader_query_horizon`，失败回退；占用 gap 查询返回任意 `Option<i64>`，本身不产生预览错误                                                                                                                                                                                                            | 数值测试覆盖负 gap、零、最小正毫米及 `i64::MAX`                                      |
| IIDM proposal                        | `build_profiles` 保证 desired 1..=100000 mm/s、min gap 不超过 128 m、headway 大于零且不超过 60 s；结合 `MotionReach` 的 speed/accel/delta 域，最小正 desired/gap 为 0.001 m，两个平方项及加速度均在有限 `f32` 范围内。非正 gap 原语直接停；正 gap 时 next speed 被限制在 0..=100 m/s，travel 不超过 125 m | 调用原 `iidm_step` 的极值组合，核对成功、整数量化和 `MotionReach` 上界               |
| 停车、信号、门、包络和降速           | 无停车绑定；保留 `speed_limit_path_envelope_from` 的原始校验。信号和门查询不返回失败，只收紧房间。空降速后缀不调用分段距离/投影；无第二套降速公式                                                                                                                                                         | 有效边界对拍及原停车、改绑、冲突/等待准入合同在两条路径下执行                        |
| 量化与位置                           | carry 小于 1000；travel 不超过 125 m，微米量化及携带和不溢出；速度不超过 100 m/s。严格本边内部上界保证 `apply_travel_mm` 不跨边，结果所需列已校验                                                                                                                                                         | carry 0/999/1000、上界相等和两侧、步长与速度域外测试；成功预览的实际位置仍在本边内部 |

这些检查不假设“所有预览都成功”：静态输入依赖受检构造，其余可失败的查询继续执行；
无法证明者回退原预览。完整缓存对拍包括空 owner 与 `built_for`，连续命令和恢复
对拍还比较规范快照。资源测试复用候选缓存的现有容量账本，核对冷/暖分配及故障重试。

## 4. 命中后的处理与失败原子性

命中时省去完整运动预览，但继续使用原 `contender_notes`，以当前 state 作为其
`preview_next` 参数。第 3 节保证三个贡献与真实预览相同且为空；这不是提交静止运动，
也不是修改车速或下一拍状态。继续执行 `take_note_alloc` 与 `apply_contender_notes`，
保持空 owner 的预留、字段和写入语义。

这一选择可能重复一次廉价 ETA 判定；首版用它避免复制 notes 的构造、分配标记及
owner 语义。不得顺带删除空 owner、改变排序、缩减外层表、跳过等待名单排序，
或把过滤结果常驻缓存到下一条命令。成功命令后的 `refresh_contender_cache`、
`preview_notes` 和它调用的 `add_spawn_contender` 全部沿用原路径。

外层表、owner 或其他现有必需预留失败仍返回 `OccupancyAllocFailed`，
不改报 `StopConstraintUnsatisfiable`。失败重建不得标记 `built_for` 有效；
派生表可以部分写入但必须整体无效，重试先重建，已提交车辆、权利、游标、日志不变。
新增筛选本身不分配，不能多出一种预留失败或吞掉原先会执行的必要预留。
故障注入按实际逻辑预留类别验证；不要求维持已经证明不会发生的空向量分配次数。

## 5. 正确性论证与验证

对每个完整重建的规范位置：未命中使用原路径；命中满足预览成功性，且三个贡献均空，
原 notes/apply 路径产生同样的 owner 和表状态。按 `live_order` 归纳，可得完整重建
后的缓存值与原路径一致。后续消费、排序和增量维护不变，因而公共命令结果、首个
拒绝原因、已提交状态与资源权威不因筛选变化。这是实现须满足的论证，不能只凭
一次场景输出摘要宣称所有前提已验证。

测试参考只能存在于 `cfg(test)` / 现有测试夹具特性或冻结的外部研究构建；默认产品
只有一条路径，不增加全量/筛选的宿主开关。参考关闭的是本次筛选，不能改动其他逻辑。

| 测试组           | 必须比较或触发的边界                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------------------- |
| 基本命中与回退   | 同边远处空贡献可命中；时窗内接近但一拍不可达必须回退；无 horizon、纯等待路线、无后续冲突                        |
| 数值边界         | 一拍上界两侧及相等、`carry_um` 的 0/999、步长/加速度证明域边界及域外、低速/零速/高速、数值失败反例              |
| 路线与几何       | 零进度、边末、零长度连接、跨边、重复物理边/重复 passage、末端、有限距离边界与 `BeyondFinite`                    |
| 权利与策略       | 等待 membership、已有冲突与下游权利、停车绑定、保护/让行、红灯停得住与停不住均按要求回退                        |
| 同一边界多条命令 | 生成/替换/移除、先成功后失败、旧车在 live 前中后部、受影响后车增量刷新、空 owner 被读取、完整重建与增量结果一致 |
| 身份与恢复       | 槽位复用及 generation、路线代次、改绑、恢复、修订切换后的首条命令，不复用旧状态的筛选结论                       |
| 失败与重试       | 外层表、notes、owner 和排序预留注入；错误类别一致；缓存无效标记、已提交状态/游标/权利不变；解除注入后重试相同   |

对照必须逐项比较 `best` 的规范顺序和 rank、`cell_approach` 的 owner/ETA、
`waiting_entrants`、空/非空 `owners` 及 `built_for`；不能只比较公开 `ticks.jsonl`。
同一命令序列再比较返回值、事件、状态摘要和资源账本。实现若新增测试计数器，
只统计扫描数、已证明空贡献数、完整预览数与回退原因，不给逐车热循环加墙钟。

## 6. 有界收益验证与停止条件

正确性测试通过后，用同一 Rust 工具链、输入、车辆计划、默认特性与普通 release，
冻结未筛选参考和候选二进制。参考绑定当前实现基线，不能直接沿用旧剖析二进制。
首轮限定十万道路机动车、16 workers、512 拍暖机加 1024 拍观察，
执行 ABBA 四次；不混用插桩计时估算产品收益。

完整保留状态、命令、事件、展开计划、拒绝与原始 diagnostics；逐拍核对 step 前
Active 为十万、step 后及补充结果、命令身份/游标、末端 pending 与资源守恒。
报告公共准入和完整命令阶段墙钟、完整重建次数、扫描/筛除/完整预览数、
端到端墙钟及 step p50/p95/p99/max。筛除与分配计数从单独诊断或测试得到，
若需要真实负载诊断，最多另加一次相同窗口，并与四次正常延迟测量分列。

资源验收覆盖新增字段、外层表与 owner 的保留容量、分配次数/字节和高水位、
失败后的存量及重试。首版不应新增常驻容量；进程工作集不替代所有权账本。
同时记录后台竞争，ABBA 只降低顺序偏差，不构成长期置信度或完全隔离证明。

遇到候选/错误/状态差异、资源丢失或半提交立即停止性能宣称并修复。
若两组相邻 A/B 比较的准入收益方向不一致、完整墙钟无可重复改善、
step 退化或资源成本上升，保留结果并停止本候选，不自动追加长测或扩到增量维护。
需要第二组 BAAB 或更长观察时，先说明未解噪声/风险、所需覆盖和结束条件。
本短窗不替代 #707 的四基线、三轮完整观察、交通质量及资源认证，
也不把准入省时当作 Core 整步 16 ms 预算已经达标。

## 7. 后续实施边界

设计接受后，独立实现任务再记录 G2，范围只含重建筛选原语、必要的共享校验、
定向测试与上述有界证据。若成功性证明要求改动公开错误、运动规则、增量 owner
语义、资源生命周期或持久化格式，应先返回设计评审，不能把这些变更夹带为优化。
实现验收完成与父级性能认证分别收口；本设计 PR 不执行优化或长测。
