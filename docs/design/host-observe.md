# 测量环境与进程观测

> **状态**：Proposed（[#1392][issue-1392] G1）<br>
> **日期**：2026-11-16<br>
> **决策依据**：[#1392][issue-1392]；[`core-runtime-performance-baseline.md`][performance-baseline]
> §5、§8.4；[`lf-synth-measurement.md`][lf-synth-measurement] §7.5；
> [`development-gates.md`][development-gates] §5.1<br>

## 1. 目标与非目标

本设计定义 `laneflow-host-observe`：测量与浸泡工具在计时区间外记录本机环境、
采集进程快照与观测子进程的统一入口。

需求来源：

- 性能基线 §5、§8.4 要求每份结果保存 OS build、CPU、内存配置、交流电或电池、
  厂商性能模式、Windows 电源计划、BIOS/固件、工具链与后台进程，P100 正式测量
  还须匹配机器指纹。synth-harness 的 `environment.json` 目前由执行者在外部采集后
  传入，工具只核对 6 个字段；urban-harness 自行读取工具链与源码状态，硬件与电源
  角色经环境变量声明。两者字段不一致，缺漏无法发现。
- `lf-synth-measurement.md` §7.5 要求受扰 round 结束后采集一次进程快照；
  `development-gates.md` §5.1 要求安静测量窗口记录后台进程。目前没有实现。
- synth 矩阵每轮启动新进程，父进程只记录退出状态，不独立记录子进程的内存与
  CPU 时间；urban-harness 浸泡看护用 `sysinfo` 自行实现了进程组追踪、驻留内存与
  僵尸判定。

本设计提供：

1. 环境记录：带版本号的结构化记录，取代人工 `environment.json`（§3）；
2. 进程快照：本机全部进程的身份、CPU 时间增量与内存（§4）；
3. 子进程观测：按身份追踪子进程及其后代的内存、CPU 时间与存活状态，给出退出
   状态，并按身份终止（§5）。

本设计不提供：

- 帧间高频计数器：由 [`os-probe.md`][os-probe] 的 `laneflow-os-probe` 负责。
- 分配计数与堆峰值。
- 已发布测量记录或历史 `environment.json` 的改写或转换。
- 计时区间内可调用的接口：本 crate 全部接口都可能分配、枚举进程或启动外部命令。
- ETW、WPR 或常驻采集服务。

## 2. 定位与依赖边界

- crate 位于 `tools/laneflow-host-observe`，`publish = false`，继承工作区
  `unsafe_code = "forbid"`。
- 只允许 `tools/` 下的 crate 依赖，或任意 workspace crate 作为 dev-dependency 引用；
  `crates/` 下的生产依赖不得引用。该约束由 xtask 检查，与 `laneflow-os-probe`
  的引用检查合并实施。
- 依赖 `laneflow-os-probe`（交流电与电池）、`sysinfo`（进程表、OS 与硬件信息，
  已在锁文件中）与 `sha2`（机器指纹，§3.4）。需要新依赖读取 WMI、注册表或 DMI 时，
  在实现 PR 中按依赖策略说明。
- 命名说明：Issue 暂名“诊断记录层”。[词汇表][glossary] §7.8 已将“诊断记录”登记为
  harness 的 `diagnostics.json`，为避免同名异义改用本名。

## 3. 环境记录

### 3.1 采集时机与组成

环境记录由 harness 在测量开始前与全部测量结束后各采集一次，写入运行目录，两份
文件均列入文件摘要清单。一份环境记录包含：

1. 自动采集字段（§3.2）；
2. 执行者填写的必填字段（§3.3）；
3. 机器指纹（§3.4）；
4. 一份进程快照（§4），作为后台进程记录。

### 3.2 自动采集字段

| 组     | 字段                                                       | Windows                                    | Linux                                                              |
| ------ | ---------------------------------------------------------- | ------------------------------------------ | ------------------------------------------------------------------ |
| 采集   | 采集时刻（UTC）、采集阶段（测量前或测量后）、本 crate 版本 | 同左                                       | 同左                                                               |
| OS     | 名称、版本与 build、内核版本、架构                         | OS 接口                                    | `/etc/os-release`、内核版本                                        |
| CPU    | 型号、物理核数、逻辑处理器数                               | OS 接口                                    | `/proc/cpuinfo`、在线 CPU 列表                                     |
| 内存   | OS 可见物理内存字节数                                      | OS 接口                                    | `/proc/meminfo`                                                    |
| 电源   | 交流电、电池存在、电量（`os-probe.md` §3.5）               | 同左                                       | 同左                                                               |
| 电源   | 电源计划（GUID 与名称）                                    | `powercfg /getactivescheme`                | 不可用                                                             |
| 电源   | CPU 调频策略、平台性能配置                                 | 不可用                                     | `scaling_governor` 取值集合、`/sys/firmware/acpi/platform_profile` |
| 固件   | BIOS 厂商、版本与日期                                      | 固件信息接口                               | `/sys/class/dmi/id` 的 `bios_*`                                    |
| 工具链 | `rustc -Vv` 全文、`cargo -V`、主机 target                  | 调用方指定工具链选择（如 `+1.99.1`）后执行 | 同左                                                               |
| 源码   | 提交（40 位十六进制）、树对象、工作树是否干净              | git                                        | git                                                                |

- 字段取不到时记为不可用并附原因，不得填空串、零或省略。
- “工作树干净”沿用 urban-harness 现行判定：`git status --porcelain
  --untracked-files=all` 为空，且索引中没有 skip-worktree 或 assume-unchanged 条目；
  git 命令锚定到 checkout 目录执行。
- 构建命令、构建参数、rustflags 与 profile 属于各 harness 的构建协议，不进入
  环境记录，仍由 harness 自己的测量记录保存与核对。

### 3.3 执行者填写的必填字段

| 字段         | 含义                                                           |
| ------------ | -------------------------------------------------------------- |
| 厂商性能模式 | 厂商控制软件中的性能模式；机器没有该功能时写明“无厂商性能模式” |
| 硬件角色     | 性能基线 §5 的 R0、P10、P100、O1，或“未认证”                   |

- 执行者在单独的输入文件中提供这些字段；输入文件不得包含自动采集字段。
- 每个字段必填，不得为空、只含空白，或写成 `unknown`、`unavailable`、`n/a` 等
  占位值（不区分大小写）。缺失时 harness 拒绝开始测量。
- 硬件角色为 P100 时，机器指纹须与
  [`road-editing-source-reference-machine-v1.json`][reference-machine-json] 的
  `hardwareIdentityScheme` 与 `hardwareIdentitySha256` 完全一致，否则拒绝开始；
  其他角色只记录指纹，不做匹配。

### 3.4 机器指纹

- 纳入环境记录。方案固定为性能基线 §5 的 `laneflow-p100-hardware-identity-v2`，
  不另立方案；摘要角色为跨记录核对的互操作摘要，算法随该方案为 SHA-256
  （[ADR 0033][adr-0033]）。
- 只记录方案名与 64 位小写十六进制摘要。三个原始 SMBIOS 值不得出现在记录、日志
  或错误消息中。
- 仅 Windows 采集。该方案按 Windows WMI 类定义，Linux 上记为不可用；为 Linux
  定义指纹方案不在本设计范围内。
- 环境记录在计时区间外采集，允许使用 WMI。采集接口在实现 PR 中选定，验收条件是在
  P100 参考机上得到已发布的摘要。

### 3.5 前后一致性

测量前与测量后两份记录中，以下字段须一致：OS 版本与 build、BIOS、电源计划、
CPU 调频策略、平台性能配置、交流电状态、工具链、源码提交与干净状态、机器指纹、
执行者填写字段。任一不一致时，harness 在汇总中写明差异字段，该次测量不得标记为
完整。电量、采集时刻与进程快照不参与比较。

### 3.6 格式与版本

- 编码为 JSON，顶层带格式名 `laneflow-environment-record` 与整数版本号，首版为 1。
- 读取端只接受已知版本，拒绝未知字段，不转换旧版本。
- 增删字段、改变字段语义或必填字段集合时，版本号加一。
- 测量记录经文件摘要清单引用环境记录，不复制其内容。

### 3.7 与现有记录的对应关系

| 现有字段                                                          | 新环境记录                                 |
| ----------------------------------------------------------------- | ------------------------------------------ |
| synth `implementation_commit`                                     | 源码提交；harness 继续核对与命令行参数一致 |
| synth `source_clean`                                              | 工作树是否干净（由工具判定，不再由人声明） |
| synth `rustc_vv`、`cargo_version`、`target`                       | 工具链组                                   |
| synth `build_command`、`test_build_command`                       | 不进入环境记录，改为 harness 构建声明参数  |
| synth 声明中的 OS、CPU、内存、AC、电源计划、厂商模式、后台进程    | 对应自动字段、必填字段与进程快照           |
| urban `git_commit`、`git_status`、`rustc`、`cargo`、`target`      | 源码与工具链组                             |
| urban `os`、`architecture`                                        | OS 组                                      |
| urban `hardware_role`（环境变量）                                 | 必填字段“硬件角色”                         |
| urban `power_role`（环境变量）                                    | 改由电源组自动采集，环境变量退役           |
| urban 构建参数、rustflags、profile、构建提交、worker 数、计时范围 | 不变，留在测量记录                         |

## 4. 进程快照

- 一次快照内部读取进程表两次，间隔由调用方给定（默认 1 s）并记录。
- 每个进程记录：PID、启动时刻、父 PID、可执行文件名、两次读数的累计 CPU 时间、
  区间 CPU 时间增量、第二次读数的驻留字节、状态（运行、已退出未回收、其他）。
- 进程以 PID 加启动时刻识别。只出现在一次读数中，或两次启动时刻不同的进程，
  区间增量记为不可用。
- 权限不足读不到的字段记为不可用，进程仍列出，不过滤任何进程。
- 不记录命令行、完整路径、环境变量与用户名：这些内容可能含本机路径或敏感信息，
  而进程快照会写入运行目录并可能随证据发布。
- 累计 CPU 时间按 `sysinfo` 提供的毫秒粒度记录，不换算为更细单位。
- 调用方：受扰 round 结束后、下一个 round 开始前（`lf-synth-measurement.md` §7.5）；
  环境记录（§3.1）。round 运行中不采集。

## 5. 子进程观测

### 5.1 观测范围

调用方用标准库启动子进程后，把子进程交给观测器。观测范围由调用方选择并记录：

- **仅直接子进程**：每次采样只刷新该 PID，开销与本机进程数无关；
- **进程组**：直接子进程及其全部后代，每次采样扫描整个进程表。

进程组成员判定沿用浸泡看护现行规则：

- 成员以 PID 加启动时刻识别；某 PID 的启动时刻变化时，旧成员移出；
- 父进程是已知成员、且启动时刻不早于父进程的进程，加入成员；
- 成员重新挂靠到其他父进程后，仍按原身份追踪。

### 5.2 采样

每次采样对每个成员记录：PID、启动时刻、父 PID、驻留字节、累计 CPU 时间、是否
已退出未回收。

- 驻留字节读到 0 时记为不可用，不记为 0。
- Linux 已退出未回收的进程驻留为 0，记为“已退出”，不当作“未测得”（浸泡看护 #1097
  的判定）。Windows 没有对应状态，该标记恒为否。
- 采样间隔由调用方给定并写入记录。

### 5.3 退出与汇总

子进程退出后，观测器给出：

- 退出状态：退出码；Unix 上被信号终止时记录信号编号；
- 采样峰值：采样期间直接子进程驻留字节的最大值；
- 采样 CPU 时间：最后一次采样的累计 CPU 时间；
- 采样次数与采样间隔。

采样峰值与采样 CPU 时间都是**下界**：两次采样之间的峰值和最后一次采样后的 CPU
消耗无法观测，记录中按此标注。进程退出并被回收后，`sysinfo` 与 `/proc` 都不再
提供其计数。

精确的生命周期峰值与 CPU 时间由子进程退出前经 `laneflow-os-probe` 自报
（`os-probe.md` §3.2、§3.3）。父进程同时持有两组数据时，核对自报驻留峰值不小于
父进程采样峰值；不满足时该次运行记为不一致。CPU 时间两侧读取时刻不同，不做核对。

未采用的方案：在子进程回收前经进程句柄读取精确值（Windows 进程句柄上的 CPU 时间与
内存计数，Linux `wait4` 的资源统计）。这需要新的手写 `unsafe` 或扩大
`laneflow-os-probe` 的受审计边界。若下界与自报不能满足后续需求，另立任务修改
`os-probe.md`。

### 5.4 按身份终止

观测器可终止进程组：先终止直接子进程以阻止继续派生，再逐个终止 PID 与启动时刻
仍匹配的已知成员，直到直接子进程被回收、其余成员都已退出，或超过调用方给定的期限。
超过期限时返回错误，不报告成功。观测器被丢弃时执行同一终止流程。

### 5.5 开销

观测在父进程中运行，与被测子进程共用本机。正式测量中，父进程采样属于测量环境的
一部分：使用仅直接子进程范围，采样间隔不短于 1 s，范围与间隔写入矩阵汇总。

## 6. 迁移

- **synth-harness**：接收 `<environment.json>` 的入口改为接收执行者输入文件与构建
  声明参数，由工具生成测量前后两份环境记录；必填字段缺失或 P100 指纹不符时，
  矩阵在启动任何子进程前停止。矩阵为每个子进程记录退出状态、采样峰值、采样 CPU
  时间与采样参数，并与子进程自报的资源字段核对（§5.3）。
- **urban-harness**：测量记录中的环境字段改由环境记录提供，`LANEFLOW_HARDWARE_ROLE`
  与 `LANEFLOW_POWER_ROLE` 退役；构建协议字段与核对规则不变。测量记录与诊断记录
  格式随之升版，不转换旧记录。
- **浸泡看护**：进程组追踪、驻留内存、僵尸判定与终止改用 §5，判定语义不变，
  现有确定性回归测试全部保留。
- **#1388**：受扰 round 的进程快照调用 §4。
- 两个 harness 的 README 写明旧字段与新记录的对应关系（§3.7）。已发布测量记录
  与历史 `environment.json` 不改写。

## 7. 平台

Windows 与 Linux 均实现并测试。其他平台编译通过，平台相关字段记为不可用，进程
观测按 `sysinfo` 的支持情况如实标注。

## 8. 实现验证

实现至少验证：

- 必填字段缺失、为空、只含空白或为占位值时拒绝；输入文件含自动字段时拒绝；
- 记录含未知字段或未知版本时读取失败；
- 机器指纹按 v2 方案的固定输入有测试向量；注入的原始 SMBIOS 值不出现在记录、
  日志与错误消息中；P100 角色指纹不符时拒绝；
- 前后两份记录的一致性比较能识别 §3.5 的每类字段差异；
- 进程快照列出本进程与测试启动的子进程；只出现在一次读数中的进程增量为不可用；
- 子进程观测：退出码、Unix 信号、后代追踪、PID 复用后的成员移出、Linux 已退出
  未回收状态、按身份终止与超时错误；
- 自报峰值与采样峰值的核对规则有单元测试；
- 浸泡看护迁移后现有确定性回归测试全部通过；
- xtask 对 `crates/` 生产依赖引用本 crate 的检查与拒绝测试。

P100 参考机上复现已发布指纹属于人工验证，在实现 PR 中记录结果，不进入 CI。

计量类别：不敏感。本 crate 不产生计时结论；§5.5 的采样开销在正式测量中按所属
测量协议的安静测量窗口要求运行。
