## 1. 结论

`spawn_vehicle` 构造的是当前提交时点的车辆状态。它不表示这辆车从当前路线起点、以零速出发。

路线从哪条边开始记录，不等于车从那里开始运动。范围外进来的车，和仿真开始时已经在路上的车，都不因为域内加速距离不够而被拒绝。来源没有声明，不是输入错误，也不能因此跳过当前的安全检查。

普通新鲜摆放在既有的引用、进度、限速、路线准入、车身重叠和通行权威检查之后，还要同时满足：

1. 当前已经要求停车的门，按该车紧急减速度停得住。
2. 前方更低的限速，按该车紧急减速度降得到。
3. 新车相对最近前车，按新车自己的紧急制动，下一拍不必靠超出制动能力的硬投影才避免重叠。
4. 新车成为已有移动后车的前车时，后车用后车自己的参数和已选路线，也能同样安全。

舒适制动不够、但紧急制动仍满足时，命令成功，不另附诊断对象。硬失败用单独的错误变体说明原因。调用方提交的位置和速度原样采用，不悄悄改速、改位置或换路线。

这些检查只发生在命令路径，不加到每辆活动车的每个仿真拍上。

## 2. 谁走哪一层

| 入口 | 引用、重叠、权威 | 本节运动安全 | 出生历史 |
| --- | --- | --- | --- |
| `spawn_vehicle` | 走 | 走 | 不推断零速历史 |
| `replace_completed_vehicle` | 走 | 走 | 不推断零速历史 |
| `leave_parking` | 走自己的资源转移 | 复用同一后车算式，候选速度仍为 0 | 不套用 |
| 快照恢复、修订切换 | 保持原有完整性 | 不走 | 不走 |

恢复和切换不把已经在世界里的状态重新当成新鲜出生。已经在路上、之后才来不及停的车，仍按 [#740](traffic-runtime-near-gate-frontier.md) 的运动到达下界处理。出生检查不改那条运行时规则。回归测试若要保留“已经停不住仍按运动到达”的场面，在测试特性 `placement-fixtures` 下用 `place_existing_active_vehicle` 走同一条提交，不把速度改温和。默认构建没有这个入口，它也不是宿主的新需求入口。信号走廊 catalog 的初始人口走 `spawn_vehicle`：计划位置不变，初速若过不了当前检查就按 1 m/s 降低到放得进为止。之后新进入走廊的车仍走 `spawn_vehicle`。

同一拍里连续调用时，先成功的车已经提交。后一次检查和下一拍都能看见它。失败不留下车辆、路线引用、停车资源、冲突状态或命令游标。占用索引若在失败前重建，只影响派生索引，不改变已提交车辆。

## 3. 运动安全

### 3.1 当前必须停车

沿候选路线找下一道当前策略为 `DenyAndStop` 的机动门，包含没有信号组、但策略仍然拒绝通过的门。距离算到该 hop 的终点。零进度、且不在路线第一条边上时，仍把车看作停在上一 hop 的门上。

距离是有限毫米、并且 `can_stop_before` 不成立时，拒绝 `StopConstraintUnsatisfiable`。速度为 0 视为已经停住。紧急减速度不是有限正数、且速度不为 0 时，无法证明停得住，也拒绝。距离溢出到有界毫米量程之外时，不把这道门当成当前约束。连续刹停距离通过之后，仍要做第 3.3 节的第一拍预览；求解器这一拍若把车截成超出紧急制动的急停，仍然拒绝。

`can_stop_before` 与红灯到达下界共用同一个函数：比较的是 `v² / (2a)` 与门距。新鲜摆放被拒绝的，就是运行时会当成“停不住、因而保持运动到达下界”的那一类。不停用未来会变绿或应该能申请到通行权来放行。已经越过门、落在冲突覆盖内且没有权威的位置，仍由原有的 `ConflictAuthorityRequired` 拒绝，不改写成停车约束。

只存在冲突资源、但当前信号并不要求停车时，不把前方路口本身当成必须停下的点。冲突区已经由其他车占用时，下一拍给不出通行权，第一拍预览把最近一个这样的准入点算进停车距离。空着、并且没有别的车这一拍也够得到的冲突区，仍可能获得通行权，不把它当成必须停下的点，也不为它预写通行权或排队。已经有别的车这一拍会申请同一块区域时，新车的通行权没有保证，第一拍要能在那里停下。新鲜车还没有等待计划，第一拍不预写等待停车。

当前这一边可以越过、但这一拍开得到后面某道拒绝通过的门时，硬房间算到那道门的边末，包括没有信号组、策略仍然拒绝的门。第一拍若顶到这道门并被打成急停，同样拒绝。这一拍够不着的更远的门不收紧这一拍的硬房间。

### 3.2 前方更低限速

前方每一次目标速度低于当前初速的限速下降都要检查。最近一次下降的目标如果仍不低于当前初速，不能因此跳过后面更低的限制。房间是从当前进度到该次下降所在边终点的距离。用同一紧急减速度检查 `(v² - v_target²) / (2a)` 是否不超过这段房间。任何一次不够都拒绝 `DownstreamSpeedUnsatisfiable`。

当前边基础限速的比较保持不变：初速可以等于当前边限速，也可以等于 `100_000` mm/s 的数值上限，但不得超过。`desiredSpeed` 不是物理最高速度。

### 3.3 前车与后车

新鲜摆放按当前步进求解器本拍真正承认的空间判断，不把前车下一拍会前进的距离加进后车空隙。求解器的 `hard_room_mm` 只用拍初占用快照：`max(0, gap - follower.min_gap)`，毫米整数，空隙不大于 0 时房间为 0。跟车设计里的前车位移传播仍然不是本拍求解器的行为。

后车用自己的 `min_gap`、紧急减速度、固定步长和已选路线。预测调用与正式步进相同的运动内核：

- 新车无论前面有没有车，都先用同一运动内核预览自己的第一拍。没有前车时前车空隙为空。红灯、未放行的边末、路的尽头、已经被其他车占用的冲突区，或空着但已有别的车这一拍够得到的冲突区，把行程截断，且截断结果超出紧急制动时，拒绝 `StopConstraintUnsatisfiable`。空着、且没有别的车这一拍够得到的冲突区，不在这次预览里变成停车点。
- 新车跟在已有前车后面时，硬房间还包含这名前车的快照空隙，以及这辆新车自己的信号、路终、边末许可和已占用冲突区。前车空隙造成的截断记为 `UnsafeLeader`。
- 新车成为已有移动后车的前车时，只把这名前车造成的快照空隙拿来判断，不把后车自己的信号或路终清零算成新车的责任。

本拍若被硬房间截断（房间为 0，或取整后的行程顶到房间），提交的行程必须不少于该车紧急制动在本拍的最小行程，并且截断后的速度不得低于 `max(0, v - b * dt)`。做不到就拒绝。没有硬截断时，速度沿求解器自己的舒适模型变化，不另加前车未来位移。双方速度为 0 时最小行程为 0，不重叠即可成功。舒适制动不够、但上述紧急包络仍满足时，命令成功，不另附诊断对象。

物理重叠仍先由原有重叠检查拒绝。

前车查询走路线上的占用索引，取求解器同一前视窗内最近、且后杠间隙非负的已提交活动车，并带回这辆车的身份。后车先在制动窗内的车身边和上游边收集局部候选，再按每辆后车自己的路线做精确间隙过滤；跨边、分支、机动 transition 和重复出现都留在这步过滤里，不改成“只看同一条边”。环线上同一条物理边被车身盖住两次时，两段后杠窗口都保留，收集完再按车辆去重。已有更近前车的跳过。判断更近前车时排除的是后车自己。候选自己还不在索引里。多个后车按占用记录上的活动顺序取第一个失败的。后车名单最后收成结果时也先做可失败预留。

驶离停车仍使用原来的静止前车算式：离开的车速度为 0，不套用上面这套“前车还会往前开”的加项。

命令前若派生占用索引与当前提交序号不一致，按驶离停车的同一规则重建。每条边单独存放自己的占用记录和桶内后缀下标。同一次成功生成只把新车的记录插进它所在的边，提交前只为这些边预留新增条数；插入一条边不会挪动其他边的记录。全部记录条数单独记着，生成时加上新条数，不把每条车道再加一遍。新车自己的记录名单也先数清条数，再做可失败的预留。机动反向表的写入游标同样按可失败分配复制。分配失败返回 `OccupancyAllocFailed`，不提交车辆。替换和步进会改变已有车辆的位置或顺序，下一次命令再重建。

后车候选不超过本网络最高限速下、任一车型本拍跟车窗能到达的距离。这个距离按当前路网和步长记一次，不在每辆新车上重扫限速。车身所在边按该边上的后杠开窗。上游既包含车道前驱，也包含只在机动 transition 里出现的入口；上游边按已经走过的距离，从边的终点往回开窗。同一条边能从多条路到达时，保留更短的那次距离，并按这次距离重新开窗。同一条边先被当成车身时，保留后杠窗口。超出这个距离就不再往上游走。

## 4. 错误

`SpawnError` 与 `ReplaceError` 各增加：

| 变体 | 含义 | 调用方 |
| --- | --- | --- |
| `StopConstraintUnsatisfiable` | 当前必须停车的约束停不住 | 可稍后重试 |
| `DownstreamSpeedUnsatisfiable` | 降不到前方更低限速 | 可稍后重试 |
| `UnsafeLeader` | 相对最近前车不安全 | 可稍后重试 |
| `UnsafeFollower` | 使已有移动后车不安全 | 可稍后重试 |
| `OccupancyAllocFailed` | 占用索引分配失败 | 世界状态未改变 |

未知 profile、非法进度、超限速、来源条件不可达（一旦有声明）仍是输入错误。重叠在 `spawn_vehicle` 上仍是 `Overlap`，在替换上仍是可重试的 `Blocked`。

宿主决定是否重试、取消需求或另找一个状态。运行时不维护隐藏的需求队列，也不把暂时插不进去写成这辆车已经消失。

## 5. 明确不做

- 不把“从当前路线起点、零速、按最大加速度开得到”写成所有摆放的条件。
- 不根据路线首边、图上没有前驱的边或画面边缘猜测开放边界。车尾在路线起点截断的现行合同保持不变，直到调用方能明确绑定真实入口。
- 不在本次给 `VehicleSpawnInput` 增加历史起点字段。没有声明就不做可达性检查。通过速度上界也不等于证明存在完整合法轨迹；将来增加声明时，只拒绝“即使沿路线以最大加速度前进，离散步进仍到不了该速度”的上界。
- 不把小于期望间距单独当成非法，也不把高于 `desiredSpeed` 当成物理不可能。
- 不修改 1 万辆 / 2 ms 与 10 万辆 / 16 ms 的预算，也不关闭 #707。
