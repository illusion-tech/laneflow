## 1. 结论

`spawn_vehicle` 构造的是当前提交时点的车辆状态。它不表示这辆车从当前路线起点、以零速出发。

路线从哪条边开始记录，不等于车从那里开始运动。范围外进来的车，和仿真开始时已经在路上的车，都不因为域内加速距离不够而被拒绝。来源没有声明，不是输入错误，也不能因此跳过当前的安全检查。

普通新鲜摆放在既有的引用、进度、限速、路线准入、车身重叠和通行权威检查之后，还要同时满足：

1. 当前已经要求停车的门，按该车紧急减速度停得住。
2. 前方更低的限速，按该车紧急减速度降得到。
3. 新车相对最近前车，按新车自己的紧急制动，下一拍不必靠超出制动能力的硬投影才避免重叠。
4. 新车成为已有移动后车的前车时，后车用后车自己的参数和已选路线，也能同样安全。

舒适制动不够、但紧急制动仍满足时，命令成功，不另附诊断对象。硬失败用单独的错误变体说明原因。调用方提交的位置和速度原样采用，不悄悄改速、改位置或换路线。

这些检查只发生在命令路径，不加到每辆活动车的每个仿真拍上。

## 2. 谁走哪一层

| 入口                        | 引用、重叠、权威 | 第 3 节运动安全                  | 出发状态                           |
| --------------------------- | ---------------- | -------------------------------- | ---------------------------------- |
| `spawn_vehicle`             | 走               | 走                               | 未声明不推断；声明了才检查速度上界 |
| `replace_completed_vehicle` | 走               | 走                               | 只用本次新输入的声明，不继承旧车   |
| `leave_parking`             | 走自己的资源转移 | 复用同一后车算式，候选速度仍为 0 | 不套用                             |
| 快照恢复、修订切换          | 保持原有完整性   | 不走                             | 不走                               |

恢复和切换不把已经在世界里的状态重新当成新鲜出生。已经在路上、之后才来不及停的车，仍按 [#740](traffic-runtime-near-gate-frontier.md) 的运动到达下界处理。出生检查不改那条运行时规则。回归测试若要保留“已经停不住仍按运动到达”的场面，在测试特性 `placement-fixtures` 下用 `place_existing_active_vehicle` 走同一条提交，不把速度改温和。已经完成的车要在同一场面换成下一代时，用 `replace_existing_completed_vehicle`。默认构建没有这两个入口，它们也不是宿主的新需求入口。信号走廊 catalog 的初始人口走 `spawn_vehicle`：计划位置不变，初速若过不了当前检查就按 1 m/s 降低到放得进为止。之后新进入走廊的车仍走 `spawn_vehicle`。

同一拍里连续调用时，先成功的车已经提交。后一次检查和下一拍都能看见它。失败不留下车辆、路线引用、停车资源、冲突状态或命令游标。占用索引若在失败前重建，只影响派生索引，不改变已提交车辆。

## 3. 运动安全

新鲜摆放只回答三件事。第一，按紧急制动算，这段距离是不是停得住，这是连续制动的必要条件。第二，用现在这个离散求解器看下一拍会不会被硬截断，截断之后还在不在紧急制动包络里。第三，这不是一条以后一直安全的完整轨迹；跟车模型这一次也不重写。

没有实测之前，不把某次改动写成城市规模的加速。

### 3.1 当前必须停车

沿候选路线找下一道当前策略为 `DenyAndStop` 的机动门，包含没有信号组、但策略仍然拒绝通过的门。距离算到该 hop 的终点。零进度、且不在路线第一条边上时，仍把车看作停在上一 hop 的门上。

距离是有限毫米、并且 `can_stop_before` 不成立时，拒绝 `StopConstraintUnsatisfiable`。速度为 0 视为已经停住。紧急减速度不是有限正数、且速度不为 0 时，无法证明停得住，也拒绝。距离溢出到有界毫米量程之外时，不把这道门当成当前约束。连续刹停距离通过之后，仍要做第 3.3 节的第一拍预览；求解器这一拍若把车截成超出紧急制动的急停，仍然拒绝。

`can_stop_before` 与红灯到达下界共用同一个函数：比较的是 `v² / (2a)` 与门距。新鲜摆放被拒绝的，就是运行时会当成“停不住、因而保持运动到达下界”的那一类。不停用未来会变绿或应该能申请到通行权来放行。已经越过门、落在冲突覆盖内且没有权威的位置，仍由原有的 `ConflictAuthorityRequired` 拒绝，不改写成停车约束。

只存在冲突资源、当前门也允许通过时，不把路口本身当成必须停下的点。新鲜摆放和下一拍用同一问法：这辆车若已经在路上，下一拍会不会在某个这一拍够得到的入口被硬截断。红灯、没有信号组的拒绝门和路的尽头仍由运动内核处理。这一拍行程上界够不着的更远入口不再查让行、下游或排队。

冲突区已经由其他车占用时，停车点在这道门。空着的区里，只有这一拍舒适预览真会申请、并且按正式顺序排在新车前面、而且这一拍真能占上的已有车，才要求新车在这里停下。占上要同时看路口和下游。更早的车已经占了这个路口时，后面的车就算下游不重叠也占不上，不能再挡更后面的人。下游声明是空的、因为路尾放不下而没申请到的，也不算占上。排队入口如果同时有冲突，同区检查照样做。正式下一拍一辆车只准备第一道资源门；这道门给过之后，这一拍还够得到的下一道资源门就是停车点。

普通生成的更新序号是放上道路之前的名单长度，替换沿用旧车原来的名次，包括这辆车在名单前部、中部或后部。比较还包括首次具备资格的时刻和已有的排队序号，和正式下一拍的候选顺序一致。平局时输给已经在路上的车。每个冲突区记下这一拍会申请的车，不只留最优先的一辆；没申请到的不算占用。新车自己会赢时不停，但如果因此让已经在路上的车超出紧急制动急停，这次生成拒绝。已经自己会急停、或者算不清的旧车，不算到这次生成头上。名单同时对上世界世代和观测序号。修订切换，以及已经提交的停车预留、取消预留或改绑路线，都会把名单作废。同一次绑定再预留、世界没有变化时，可以继续用这份名单。对不上，或这次没法把受影响的旧记录更新完整，整份作废，下次生成再重建。能对上时，只撤掉并重算受影响的旧车，不把半份更新标成当前。材料不齐就不放行。分配失败是 `OccupancyAllocFailed`，不当成停不住，走廊也不会因此把初速改低。

让行按每个让行目标格点判断，不到整个区。到达算到冲突入口，用加上步长和清空时间之后的前导，必须严格更晚才通过。对方停在拒绝门前并且紧急制动停得住时，到达推迟到放行，晚于证明时窗就不记；停不住的仍保留运动下界。受保护相位不做让行。后随只看这个格点自己的已提交清空时刻，没有清空历史就跳过。证明时窗是各条间隙派生前导的最大值再加 1 毫秒。

下游只查这一处够得到的入口。车身放不下、会越过下一道门，或已提交声明的区间和间距叠在一起，都要能在入口停下。这一拍里名次更靠前、并且真能占上声明的车，也算进这次检查；判断时要把更前面的车这一拍已经占上的路口和下游声明都算进去，不能只看账上原有的声明。没申请到的不算，空的没申请到也不挡。声明列表是空的就不挡；索引还没建好时按已提交声明逐条看是否相交，不因为索引脏就挡住另一条路上的车。检查完不留下通行权、排队名额或命令记录。

排队只看这一拍够得到的最近入口。已在区里的车，加上这一拍会更早进去的车之后，名额或长度不够，就停在这个入口。这个入口给得进、但同一拍预览还会越过下一处入口时，停车点在下一处。够不着的满区不在生成时加严。新车抢走已有车的名额时，即使这个入口上没有冲突，也要复核那辆已有车能不能急停。新鲜车不预写通行权，也不预写排队名额。

当前这一边可以越过、但这一拍开得到后面某道拒绝通过的门时，硬房间算到那道门的边末，包括没有信号组、策略仍然拒绝的门。第一拍若顶到这道门并被打成急停，同样拒绝。这一拍够不着的更远的门不收紧这一拍的硬房间。

### 3.2 前方更低限速

前方每一次目标速度低于当前初速的限速下降都要检查。最近一次下降的目标如果仍不低于当前初速，不能因此跳过后面更低的限制。房间是从当前进度到该次下降所在边终点的距离。用同一紧急减速度检查 `(v² - v_target²) / (2a)` 是否不超过这段房间。任何一次不够都拒绝 `DownstreamSpeedUnsatisfiable`。

当前边基础限速的比较保持不变：初速可以等于当前边限速，也可以等于 `100_000` mm/s 的数值上限，但不得超过。`desiredSpeed` 不是物理最高速度。

### 3.3 前车与后车

新鲜摆放按当前步进求解器本拍真正承认的空间判断，不把前车下一拍会前进的距离加进后车空隙。求解器的 `hard_room_mm` 只用拍初占用快照：`max(0, gap - follower.min_gap)`，毫米整数，空隙不大于 0 时房间为 0。跟车设计里的前车位移传播仍然不是本拍求解器的行为。

后车用自己的 `min_gap`、紧急减速度、固定步长和已选路线。预测调用与正式步进相同的运动内核：

- 新车无论前面有没有车，都先用同一运动内核预览自己的第一拍。没有前车时前车空隙为空。红灯、未放行的边末、路的尽头，以及上一节里下一拍会硬截断的入口，把行程截断；截断超出紧急制动时拒绝 `StopConstraintUnsatisfiable`。下一拍给得进的入口不在这次预览里变成停车点。
- 新车跟在已有前车后面时，硬房间还包含这名前车的快照空隙，以及这辆新车自己的信号、路终、边末许可和已占用冲突区。前车空隙造成的截断记为 `UnsafeLeader`。
- 新车成为已有移动后车的前车时，用这辆后车在同一批已有约束下的完整运动做前后比较。硬房间沿用求解器的 `max(0, gap - min_gap)`。已有的红灯、排队、冲突或下游停车如果不比这个跟车房间更松，这次生成不记成 `UnsafeFollower`。只有新的跟车房间把后车打出紧急包络、而原来不会时才拒绝。

本拍若被硬房间截断（房间为 0，或取整后的行程顶到房间），提交的行程必须不少于该车紧急制动在本拍的最小行程，并且截断后的速度不得低于 `max(0, v - b * dt)`。做不到就拒绝。没有硬截断时，速度沿求解器自己的舒适模型变化，不另加前车未来位移。双方速度为 0 时最小行程为 0，不重叠即可成功。舒适制动不够、但上述紧急包络仍满足时，命令成功，不另附诊断对象。

物理重叠仍先由原有重叠检查拒绝。

前车查询走路线上的占用索引，取求解器同一前视窗内最近、且后杠间隙非负的已提交活动车，并带回这辆车的身份。后车先在制动窗内的车身边和上游边收集局部候选，再按每辆后车自己的路线做精确间隙过滤；跨边、分支、机动 transition 和重复出现都留在这步过滤里，不改成“只看同一条边”。环线上同一条物理边被车身盖住两次时，两段后杠窗口都保留，收集完再按车辆去重。已有更近前车的跳过。判断更近前车时排除的是后车自己。候选自己还不在索引里。多个后车按占用记录上的活动顺序取第一个失败的。后车名单最后收成结果时也先做可失败预留。

驶离停车仍使用原来的静止前车算式：离开的车速度为 0，不套用上面这套“前车还会往前开”的加项。

命令前若派生占用索引与当前提交序号不一致，按驶离停车的同一规则重建。每条边单独存放自己的占用记录和桶内后缀下标。同一次成功生成只把新车的记录插进它所在的边，提交前只为这些边预留新增条数；插入一条边不会挪动其他边的记录。全部记录条数单独记着，生成时加上新条数，不把每条车道再加一遍。新车自己的记录名单也先数清条数，再做可失败的预留。机动反向表的写入游标同样按可失败分配复制。分配失败返回 `OccupancyAllocFailed`，不提交车辆。替换和步进会改变已有车辆的位置或顺序，下一次命令再重建。

后车候选不超过本网络最高限速下、任一车型本拍跟车窗能到达的距离。这个距离按当前路网和步长记一次，不在每辆新车上重扫限速。车身所在边按该边上的后杠开窗。上游既包含车道前驱，也包含只在机动 transition 里出现的入口；上游边按已经走过的距离，从边的终点往回开窗。同一条边能从多条路到达时，保留更短的那次距离，并按这次距离重新开窗。同一条边先被当成车身时，保留后杠窗口。绕环走过一段正距离后再回到这条物理边，按这次距离从边的终点重新开窗。超出这个距离就不再往上游走。

## 4. 显式出发状态

出发状态是这次生成或替换命令上的可选声明。它只回答一个必要条件：沿候选路线，从声明的前保险杠位置和出发速度，用当前候选车型的最大加速度、世界固定步长和既有速度量化，要达到待验初速至少需要的路线距离，是不是已经长于声明位置到当前车头的路线距离。更长就拒绝。不超过就只说明这一项没有排除该初速。当前摆放检查照旧做。

来源检查只能额外拒绝，不能额外授权。它不证明车尾在仿真范围外，不建立入口方向，不补上游路径，也不授予停车、等待区或冲突区的权威。真实入口和网内完整车身仍是另一块，不在本节。

### 4.1 命令

`VehicleSpawnInput::new` 的参数不变，出发状态默认为没有。调用方用 `with_departure` 附上一个 `VehicleDepartureState`，也可以再读回来。声明和当前摆放共用这次输入的同一条路线，不再另给路线句柄。两条路线在哪里接上、重复边如何对齐，不在本节解决。

`VehicleDepartureState::new` 记下路线出现项下标、该出现项上的前保险杠进度，以及出发速度。位置和速度一起出现，不能只填一半。进度与当前车辆进度一样，指前保险杠，不改成车身中心，也不把车长算进加速距离。

| 检查   | 规则                                             |
| ------ | ------------------------------------------------ |
| 出现项 | 下标必须落在候选路线里                           |
| 进度   | 不超过该出现项对应边的长度                       |
| 顺序   | 出发位置不得位于当前摆放位置之后                 |
| 速度   | `0..=100_000` mm/s                               |
| 重复边 | 同一条物理边出现多次时按出现项算，不按第一次匹配 |

相邻出现项的边末和下一边零进度，几何距离可以为零，仍按路线顺序区分。不把两侧的门和权威并成同一处。

真实起点在未建模范围外、又没有可检查的路径时，保持未声明。未声明不表示那个起点不合法。不为了填上这个字段编造域外路线，或随手提交一段历史行驶距离。

本节不加出发时刻。没有历史时间，就不能问能否恰好在当前时刻到达。声明用的是当前候选车型和固定步长，不是运行时对真实世界历史的认证。

声明只属于这次命令。接纳之后不写入 `VehicleState`、快照车辆记录或逐拍状态。替换不继承被替换旧车的历史。宿主若重放原命令，应保存原始输入，包括可选声明。显式降低初速或重建输入时必须保留这份声明，不能因为重新调用不带声明的构造而把它丢掉。运行时不自动降速。

### 4.2 判据

不读取当前灯色、占用、排队或通行权威来推断过去。不用 `desiredSpeed` 限制历史速度。本节也不追溯历史沿途限速。这是有意放宽的必要条件。当前位置和前方降速仍按第 3 节检查，不因此放宽。将来若要收紧成遵守静态限速的历史速度包络，须单独写明修订和历史假设，不能混进这个检查。

不复用完整舒适驾驶求解器。那个求解器会把期望速度和当前世界状态带进来。速度上界只复用既有的一步积分、速度量化和微米余数舍入。舍入仍是 ties-to-even。路线距离仍用有界距离和分段坐标，不为这项检查改宽全局路线坐标。

待验初速不高于声明出发速度时，这一项直接通过。这不证明减速历史可行，当前安全仍然完整检查。

否则从待验初速往回求每一拍的速度下界，直到不高于声明出发速度。一拍速度上界是：从已量化速度出发，以最大加速度走这一拍，量化之后的速度。要在一拍之后至少达到某个速度，拍初速度至少要多大，由这个上界反过来给出。每一拍再按拍初速度下界、能够量化到目标速度的未舍入终速下界，以及既有积分和微米舍入，取该拍位移的保守下界。各拍下界相加，得到达到待验初速至少需要的距离。

下界大于现有路线距离时拒绝：初速超过了这份声明允许的上界。下界不超过现有距离时，来源上界没有排除该初速。相加后的下界不必对应一条真实可执行轨迹。每一步都向更容易达到的方向取界，避免把上界算低，从而误拒绝本来可能的状态。

`BeyondFinite` 不是声明错误，也不是零距离。比较用已有有界距离合同。已经能证明现有距离不小于这个下界时，上界检查结束。不设“模拟超过若干拍就当成不可达”的上限。算法不收敛、数值不受支持和已经证明不可达，分开处理。

未声明时直接返回，不扫描路线前缀，也不增加每辆活动车每一拍的工作。

实现集中在一个私有检查里，并证明三件事：一拍速度上界对输入速度单调，并且没有低估最大加速度下的一拍速度；每拍位移下界没有因舍入而算高；总距离比较正确处理微米余数和候选的毫米位置。求能够量化到目标速度的未舍入速度下界时，不能忽略 ties-to-even 的临界点。数值上还要用少量步数、不同加速度选择和舍入边界做独立参照，不能只用这个检查对照自己。

### 4.3 接入和错误

生成和替换在基础输入有效之后、依赖当前交通状态的暂时接纳检查之前做这项检查。基础输入包含路线后缀准入和等待区起步校验；有声明时这两项先于出发检查。容量、车身重叠和当前冲突权威仍属于暂时接纳，留在出发检查之后。没有声明时，首错顺序和现有行为不变，容量仍先于其余输入错误。不放进恢复和切换共用的 `validate_unparked_vehicle`。

失败不提交车辆，不推进命令游标或观测序号，不留下路线引用、停车资源或冲突权威。派生占用索引仍允许在失败前重建，但不改变已提交交通事实。生成不得新增车辆或消费槽位。替换不得使旧句柄失效。

| 结果                                | 同一份输入再试                                                   |
| ----------------------------------- | ---------------------------------------------------------------- |
| `InvalidDepartureState`             | 须修正声明。路线、车型和步长不变时，等下一拍交通变化不能让它通过 |
| `InitialSpeedExceedsDepartureBound` | 须降低初速或更换输入。同上，等交通变化不能让它通过               |
| 当前停车约束、前车、后车            | 保持第 5 节的可重试处理                                          |
| `DownstreamSpeedUnsatisfiable`      | 保持须降低初速或更换输入                                         |

`InvalidDepartureState` 带声明自身的原因：出现项越界、进度非法、出发位置在当前摆放之后、速度越界。`InitialSpeedExceedsDepartureBound` 只表示初速超过这份声明下的速度上界，不表示已经做完完整轨迹分析。不必为了错误消息再求出最紧的最大速度。

Bevy 适配器只把当前停车约束、前车和后车映射成可重试。这两类来源错误进入 `VehicleReplace` 并记录错误，不扩大可重试分支。

验收要同时覆盖生成和替换。未声明时，短进口和网内已经在行驶的车与现在的接纳一致，不补零速历史。同一候选在未声明、零速声明和非零出发速度下，只有声明才增加对应上界。声明零速且初速超过上界时返回 `InitialSpeedExceedsDepartureBound`。初速不高于出发速度但当前停不住时，仍由当前安全拒绝。来源上界通过但前车或后车不安全时，仍由第 3 节拒绝。重复边按出现项。下标、进度和顺序错误彼此可区分。相邻边的边末和零进度、零距离和跨多边不漏算、不重复算。不同固定步长按各自离散合同校验。临界速度、ties-to-even、微米余数，以及最大加速度整拍落在目标前、恰好落点和跨过落点，都不能造成误拒绝。只改声明段之外的前缀并调整下标后，结果不变。有界距离超出有限范围时，不把声明当成非法。同一份超上界输入反复提交得到同一错误，世界不变。降低初速重建输入时声明仍在。快照恢复、修订切换和既有状态夹具不执行这项检查。同一个当前状态在未声明和有效声明下都被接纳时，提交后的交通状态一致。

## 5. 错误

`SpawnError` 与 `ReplaceError` 各增加：

| 变体                                | 含义                           | 调用方                                   |
| ----------------------------------- | ------------------------------ | ---------------------------------------- |
| `StopConstraintUnsatisfiable`       | 当前必须停车的约束停不住       | 可稍后重试                               |
| `DownstreamSpeedUnsatisfiable`      | 降不到前方更低限速             | 同一输入再试仍失败，须降低初速或更换输入 |
| `UnsafeLeader`                      | 相对最近前车不安全             | 可稍后重试                               |
| `UnsafeFollower`                    | 使已有移动后车不安全           | 可稍后重试                               |
| `OccupancyAllocFailed`              | 占用索引分配失败               | 世界状态未改变                           |
| `InvalidDepartureState`             | 出发声明自身不合法             | 须修正声明                               |
| `InitialSpeedExceedsDepartureBound` | 初速超过这份出发声明的速度上界 | 须降低初速或更换输入                     |

未知 profile、非法进度、超限速仍是输入错误。重叠在 `spawn_vehicle` 上仍是 `Overlap`，在替换上仍是可重试的 `Blocked`。没有出发声明时不做第 4 节的检查。

宿主决定是否重试、取消需求或另找一个状态。运行时不维护隐藏的需求队列，也不把暂时插不进去写成这辆车已经消失。

## 6. 明确不做

- 不把“从当前路线起点、零速、按最大加速度开得到”写成所有摆放的条件。没有出发声明时，不补一段零速历史。
- 不根据路线首边、图上没有前驱的边或画面边缘猜测开放边界。车尾在路线起点截断的现行合同保持不变，直到调用方能明确绑定真实入口。第 4 节的出发声明不完成这件事。
- #747 没有给生成输入增加出发状态。第 4 节增加的是可选声明，并且只拒绝速度上界已经不可能的初速。通过这个上界不等于证明存在完整合法轨迹，也不追溯历史沿途限速。
- 不把小于期望间距单独当成非法，也不把高于 `desiredSpeed` 当成物理不可能。
- 不修改 1 万辆 / 2 ms 与 10 万辆 / 16 ms 的预算，也不关闭 #707。
