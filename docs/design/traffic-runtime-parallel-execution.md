# TrafficWorld 单世界精确并行执行

**文档状态**: Accepted<br>
**最后更新**: 2026-09-17<br>
**适用范围**: 道路机动车首版独立计算并行、规范串行联合裁决与整拍提交<br>
**设计入口**: [#220](https://github.com/illusion-tech/laneflow/issues/220)<br>
**关联决策**: [ADR 0030（Accepted）](../adr/0030-single-world-parallel-execution.md)<br>
**配套设计**: [执行配置与资源](traffic-runtime-execution-config.md)、
[串行阶段协议](traffic-runtime-phase-protocol.md)

本文定义首版并行范围：分发只读输入上的独立计算，P4 联合资源裁决由协调器按现行
规范顺序串行执行。P1 索引发布、共享前沿归约、P5 资源转移、P6 准备与 P7 发布
也保留单一写入者。一个阶段可包含并行计算与串行消费，不因阶段编号相同就允许
任意函数并发。P4 组件并行属于后续独立设计，见 §10。

本文为已接受的执行合同；生产当前仍只支持 worker 1，多 worker 能力须经真实调度与等价验收。领域算法唯一由
[Waiting/Conflict 联合合同](waiting-zone-conflict-right-of-way.md)、
[Waiting 本地合同](traffic-runtime-waiting-zone.md)、
[路权策略](traffic-runtime-right-of-way-policy.md)、[跟车](vehicle-following.md)及
[停车](parking-system.md)定义；本文只细化等价执行方式。

## 1. 等价范围

串行参考是同一领域算法下、包含完整 Conflict/Policy 的单 worker `TrafficWorld`。
实施及实验在 GitHub 固定完整参考提交、工具链、feature、输入与运行环境，不能使用
已退役运行时或简化交通模型作为 oracle。

比较已提交车辆/路线/资源、tick/time、命令/事件游标、迁移日志效果、最新决策/事件、
停车到达结果、公开逻辑错误，以及失败重试和 fresh replay。私有存储地址、容器容量、
重建索引字节和授权序号数值不必相同，但有效性、配对及耗尽条件必须相同。首版 P4
沿用现行序号生成，无需因任务划分重编号。

所有交通求值读取 C(T)，可再读取已冻结的派生输入和本拍裁决，不能读取其他车辆
未提交的位移。运行任务不暴露公共查询或宿主回调；同步 `step` 成功或错误返回前
任务全部结束。跨块不额外延迟一拍，不修改数值精度、浮点表达式顺序或逐拍安全约束。
同环境确定性不扩展为跨 CPU、跨浮点实现的位级承诺。

## 2. 工作集、身份与失效

| 对象                                    | 用途                            | 失效及约束                                           |
| --------------------------------------- | ------------------------------- | ---------------------------------------------------- |
| `VehicleHandle(slot, generation)`       | 车辆身份与槽位访问              | 核验完整句柄；槽位复用不能命中旧记录                 |
| 逻辑更新位置（Logical Update Position） | 本拍 live 序列中的规范位置      | 生命周期命令后重建或可靠维护，不能用 worker 编号替代 |
| 活动紧凑位置（Active Compact Position） | live 的 Active 投影中的连续位置 | 仅定位，保留完整句柄与逻辑更新位置                   |
| 执行块（Execution Block）               | 独占连续输出范围的物理任务      | 可重分块，不改变交通身份、领域次序或资源归属         |

Active 投影保序分块，块数可大于线程数。非 Active 的异常 membership、reservation
或资格检查仍在原义务位置执行。共享输入不是某个地理块的局部世界：路线/前视窗
驱动的只读邻域覆盖完整前车链、环、车身区间和资源查询，可用全世界的窄只读视图
表达，不要求复制 halo，也不能使用固定距离或各块独立 projection 截断依赖。

任务只持有当前操作的借用。换根、spawn/despawn、路线变更、提交后 Active 投影变化
及同 tick 失败重试均须维护计划/工作集有效性；相同槽位数、容量或 NetworkRevisionId
不能证明旧绑定可复用。无活动任务时才替换分块，恢复及切换按配套设计准备目标计划。
首版不维护资源组件目录，不引入地理边界迁移或新的 Handle provenance。

## 3. 首版阶段图与写入者

箭头表示消费者所需输入，不要求九次遍历；图中的并行仅限下表明确列出的纯计算。

```mermaid
flowchart LR
    P0["P0 输入/不变量"] --> P1["P1 拍初索引"]
    P1 --> P2["P2 独立预览 + 规范消费"]
    P2 --> P3["P3 独立候选求值 + 规范组装"]
    P3 --> P4["P4 串行联合裁决"]
    P4 --> P5["P5 独立运动 + 串行资源转移"]
    P5 --> P6["P6 完整 CommitPlan"]
    P6 --> P7["P7 单次发布"]
    P7 --> P8["P8 结果交付"]
```

记 B 为世界绑定，C(T) 为拍初状态，D(T) 为已完成的派生查询，W 为工作区，A 为管理
状态。协调器是本次同步 step 中负责规范消费和共享写入的调用方，不是第二交通权威。

| 阶段 | 读取                                  | 首版物理执行                                                       | 进入消费者前的条件                                             |
| ---- | ------------------------------------- | ------------------------------------------------------------------ | -------------------------------------------------------------- |
| P0   | input、B、C(T)                        | 协调器校验并计算下一时钟                                           | 保留输入/不变量首错次序                                        |
| P1   | B、C(T)                               | 协调器构建 occupancy/leader 查询                                   | 完成索引后才借出共享视图                                       |
| P2   | B、C(T)、D(T)                         | 分块计算逐车 horizon/运动预览；协调器消费 Waiting 求值结果         | Waiting 前置约束已冻结，完整句柄及缓存证明有效                 |
| P3   | 同上、已冻结意图及 approach frontier  | 分块计算无共享写入的候选字段；协调器形成前沿、请求、候选表和调度器 | 候选依赖的共享归约已完成；Waiting 本地可行不等于 grant         |
| P4   | C(T) 资源、请求、规范前序 staged 声明 | 协调器执行现行 Waiting/Conflict/下游联合裁决                       | 所有 P3 借用归还，候选总序已确定                               |
| P5   | C(T)、D(T)、最终裁决、signal(T)       | 分块执行逐车运动；协调器消费到达记录并准备资源转移与下一信号/资格  | grants/stop 输入冻结；共享转移只能消费已规范接纳的完整运动结果 |
| P6   | B、C(T)、W、A 日志需求                | 协调器校验、准备结果与 CommitPlan                                  | 可恢复校验、必要容量、日志输入有效性与读取次序证明已闭合       |
| P7   | 完整 CommitPlan                       | 协调器统一发布                                                     | 无活动任务、无可恢复错误出口、无必要内存增长                   |
| P8   | 已提交状态与已有结果                  | 返回结果，回收已消费暂存                                           | 不新增领域运算、失败分配或宿主回调                             |

首版不并行改写 P1、P4、资源转移、输出排序或 P7；这些路径仍计入整步延迟。P3 的
frontier 先按 owner 合并，再保留不同 owner 的最保守值；该共享归约完成后，依赖它的
候选计算才能分发。不把多资源贪心授权当作逐车纯计算。

## 4. 独立计算与规范消费接口

### 4.1 任务输入输出

任务接口包含窄只读视图、完整实体身份、逻辑位置、已冻结前置约束、独占输出范围
和尝试世代（Attempt Epoch）。输出是该计算区间的值或完整领域错误，附分支和检查
位置；它不直接追加共享候选/事件，不获得 grant，不更新资源台账或全局计数。
若一个任务覆盖多车，须保序报告已完成前缀及其首错；尚未计算的后缀保持未完成。
错误回报还须保留该错误之前、尚未被规范消费的义务所需的成功值前缀，覆盖车辆之间
及失败车辆内部，不能只保存失败车辆之前的完整车辆结果。未物化的输入由协调器在
原逻辑位置通过相同领域原语补齐。可以拆小计算段、携带局部成功值或在错误路径
补算，不冻结唯一结果类型；不得仅返回丢失更早必要输入的整车 `Err`。

每个可分发函数须列明输入生产者、消费者和无共享写入的字段证据。保留底层同一套
领域原语；融合路径直接调用它，多 worker 路径只改变调度与结果交付。不得先串行
执行完整求值或 oracle，再把重复计算包装成并行路径。

投机求值不能把串行本会以领域错误拒绝的非法句柄、路线下标或资源地址变成越界
panic。安全读取须先以受检访问取得数据，把失败作为带逻辑位置的结果暂存；取得
只读视图所需的安全准备不授权提前公开领域错误。只有已冻结且不依赖前序暂存
写入的值才能投机，未物化结果须在规范位置补算完成后才算该检查已解析。

| 计算段        | 可交给任务的内容                                                                 | 协调器保留的检查与写入                                                |
| ------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 运动/前视预览 | 从 C(T)、完整路线、occupancy 与已确定约束求值                                    | live/Active 身份检查、Waiting 计划与共享缓冲写入                      |
| 候选字段      | 在完整 frontier 下求 eligibility、Gate、ETA、cell/downstream 声明值              | 规范候选下标、checked 长度/编码、真实必需 reserve、候选与请求组装     |
| 最终逐车运动  | 原 Parking 检查、Waiting stop、Conflict stop、缓存复用证明或重算、运动与到达求值 | 逐车到达记录实际 reserve、next state 接纳、后续 Waiting/Conflict 转移 |

这是提取边界，不能直接把当前含 `&mut StepWorkspace` 的整段函数提交到线程池。
逐出现项 exact distance、directed 运算顺序和 `Finite(0)` / `OutsideHorizon` /
`Unprovable` 保持；同车同拍 ETA 输入复用不变成跨车/跨拍缓存。缓存按完整句柄与
约束证明命中，不能因分块而把原先应重算的运动当作可复用。

### 4.2 逻辑检查地址与首错

逻辑检查地址（Logical Check Address）来自串行调用路径、规范循环位置与子分支。
P0～P8 是职责标签，不能用 `(phase, vehicle, error enum)` 或完成次序重排错误。
独立计算可提前完成，但错误只能在原逻辑位置被消费；协调器穿插执行原有的必要
预留、编码与共享检查，不把这些检查统一提前到分发前。

例如 P5 的较早车辆已算出停车到达，较晚车辆报告 `NonFiniteMotion`。协调器仍先
执行较早车辆的真实到达记录 reserve；若失败，返回 `ParkingObservationAllocFailed`。
把所有 worker 的错误先取最小车辆下标再统一生成输出，会遗漏这类交错义务。
P3 多段计算同理：某段的值就绪不代表它之前的共享 reserve、分支或 frontier 已成功。

同车内部也有交错义务：现行资源候选先计算、排序及去重 cell 声明，再为
`conflict_candidate_cells` 执行真实 reserve，随后准备 downstream 声明及其 reserve。
若 downstream 求值报 `ConflictInvariantViolation`，回报仍须让协调器得到此前 cell
集合或用同原语补齐，以兑现更早的必要 reserve。仅用
`Result<CompleteCandidateFields, StepError>` 丢弃全部局部结果不能满足该义务，
除非另有保留/补算协议。实现必须验证下列同车反例，不能只覆盖不同车辆的错误：

| 场景                                                                       | 必须得到的结果                                                 |
| -------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 同一车辆的 cell 必要 reserve 注入失败，downstream 更晚位置同时注入领域错误 | 较早的 `ConflictScratchAllocFailed` 优先，不能直接返回更晚错误 |
| 改变 worker 数、任务块边界及完成顺序                                       | 首错与失败后的公开状态保持一致                                 |
| 清除两处注入并重试                                                         | 与原提交状态上无故障 fresh 执行一致                            |

cell 注入必须命中真实必要增长，记录实际访问位置与需求；已有余量足够时不得制造
分配失败。串行或融合路径因较早失败而未执行下游检查时应如实记录，并通过清除
较早注入验证下游故障可达，不把未执行的注入记为已经命中。

完成前沿（Completion Frontier）记录规范消费到哪里。每个更早义务都必须已成功、
失败或由确定分支关闭，缺失、旧 epoch 或取消回报不是成功。首版可用连续输出范围
和保序消费完成这一协议，无需通用依赖图调度器或完整叶级地址运行时对象；但代码
提取和故障注入必须能映射至实际串行叶级检查。

### 4.3 join、取消与失败清理

首版采用完整 join：已分发任务完成自身有限计算，全部归还借用后再返回首错。
停止新分发仅针对已证明晚于当前最早已知错误、且不为更早未完成义务提供输入的
批次。较晚错误先返回时，尚未分发的更早必需计算仍要补齐；不能按队列抵达时间
把它们丢弃。首版不依赖任务内提前取消来获得正确性；必须统计错误后的多做工作。
若以后提前取消，也须先证明相同的逻辑先后与消费者条件。

每次尝试有独立 epoch；同 committed tick 重试也更新。回报先核验 epoch、块范围和
完整句柄，再进入规范消费。回绕仅在无任务边界完整失效后处理。领域错误后先 join，
再撤销本次 Waiting/Conflict 暂存、销毁全部 grant，最后恢复私有序号基线。不能让
旧 capability 存活到同 owner、同 tick、同整数重现。

线程 panic 不映射为交通 `StepError`。在支持 unwind 的构建中先收拢已分发任务和
借用，再传播 panic；该世界退出可用状态，后续交通/管理操作不得继续执行，宿主须
销毁并重建。私有失效标记与 drop 收尾由执行器实现验证，不增加公开恢复入口。
`panic=abort` 遵循进程终止语义。领域失败可重试的承诺不扩展到 panic 或系统终止。

## 5. 借用、容量与成本边界

只共享 B/C(T)/已完成 D(T) 与不可变裁决，任务独占输出切片；协调器独占共享工作区
写入、领域数量与完成记录。只读方法不自动证明整个聚合为 `Sync`，诊断和测试模式
的内部可变计数必须通过窄字段视图或任务局部记录、join 后汇总，不能靠未经证明的
`unsafe impl Sync`。借出任何元素后，其 backing 在全部任务归还前不得扩容或重分块。

并行专用缓冲、队列和任务分段有 checked 长度与明确上界，不能按块复制全世界。
活动/候选/退休计划、输出、局部变长声明、队列、辅助线程栈与保留容量分别计账。
候选/运动输出暂存目标为 `O(N + C)`，N 为实际活动计算数，C 为声明数；共享输入
保持单份，不能隐藏 `worker_count × 全车辆/全车道/全资源表`。

仅为并行执行增加的可选工作区准备失败时，在未分发或 join 后退回同领域原语的
融合求值，不新增领域 `StepError`；不得静默降低宿主要求的已安装执行能力。融合
是本阶段执行选择，执行资源仍由安装合同提供。若局部变长结果不能在已有空间表示，
保留“未物化”的内部状态，由协调器在原逻辑位置求值/准备，不能伪造领域分配错误。
该回退需覆盖首错与成本，避免重复昂贵工作成为正常路径。

领域本来就必需的 reserve 保留原错误与真实需求。投机大额预留失败不能在原逻辑
位置重放，因为该义务可能不发生或已有余量足够；只有真实需求超过容量且准备失败
时才产生原错误。重复 reserve 的逻辑地址须含访问序号及 `len / required / capacity`。
物理分配次数随容量复用不同，不用共享“第 N 次 malloc”代替逻辑故障注入。

容量可在全部任务 join 后复用，但映射必须按新拍完整键重建或可靠维护。冷启动、
增长、同容量重建、高水位后收缩分别计量。安装/恢复/切换的必需计划准备失败沿用
配套设计的显式执行错误，不能把管理操作与 tick 的可选并行工作区混成一个错误面。

## 6. P4 规范串行联合裁决

首版继续使用现行候选构造顺序、完整比较键和 Waiting 链就绪关系；不改为原始键
全局排序，不引入固定链前缀最大键重排，也不按 worker 完成顺序授予资源。
P3 并行仅提供字段值，规范候选下标仍由协调器在原位置确定。

Waiting 台账、休眠 watcher、自等待和潜在成环检查，ConflictZone/cell、下游物理
存储、全局容量与私有 grant 序号都由同一个协调器处理。保留
`Waiting stage/cycle → cells_unavailable → preflight_no_grant → try_acquire`
的条件顺序，以及 grant 后的编码、Waiting claim 激活和结果暂存错误。

每个 bundle 全有或全无。正常 NoGrant 不变成 step 错误，不消耗 grant 序号；未实际
crossing 的成功 grant 和纯 Waiting grant 继续消耗序号。失败时按完整 step 合同回收
本次暂存与凭证后恢复基线，已有 reservation 的配对保持。

首版无需每拍构建联合支持图、拆分组件资源表、分配组件序号额度或绑定临时 grant。
这些成本也不能被算作首版必经成本或首版 G1 的未完成义务。P4 串行段的耗时和占比
必须单独测量，作为实际加速上限的输入。

## 7. P5～P8 的准备与发布

最终逐车运动消费 C(T) 与完整 P4 结果。协调器按逻辑位置接纳成功 next state 和
停车到达，随后按原顺序完成 Waiting admission、下一信号、Conflict crossing/clear/
release、唯一 traversal、资格和输出。判断用 signal(T)，历史归因不按拍末灯态重写。

首版事件计数、真实容量准备、生成、规范排序和日志准备仍由协调器执行；不引入
并行事件填充或并行写回。相同主键保留现行 tie-break，事件顺序、授权顺序和实际
crossing 顺序各按自身合同，不能用线程顺序统一。同拍 enter/leave 即使终态无成员，
仍保留 admission 序号消耗与事件。零事件仍执行原计数/校验。

P6 完成日志所需输入的有效性、旧/新值读取次序和容量证明，准备发布缓冲并完成
全部可恢复校验，再生成 `CommitPlan`。P7 可以沿用现行依赖顺序，流式读取已证明
有效的输入并编码日志，不要求提前读取或额外物化全量 delta。日志未武装时，省略
日志专用的比较、路线定位和 delta 物化；车辆写回、资源提交及时间推进照常完成。

Conflict crossing 直接改写 committed reservation；`discard_staged` 和序号恢复不能撤销它。
因此第一笔 committed 写入后不得再出现未处理的可恢复错误。局部 preflight 通过
不能代替完整运动、Waiting、clear/release、事件与日志准备。

P7 沿用有序发布，进入时已无任务，且不再需要内存增长。须用真实分配器或等价证据
验证，不能只检查函数没有 `Result`。有界 journal 溢出仍使迁移候选失效，活动世界
完成本拍；不能包装成已开始发布的 step 可恢复失败。提交前错误保留旧状态、时间、
游标、日志和历史成功批次；物理缓存及容量可按合同保留。

P8 不分配新结果、不回调宿主。P6/P7 的进一步扫描、排序、复制优化可以另立等价
优化项，不能借首版并行改动扩展共享写入或松动提交边界。

## 8. 成本模型与实验合同

首版目标是在同一语义工作量上降低独立计算延迟。令 Q 为保留串行的工作时间，Wi
为某个可分发计算段的总工作，Si 为该段分块后最长任务工作，B 为新增且不可重叠的
准备/分发/归约开销。理想化下界为 `Q + B + Σ max(Wi / p, Si)`，实际还要加屏障、
调度与不均衡等待。阶段重叠只有经数据寿命与首错证明后才能改变这个模型；不能
用车辆数、组件数或候选占比直接推导加速比。

P5 的 Wi 以缓存复用后的真实工作计量：分别记录 `MotionPreview` 命中、运动内核
重算车辆数、停车/停止约束检查及结果暂存/规范接纳成本，不能按每辆车一次完整
运动求值估算。共享前沿的串行成本包括车辆/路线出现项遍历、精确距离和 ETA 下界
计算，不能只记最后的合并。若保留串行部分已超过预算，增加 worker 本身不足以
达标；高缓存命中下选择融合执行不改变已安装执行能力。

单 worker 使用融合路径，不创建辅助线程。空集、小工作集和可选工作区回退有明确
成本；阈值只决定本阶段谁执行，不改变配置、首错、容量和输出。规则用已知工作量
决定，不用投机执行的结果反过来决定交通语义。线程库和任务粒度在该合同内选择。

| 维度       | 必须报告                                                           |
| ---------- | ------------------------------------------------------------------ |
| 语义工作   | Active/live/高水位、预览/候选/声明数、精确查询访问量、P4 裁决数    |
| 串行与跨度 | P1/P4/共享转移/P6/P7 时间，可分发工作、最长块工作及屏障等待        |
| 调度       | 实际并发、块数、粒度、负载不均、错误后多做工作、融合回退次数和原因 |
| 数据访问   | 扫描/排序、物化/复制/写回字节、重复求值与缓存命中/失效             |
| 内存       | 逻辑长度、保留容量、峰值 scratch、活动/候选/退休计划、队列与线程栈 |
| 延迟       | 整步 p50/p95/p99/max；命令、观测、表现与管理操作分别计时           |

比较历史串行 R0、局部算法优化后串行 R1、新架构单 worker P1、同架构多 worker Pp。
分别报告 R0/R1 算法收益、P1/R1 架构开销、P1/Pp 并行收益，附绝对延迟和内存，
不能用 R0/Pp 一个比值混合归因。这里的基线名 P1 与阶段 P1 分属不同语境。

实验覆盖 1/2/4/8/16 worker，块数少于/等于/多于 worker，完成置换、空集、少车、
长路线/前车链/环、共享路线、Waiting 密集变化、集中资源竞争、生命周期和 journal
开关。需要观察到实际任务并发，不把“接受 worker 参数但全部串行”算作交付。硬件
不支持的项明确未测；未测不能登记为通过。集中竞争检验保留的 P4 串行成本，不要求
首版生成组件或 SCC 图。

规模矩阵继承[产品性能合同](core-runtime-performance-baseline.md)：一万道路机动车
16 ms 固定步长、Core p95 2 ms/tick；十万规模 33 ms、Core p95 16 ms/tick。
标称个体数、Active 数和呈现数分开；CN-URBAN 衰减轨迹与稳定 Active 对照分列，
不把 CN-URBAN 改称 LF-SYNTH W1。P4 保持串行不降低预算，也不预先保证预算通过。

先筛选机制与成本，再对胜出候选做同条件三轮完整观察窗口与规定检查点。正常
release latency 不带逐阶段插桩；计数、分配诊断与 WPR 配对单独运行，固定 source/
binary/PDB、时间范围和硬件状态。不相加不同层的 p95 推导整帧 p95；旧二进制画像、
短前缀、单次墙钟尖峰、多世界吞吐和 Adapter LOD 均不替代当前单世界性能验收。

## 9. 首版冻结与实施验收

| 窄只读借用和唯一输出      | 生产/诊断/测试模式可编译，任务借用期间无扩容，无按块全表复制                            |

落地配置/快照、资源与共同状态准备、独立计算调度及完整等价/性能验收；各切片单独

评审；函数划分、内部队列和任务粒度在已冻结边界内由实现证据选择。

## 10. 后续 P4 组件并行的独立边界

P4 的进一步并行不属于首版完成条件。若另立设计，应重新评审以下输入，不能直接
把此前有界机制当成已冻结的生产组件算法：

- 完整规范键和 Waiting 链就绪关系；固定链前缀最大键仅在固定、不相交、无条件
  释放后继的链模型下成立，不能泛化为原始键全局排序或任意条件 DAG。
- 当前激活 Waiting 图、潜在资源支持图和候选执行依赖图的区别；旧/新 hold、休眠
  watcher、自等待、潜在成环、ConflictZone 与下游间距形成的联合闭包。
- 每份暂存资源的唯一写入者、局部目录/全局完整身份映射及未知键拒绝；无每组件
  全表复制，组件内进一步并行有独立写域与依赖证明。
- 跨组件全局容量、实际 reserve、首错完成前沿与序号额度；临时 grant 若存在，须
  在首个最终配对消费者前一致绑定全部载体，且失败先 join/销毁凭证再回退。
- 将上述机制贯通完整 step、真实 Waiting 依赖、事件和 journal；测量工作量、最大
  组件/加权跨度、准备/归约成本及整步收益，再决定是否启用。

对组件内串行候选，`B + max(W / p, max(Wc))` 只是该策略的理想下界，不是领域
最小 DAG 跨度。构图若不能抵消成本，继续使用首版规范串行 P4；不为后续实验保留
两套生产资源权威、兼容开关或预先安装未使用的组件目录。
