# 语言与术语政策

## 1. 规范来源与收录范围

长期设计以中文术语和中文定义为准，英文只辅助理解、代码对接或外部交流。
规范词条来自 `docs/reference/terms/`，阅读入口为[术语表][glossary]；数据格式和
维护命令见[术语目录规范][catalog]。编辑 TOML 正本，不修改生成词条正文。

收录项目特有概念、跨文档需要统一的领域术语、容易发生歧义的名称，以及必须说明
语义的代码标识符。通用自然用词无需逐个登记；不能因为出现英文就扩充词表。
同一概念只维护一份定义，按领域交叉索引；技术合同仍由所属 ADR、design 或
reference 维护，术语不能新增或覆盖这些合同。

## 2. 首次出现、英文与精确标识符

1. 每篇文档中需要解释的规范领域术语首次出现时写“中文术语（English Alias）”，
   后文优先中文。独立阅读的长章节必要时重述，普通自然用词不强制中英夹注。
2. 中英文冲突时以规范中文定义为准，英文辅助名不得新增、删除或改变语义。
3. Rust 类型、包、字段、版本、算法专名和协议常量等精确标识符保留原拼写并使用
   行内代码，正文以中文解释；不翻译第三方商标或协议匹配字面量。
4. 缩写首次出现给出中文含义、英文全称与缩写。允许简称必须在词条的
   `short_forms` 中登记适用语境，不能用未定义简称掩盖概念差异。
5. 无通行中文名的领域词可登记借词，英文原词为规范名、中文定义仍为准；正文首次
   出现夹注登记的中文释义，如 fixture（固定测试环境）。

新领域概念进入正式设计时，应同时补充规范名、英文辅助名、中文定义和责任来源。
提案词条应明确其语境；收录不表示设计接受、实现完成或数值认证。

## 3. 用词判定与旧称

用词问题按句义区分：

- 未定义简称：改用已登记规范名，或登记有明确适用条件的简称。
- 实验室行话与口语：说明实际机制与动作；确为独立概念时再登记词条。
- 逐字直译：结合领域建立自然中文名与英文辅助名，保留必要的精确标识符。
- 同物异名：选定一个规范名，其余按语境登记为允许简称或旧称。

稳定改名由[旧称查询][former-names]登记；已废止概念单列在
[停止采用的概念][retired-concepts]。措辞不能一对一替换时使用[措辞指南][wording]。
三类登记共同确定适用范围与例外，不能另建工具私有禁词清单。

旧称中的同义派生复合词按登记范围处理，但同形异义、精确标识符与明确例外保留。
不以裸字符串匹配判断违规，也不自动改写代码或协议名称。

已关闭 Issue / PR 正文、Git 历史和通过固定提交 URL 引用的历史记录不改写。豁免
不延伸到新写正文：引用历史证据须区分当时术语与现行说明，不把旧概念重新宣称为
现行能力。反例与旧称登记本身保留原词。

当前文档树不保存已关闭任务的验证轮次或截图；查阅当时证据使用 Git 历史与对应
Issue / PR。不得用后续提案重新定性旧结论；确需按后续框架解释时，保留原陈述并
明确标注重述依据，不能让新解释冒充原始证据。

## 4. 数量与规模

数量级、单位和计数对象必须清楚。中文正文可使用“一千”“一万”“十万”等写法；
表格、公式和机器输入宜使用完整十进制数字。语境清楚时允许 `k`、`M` 或 `1 万`，
不设自动检查；小写 `m` 不得与米产生歧义。代码、测试、文件及协议标识符保留原文。

交通仿真规模不使用 Agent 或“代理”计数，Agent 默认指 AI Agent 工作流。长期
通用规模按交通执行域分别报告交通参与单元及个体、活动、意图更新、表现、聚合记录
和聚合等价数量；不同执行域的未分解总数不能成为可比较性能指标。

当前 `TrafficWorld`、车辆 API、工作负载及历史证据保持道路机动车特化标注；现有
五类车辆计数继续用于其对应报告。长期六类通用计数不表示其他执行域已实现，不
改写当前性能门槛或历史证据，也不让当前车辆实现反向定义长期交通运行时。

## 5. 修订与审阅

改变概念含义、职责或边界属于设计变更，应先更新责任设计，再同步术语。中文错字、
语序和等义表述调整属于编辑修订；仅修改英文辅助名不得改变中文含义。

规范名变化应同步现行引用、旧称映射和必要的简称。定义收短时保留必要区别，细节
转为责任文档链接，不能丢失检测覆盖、当前与目标边界、失败行为或历史证据限制。

审阅核对语义与来源；机器只检查目录结构、名称登记、引用和生成一致性。不得用
结构检查通过代替技术审阅，也不新增自然语言禁词或实现完成自动判断。
