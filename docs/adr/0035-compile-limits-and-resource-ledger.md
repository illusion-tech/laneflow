# 0035 编译资源合同分四类边界，规范路网容量由生产端与消费端共同约束，受控分配统一经资源账本

<a id="applicability"></a>
## 适用边界与依据

本文为 #1296 G1 第二次修订的待接受正本，取代 2026-11-16 接受的第一次修订（见[固定提交][adr-0035-revision-1]）；
初版见[固定提交][adr-0035-initial]。

设计入口： [#1296][issue-1296]、[#1288][issue-1288]
关联决策： [ADR 0024][adr-0024]、[ADR 0025][adr-0025]

本文决定：编译资源合同分为**来源处理限额**、**规范路网容量**、**制品格式边界**与**操作资源
预算**四类边界，每类约束各自领域的对象，不跨领域借用维度；规范路网容量约束最终规范路网，
编译端从最终 LIR、消费端从最终 LFCA 字节按同一定义各自统计并执行；编译、发射与公开检查的
受控分配一律经同一个编译器资源账本按计划授予。账本模型见[编译器资源账本][resource-ledger]，
维度、规范计数定义与配置档见[编译器基础 §5.3][compiler-limits]。

## 背景

### #1288 暴露的失配

`CompileLimits` 曾有 `LF-COMP-P100-INITIAL-v1`、逐项继承 v1 的 `LF-COMP-P100-INITIAL-v2`
与 `LF-COMP-SINGLE-NETWORK-1M-v2` 三个具名配置档，每个维度都是手写常量。P100 v1 允许
11,265 个稳定实体，但发射期 `ArtifactIndex` 对每个身份行计入 76 B，与编译管线共用
304,896 B 的 `StageScratchBytes`：实测 4,011 个稳定实体可以发射，4,012 个失败。来源是
`a6d73e5d`（#563）把发射期索引改为计入共用暂存计量器，常量没有随之重新校准，也没有
任何检查发现这一点。

### 初版决定与实现前调研

初版（见页头固定提交）的方向是：配置档只声明容量与宿主预算，暂存、输出与可移植对象
字节作为**推导字节维度**，其上限由与记账共用的成本公式代入容量上限求出。实现前对全部
记账点的调研（2026-11-16，`051f515a`）发现，问题不止于常量与公式脱节：

1. **记账没有统一抽象。** 编译器内至少有七套各自独立的内存计量结构：HIR 的
   `DomainBudget`、源映射冻结的 `SourceMapSizing`、发射器的 `Scratch`、道路编辑的
   `PreflightScratch`、`GeometryScratchAllowance`、`GeometryScratchBudget` 与
   `GeometryCompilationBudget`；HIR 计划、MIR、LIR 与源映射冻结各自复制了一份同名的
   字节折算函数，各阶段又分别手工累加上游阶段的存续字节。三种时机并存：开工前计划
   （HIR、MIR、LIR、源映射）、边分配边记账（发射器）、逐次分配前预检（道路编辑）。
   #1288 正是一处分配换了计量器、却沿用另一阶段上限的结果。
2. **计划与分配只靠约定对应。** HIR、MIR、LIR 与源映射冻结的计划层约有 316 处按
   “元素类型 × 计数”申请字节，实际分配写在另外的文件里，按同一计数预留容量；二者的
   类型与计数是否一致只靠人工保持，个别位置用 `debug_assert_eq!` 核对长度。
3. **发射阶段不在宿主预算内。** 发射器只计暂存与最终对象字节数：LFCA/LFSM/LFSD 的
   内存对象树、编码缓冲、内存发射路径返回的对象字节都不计入
   `CompilerControlledLiveBytes`；差异路径另有按 `(EntityKind, StableId128)` 建立的有序
   映射与几何字节副本，没有计入任何维度。
4. **推导上界不表达独立的宿主资源意愿。** 计划公式的输入是数十个内部计数（路口、流向、
   机动路径、车道组成员等），它们共同受声明数、稳定实体数、关系出现记录数等容量约束；
   公式含条件分支、`min` 与跨领域耦合。由容量模型必然推出的内部字节上界是健全的，
   但它只是容量的函数，不表达宿主允许多少资源；初版已把越过推导边界归为内部缺陷，
   作为公开限额只是让每个推导维度多维护一份诊断面与已知向量。
5. **部分操作资源预算维度没有执行对象。** 编译器不跨编译保留容量，
   `Compiler::retained_capacity_bytes()` 恒为零；P100 档未定义可移植对象与 bundle 维度，
   而百万档的 bundle 上限等于单对象上限的两倍，不是独立校准的宿主资源边界。

根因是：限额（宿主允许多少）与记账（编译器实际申请多少）没有分开建模，记账又分散在
各阶段各写一套。第一次修订把二者分开，并把记账收敛到一处。

### 第一次修订的制品容量在实现前不成立

第一次修订（见页头固定提交）第 4 节规定外部可移植字节按**制品容量**准入：从受检
LFCA/LFSM/LFSD 统计实体行、关系出现记录行、几何点与几何字节、策略成员行、字符串与向量
字节以及 LFSD 变化表行数，与所选配置档的来源侧维度比较。实现前逐项核对编译期计数
（2026-11-17，#1296 第 3c 层）发现，部分统计量与来源侧维度不能直接对应，照此准入
会拒绝本配置档自己编译出的合法制品：

1. **字符串。** 来源侧 `TotalStringBytes` 统计来源资源模型计入的逻辑字符串字节。LFCA
   把法规辖区、版本字符串逐行写出，LFSM 的 namespace、owner/local key 随来源位置重复，
   制品 UTF-8 字节可以超过来源字符串字节；provenance 中的 `compiler_build_id` 允许 1–128
   字节，与来源侧 `SingleStringBytes` 无关。
2. **关系。** 来源侧 `RelationOccurrenceCount` 统计来源声明中的多值关系成员。LFCA 第 4 节
   含编译器派生的路口内部边，最终规范路网的关系出现记录不一定不超过来源关系数。

根因是 `CompileLimits` 让一组维度同时承担来源处理、规范路网规模与操作资源三种职责，
名称接近的量（来源字符串字节与制品 UTF-8 字节、来源关系与规范关系、物理表行与逻辑记录）
被当作同一合同。只按维度名称把制品统计映射到来源维度，即使个别映射恰好有可证明的上界，
也不能据此把两个领域视为同一个模型。本次修订按领域重新划分边界。

## 决策

### 1. 编译资源合同分四类边界

| 边界         | 回答的问题                           | 约束对象                                                                 | 执行方                       |
| ------------ | ------------------------------------ | ------------------------------------------------------------------------ | ---------------------------- |
| 来源处理限额 | 允许接收和处理多大的编制输入         | 模块、来源字节、声明、来源字符串、来源关系、标识字段与各阶段记录         | 编译单元准入与编译管线       |
| 规范路网容量 | 允许交付或消费多大的规范路网         | 稳定实体、规范关系出现记录、规范几何点与登记的实体子类                   | 编译端与外部 LFCA 的消费入口 |
| 制品格式边界 | 允许读取或生成怎样的物理对象         | 对象字节、chunk、字段、向量、嵌套深度与字段值长度                        | 调用方 `FormatLimits` 与格式 |
| 操作资源预算 | 这次编译、发射或检查可以使用多少资源 | 编译器控制总存续字节、编译后保留的容量字节；工作量与取消见第 3 节第 9 条 | 编译器资源账本               |

- **来源处理限额**只在编译单元准入与编译管线内执行，不用于约束外部制品，也不从制品反推。
  HIR、MIR、LIR 等阶段记录数属于编译实现的处理边界，对外部制品的消费者不可见。来源侧
  `RelationOccurrenceCount`、`StringItemCount`、`SingleStringBytes` 与 `TotalStringBytes` 的
  名称与文档明确限定为来源侧口径。
- **规范路网容量**是编译端与消费端共享的合同，定义与执行见第 4 节。
- **制品格式边界**见第 2 节。
- **操作资源预算**由账本执行，见第 3 节。

**事实不自动成为限额。**另设两类事实：**规范路网规模**（canonical network usage）是一份
规范路网实际包含的实体、关系与几何点数；**制品结构统计**（artifact shape）是一份物理制品
实际包含的行、字段、UTF-8 字节、向量元素、来源位置、路径步、变化行与 before/after 载荷。
规范路网规模与规范路网容量比较；制品结构统计只作为资源计划的输入，与算法一起求出计划，
不与任何限额维度比较。只有表达独立产品要求的量才成为限额，其余量作为真实成本进入计划，
避免产品容量随字符串去重、字段布局或辅助索引一类序列化细节变化。

**具名配置档只是组合入口。**`LF-COMP-P100` 与 `LF-COMP-SINGLE-NETWORK-1M` 继续是调用方
选择的具名配置档，各自组合一份来源处理限额、一份规范路网容量与一份默认操作资源预算；
字段私有，受控构造，不开放任意拼装的无限配置。编译器持有完整配置档；外部制品的消费
入口需要规范路网容量、`FormatLimits` 与操作资源预算（或已绑定该预算的操作上下文），不读取
来源处理限额。账本只依赖操作资源预算的视图，具名配置档负责提供这些政策。

**跨领域比较在类型上不可构造。**统计、政策与计划分开建模：事实提取只回答“有什么”，
不读取配置档；容量判定只比较同一领域的事实与政策；计划由制品结构统计与算法求出。跨模块
边界上不提供“裸计数加通用维度枚举”的任意组合接口，规范路网规模不能传给来源处理限额的
比较，制品结构统计也不能传给规范路网容量的比较。具体类型名在实现时登记。

编译器资源策略造成的正常拒绝只来自来源处理限额、规范路网容量与操作资源预算；调用方
`FormatLimits` 与线格式硬上限造成的拒绝另属格式边界。`StageScratchBytes`、`OutputBytes`、
`PortableObjectBytes` 与 `PortableBundleBytes` 已从 `CompileLimits` 删除，不拆分、不推导。
暂存峰值、输出逻辑字节与各阶段存续峰值由账本报告，供证据与回归比较使用，不参与拒绝。
删除四个字节维度会扩大可接受的输入集合，这是有意作出的行为变化。

### 2. 可移植字节边界交给格式预算与操作资源预算

- 单个可移植对象的字节由调用方传入的 `FormatLimits::max_object_bytes`（调用方接收预算）
  与线格式原语硬上限约束，超出时按格式边界报告。字符串的格式合法性与字段值长度同属
  格式合同。
- 内存发射路径的对象字节计入发射账本的宿主存续预算。
- 成功候选固定包含三个对象，每个对象受接收预算 `M` 约束，最终候选字节不超过 `3M`，
  不需要独立的 bundle 维度；该上界不描述累计 I/O（预备 LFCA 另写一次后释放）。
- 本设计不把单次发射的磁盘总字节定义为编译器资源预算。暂存存储额度和并发任务治理由
  宿主负责；编译器执行单对象格式预算、受控内存预算和临时对象生命周期保证。
- 单对象字节不以配置档推导的静态上界证明。具体对象按实际编码结构作受检尺寸计算，执行
  `FormatLimits` 与线格式硬上限。规范路网容量不约束来源文档、来源位置、贡献来源集合、
  路径步与文本载荷等制品结构量，不足以单独推出单对象字节上界。生产端如需静态生成上界，
  须列出完整依赖（来源处理限额、规范路网容量、独立字段合同、对象种类与差异两侧约束）并
  限定证明范围；生产端的上界分析可以使用来源处理限额，但这不构成外部消费者按来源处理
  限额准入的理由。

### 3. 受控分配统一经编译器资源账本

每个**宿主发起的顶层操作**（一次编译单元准入、一次编译、一次发射，或宿主直接调用的
一次公开检查）持有一个**编译器资源账本**（compiler resource ledger），对照所选配置档的
操作资源预算记账。账本合同的完整定义见[编译器资源账本][resource-ledger]，本节冻结以下
要点：

1. **顶层操作划界**：顶层操作内部调用的逻辑不新建账本，只在父账本上取得子预算；发射期
   调用的策略检查共用发射账本，本次发射已生成的对象在检查期间持续计入。检查器仍从最终
   字节独立建立语义检查视图，ADR 0024 的检查独立性不受影响。
2. **输入归属**：按值移入的存储由本次操作拥有并计入（编译单元计入编译账本，口径与现有
   编译存续总量一致）；借出或共享引用延续的存储（`CompilationOutput`、调用方字节、既有
   backing 的浅克隆）不计入；本次新建的容器与复制、驻留的载荷计入。发射与检查账本是
   新增口径，比较新旧峰值须注明口径。
3. **计划准入与预留守恒**：每个编译遍在任何与计数成正比的分配前按实际计数求出计划
   峰值。账本维护存续 `L` 与已准入、尚未消费的预留 `R`，准入新计划时检查
   `L + R + P ≤ B`（`B` 为 `CompilerControlledLiveBytes`），不成立即在分配前拒绝；授予把额度
   从预留转为存续，释放把额度归还本遍，编译遍结束或取消时退还未消费预留。同一时刻只有
   一个活动的顶层编译遍预算，子预算按栈嵌套。计划所用的计数取自本次输入的实际事实：
   编译管线取已通过来源处理限额的计数，消费外部字节的入口取受检视图的制品结构统计。
4. **授予驱动分配并随存储持有**：受控存储只能由账本存储入口按授予的类型、数量与受检
   `Layout` 创建，不存在先扣字节、再另写分配的两步流程。本遍同时存续的授予之和超出
   计划峰值属编译器记账缺陷，报告为内部错误，不作为资源限额诊断；比较对象是同时存续
   之和，不是历次申请总量。扩容、深复制、新增嵌套存储与存储形态转换各需新的授予；
   共享 backing 的浅克隆共用一份授予，最后一个句柄释放时归还；所有权移动不改变计费。
5. **计量口径**：账本计量受控请求字节，即授予请求的 `Layout` 大小；分配器内部开销与可能
   多给的容量由分配器层证据衡量，账本不对容器实际 `capacity()` 作硬上界承诺。
6. **返回点转交与报告**：顶层操作或 builder 的一次准入调用终止时，`Ok` 与 `Err` 返回值
   接管的存储都在返回点显式转交宿主：成功的编译输出与发射候选，以及失败返回的诊断集合
   及只由它持有的存储。转交的存储仍然存活，与“已释放”分开记录，不得为满足结束检查而
   提前归还；诊断集合对账本仍持有的共享 backing 只复制句柄，授予留在原账本。账本报告
   存续峰值、各阶段工作集峰值、已释放与转交宿主字节以及保留容量。
7. **预算耗尽后的错误出口**：每次编译与每次准入调用在开始时预留固定的失败诊断额度并
   计入 `L + R ≤ B`；成功时退还，失败时其授予随诊断集合转交宿主，下一次准入调用重新
   预留。发射与检查路径的资源失败与记账缺陷错误不分配堆内存。失败返回时，除转交宿主的
   诊断存储外，本次持有的存储全部释放、未消费预留全部退还；同一 `Compiler` 可立即用于
   下一次操作。builder 的某次 `add_*` 失败只回滚本次 candidate 与临时工作存储，已准入
   模块及其账本状态保持不变，同一 builder 可继续准入。
8. **覆盖范围**：编译管线全部编译遍、单制品发射、差异发射、发射期自校验与公开检查入口
   使用同一账本模型。发射的内存对象树、编码缓冲、实体索引、比较投影、变化行与内存
   发射对象字节全部经账本授予。
9. **工作量与取消**：操作资源分内存与工作量两类。内存额度在存储释放后归还；已完成的
   扫描、访问与比较消耗的工作量不因临时对象释放而退还；取消负责宿主终止操作，不改变
   规范结果。工作量预算不得借用来源处理限额或规范路网容量的维度作上限。现有 MIR 策略
   校验的 `WorkBudget` 以来源侧 `RelationOccurrenceCount` 为上限，属待迁移的现状；工作量
   单位、配置档默认值与取消接入另行立项，本次修订不新增工作量维度，也不改变共享静态
   路网构建已有的工作预算与取消标志。

账本取代背景第 1 条列出的各内存计量结构与重复的字节折算函数，阶段内部的计划公式迁入
账本计划。

### 4. 规范路网容量由生产端与消费端共同约束

**约束对象。**规范路网容量约束**最终规范路网**，维度为：

- 稳定实体总数（`StableEntityCount`）；
- 有独立产品意义的实体子类数：机动门（`ManeuverGateCount`）与等待区（`WaitingZoneCount`）；
- 规范关系出现记录数（`CanonicalRelationCount`，新增）；
- 规范几何点记录数（`GeometryPointCount`）。

各维度的计数定义、LIR 投影与 LFCA 投影见[编译器基础 §5.3][compiler-limits]。现有
`StableEntityCount`、`ManeuverGateCount`、`WaitingZoneCount` 与 `GeometryPointCount` 由来源侧
维度改为规范路网容量维度，含义改为最终规范路网中的数量。它们现有的执行位置（编译单元
准入与 HIR 计划）可以作为早期检查保留，但不再是唯一执行点：编译成功前仍按最终 LIR 统计
检查一次，早期检查是否覆盖最终规模不作为前提。

**规范关系出现记录。**`CanonicalRelationCount` 统计本版本明确登记为容量计数对象的规范关联
出现记录。参与集合与每个角色的唯一计数投影以[可移植规范制品 §4.3][role-registry] 的
`sourceRelationRole` 登记为唯一定义：本版参与集合为 role 1–32；role 33–36 的 subject 是没有
独立实体身份的路权策略局部成员，不计入。计数规则：

- 一个出现位置由所有者实体、角色及该角色规定的局部序号确定。来源直接声明的关系与编译器
  展开或派生的关系都计入；不按端点去重，不同角色、owner 或合法出现位置分别计入；物理上
  写在实体字段、向量还是关系表不改变计数。
- 同一已登记关联的双向物理表示只按其唯一投影计一次；未登记的字段引用不计入。
- role 19 `SignalPhaseState` 按每条 `SignalPhase.states` 状态记录计 1；role 28、29、32 按
  实际存在的车道边几何、设施带几何与冲突区区域记录各计 1，与几何点数无关。

容量计数与 LFSD 差异通道分别定义：role 19 的变化仍只进入 StaticRule，role 28、29、32 只
进入 Geometry，不因计入容量而生成 RelationChange；容量投影只计数，不为此建立和排序完整
的关系元组。新增角色必须同时登记容量归属、唯一投影与差异通道，实现以穷尽的角色匹配
决定归属。`CanonicalRelationCount` 与来源侧 `RelationOccurrenceCount` 分别定义、分别执行；
路权策略局部成员等其他逻辑记录登记为规范统计，按实际规模进入资源计划，不自动增设公开
上限。定义按出现位置计数，因此从制品统计时只需顺序扫描，不需要为去重建立集合。

**两侧独立投影，同一定义。**编译端从最终 LIR 统计规范路网规模 `U_LIR`，消费端从最终 LFCA
字节的受检视图独立统计 `U_LFCA`；两侧共享计数定义与登记元数据，投影实现独立，消费端
不信任生产端自报的计数。对任意规范路网 `N`：

```text
U_LIR(N) = U_LFCA(encode(N))
```

两侧相等只证明两个投影相符；统计对象由计数定义与角色登记独立确定，验收须以明确的
期望数值核对固定向量，不能只断言两侧结果相同。

**生产端。**编译成功前，最终 LIR 必须满足 `U_LIR ≤ C`（`C` 为所选配置档的规范路网容量）；
能够提前得知派生规模的阶段可以更早拒绝。来源处理限额通过不保证规范路网容量通过：编译
派生的规范路网超出容量时，编译按规范路网容量正常拒绝。

**消费端。**不来自本次编译的 LFCA 字节（`PortableDiffBase::Artifact` 的 base，以及公开检查
入口接收的 LFCA）在格式预检之后、计划准入与建立索引之前，按所选配置档的规范路网容量准入：

1. 格式预检并借用扫描，取得制品结构统计与可直接求出的规范路网规模；
2. 规范路网规模超出容量的输入在此拒绝，错误标明输入一侧与规范路网容量维度；
3. 按制品结构统计求出索引与检查的计划，经账本准入后建立索引；
4. 完成需要索引的检查后，才返回相应的受检能力。

早期扫描得到的规模可以用于拒绝超规模输入，但不表示完整语义检查已经通过。准入结果绑定
同一份输入与同一份政策：以受检视图、不可变来源句柄与政策快照表达，不以可复用的布尔
标志表达；容量通过也不等于取得分配许可，授予仍属当前操作的账本。

**闭包。**消费者选用的规范路网容量逐维不小于生产者时，`U_LFCA = U_LIR ≤ C_producer ≤
C_consumer`，消费者的容量准入必然通过。消费者无需知道来源模块数、来源文本组织、字符串
共享方式或编译器内部记录数，也不需要把生产时的配置档写入制品。完整操作成功另需：消费者
支持该格式版本、对象满足消费者的 `FormatLimits`、本次操作的计划在操作资源预算内，以及
该入口负责的结构、绑定与语义检查通过。需要以更大的既有制品为差异 base 时，调用方选择
规范路网容量覆盖它的配置档。

**LFSM 与 LFSD 不另设容量。**LFSM 是来源映射，不表示另一份路网：其来源位置、贡献来源
集合、路径步与 owner-local 来源记录按制品结构统计进入检查计划，由格式边界、绑定检查与
操作资源预算约束。LFSD 描述两份路网之间的变化：base 与 target LFCA 各自按规范路网容量
准入；生成 LFSD 时由两侧内容推导变化表的计划上界；检查外部 LFSD 时统计其实际结构，外部
声明的变化行数不作为可信的计划依据。字段修改行按实体种类的可修改字段数计入，不简化为
“每个实体一行”。

**类型位置。**规范路网容量的值类型、规范计数定义与关系角色登记放在中立合同层
`laneflow-static-contract`；P100 与百万档的校准常量、LIR 投影与生产端执行留在
`laneflow-compiler`。共享静态路网构建是否、以何种容量值准入 LFCA 另行决定，其现有
`SharedNetworkBuildLimits` 不变；ADR 0025 中静态网络层不依赖编译器私有 LIR 与发射器的
约束保持不变。

### 5. 发射端目标索引只建立一次

LIR 实体规范顺序按 Identity v1 原像排序，不是 StableId 字节序，本设计不改变它。目标
LFCA 的 StableId 排列由发射上下文建立一次，经账本授予，供目标关系投影自校验与 LFSD
构建共用；差异 base 仍按原规则建立索引并检测重复。`check_portable_policy_diff` 继续从
最终字节独立建立检查视图，ADR 0024 的后发射 bundle 检查合同不变。

### 6. 配置档校验与资格验证

配置档的自洽要求分为两部分。

**配置档校验**核对配置本身可以解释与执行：

1. 每个维度属于正确的边界，单位与范围明确；容量兼容比较只发生在同一领域的同名维度之间。
2. **整数与平台可表示性**：维度值、相关常量与乘加在受检算术下可表示，转换为 `usize` 的值
   在目标平台可表示。单对象字节不在配置档校验中以容量推导的上界证明（第 2 节）。
3. 操作资源预算不小于入口预留的失败诊断额度。

**配置档资格验证**核对具名配置档兑现其公开能力：

1. **可成功规模**：对来源处理限额中除诊断数外的每个维度，与规范路网容量的每个维度，
   构造一份在该维度取可达上限、其余维度取构造所需最小值的输入，正向完成编译、单制品
   发射与 Genesis、以自身为 base、两侧 StableId 不相交、身份保持而内容大量修改、关系
   重连等正向差异场景，账本峰值不超出操作资源预算。无法单独逼近上限的维度须说明由
   哪个维度连带约束。
2. **两侧统计一致**：同一规范路网的 LIR 统计与最终 LFCA 独立统计逐维相等，且与固定向量
   的明确期望数值相等。关系计数的固定向量包含 role 19、28、29、32；改变灯色、几何坐标或
   只增加某份几何的点数时 `CanonicalRelationCount` 不变（后者使 `GeometryPointCount`
   增加）；双向表示不重复计数，不同出现位置不被端点去重；LFSD 原有通道与规范制品字节
   不变。
3. **规范统计不随制品结构变化**：同一规范路网、同一规范路网容量下，使用不同规模的合法
   来源映射，规范统计不变，格式检查与资源计划随实际结构变化。
4. **诊断保留**：诊断数只在失败路径验收：恰好 16 条、至少 17 条并设置截断、较小规范键
   替换已保留项，且不返回成功输出或部分发射候选。
5. **账本一致性**：常规测试中任何时刻每个编译遍同时存续的授予之和不超出其计划峰值，
   `L + R ≤ B` 成立，分配请求全部来自授予，编译遍结束时无未归还授予。
6. **预算耗尽的错误出口**：操作资源预算耗尽时仍能返回错误、释放未转交的资源并允许
   下一次操作；保留第一次 `add_*` 失败的诊断集合后，同一 builder 继续添加合法模块并完成
   `build`，旧诊断仍可读取、已准入模块不丢失、存储不重复计费、授予不提前归还。
7. **分边界拒绝**：超过来源处理限额、规范路网容量、格式边界与操作资源预算的输入分别在
   对应边界拒绝；base 超出规范路网容量时在建立索引前按 base 一侧与规范路网容量维度拒绝；超过
   操作资源预算的组合在分配前按 `CompilerControlledLiveBytes` 拒绝；拒绝后资源归还。

以下两个命题**不是**自洽要求：“来源处理限额全部通过则规范路网容量必然通过”，以及
“规范路网容量全部通过则任意操作组合必然在操作资源预算内”。必须保证的是：编译器成功
交付的规范路网，与从其最终字节重新取得的规范路网，容量含义一致。

P100 配置档的校验与资格验证在常规 CI 中运行，不得只放在 `#[ignore]` 测试中；百万档在
常规 CI 中执行配置档校验，可成功规模由其端到端证据入口承担。

### 7. 新配置档取代既有三档，1.0 前不并存

| 新配置档标识符              | 构造器                               | 来源处理限额与操作资源预算来源                 |
| --------------------------- | ------------------------------------ | ---------------------------------------------- |
| `LF-COMP-P100`              | `CompileLimits::p100()`              | 继承 `LF-COMP-P100-INITIAL-v2` 的对应维度      |
| `LF-COMP-SINGLE-NETWORK-1M` | `CompileLimits::single_network_1m()` | 继承 `LF-COMP-SINGLE-NETWORK-1M-v2` 的对应维度 |

规范路网容量中由来源侧改划过来的四个维度沿用现值；新增的 `CanonicalRelationCount` 按
role 1–32 的口径取值，不得直接复制来源侧 `RelationOccurrenceCount` 的数值，也不得沿用现有
关系元组数量；初始值由最终规范统计与支持的工作负载求出，经维护者批准后先于两端执行
登记，资格验证后按需再校准。

按 [1.0 前开发原则][pre-1-0]，标识符与构造器不带世代后缀；被取代的三个配置档及其构造器
随实现删除，不保留别名，现有调用方一并迁移。配置档标识符只出现在编译诊断与生成器、
测量入口的工作负载清单文本中，不进入 LFCA、LFSM、LFSD 或 `NetworkRevisionId`；退役旧
配置档不改变任何制品字节。配置档按第 1 节拆分为三部分组合后，构造器名称是否随之调整在
实现时决定，不保留并行入口。

## 后果

- #1288 类失配从结构上消除：分配必须持有授予，授予来自经操作资源预算准入的计划，不存在
  “换了计量器却沿用另一阶段上限”的路径。
- 外部制品不再借用来源处理限额，消费入口不必从来源规模推测制品成本；新增派生关系、增加
  来源映射内容、调整字符串共享或内部存储布局时，变化分别落在规范路网定义、制品结构统计
  与资源计划中。
- 编译端新增最终规范路网容量检查：来源处理限额内的输入可能因派生关系、相位状态或几何
  归属等登记关联超出 `CanonicalRelationCount` 而被拒绝。
- 错误分为：来源处理限额超限、规范路网容量超限（标明输入一侧）、格式边界或接收预算
  超限、操作资源预算超限、输入结构或相关语义不合法、内部计划与授予或结构一致性缺陷、
  分配器拒绝请求。来源处理限额的维度名不用于报告制品成本。
- P100 档声明的 11,265 个稳定实体在操作资源预算内可以发射与差异发射；#1288 的 G2 Routing
  证据入口改用 `LF-COMP-P100` 后恢复可运行，§7.1 是否重新取证由维护者裁定。
- 发射阶段首次纳入操作资源预算。若某个既有官方 fixture（固定测试环境）的发射峰值超出
  预算，资格验证在 CI 中失败；须先排除重复计费、未归还预留与不必要的存续延长，再记录
  真实峰值并显式调整操作资源预算、说明依据。
- 资源账本分三步合入（见[资源账本 §9][resource-ledger-order]）；规范路网容量按以下顺序
  落地，均在 #1296 内以有依赖关系的 PR 推进：建立规范统计定义、共同容量类型与两侧统计
  实现，两侧统计在现有真实产物上一致；按新口径给出经批准的 `CanonicalRelationCount` 初始
  值；生产端在编译成功前执行规范路网容量；消费端的外部 LFCA、差异 base、LFSM 与 LFSD
  改用各自的政策与结构计划；分离来源处理限额、规范路网容量、格式边界与操作资源预算的
  错误；完成资格验证矩阵并按需再校准，删除旧路径。
- 编译诊断不再出现 `max_stage_scratch_bytes`、`max_output_bytes`、
  `max_portable_object_bytes` 与 `max_portable_bundle_bytes`；对应量出现在账本报告中。
- 授予超出计划由资源限额诊断改为编译器内部缺陷，调用方不能通过调整配置档绕过。

## 被拒绝的替代方案

### 推导字节维度作为限额（初版）

见背景第 4 条。由容量模型必然推出的内部字节上界不表达独立的宿主资源意愿；本设计取消
其公开限额身份，避免维护冗余维度。必要的不变量检查（计划峰值、账本一致性与具体对象的
受检尺寸计算）保留在实现和测试中。初版要解决的“常量与记账脱节”由账本的计划准入与
按计划授予解决。

### 外部制品按来源侧维度准入（第一次修订）

见背景“第一次修订的制品容量在实现前不成立”。按维度名称把制品统计映射到来源维度，会
拒绝本配置档自己编译出的合法制品；只保留恰好可证明的几个映射，又让外部消费者继续依赖
来源处理模型，新增派生关系或调整字符串布局时同类失配会再出现。

### 为制品结构统计的每个量设公开上限

会形成一套需要长期校准的物理容量配置，并把产品容量绑定到序列化布局：同一规范路网仅因
字符串去重、字段布局调整或增加辅助索引就可能变成“超出容量”。制品结构统计只作为计划
输入，物理对象边界由格式合同约束。

### 保留各阶段暂存常量作为第二道限额

暂存常量与操作资源预算重复约束同一份内存，且任何记账口径补全都会再次要求校准，正是
#1288 的成因。

### 有界计数类型追踪每个内部计数受哪个容量约束

只有推导上限需要它。去掉推导限额后，内部计数受来源处理限额约束由准入保证，操作资源
预算由账本按实际计数核对，类型层追踪不再有消费者。

### 以全局分配器计数代替账本

`GlobalAlloc::alloc` 在实际分配前收到 `Layout`，可以检查剩余额度并返回空指针，因此全局
分配器能在分配前拒绝。不采用它作为生产账本的理由是：它是进程级的，不天然携带编译调用、
阶段与资源归属，无法区分编译器受控分配与宿主分配；计划准入、所有权转移与可恢复的领域
诊断仍需额外机制；计数分配器与计时测量不能同进程运行的规则也使其不适合作为生产路径。
分配器层证据继续由 `stats_alloc`、`dhat` 在测量入口承担。

### 把 bundle 字节保留为操作资源预算维度

编译器拥有本次创建的临时 backing，也能累计自己写出的字节，技术上可以实施单次任务
磁盘限额；不这样做是产品边界选择：单次发射的磁盘总字节不定义为编译器资源预算，暂存
存储额度和并发任务治理由宿主负责。最终候选字节已由三对象结构与单对象接收预算界定为
不超过 `3M`；内存发射路径的对象字节由账本计入操作资源预算；现有 bundle 数值也没有
独立校准来源。

### 原地调大 v1 的暂存常量，或新档只把暂存常量调大

`limits.rs` 规定配置档语义不可原地改变；新档的手写常量仍与记账无关，同类失配会再出现。

### 把发射期 StableId 排列持久化进 LFCA

运行时借用违反 ADR 0025 构建完成后不借用 LFCA 的决定；运行时复制需要提升 LFCA 版本，
只省去运行时身份索引排序与差异 base 的索引构建，仅在[共享静态路网身份索引][shared-identity]
改造实测后仍证明排序成本构成阻断时另行立项。
