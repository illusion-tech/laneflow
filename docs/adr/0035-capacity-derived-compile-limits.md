# 0035 编译资源上限按容量推导与配置档自洽检查

**状态**: Proposed（#1296 G1，待维护者接受）<br>
**日期**: 2026-11-16<br>
**适用范围**: `laneflow-compiler` 的 `CompileLimits` 配置档定义方式、字节维度来源、阶段暂存
维度划分与配置档自洽检查；不改变任何可移植制品字节、格式版本或 `NetworkRevisionId`<br>
**设计入口**: [#1296][issue-1296]、[#1288][issue-1288]<br>
**关联决策**: [ADR 0024][adr-0024]、[ADR 0025][adr-0025]

本文决定：编译资源上限配置档只声明容量与宿主预算；编译器私有结构的字节上限一律由
与实际记账相同的成本公式推导；配置档自洽检查阻止二者再次失配。维度、阶段划分与检查
口径见[编译器基础 §5.3][compiler-limits]。

## 背景

`CompileLimits` 现有三个具名配置档：`LF-COMP-P100-INITIAL-v1`、逐项继承 v1 的
`LF-COMP-P100-INITIAL-v2` 与 `LF-COMP-SINGLE-NETWORK-1M-v2`。每个维度都是手写常量：
计数维度来自 #308 压力分层或百万档证据，字节维度（暂存、输出、存续）同样按当时实现的
实测或估算写定。

#1288 发现这种定义方式会自相矛盾：

1. P100 v1 允许 `max_stable_entity_count = 11265`，但发射期 `ArtifactIndex` 对每个身份行
   计入 76 B 暂存（72 B 实体条目 + 4 B StableId 排列），与编译管线共用
   `max_stage_scratch_bytes = 304896`。实测 4,011 个稳定实体可以发射，4,012 个失败。
   v2 逐项继承 v1，同样受限。
2. 失配来源是 `a6d73e5d`（#563）的记账口径补全：发射期索引从未计量的 `BTreeMap` 改为
   计入共用暂存计量器的 `Vec`。实际内存更少，但新计入的占用落进了按 HIR 阶段校准的
   维度，常量没有随之重新校准，也没有任何检查发现这一点。
3. 差异发射对 base 与 target 各建一个 `ArtifactIndex`，计入同一计量器，可发射规模约再
   减半（代码推断）；差异路径另有按 `(EntityKind, StableId128)` 建立的有序映射与几何
   字节副本，没有计入任何维度。

根因不是某个常量偏小，而是“计数维度”与“由计数决定的字节占用”被分别手写：记账代码
改了，常量不会跟着改；常量改了，也没有检查证明它覆盖了计数维度允许的输入。

## 决策

### 1. 配置档只声明两类量

每个具名配置档只声明：

- **容量维度**：编译单元允许的输入与中间记录规模，如模块数、来源文档数、来源字节、
  声明数、稳定实体数、各阶段记录数、引用、关系、字符串项与字符串字节、几何点、
  诊断数。
- **宿主预算维度**：宿主为一次编译提供的资源，即编译器控制总存续字节与一次编译后
  允许保留的容量字节。

配置档不再声明编译器私有结构的字节上限。

### 2. 字节维度由成本公式推导

阶段暂存、输出与可移植对象字节等描述编译器自身结构的维度，统称**推导字节维度**。
每个推导字节维度的上限，等于把配置档全部容量维度的上限代入该维度成本公式所得的值。

成本公式与运行期记账共用同一份定义：记账点按实际计数调用公式求出本次申请的字节，
配置档构造时按容量上限调用同一公式求出上限。公式对每个容量输入单调不减，全部乘加
使用受检算术。不存在独立维护的字节常量，记账口径变化会同时改变上限。

推导规则成立的前提是：决定分配规模的每一份输入都先经过容量约束。编译单元来源由编译
资源上限的受检边界约束；不来自本次编译的可移植字节（差异 base，以及公开检查入口接收的
LFCA、LFSM、LFSD）另按**制品容量**准入：只统计可从受检制品直接取得的实体、关系、几何、
策略成员、字符串与变化行规模，在建立索引或按行数分配之前完成，错误标明输入一侧与容量
维度。差异 base 须满足本次发射所选配置档的制品容量，差异成本按 base 与 target 两侧各取
配置档容量推导。

对已通过容量准入的输入，若记账仍超出由同一容量模型推导的上限，属于编译器记账或成本
模型缺陷；诊断仍按该推导维度报告，便于定位。正常输入的拒绝来自容量维度、制品容量与
宿主预算维度。

### 3. 暂存按阶段拆分

现有单一 `StageScratchBytes` 拆为三个推导字节维度：编译管线暂存
`PipelineScratchBytes`（来源准入到 LIR 冻结）、单制品发射暂存 `EmissionScratchBytes`
（LFCA/LFSM 发射与发射期自校验）、差异发射暂存 `DiffEmissionScratchBytes`（LFSD 的
base 与 target 索引、配对、几何比较与差异策略检查）。各维度取本阶段内互斥编译遍的
峰值，阶段之间不再共用一个按某一阶段校准的上限。

发射与差异发射与 HIR 构建计划相同：开工前按实际计数计算本次预算，超限在分配前拒绝。
差异发射的成本公式覆盖最大变化量（before/after 载荷与各变化表在组装前同时存续），不只
覆盖零变化；差异路径现有未计量的有序映射与几何副本必须纳入差异发射暂存。

LIR 实体规范顺序按 Identity v1 原像排序，不是 StableId 字节序，本设计不改变它。发射器
需要的目标 StableId 排列由发射上下文建立一次，供目标关系投影自校验与 LFSD 构建共用；
`check_portable_policy_diff` 仍从最终字节独立建立检查视图，ADR 0024 的后发射 bundle 检查
合同不变。

### 4. 配置档自洽检查

每个具名配置档必须通过：

1. **推导闭合**：全部推导字节维度可由容量上限无溢出地求出；可移植对象与 bundle 发射
   上界不超出线格式可表示范围与原语硬上限，且目标平台可表示。`FormatLimits` 是调用方
   接收预算，不是这里的比较对象。
2. **可成功规模维度**：对除诊断数外的每个容量维度构造一份在该维度取可达上限、其余
   维度取构造所需最小值的输入，完整执行编译、单制品发射与 genesis、以自身为 base、
   两侧 StableId 不相交、身份保持而内容大量修改、关系重连等差异场景，全部维度（含宿主
   预算）都必须通过。无法单独逼近上限的维度须说明由哪个维度连带约束。
3. **诊断保留维度**：成功编译输出不含错误诊断，诊断数只在失败路径验收：恰好 16 条、
   至少 17 条并设置截断、较小规范键替换已保留项，且不返回成功输出或部分发射候选。

base 超出制品容量时须在建立索引前拒绝。超过宿主预算的组合在分配前按宿主预算维度拒绝，
不得被归因为推导维度缺陷。P100 配置档的上述检查在常规 CI 中运行，不得只放在 `#[ignore]`
测试中；百万档在常规 CI 中执行推导闭合，可成功规模维度由其端到端证据入口承担。

### 5. 新配置档取代既有三档，1.0 前不并存

| 新配置档标识符              | 构造器                               | 容量与宿主预算来源                         |
| --------------------------- | ------------------------------------ | ------------------------------------------ |
| `LF-COMP-P100`              | `CompileLimits::p100()`              | 继承 `LF-COMP-P100-INITIAL-v2` 的对应维度  |
| `LF-COMP-SINGLE-NETWORK-1M` | `CompileLimits::single_network_1m()` | 继承 `LF-COMP-SINGLE-NETWORK-1M-v2` 的对应维度 |

按 [1.0 前开发原则][pre-1-0]，标识符与构造器不带世代后缀；被取代的三个配置档及其构造器
随实现删除，不保留别名。现有调用方（`laneflow-scenario`、走廊与路口生成器、城市与
LF-SYNTH 生成器、LuST converter、`laneflow-bevy` 示例与测试、编译器与运行时测试、fuzz
目标）一并迁移。

配置档标识符只出现在编译诊断与生成器、测量入口的工作负载清单文本中，不进入 LFCA、
LFSM、LFSD 或 `NetworkRevisionId`；退役旧配置档不改变任何制品字节。推导值随编译器成本
公式变化，复现某次测量所用的精确上限以该测量绑定的提交为准，不以标识符为准。

## 后果

- 同类失配从结构上消除：记账口径补全会同时提高推导上限；若补全使单维最大输入超出
  宿主预算，自洽检查在 CI 中失败，须显式调整容量或宿主预算。
- P100 档声明的 11,265 个稳定实体真正可以发射与差异发射。#1288 的 G2 Routing 证据
  入口改用 `LF-COMP-P100` 后恢复可运行；§7.1 是否重新取证由维护者裁定。
- 推导字节维度不再是可调参数。需要更大或更小的资源边界时，只能调整容量维度或宿主
  预算维度，并重新通过自洽检查。
- 编译诊断中的 `max_stage_scratch_bytes` 由三个阶段维度取代，诊断字段名随实现更新。
- 以更大的既有制品为差异 base 时，调用方须选择容量覆盖该 base 的配置档；公开检查入口
  对调用方字节先做制品容量准入，再建立索引。

## 被拒绝的替代方案

### 原地调大 v1 的暂存常量

`limits.rs` 规定配置档语义不可原地改变；即便新建配置档，下一次记账口径补全仍会再次
失配。

### 新配置档只把暂存常量调大

仍是与记账公式无关的手写常量，不能证明覆盖计数维度允许的输入，同类不一致会再出现。

### 把发射期 StableId 排列持久化进 LFCA，运行时借用

违反 ADR 0025 构建完成后不借用 LFCA 的决定；推翻它的代价远大于每实体 4 B 的收益。

### 把发射期 StableId 排列持久化进 LFCA，运行时复制

可行，但需要提升 LFCA 版本，只省去运行时身份索引排序与差异 base 的索引构建。仅在
[共享静态路网身份索引][shared-identity]改造实测后仍证明排序成本构成阻断时另行立项。
