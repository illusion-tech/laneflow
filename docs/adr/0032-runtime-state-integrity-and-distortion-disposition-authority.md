# 0032 运行时状态完整性校验与失真处置权威

**状态**: Accepted<br>
**日期**: 2026-10-16<br>
**最后更新**: 2026-10-25<br>
**适用范围**: 运行时状态失真的检测权、停用语义与恢复处置权威边界<br>
**设计入口**: [#955](https://github.com/illusion-tech/laneflow/issues/955)<br>
**关联决策**: [ADR 0021](0021-traffic-infrastructure-and-host-boundary.md)、
[ADR 0030](0030-single-world-parallel-execution.md)<br>
**关联设计**: [运行时状态完整性校验与失真恢复](../design/traffic-runtime-state-integrity.md)、
[运行时快照 §6](../design/traffic-runtime-snapshot.md)

本文冻结运行时状态完整性失真的处置权威与 Runtime 内检测范围。详细机制（前像、共享路网修订认证、
漏检面、遥测、认证成本口径）见关联设计；本文只回答“为什么这样定”。

## 背景

#794 归因调查确认：普通机器（无系统级 ECC）在内存压力下存在页级内存失真，其指纹
为 4 KiB 页边界分歧、整页替换、页整数倍位移与零页，且对普通 `fs::read` 与映射读回
同样可见。环境失真不可由软件根除；LaneFlow 代码清白不等于运行时状态可信。

现行合同（`traffic-runtime-snapshot.md` §6）规定失同步只诊断、不自动纠偏、处置归
宿主；输入命令序列与检查点由宿主记录（ADR 0021）；确定性状态摘要前像为 #302 冻结的
SHA-256（ADR 0033 / #1035 G1 起更换为 BLAKE3-256，本决策不依赖具体算法）；共享路网修订
不在 C(T) 内（ADR 0030）。确定性是重演的必要条件，但不自动提供
正确性判据：它保证相同输入得到相同输出，不保证内存里的状态仍是曾经提交过的状态。
失真一旦进入运行时状态，需要的是正确性判据与唯一处置权威，而不是又一套回放链。

## 决策

1. **一条权威政策，两个阶段**：阶段一，检测发现失配或检测过程不可信，失真对象即
   **停止使用**——不自动纠偏、回滚、重演或重启；阶段二，**处置归宿主**——宿主按
   检查点 + 输入命令序列恢复与重放，用检查点三元组定位首个分歧区间。停用由宿主执行；
   Runtime 只交付检测结论、判因与失配位置，不持有失效状态、不自行失败关闭。
2. **检测与处置分权**：检测能力在 Runtime 侧（修订认证）与宿主侧（审计重放），
   停用与处置权在宿主（恢复面）。这与
   ADR 0021 的宿主边界、snapshot §6 的处置归属一致，不新增隐藏输入权威，不要求
   Runtime 持有命令日志或存档清单。
3. **停用与失同步只诊断不冲突**：失同步的状态仍是合法确定性状态，故只诊断不停用；
   完整性失配的对象可信度已被破坏，故先停用再处置。两者处置权同属宿主，区别只在是否
   停用，权威不双轨。
4. **已发布结果不撤销**：停用不回退已发布事件 / 观测 / 宿主副作用。事件去重、
   副作用回退与句柄重绑属于宿主回放链；Runtime 不隐藏、不重发、不去重。
5. **共享路网修订独立失败语义**：共享路网修订不在 C(T) 内，不属回滚 / 重演可修复面；认证
   失败的修订不投入使用，在用修订审计判定修订失配（判因非「来源」）时宿主停止该修订的全部
   消费者（所有世界与 Spatial）——判因「来源」只说明审计输入损坏，不停用修订——停止 = 不再发起新调用，在途同步调用正常返回，其后返回的结果按已发布结果
   由宿主处置（关联设计 §3 宿主侧停止边界）；处置只能是在途调用与宿主任务结束后的修订
   重建与重新恢复 / 绑定；共享路网修订本身保持不可变、无原子，遥测
   单列判因类别。
6. **无可信基准不作宣称**：期望值无法独立建立或核验（取自被认证对象自身、失配复算
   后修订侧证据不可复现或复算未完成、来源侧失配后复算转为修订侧失配、修订比较阶段 panic；
   归类见关联设计 §2.2）时，判因为「无法判因」，不得宣称
   检测或恢复成功。
7. **Runtime 侧检测范围分期**：本期 Runtime 侧只提供**修订认证**——在修订投入使用
   之前（安装、恢复、Spatial 绑定、切换）与宿主显式审计时，验证宿主提供的来源并按来源重建候选修订
   与当前修订比对（耐久前像复用 `NetworkRevisionIdV1`；具体规则以关联设计 §4.2 为准）；
   完整性不进入 tick 路径。C(T) 与每拍
   重写的热状态由宿主检查点对拍与审计重放覆盖，Runtime 不登记检查点锚、命令摘要、
   逐记录期望值或输出批次期望值。运行中检测（共享路网修订轮转校验与热状态保护）须以
   Runtime 堆失真的观测证据为前提，另开 G1。

## 取舍

- **为什么不自动回滚 / 内重演**：自动改变状态的方案必须先回答已发布事件 / 观测 /
  宿主副作用怎么办、句柄映射怎么迁移、修订切换怎么交互、事件如何去重、执行主体与
  宿主怎么协调；不能安全处理已发布结果时只能停止或交宿主——那等于把复杂度收下后
  又退回宿主处置，却多出一条并行权威。1.0 前只留一套权威，不为弯路堆双轨。
- **为什么不只停用不给处置**：检出了但没人处置会留下悬空态——对象停了，宿主却没有
  合同化的恢复入口。停用与宿主处置合成一条政策的两个阶段，恢复入口就是现行检查点 +
  重放设施。
- **为什么修订认证放 Runtime 侧**：共享路网修订被全部世界同时消费，且不可由回滚 / 重演
  修复；宿主对拍只能在状态已经错了之后显形，也分不清失真与确定性缺陷。认证复用已
  冻结的 `NetworkRevisionIdV1` 前像，在修订投入使用之前给出对象级结论，成本只发生在
  安装、恢复、切换与审计时。
- **为什么停用由宿主执行、本期不做运行中轮转**：坏修订唯一的处置是宿主重建，Runtime
  自行失败关闭不改变处置路径，却要求每个消费者携带可核对的失效状态（绑定聚合、核对
  点、发布线性化、快照门控）；运行中轮转则要求校验器自身的基线、游标、缓冲与模式
  状态都受同一故障模型保护，并逐项列举每一条读修订路径。这两类列举没有封闭边界：
  每新增一份校验状态，就产生下一份待保护状态，每新增一条读修订路径，就多一个核对点
  或漏检项；而运行中 Runtime 堆失真尚无观测证据。
- **为什么热状态不在 Runtime 内检测**：热记录每拍读后重写，失真在被轮转校验轮到之前
  就会被下一拍推导进合法状态，单次事件检出概率约为轮转周期的倒数，秒级检测界只是
  名义值；逐记录与写集增量期望值是每拍成本，按现行规范化实测（十万记录约 31–35 ms）
  推算远超 5% 预算；现行 P7 为原地写，热表元素含枚举与 padding，失真可能在检出前就
  触发未定义行为。#794 的已归因证据全部来自文件写出 / 读回路径，已通过 #954 实施写后读回校验，
  Runtime 堆失真尚无观测证据。宿主审计重放可在独立世界或另一台机器上覆盖 C(T) 中改变摘要等价类的失真
  （同一等价类内的归属置换须宿主比对身份映射）；
  换机器重放是判因证据，需与独立认证的输入、重复重放共同支持才下判因。
- **代价**：tick 路径与稳态保留内存不增加；新增负担只是安装、恢复、切换与审计时的
  认证停顿与认证峰值。代价落在检测能力上：修订投入使用之后的运行中失真要到下一次
  宿主审计或重新认证才能检出，Runtime 不承诺检测滞后上界；热状态的检测滞后由宿主
  检查点策略决定。

## 未采用的方向

- 磁盘检查点自动回滚（(c)）与 Runtime 内重演（(d)）：见取舍；若未来采用，必须单开
  G1 与 ADR 改写并承担全套合同修订义务（已发布结果处置、句柄映射、修订切换、事件
  去重、执行主体协调），不能安全处理已发布结果时停止或交宿主。
- 把完整性期望值写入快照或摘要前像：会把诊断面变成交通状态，污染 #302 摘要与
  LFRS 版本轴。
- 每 tick 全量校验：超出韧性预算，且把校验推进提交关键路径。
- 热状态的 Runtime 内逐写保护（逐记录保留期望值、写集增量物理期望值、输出批次放行
  门）：检测界对每拍重写的对象不成立、每拍成本超预算、查询入口可绕过放行，见取舍；
  二期入口条件见关联设计 §9。
- 共享路网修订运行中轮转校验与 Runtime 内修订级失效传播（入口预检、物理布局基线、完整性
  租约与绑定聚合）：见取舍；二期入口条件见关联设计 §9。
- 以「多数副本正确」或容差判定代替停用：失真不可信时不设裁决多数。
- 另设独立的修订内容规范编码与旁车文件：与 LFCA 规范语义载荷平行，构成第二套规范
  编码；耐久修订内容前像复用 `NetworkRevisionIdV1`。
- 从当前修订反向编码语义载荷：修订不保留规范身份前像（`shared-static-network.md`
  §5.1），认证只按来源重建候选修订比对。
- Runtime 侧检查点锚与命令摘要登记：与宿主持久副本分歧时只能判「无法判因」，不比
  宿主自行核对持久副本多出判据。

## 验收与实施边界

实施按关联设计 §10 切片拆分（A 修订认证 → C 宿主审计支持的重放 harness → E 故障
注入验收与浸泡取证；C 的摘要路径可先交付）；全部实现以 #955 设计为前置，仅实际复用 #954 交付能力的切片依赖
#954 的交付能力。验收口径是故障注入 / 故障机实测（#794 归档口径），不以干净机器全绿为产品
保证。本 ADR 接受不等于实现完成；实测若推翻认证成本口径或前像选型，返回 G1 改写
关联设计并同步本 ADR 取舍记录。
