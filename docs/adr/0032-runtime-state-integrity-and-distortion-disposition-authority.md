# 0032 运行时状态完整性校验与失真处置权威

**状态**: Accepted<br>
**日期**: 2026-10-16<br>
**最后更新**: 2026-10-16<br>
**适用范围**: 运行时状态失真的检测权、失败关闭语义与恢复处置权威边界<br>
**设计入口**: [#955](https://github.com/illusion-tech/laneflow/issues/955)<br>
**关联决策**: [ADR 0021](0021-traffic-infrastructure-and-host-boundary.md)、

本文冻结运行时状态完整性失真的处置权威。详细机制（前像、登记表、校验间隔、遥测、
性能协议）见关联设计；本文只回答“为什么这样定”。

## 背景

#794 归因收口确认：普通机器（无系统级 ECC）在内存压力下存在页级内存失真，其指纹
为 4 KiB 页边界分歧、整页替换、页整数倍位移与零页，且对普通 `fs::read` 与映射读回
同样可见。环境失真不可由软件根除；LaneFlow 代码清白不等于运行时状态可信。

现行合同（`traffic-runtime-snapshot.md` §6）规定失同步只诊断、不自动纠偏、处置归
宿主；输入命令序列与检查点由宿主记录（ADR 0021）；确定性状态摘要前像为 #302 冻结的
SHA-256；共享静态根不在 C(T) 内（ADR 0030）。确定性是重演的必要条件，但不自动提供
正确性判据：它保证相同输入得到相同输出，不保证内存里的状态仍是曾经提交过的状态。
失真一旦进入运行时状态，需要的是正确性判据与唯一处置权威，而不是又一套回放链。

## 决策

1. **一条权威政策，两个阶段**：阶段一，校验发现失配或校验过程不可信即**失败关闭**
   ——世界停止推进，不自动纠偏、回滚、重演或重启；阶段二，**处置归宿主**——宿主按
   检查点 + 输入命令序列恢复与重放，用检查点三元组定位首个分歧区间。Runtime 只交付
   检测结论、判因与失真指纹。
2. **检测与处置分权**：检测权在 Runtime（校验面），处置权在宿主（恢复面）。这与
   ADR 0021 的宿主边界、snapshot §6 的处置归属一致，不新增隐藏输入权威，不要求
   Runtime 持有命令日志或存档清单。
3. **失败关闭与失同步只诊断不冲突**：失同步的状态仍是合法确定性状态，故只诊断不停
   机；完整性失配的状态可信度已被破坏，故先停机再交宿主。两者处置权同属宿主，区别
   只在是否停机，权威不双轨。
4. **已发布结果不撤销**：失败关闭不回退已发布事件 / 观测 / 宿主副作用。事件去重、
   副作用回退与句柄重绑属于宿主回放链；Runtime 不隐藏、不重发、不去重。
5. **共享静态根独立失败语义**：共享根不在 C(T) 内，不属回滚 / 重演可修复面；共享根
   失配触发**根级失效（poison）**并传播给全部绑定消费者（所有世界与 Spatial），不止
   检测方；失效标记由共享根完整性租约承载（共享根本体保持不可变、无原子）；处置
   只能是根重建后所有消费者重新恢复 / 重绑，遥测单列判因类别。
6. **无可信基准不作宣称**：期望值无法建立或独立核验（登记表三层互证分歧、页隔离
   不成立、检查点锚 / 命令游标分歧）时，判因为「无法判因」，不得宣称检测或恢复成功。

## 取舍

- **为什么不自动回滚 / 内重演**：自动改变状态的方案必须先回答已发布事件 / 观测 /
  宿主副作用怎么办、句柄映射怎么迁移、修订切换怎么交互、事件如何去重、执行主体与
  宿主怎么协调；不能安全处理已发布结果时只能停止或交宿主——那等于把复杂度收下后
  又退回宿主处置，却多出一条并行权威。1.0 前只留一套权威，不为弯路堆双轨。
- **为什么不只失败关闭不给处置**：检出了但没人处置会留下悬空态——世界停了，宿主却
  没有合同化的恢复入口。失败关闭与宿主处置合成一条政策的两个阶段，恢复入口就是现行
  检查点 + 重放设施。
- **为什么检测放 Runtime 而不是纯宿主对拍**：宿主对拍只能在状态已经错了之后显形，
  且把失真与确定性缺陷混在同一信号里；Runtime 内检测提供更短的检测滞后、对象级判因
  与失真指纹，使宿主处置有可信输入。
- **代价**：校验摊销成本与稳态保留内存（登记表、页映射）是新增负担，按单列预算
  控制（校验摊销比例 ≤ Core p95 主行的 5% 为合同值、分规模绝对值待验证）；检测滞后
  有显式上限但不为零。

## 未采用的方向

- 磁盘检查点自动回滚（(c)）与 Runtime 内重演（(d)）：见取舍；若未来采用，必须单开
  G1 与 ADR 改写并承担全套合同修订义务（已发布结果处置、句柄映射、修订切换、事件
  去重、执行主体协调），不能安全处理已发布结果时停止或交宿主。
- 把完整性期望值写入快照或摘要前像：会把诊断面变成交通状态，污染 #302 摘要与
  LFRS 版本轴。
- 每 tick 全量校验：超出韧性预算，且把校验推进提交关键路径。
- 以「多数副本正确」或容差判定代替失败关闭：失真不可信时不设裁决多数。

## 验收与实施边界

实施按关联设计 §9 切片拆分（A 登记表 → B 物理层 / C 逻辑层 → D 失败语义与账本 →
E 故障注入验收）；全部实现 blocked-by #955，仅实际复用 #954 交付能力的切片依赖
#954。验收口径是故障注入 / 故障机实测（#794 归档口径），不以干净机器全绿为产品
保证。本 ADR 接受不等于实现完成；实测若推翻性能预算或前像 / 哈希选型，返回 G1 改写
关联设计并同步本 ADR 取舍记录。
