# 0030 单世界精确并行与执行配置分离

**状态**: Accepted<br>
**日期**: 2026-09-16<br>
**最后更新**: 2026-09-17<br>
**适用范围**: `TrafficWorld` 首版独立计算并行、执行配置、快照与修订切换边界<br>
**设计入口**: [#220](https://github.com/illusion-tech/laneflow/issues/220)<br>
**关联设计**: [并行执行](../design/traffic-runtime-parallel-execution.md)、
[执行配置与资源](../design/traffic-runtime-execution-config.md)、
[串行阶段协议](../design/traffic-runtime-phase-protocol.md)

本文具体化 [ADR 0003](0003-runtime-tick-and-determinism.md) 的同环境确定性合同与
[ADR 0021](0021-traffic-infrastructure-and-host-boundary.md) 的单世界并行边界。首版
并行化独立计算，P4 联合资源裁决保持规范串行。当前配置 API 已拆分、快照采用
LFRS 6，生产支持 worker 1–16（#705 开放，P2 预览真实多 worker 分发，P3/P5
仍串行待 #706）；接受本设计不表示城市性能认证已完成（#707）。

## 背景

同一交通世界的跟车、Waiting、Conflict 和下游存储存在跨块依赖。按车辆或地理分块
不足以证明资源裁决可交换；不同资源的候选仍可能共享全局容量、授权序号和错误
顺序。组件准备、映射和归约本身也有成本，不能仅凭组件数承诺加速。

串行 P0～P8 已区分拍初读取、候选暂存、完整校验与一次提交。独立计算可复用这套
合同，而不同时改写联合资源裁决。worker 属于执行要求，四类容量与固定步长属于
交通配置；逻辑摘要已经排除 worker，配置分离不意味着曾有摘要确定性缺陷。

## 决策

### 1. 一个逻辑世界、一套交通权威

保留唯一公开 `TrafficWorld` 和同步 `step(&mut self, ...)`。任务读取同一 C(T)，
再消费已冻结派生输入及裁决；分块不改变 Handle/代次、业务次序、资源权威或宿主
绑定，跨块不增加一拍延迟，不新增可独立步进的公开子世界。

相同根、交通配置、初态、输入和运行环境下，合法 worker 数、分块和完成置换必须
产生相同状态、决策、事件、公开逻辑首错与 retry/fresh replay。保持单车表达式和
数值顺序；不通过执行配置引入多频率、近似、聚合或跨平台位级承诺。

### 2. 首版并行独立计算，P4 保持规范串行

P2 运动/前视预览、P3 已冻结只读输入上的候选字段、P5 最终逐车运动可以按独占
输出范围分发。协调器保留共享索引/前沿构造、候选规范组装、P4、资源转移、事件
归并、P6 准备及 P7 发布。阶段名称不是并发许可，具体函数须证明输入完整且无共享
写入，错误和值都由协调器在原逻辑位置消费。

P4 沿用现行 Waiting 链调度、完整候选键、条件拒绝、资源束、全局容量及 grant 序号。
首版不构建组件图、不拆资源表、不绑定组件临时序号。P4 组件并行后续单独设计，
不作为首版 G1 或实施完成的前置，也不因此放弃确定性和整步性能目标。

### 3. 交通配置、执行资源和计划分开

`WorldConfig` 只保留四项语义容量与固定步长；新增 `ExecutionConfig`，安装和 fresh
restore 显式接收。非零 worker 数包含调用线程，1 使用不创建辅助线程的融合路径。
活动世界独占资源；候选只有私有交通状态、目标计划与工作区。切换继承执行配置与
资源，目标计划在换根前准备并同界晋升，失败不发布半个世界。

worker/分块不进入共享静态路网、快照、交通身份和摘要，延续
[ADR 0025](0025-checked-canonical-network-and-shared-static-network.md) 的分层。
首版计划保存根绑定、独立任务范围与缓冲需求，不提前维护后续资源组件布局。

### 4. 首错、join 和提交保持精确

逻辑检查地址来自实际串行路径和规范位置，不按阶段、错误枚举或完成顺序取最小。
worker 的计算结果不跳过协调器穿插执行的必要 reserve、编码和共享检查。完成前沿
证明更早义务已解析后才可确定首错。

首版完整 join 已分发任务，仅停止逻辑上更晚且不再被更早义务需要的分发；更早缺失
计算仍须补齐，不依赖任务内提前取消。借用归还后再清理暂存与 grant、恢复失败
attempt 序号基线。尝试世代防止同 tick 重试
消费旧回报。panic 的 join、失效与 drop 边界见详细设计，不冒充可重试 StepError。

仅为并行增加的可选 scratch 准备失败可使用同原语融合求值；领域真实 reserve 仍在
原逻辑位置失败，安装/恢复/切换的必需执行准备有独立错误。P6 完成 CommitPlan，
P7 统一发布且不再有可恢复错误或必要增长，P8 交付既有结果。

### 5. 容器格式单独升级

删除 LFRS worker 字段，容器采用 6；Runtime 状态 5、摘要 7 保持，因为交通
状态和摘要前像不变。静态契约、切换描述符、观测/Routing 身份版本不变。完整恢复
交通校验后才校验并初始化执行资源；该执行错误位置是明确的新 API 合同。

1.0 前仅保留一套当前 schema、签名和错误，不增加旧格式转换或兼容别名。捎带改变
交通状态、摘要规则或其他持久化字段必须重新判断版本轴。

## 取舍

世界独占资源使寿命、join 和 drop 归属明确，多世界分别支付资源。共享执行器需要
另定重入、饥饿、借用与全局预算，暂不纳入公共 API。

P4 串行限制潜在加速，但减少首版每拍图准备、跨组件资源与首错协调成本。实际整步
收益取决于独立计算占比和任务粒度；没有保证仅这些阶段就能达到产品预算。保留
四基线与一万/十万完整窗口验收，失败须报告或优化，不能静默降低目标。

完整 join 简化取消证明，但领域错误后可能多做计算，必须测量该开销。单 worker、
小工作集和可选准备失败的融合求值共享同一领域原语，不保留两套交通求解器。
私有执行资源采用每世界独占的 Rayon `rayon-core` 线程池，作用域借用归还与 OS
线程退出分别结算。LaneFlow 自有计划、缓冲和登记表采用 checked reserve；后端
内部调度分配遵循进程级 OOM 语义，边界见[执行配置与资源 §3](../design/traffic-runtime-execution-config.md#3-私有所有权)。
任务粒度仍按真实独立计算与整步测量选择。

## 未采用的方向

- 多个公开世界拼接城市、固定宽度 halo 或各块独立 projection。
- 按线程完成次序授权/返回错误，或提前发布局部结果。
- 每 worker 克隆全世界/全资源表，或将候选准备成第二个活动线程池。
- 把 P4 组件研究直接转为首版每拍必经架构，未经完整组合及收益验证。
- 快照保存执行布局，或为未发布的旧 worker API 保留兼容层。

## 验收与实施边界

实施依据包括独立段与规范消费者、身份/借用/容量、首错与完整 join、资源和计划
寿命、公开 API/版本选择，以及具体成本模型和实验矩阵。此前 P4 有界证据可供后续
设计复核，但首版不声称跨组件联合算法已闭合。

实施另立工作项：配置/快照、资源/共同状态准备、独立计算分发和规范消费、整步等价
及城市性能验收。1/2/4/8/16 worker 的状态、事件、首错、失败重试及真实并发验证
继续适用。G1 接受不等于实现完成，部分阶段或配置拆分通过也不等于首版整体通过。
测量与进度留在 GitHub，不把单次探针写成长期能力事实。
