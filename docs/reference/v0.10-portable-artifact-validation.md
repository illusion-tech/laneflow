## 1. 当前事实与禁止误读

- `laneflow-compiler::CompilationOutput` 已原子拥有配对的
  `ValidatedCanonicalLir` 和 `ValidatedSourceMapInput`；
- 当前 workspace 没有 `laneflow-format`，也没有 LFCA/LFSM/LFSD/LFCP 生产实现；
- 当前 `CompilationMetrics::semantic_fingerprint` 只服务同版本重复编译和性能证据，
  不是 artifact digest 或 `NetworkRevisionId`；
- #292/#296 的成功 CI 证明前置编译器和 production source 已交付，不证明 #298 格式；
- 本计划中的“预期”“必须”不是已执行结果。G2 后只能把实际命令、提交、原始输出和
  digest 填入结果列，不能把计划文本改写成追认式通过。

## 4. 已知向量与独立复核

G1 不建设向量平台。设计正文直接保存两个 revision 的完整构造配方、逐节长度/摘要、
payload 长度/摘要、单 byte 差异 offset，以及四类对象的公共目录 offset 锚点；非作者
必须能用任意通用十六进制查看器和 SHA-256 工具人工复算。该复核不要求 JSON、JSON
Schema、xtask、代码生成器或仓库内第二套 emitter。

G2 才把设计冻结的语义输入 materialize 为固定 `expected.lfca/.lfsm/.lfsd` bytes；#299
receipt 格式冻结后再增加 `expected.lfcp`。每组 fixture 使用普通 Markdown README 记录
语义输入、版本、length、digest、revision 和关键 offset，不增加机器可写的
`expected.json`。测试只读固定 expected bytes，禁止先调用 production emitter 覆写期望
再与自身比较。更新 expected bytes 必须在 PR 中展示语义差异、版本决策和旧向量处置。

职责分离为：G1 规范作者给出可人工复核推导；G2 production emitter 与固定 bytes 比较；
#299 独立验证器不调用 emitter，独立重算结构、身份与 revision。没有第三个永久 oracle
角色，也不把一次性复核脚本升级为项目基础设施。

G1/G2 审阅逐结构核对 ASCII 图、图后 `where:`、offset/constraint 表、附录 A 与向量
offset。图是结构化可读视图，规范约束以 `where:`、表和附录 A 为准；任何不一致都是
设计缺陷。图中的 32-bit wire slot 不得误读为网络字节序，所有多字节整数继续使用小端序。

## 5. 跨平台与确定性执行矩阵

| 轴         | 最小集合                                                                     |
| ---------- | ---------------------------------------------------------------------------- |
| OS/target  | Windows `x86_64-pc-windows-msvc`；Ubuntu `x86_64-unknown-linux-gnu`          |
| process    | clean process；同进程重复；不同 hash seed/分配地址                           |
| workers    | single-thread；每个正式支持的 worker 数                                      |
| workload   | min headless；full spatial；P100 正式最高级；硬上限附近                      |
| comparison | artifact、source map、semantic diff exact bytes + digest + length + revision |

共享 CI 必须上传或核对同一已知摘要，不接受“各平台测试都绿但没有交叉比较 exact bytes”。
若某平台尚非 LaneFlow 正式支持目标，只能作为附加观察，不能用它替代 Windows 本机和当前
Ubuntu required CI 的双轴证据。

## 6. 性能与资源证据

G2 在 #292 的合法 P100 production workload 上至少记录：

- artifact/LFSM/LFSD 各自和总输出 exact bytes；
- emitter wall-clock、hash wall-clock 与 end-to-end compiler + emitter wall-clock；
- 暂存容量、compiler-controlled peak、失败后的 retained bytes；
- single-thread 与支持 worker 数的结果；
- min、正式五级最高级和代表性大输入；格式硬上限负向测试不兼任性能 workload；
- Windows 固定机原始轮次和共享 CI correctness/determinism。

格式硬上限已由设计正文作为安全天花板冻结，G2 benchmark 不得修改同一 wire version 的
常量。产品性能门槛沿用其所属性能议题和 P100 证据；#298 只报告增量成本，不为此复制一套
调研 harness，也不得把 #292 内部 LIR 的 `output_logical_bytes` 当作 LFCA 文件大小。
