### 3.3 长度、损坏、上限和原子性

| ID         | 输入/故障点                                                            | 预期                                                              |
| ---------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `SEC-001`  | 已知 transport 长度超过上限                                            | hash/read 前 O(1) 拒绝                                            |
| `SEC-002`  | 未知流超过上限                                                         | 只读取到 `max + 1` 后拒绝                                         |
| `SEC-003`  | count/stride/offset 算术溢出                                           | checked failure；不分配、不 panic                                 |
| `SEC-004`  | 每个 byte boundary 截断                                                | 稳定 truncated/length mismatch                                    |
| `SEC-005`  | 每个 section 单 bit 损坏                                               | descriptor digest 或语义验证失败                                  |
| `SEC-006`  | 调用方上限高于格式硬上限                                               | 配置失败；不得扩大 effective limit                                |
| `SEC-007`  | 合法对象高于调用方上限但低于格式上限                                   | hash/read 前按调用方上限失败；wire 版本不变                       |
| `SEC-008`  | Table `rowCount` 与完整 Row 数不符；`rowsByteLength` 自洽但多/少一行   | 建立 row slice 或按 count 分配前失败                              |
| `SEC-009`  | Row `fieldCount` 与完整 Field 数不符；`rowByteLength` 自洽但多/少一项  | 建立 field slice 或按 count 分配前失败                            |
| `SEC-010`  | Field VBL 与固定宽类型不符；vector 内 count 与 VBL 不符                | 解释 value 或按 count 分配前失败                                  |
| `SEC-011`  | 一层 RecordVector 合法；内嵌记录再次包含 RecordVector                  | 前者通过；后者在读取第二层 value 前失败                           |
| `SEC-012`  | 每个格式安全天花板取 `limit+1`，并记录该维度的 reachability            | 在值用于分配/hash/checked view 前拒绝；不要求不可达 limit 合法    |
| `SEC-013`  | object/section/table/row/field 的外层长度与内层累计长度不一致          | 无论整体是否未截断，均失败关闭                                    |
| `SEC-014`  | LFCA/LFSM/LFSD/LFCP 精确 section/table 数与每种 Row 的登记 field 形状  | 精确闭合形状接受；任一 `+1/-1` 或未知项失败关闭                   |
| `SEC-015`  | 每个资源维度的最大可构造合法 fixture；可达 hard limit 另取 exact limit | 最大合法值接受；下一可构造超限值拒绝                              |
| `ATOM-001` | artifact 暂存写失败                                                    | 无候选成功、无发布提交点                                          |
| `ATOM-002` | LFSM/LFSD 写、flush、close 失败                                        | 无可拆分 artifact 成功、无发布提交点                              |
| `ATOM-003` | immutable object 已存在且不同 bytes                                    | collision/mismatch；禁止覆盖                                      |
| `ATOM-004` | receipt/LFCP/manifest 提交失败                                         | 已写对象保持未引用，不形成部分发布                                |
| `ATOM-005` | 全部成功                                                               | 只有认证 manifest/指针单提交点后可称已发布                        |
| `ATOM-006` | staging 写到任一 byte 后进程崩溃，或 flush/close 前被终止              | 最终 digest key 不存在；重试不观察或继承部分文件                  |
| `ATOM-007` | 两个发布者并发安装同一 key 和相同 complete bytes                       | 恰有一个原子 winner；另一方只比较完成 winner 后安全复用           |
| `ATOM-008` | 两个发布者并发安装同一 key 但 bytes 不同                               | winner 保持不变；loser 在完成 winner 可见后稳定 mismatch          |
| `ATOM-009` | 平台 adapter 无法提供 atomic + no-replace 保证                         | `AtomicInstallUnsupported`；禁止退化为 final path 上流式复制      |
| `ATOM-010` | 安装完成后、目录持久化或 manifest 提交前崩溃                           | 恢复后 key 只可能是完整对象或不存在；任何未引用对象不算已发布     |
| `ATOM-011` | 任一候选/receipt object key 非规范或不绑定自身 digest                  | 只接受相应 digest 的 `sha256/<64 lowercase hex>`；manifest 前失败 |
| `ATOM-012` | receipt staging/write/flush/close/preflight/install/winner 任一点失败  | 不构造 LFCP、不提交 manifest；已安装候选对象保持未引用            |

## 4. 已知向量与独立复核

G1 不建设向量平台。设计正文直接保存两个 revision 的完整构造配方、逐节长度/摘要、
payload 长度/摘要、单 byte 差异 offset，以及四类对象的公共目录 offset 锚点；非作者
必须能用任意通用十六进制查看器和 SHA-256 工具人工复算。该复核不要求 JSON、JSON
Schema、xtask、代码生成器或仓库内第二套 emitter。

G2 才把设计冻结的语义输入 materialize 为固定 `expected.lfca/.lfsm/.lfsd` bytes；#299
receipt 格式冻结后再增加 `expected.lfcp`。每组 fixture 使用普通 Markdown README 记录
语义输入、版本、length、digest、revision 和关键 offset，不增加机器可写的
`expected.json`。测试只读固定 expected bytes，禁止先调用 production emitter 覆写期望
再与自身比较。更新 expected bytes 必须在 PR 中展示语义差异、版本决策和旧向量处置。

当前首组证据位于
[`LFCA-V1-FULL-SPATIAL` fixture](../../crates/laneflow-compiler/tests/fixtures/portable-v1/lfca-v1-full-spatial/README.md)：
同一次候选的 LFCA/LFSM/Genesis LFSD 已固定 length、SHA-256、revision、目录 offset 与跨对象
binding，测试仅以 `include_bytes!` 读取并比较。该证据关闭 production emitter 的完整空间
exact-byte 回归切片，不替代本节其余固定对象、跨平台矩阵或 #299 独立验证。

职责分离为：G1 规范作者给出可人工复核推导；G2 production emitter 与固定 bytes 比较；
#299 独立验证器不调用 emitter，独立重算结构、身份与 revision。没有第三个永久 oracle
角色，也不把一次性复核脚本升级为项目基础设施。

G1/G2 审阅逐结构核对 ASCII 图、图后 `where:`、offset/constraint 表、附录 A 与向量
offset。图是结构化可读视图，规范约束以 `where:`、表和附录 A 为准；任何不一致都是
设计缺陷。图中的 32-bit wire slot 不得误读为网络字节序，所有多字节整数继续使用小端序。

## 5. 跨平台与确定性执行矩阵

| 轴         | 最小集合                                                                     |
| ---------- | ---------------------------------------------------------------------------- |
| OS/target  | Windows `x86_64-pc-windows-msvc`；Ubuntu `x86_64-unknown-linux-gnu`          |
| process    | clean process；同进程重复；不同 hash seed/分配地址                           |
| workers    | single-thread；每个正式支持的 worker 数                                      |
| workload   | min headless；full spatial；P100 正式最高级；硬上限附近                      |
| comparison | artifact、source map、semantic diff exact bytes + digest + length + revision |

共享 CI 必须上传或核对同一已知摘要，不接受“各平台测试都绿但没有交叉比较 exact bytes”。
若某平台尚非 LaneFlow 正式支持目标，只能作为附加观察，不能用它替代 Windows 本机和当前
Ubuntu required CI 的双轴证据。

## 6. 性能与资源证据

G2 在 #292 的合法 P100 production workload 上至少记录：

- artifact/LFSM/LFSD 各自和总输出 exact bytes；
- emitter wall-clock、hash wall-clock 与 end-to-end compiler + emitter wall-clock；
- 暂存容量、compiler-controlled peak、失败后的 retained bytes；
- single-thread 与支持 worker 数的结果；
- min、正式五级最高级和代表性大输入；格式硬上限负向测试不兼任性能 workload；
- Windows 固定机原始轮次和共享 CI correctness/determinism。

格式硬上限已由设计正文作为安全天花板冻结，G2 benchmark 不得修改同一 wire version 的
常量。产品性能门槛沿用其所属性能议题和 P100 证据；#298 只报告增量成本，不为此复制一套
调研 harness，也不得把 #292 内部 LIR 的 `output_logical_bytes` 当作 LFCA 文件大小。
