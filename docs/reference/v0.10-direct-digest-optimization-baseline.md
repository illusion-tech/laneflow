# 直算摘要三版本优化对照

> **状态**：`LF-DIRECT-DIGEST-RUST1991-R1-v1` 已完成描述性实测，采用车辆连续缓冲版本。<br>
> **工具链**：三个版本均为 Rust 1.99.1，测量日期 2026-10-23。<br>
> **紧凑证据**：[`v0.10-direct-digest-optimization-baseline.json`](v0.10-direct-digest-optimization-baseline.json)。

本报告对应 #1008 / #960 的摘要构造优化。数值是单次宿主摘要调用的成本，不是仿真
`step` 的耗时，也不改变 tick 路径。SHA-256、digest 7、规范前像和公开 API 均不变。
Rust 1.98.0 的[历史基线](v0.10-attestation-production-baseline.md)保持冻结；本次仅在
同为 Rust 1.99.1 的三个实现之间比较，不能将跨工具链差异归因于实现优化。

第 1 项完成版包含前一轮查找优化，因此它相对原始版的差值不能单独归因于分组预留。
分组预留同时影响直算与捕获后的摘要构造；表中现行路径始终使用对应版本自身的实现。
连续缓冲先作为仅替换 `snapshot_digest.rs` 的本地候选编译，测量后将字节完全相同的
源码提交；JSON 保存三个源文件的 SHA-256 和每个执行二进制的 SHA-256。

工作负载沿用 `LF-ATTEST-MIXED-SYNTHETIC-TIERS-v1`：一万、十万、一百万稳定静态实体，
分别装载一千、一万、十万辆车，以及 437、4369、43693 条路线。这是混合合成短链记录
负载，不认证同规模城市运行质量。

## 测量方法

- AMD Ryzen 9 9955HX，16 核／32 逻辑处理器，66232508416 B 物理内存；Windows 11
  build 29683.1000，交流电、平衡电源方案。Rust 1.99.1 / LLVM 23.1.1，release 构建。
- 用户分别授权计时与计数／堆峰值窗口；预先编译，窗口内顺序运行，清除 `LF_ATTEST_SMOKE`。
  计时用时 176.83 s，计数／堆峰值用时 373.30 s，分别在 300 s / 480 s 预算内完成。
  共 15 个独立测试进程，全部通过，无超时或缺失档位。
- 计时按 baseline → step1 → arena → arena → step1 → baseline 执行。每进程每档暖机
  两次，记录五对样本；每对都验证 direct 与 capture + digest 的摘要相等。快照析构在
  计时区外；端到端耗时来自连续调用的单独计时，不将两个分段中位数相加。
- 每版本一个 `stats_alloc` 进程；每档直算使用两个独立 Region，断言分配字节完全相等。
  每版本两个独立 DHAT 进程，三档峰值逐项一致。两种分配器与计时进程分开运行。
- 下文每轮中位数来自五个样本；合并中位数来自两轮十个原始样本，偶数取中间两数均值。
  所有原始计时样本均保留，包括离群值；不把两轮中位数的均值称为合并中位数。

## 分配与堆峰值

单位为字节。分配量包含 `realloc` 净增长，既不是分配次数也不是同时存活字节；
DHAT 峰值是堆请求字节，不包含分配器元数据、分析器自身开销、栈或进程 RSS。

| 车辆数 | 原始版分配 / 堆峰值 | 第 1 项完成版分配 / 堆峰值 | 连续缓冲版分配 / 堆峰值 |
| -----: | ------------------: | -------------------------: | ----------------------: |
|   1000 |     749944 / 712968 |            726040 / 689064 |         751288 / 682312 |
|  10000 |   6802688 / 6432976 |          6563840 / 6194128 |       7135808 / 6446096 |
| 100000 | 62457616 / 58760352 |        60068560 / 56371296 |     64084304 / 57187040 |

| 车辆数 | 原始版 / 第 1 项归一化预算边界 | 连续缓冲版归一化预算边界 | 连续缓冲版现行路径分配 / 堆峰值 |
| -----: | -----------------------------: | -----------------------: | ------------------------------: |
|   1000 |                         593546 |                   617546 |               1174596 / 1004052 |
|  10000 |                        5933330 |                  6173330 |              11031493 / 9343765 |
| 100000 |                       59332418 |                 61732418 |            103909126 / 87867670 |

连续缓冲减少逐车独立缓冲，但增加范围与借用视图、连续缓冲容量余量。十万辆车时，
相对第 1 项完成版，累计分配增加 4015744 B（6.69%），堆峰值增加 815744 B（1.45%）；
相对原始版，分配增加 1626688 B（2.60%），堆峰值减少 1573312 B（2.68%）。
因此这是有内存代价的时间优化，不宣称所有内存指标改善。

归一化预算因范围和视图表的计费增加每车 24 B；十万辆车时从 59332418 B 增至
61732418 B，仍在本次 64 MiB 调用限额内。每档均验证边界值成功、少一字节返回
`LimitExceeded`。预算只覆盖指定归一化存储，不能冒充实际堆峰值，也不能承诺旧的
紧限额在新实现上仍成功。直算和现行路径调用退出后新增堆保留均为零。

## 采用结论与边界

按性能优先目标采用连续缓冲版：十万辆车档位相对第 1 项完成版，两轮耗时分别减少
19.63% 和 12.49%，合并中位减少 16.74%，额外堆峰值约 0.82 MB。一万辆车档位两轮
方向不一致，合并中位反而增加 2.16%；不宣称各规模均从连续缓冲获益。
第 3 项流式哈希继续暂缓，本次保持 SHA-256 和同一套摘要权威。

本次是授权窗口内的描述性对照，没有隔离操作系统；窗口前全机 CPU 快照为 16%。
镜像进程顺序不能消除频率、调度与缓存影响，每个样本也固定先 direct 后现行路径。
例如第 1 项版十万辆车第一轮有一个 116.36 ms 的现行路径样本，已保留在 JSON 中。
两轮范围不是置信区间，不能外推为生产 SLA 或长期上界。

原始日志与预编译二进制保留在本地忽略目录
`target/pr1008-digest-1991-20261023-r1`；JSON 保存逐样本数据、全部运行状态和内容哈希，
不承诺本地原始日志的外部下载或长期恢复。本轮未重测根认证墙钟或并发 tick 干扰；
计数测试附带输出的根认证分配与峰值作为原始运行记录保留，不扩充本报告的性能结论。

## 复现入口

分别检出表中三个源码提交，使用同一 Rust 1.99.1 工具链，在测量窗口之前编译：

```powershell
cargo +1.99.1 test --release --locked -p laneflow-runtime --test attestation_wall_clock_evidence --test attestation_allocation_evidence --test attestation_heap_peak_evidence --no-run
```

取得新的两个安静窗口后，确保 `LF_ATTEST_SMOKE` 未设置。按 JSON 的进程顺序运行
对应提交的预编译测试二进制：墙钟参数为
`--ignored --nocapture --test-threads=1 --exact direct_digest_wall_clock_evidence`，
计数与堆峰值参数为 `--ignored --nocapture --test-threads=1`。每版本计时两进程、计数
一进程、堆峰值两进程，保持顺序运行。环境或源码变化时新建证据修订，不覆盖本记录。
